react-aria-starter Design System

packages/design.md 에서 추출한 단일 공통 token / 패턴 reference 를 시각화한 문서입니다. OKLCH relative-color 모델과 light/dark adaptation 을 기반으로 하며, 시각 정본(runtime SSOT)이 아니라 정본을 저작할 때 참조하는 입력 가이드입니다 (ADR-142).

OKLCH relative color 11 base hues · 16-step scale light / dark adaptation React Aria [data-*] states 56 CSS · 2 token + 54 component

Overview

starter 56개 CSS 의 token/패턴을 중복 제거해 한 곳에 정규화한 reference. 모든 컴포넌트는 .react-aria-{Component} 단일 루트 클래스로 시작하고, 상태는 클래스 토글이 아닌 [data-*] 속성으로 표현됩니다.

스타일링 원칙

  • 단일 루트 클래스 .react-aria-{ComponentName}
  • 상태 = [data-*] 속성 (RAC 가 DOM 주입)
  • 색상 하드코딩 0건 — 전부 var(--*) 토큰
  • CSS Nesting &[data-*] 적극 사용

token vs 런타임 주입 변수

일부 var(--*) 는 token 이 아니라 RAC 가 런타임에 주입하는 레이아웃 변수입니다 (token 표에서 제외).

--trigger-width --origin --percent --tree-item-level --disclosure-panel-height

Colors

모든 색상은 OKLCH 색공간의 oklch(from … l c h) relative color 로 파생됩니다. 한 base hue → 16단계 스케일 oklch(from {base} {lightness-N} {chroma-N} h).

Base hue 11종

--tint 하나만 바꾸면 전 컴포넌트 강조색이 전환됩니다 (기본 --indigo). 칩을 눌러 tint 를 바꿔보세요.

16단계 스케일 — 현재 tint (indigo)

16단계 스케일 — gray (중립)

lightness 반전: --gray-100 은 라이트에서 "거의 흰색", 다크에서 "거의 검정". 시맨틱 토큰 (--text-color: var(--gray-1200))이 코드 변경 없이 양 테마에서 대비를 유지합니다. 우상단 Dark 토글로 반전을 확인하세요.

Elevation & Depth

라이트/다크에서 서로 다른 box-shadow 레시피를 쓰는 물리적 입체 표현. --popover-shadow 는 라이트 0 8px 20px rgba(0 0 0/.12), 다크 … /.5.

.button-base / .indicator / .inset 는 다중 inset shadow 레시피를 쓰고, 라이트/다크에서 하이라이트·그림자 방향이 반전됩니다.

composition spec(shadows.ts)은 none/sm/md/lg/xl/inset/focus-ring 6단계 elevation 토큰을 이미 보유 — starter 의 단일 --popover-shadow 는 lg/xl 단계에 대응. (Mapping 참조)

Shapes

border-radius 4단계 스케일. 완전 둥근 형태(9999px)는 토큰이 아니라 반복 리터럴 — pill 패턴 (18곳).

Components

상태는 클래스가 아니라 RAC 가 주입하는 [data-*] 속성으로 트리거됩니다. utilities.css 의 3개 공통 시각 패턴이 로컬 진입점 변수를 노출해 1줄 오버라이드로 변형됩니다.

Motion

표준 transition 200ms — 전체 CSS 36회. 토큰화되어 있지 않은 de-facto 표준값입니다.

De-facto standards

  • transition duration 200ms (36회)
  • border-width 1px / focus-outline 2px
  • 흰색/검정 alpha 오버레이 (specular highlight · inner shadow)

오버레이 진입/이탈은 [data-entering] / [data-exiting] + 런타임 주입 --origin 방향 transform.

Mapping

starter token/패턴을 composition 시맨틱으로 번역하고 ADR-142 의 어느 SSOT 로 반영되는지 기록합니다. composition 시맨틱 정의는 .claude/rules/css-tokens.md 가 정본입니다.

starter rule composition 시맨틱 ADR-142 반영 대상
⚠️ elevation 매핑 비대칭: starter 는 shadow 를 토큰화하지 않고 --popover-shadow 단일 값 + utility inset 레시피로만 표현합니다. composition spec 의 6단계 elevation 척도를 정본으로 두고 starter 레시피 흡수 여부는 별도 판정 대상입니다.

Do's and Don'ts

✓ Do

  • starter 업데이트로 다시 들어올 항목은 theme/tokens 가 starter 에서 가져온다.
  • OKLCH 모델 / 시맨틱 색상 / 상태 색상 네이밍을 채택한다.
  • Typography / Layout / Elevation / Shapes 의 token scale 을 채택한다.
  • utility 패턴(button-base / indicator / inset), focus-visible, [data-*] 상태를 채택한다.
  • Motion / Mapping / Appendix 는 top-level 확장 섹션으로 유지한다.

✕ Don't

  • composition 시맨틱(--bg-*/--fg-*/--accent-*)을 starter upstream 명칭으로 대체하지 않는다.
  • S2 TokenRef 체계, tint preset system 을 starter 명칭으로 덮지 않는다.
  • 금지된 M3 토큰은 채택하지 않는다.
  • design.md 를 runtime D3 SSOT / 런타임 계약으로 승격하지 않는다.
  • react-aria-starter/src 하위에 컴포넌트별 design.md 를 추가하지 않는다.

보충 — 알약이 아니라 노치 (supaste.com)

supaste.com 의 상단 네비게이션은 떠 있는 바가 아니라 화면 edge 에 매달린 노치다. 위 여백이 없고, 아래 모서리만 둥글고, 양옆 20px 어깨(오목 fillet)가 edge 와 잇는다. 스크롤·호버·클릭에 형태는 바뀌지 않는다 — 인터랙션이 아니라 형태 언어가 요점이다: "헤더는 화면의 일부다". 그리고 이 기법은 우리 header.css 에 주석으로 이미 들어 있다.

1위 여백 0

헤더 밴드 안에 6px 띄워 두던 것을 앱 상단 edge 에 붙인다. .panel-dock 이 margin: 4px 라 지금 헤더는 y=4 부터다 — 노치만 4px 위로 당기거나, chrome 행엔 dock 여백을 주지 않는다 (구현 시 판정).

2그림자는 아래로만

--shadow-lg 의 세 층 중 ambient 0 0 6px 을 뺀다. 남기면 edge 위로 번져 "떠 있음" 으로 되돌아간다.

3어깨는 표면색

20 × 20, currentColor 로 그려 --chrome-surface 를 따르게 한다. 다크 #202023 / 라이트 gray-50 어느 쪽에서도 노치와 한 몸이어야 한다.

4아래로만 자란다

Expanded 는 노치가 늘어나는 것 — 맥북 노치 앱이 펼쳐지는 것과 같다. 위로 자랄 곳이 없으니 방향이 하나뿐이고 morph 가 단순해진다.

5토큰은 그대로

표면색·컨트롤 크기·간격은 chrome island 토큰 그대로. 반경만 하단 18 / 24. rail·action bar 와의 구분은 색이 아니라 부착이다.

트레이드오프 1 — 좌/우 그룹과의 세로 정렬

노치(36px) 는 y=0 에 붙어 세로 중앙이 18 인데, 좌/우 그룹(48px) 은 y=4 부터라 중앙이 28 — 10px 어긋난다. 좌/우 그룹을 노치 밴드에 맞춰 위로 올리거나 (32px 컨트롤이라 padding 여지 4px), 어긋남을 두고 노치를 "다른 층" 으로 읽히게 두는 두 길이 있다. 제안 아트보드는 후자로 그렸다 — 판단은 라이트 테마까지 본 뒤.

트레이드오프 2 — 라이트 테마의 "구멍" 느낌

supaste 는 검정 노치라 edge 에 뚫린 구멍으로 읽힌다. 우리 라이트 테마는 bg-raised = gray-50 위에 bg-overlay = white 라 대비가 약하다. 아래 그림자 + 어깨만으로 "붙어 있음" 이 읽히는지 라이트에서 확인해야 한다 — 제안 아트보드의 다크 토글로 바로 볼 수 있다.

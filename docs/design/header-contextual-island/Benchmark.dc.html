HIG 가 못박은 규칙

치수compact 높이 36px, 아이콘 24px, 글자 15pt / 줄높이 22. expanded 최대 높이 144pt ≈ 192px. 크기는 3단이지 무한 확장이 아니다.
한 덩어리카메라가 갈라놓은 leading·trailing 은 하나의 정보로 읽혀야 하고, 색으로 그 관계를 강화한다. 둘 중 어느 쪽을 눌러도 같은 곳으로 간다.
예측 가능한 확대expanded 는 compact 의 확대판이다 — 요소가 같은 자리에서 자라야 하고, 내용이 재배치되면 morph 가 아니라 화면 전환으로 읽힌다.
minimal 은 2건일 때활동이 둘이면 하나는 붙고 하나는 떨어져 원 또는 타원으로 뜬다. 우리 Split 단계가 여기 대응한다.

도구들이 같은 문제를 푼 방식

Photoshop — Contextual Task Bar

캔버스 하단 · 떠 있는 바 · 대상별 액션

선택하면 그 대상에 맞는 액션만 커서 근처에 뜬다. 우리 현재 action bar 가 이 모델이다.

가져옴 — 대상별로 액션 세트를 바꾼다는 발상 자체
버림 — 위치. 상단으로 올리면 이동 거리가 늘지만, 알림과 같은 자리를 쓰려면 상단이어야 한다

Figma UI3 — 하단 툴바 + 우측 인스펙터

2024 개편 · 컨텍스트 도구를 하단 플로팅으로

상단 바를 없애고 도구를 하단 플로팅으로 옮겼다. 포럼에는 "컨텍스트 도구가 보이지 않고 숨겨졌다"는 반발이 남아 있다.

가져옴 — 떠 있는 단일 표면
버림 — 자주 쓰는 컨트롤을 숨기는 것. 아일랜드는 항상 보이되 내용만 바뀐다

Cavalry — Attribute Editor + Tool Settings

우측 고정 속성 편집기, 도구 설정은 별도

선택 대상의 전부를 우측 패널에 싣는 정통 방식. 빠짐은 없지만 시선이 캔버스를 떠난다.

가져옴 — 전부를 담는 자리는 그대로 둔다 (우리 Properties 패널)
버림 — 자주 쓰는 3~5개까지 거기 두는 것

명령 팔레트 (Raycast·Arc 계열)

입력에 따라 높이가 자라는 단일 표면

하나의 알약이 아래로만 자란다. 폭은 고정, 높이는 내용에 따라 — 우리가 폭 문제를 푸는 방식과 같다.

가져옴 — 폭 고정, 세로 성장
버림 — 모달 오버레이. 아일랜드는 작업을 가리지 않는다

미디어 HUD (재생·타이머류)

아트워크 + 진행 + 컨트롤을 한 카드에

왼쪽에 큰 미리보기, 가운데 정체, 오른쪽 수치, 아래 전폭 진행 — Live Activity 확장의 표준 골격.

가져옴 — Expanded 의 4구역 격자 (lead / mid / trail / bottom)
버림 — 앨범아트 같은 장식. 우리 lead 는 실제 렌더 미리보기다

우리 캔버스가 이미 가진 것

chrome island 토큰 · ADR-192 action bar

표면·그림자·반경이 이미 --chrome-* 토큰 한 곳에 모여 있다. 아일랜드는 새 표면이 아니라 그 토큰의 반경만 다른 변종이면 된다.

가져옴 — 표면·그림자·컨트롤 크기 전부 기존 토큰
버림 — 하단 action bar 는 남길지 별도 판정 (아일랜드와 역할이 겹친다)

결론 — 아일랜드에 담는 것

  • 대상별 자주 쓰는 컨트롤 3~5개 — 전부가 아니다
  • 라이브 미리보기 — 실제 렌더된 버튼·글자·이미지·표
  • 측정값과 상태 — 원본 크기, 행 수, 상태 4종
  • 스케일·목록 — 타입 램프, 컬럼 칩, 줌 프리셋 (전폭 bottom)
  • 알림 — 저장·진행·오류. 선택은 축약으로 함께 남는다

담지 않는 것

  • 대상의 모든 속성 — Properties·Styles 패널의 몫
  • 192px 를 넘는 편집 — 벽을 넘으면 패널로
  • 구조 변경 — 삭제·이동·부모 바꾸기는 캔버스와 Navigator
  • 영구적으로 남는 알림 — 오류 목록의 본체는 Monitor 패널

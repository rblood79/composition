### H1 — camera tier와 실제 picture 내용의 동치가 성립하지 않음 (open)

- 위치: `docs/adr/design/271-zoomed-out-lod-skip-small-elements-text-line-boxes-breakdown.md:21,30,31` / 본문 대안 A:53.
- 근거: renderer가 `resolveLodTier(camera.zoom, prevTier)`를 한 번 정하지만 글자 분기는 `tier === "textbox" && fontSize × zoom < T_text`다. 현재 `renderCommands.ts:3020-3039`는 picture hit이면 self span을 재기록하지 않고 곧바로 재생한다. 키의 data identity·width·height는 zoom으로 바뀌지 않는다 (`nodePictureCache.ts:197-198`). `nodeRendererText.ts:448`의 분기는 miss 때에만 그림으로 기록된다. 따라서 camera tier 하나를 키에 더하는 것으로는 기록 내용의 identity가 완성되지 않는다.
- 반례: 같은 textbox camera tier에 머무는 두 배율 zA < zB를 고르고 글자 크기 f가 `f × zA < 2 ≤ f × zB`인 텍스트를 둔다 (그 구간이 0.1~0.12라면 18px 텍스트). zA에서 줄 상자 picture 기록 → zB로 줌인 → camera tier·dataRef·크기·키가 그대로여서 줄 상자 hit → 설계상 paragraph여야 하는 2px 이상 글자가 계속 상자로 보인다. 역순이면 작은 글자가 계속 paragraph다. 새로 기록한 노드와 기존 hit 노드가 같은 zoom에서도 다른 정책을 따른다. 같은 tier 내 font 임계 통과에는 camera 히스테리시스도 작동하지 않는다.
- 해결 방향: 실제 기록 전에 요소/self span의 **유효한 이산 표현 상태**를 정하고, 그 상태가 달라질 때 키도 달라지도록 계약을 맞춘다. 여러 내부 text가 한 self span에 들어가는 경우도 포함한다. 연속 zoom을 무조건 키에 넣어 대안 B로 돌아가라는 뜻은 아니다. per-text 조건을 유지할지, owner별 일관된 단순화 조건으로 바꿀지 명시하고 content·damage·warmup이 동일한 결정 입력/signature를 사용해야 한다. 현재 warmup에 tier만 추가하는 처방은 `fontSize × zoom` 분기를 결정할 입력도 충분하지 않다.
- 검증 범위: 캐시 hit/record/replay 소비 경로와 문서의 판정·키 계약을 정적으로 대조했다. 위 배율 이동의 실제 픽셀·히스테리시스 동작은 **UNVERIFIED**.

### H2 — 서브트리 생략 가드가 자손의 상자 밖 paint를 보호하지 못함 (open)

- 위치: `docs/adr/design/271-zoomed-out-lod-skip-small-elements-text-line-boxes-breakdown.md:22` / 본문 대안 A:53 및 R1:101.
- 근거: `renderCommands.ts:1669-1675`의 `boundsMap`은 layout 상자이며 그림자·transform·paragraph paint extents를 넣지 않는다. `getSubtreeDamageBounds` (`subtreeCommandPatch.ts:237-250`)도 paint bounds가 아니라 hit bounds의 합집합이다. 기존 damage 처리는 이 합집합만 믿지 않고 서브트리 각 ID의 unsafe/글자 overflow를 별도로 검사한다 (`:593-601`). `visitElement`는 현재 요소만 unsafe set에 추가하고 (`renderCommands.ts:1606-1609`), document 자식은 별도 재귀로 방문한다 (`:1803-1831`). `hasSparseDamageUnsafePaint`의 `node.children` 재귀 (`:1887`)는 self span의 내부 shape이며 document 자손 closure를 대신하지 않는다. `unsafeContributorsWithin` (`:2247-2258`)도 개별 unsafe ID만 돌려준다.
- 반례: overflow가 열린 3×3px 부모 P 안에 2×2px 자식 C를 두고 C에 40px spread의 바깥 그림자를 준다. zoom 0.1이면 P와 layout bounds 합집합은 최대 변 0.3px로 T_skip=0.5px 아래다. C는 unsafe지만 P는 safe다. 전체 보기에서 선형 실행 경로가 P의 `!unsafe.has(P)`를 통과해 subtree jump → 화면에서 수 px를 차지해야 하는 C의 그림자가 통째로 사라진다. viewport 후보에 C를 추가해도 조상 P에서 서브트리를 제거하면 보호되지 않는다. 이 문제는 임계값 보정으로 paint bounds가 정확해지지 않는다.
- 해결 방향: 서브트리 paint 범위를 보수적으로 계산하거나, unsafe/알 수 없는 paint를 가진 **모든 자손의 정보를 생략 후보 조상까지 전파**해 생략을 금지한다. `textPaintOverflowIds`와 아직 범위를 확정하지 못한 글자도 다뤄야 한다. stream 생성·splice 때 이 요약을 갱신하며, 단순 `boundsMap` 합집합을 paint bounds로 간주하면 안 된다.
- 검증 범위: bounds 생성, unsafe 표식, document 자식 재귀, 후보 구성, damage의 별도 unsafe 처리를 정적으로 확인했다. 반례의 실제 스크린샷·오차 수치는 **UNVERIFIED**.

### M3 — tier 전환 뒤 완료된 idle pass가 새 tier를 채우지 않음 (open)

- 위치: `docs/adr/design/271-zoomed-out-lod-skip-small-elements-text-line-boxes-breakdown.md:31` / 본문 HC2:38 및 R7:106.
- 근거: 처방은 반대 tier 즉시 해제와 warmup **source**의 현재 tier 보관이다. 하지만 `requestNodePictureWarmup` (`nodePictureWarmup.ts:65-68`)는 source를 갱신한 뒤에도 `isPassDone(stream)`이면 예약하지 않는다. 완료 판정 (`:140-146`)과 pass/cursor 초기화 (`:81-91`)에는 stream·presentationRevision만 있다. zoom tier 변경은 이 두 값을 바꾸지 않는다. `canvasScene.ts:295-296`에서 full render마다 요청해도 같은 조건으로 막힌다.
- 반례: full tier에서 화면 밖 텍스트까지 idle warmup 완료 → 같은 stream에서 textbox로 전환하며 full 글자 picture 즉시 해제 → 현재 viewport만 textbox로 기록 → 충분히 idle 대기 → pass는 이미 완료라 textbox 화면 밖 picture를 만들지 않음 → 같은 tier에서 pan/줌아웃해 새 영역 노출 → 프레임 안 cold self-span 기록 재발. `flushWarmup`을 불러도 완료된 cursor를 초기화하지 않아 같다. 이미 완료된 pass뿐 아니라 진행 중 cursor 앞쪽 항목도 새 tier로 다시 처리되지 않는다.
- 해결 방향: pass의 identity·완료 판정·재시작을 유효 LOD 상태와 연동한다. tier/signature 변경으로 entry를 retire할 때 새 pass를 예약하고 cursor를 재설정하는 수명 계약을 명시한다. H1에서 정한 실제 기록 signature와 맞춰야 한다. 이 변경의 정확한 작업 범위 최적화는 ADR-272 실행자가 정하되, 여기서 삭제한 entry를 현재 tier로 다시 채우는 조건은 이 ADR이 보존해야 한다.
- 검증 범위: 기존 완료/예약/cursor 경로에 새 해제 정책을 대입한 정적 반례다. cold 기록의 ms·표시 간격 악화 크기는 **UNVERIFIED**. 단순 테스트 커버리지 부족이 아니라 HC2가 막으려는 실제 기록 경로의 재진입이다.

### M4 — @zoom run의 재실행 인자가 zoom을 보존하지 않음 (open)

- 위치: `docs/adr/design/271-zoomed-out-lod-skip-small-elements-text-line-boxes-breakdown.md:16,48`.
- 근거: `perf-baseline.mjs:3371-3375`는 이미 `...options`로 zoom을 결과 JSON에 보존한다. 반면 `applyAddRun` (`perf-ratchet-gate.mjs:498-508`)이 저장하는 `runs[key].args`는 `harnessArgsFrom` (`:544-558`)에서 만들며 이 함수는 `--zoom`을 넣지 않는다. 실행부 `perf-ratchet-run.mjs:298-309`는 run 키를 배율로 해석하지 않고 저장된 args만 전달한 뒤 결과를 해당 seed에 넣는다. 실제 초기 배율 적용은 `perf-baseline.mjs:3223-3241`에서 `options.zoom !== null`일 때만 일어난다.
- 반례: Phase 0의 지시대로 `runKeyOf`에만 @0.1을 추가하고 `--zoom 0.1` 보고 둘로 `--add-run 60:app-pages@0.1=...` 등록 → 저장된 args에는 zoom 없음 → pre-push `--run`이 기본 카메라에서 측정 → 기본 배율 카운트를 @0.1 기준에 대입 → 정상 변경도 잘못 block하거나 축소 개요 회귀를 놓친다. 이는 입력을 더 다양하게 시험하자는 커버리지 지적이 아니라 같은 조건이라는 gate 전제를 깨는 재실행 오류다.
- 해결 방향: `runKeyOf`뿐 아니라 `harnessArgsFrom`도 비기본 zoom을 CLI 인자로 직렬화하게 Phase 0 변경 계약에 명시한다. 기본 run의 호환성을 유지하고 등록·재실행 결과의 options/run key가 저장된 조건과 맞는지 확인한다.
- 검증 범위: 등록 → args 저장 → 하니스 실행 → seed에 결과 배치 → 초기 zoom 적용을 정적으로 연결했다. 실제 ratchet 재실행·원복 RED는 **UNVERIFIED**이며 실행하지 않았다.

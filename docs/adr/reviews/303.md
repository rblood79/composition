# ADR-303 Review Log

## Round 1 — 2026-11-07 (reviewer: codex)

**판정: 승인 보류 — HIGH 3 · MEDIUM 1 · pending 4.**

범위: ADR-303 Proposed 본문·breakdown, 선행 ADR-302, 설치 @react-spectrum/s2 1.8.2 소스, catalog rule·CSS token 매핑·DOM authored style·Canvas 파생 경로 정적 대조. 제품 코드·대상 ADR·상태 승격·다른 세션 문서는 변경하지 않았다.

1. **[HIGH h1] Table에 편집 Popover의 외관을 배정한다.** `design/303-container-layer-assignment-elevation-breakdown.md:30`과 본문 `:92`는 Table에 layer-2 + shadow.md + 1px border를 고정한다. 근거로 인용한 S2 `TableView.tsx:1554-1584`는 `editPopover`이고, 실제 사용처도 셀 편집 중 `RACPopover`의 className(`:1799-1809`)이다. 일반 Table은 별도의 `table` 스타일(`:251-285`, RACTable 연결 `:558-565`)을 쓰며 기본 gray-25, quiet transparent, 그림자 없음이다. **입력 → 결과:** 편집하지 않는 일반 Table 또는 quiet Table을 배치 → 평상시부터 불필요한 elevated 그림자가 생기고, dark 기본 배경이 gray-25에서 gray-75로 변하며, 배경 고정을 적용하면 quiet 투명성도 사라진다. **수정 방향:** 일반 Table과 편집 Popover를 별도 대상으로 분리하고 Table의 quiet·drop-target 분기를 보존한다. G0 추출기는 파일 전체의 속성뿐 아니라 스타일 심볼과 실제 바인딩 대상까지 식별해야 한다. 현재 배정값은 G1의 S2 일치 조건과 양립하지 않는다.

2. **[HIGH h2] Frame별 배경 층을 DOM으로 전달하는 경로가 성립하지 않는다.** breakdown `:63-65`는 노드별 `containerLayerOf(node, resolved)` 결과를 생성 CSS로 선언한다고 한다. 본문 `:94`는 사용자가 층 토큰을 배경으로 지정한 Frame도 컨테이너로 인정한다. 그러나 현 Frame rule은 `variants: {}`와 `skipCSSGeneration: true`(`componentRulesTable.ts:6629-6643`)이고, authored 배경은 DOM runtime의 인라인 스타일(`domBinding.runtime.ts:3369-3392`)로 전달된다. **입력 → 결과:** 같은 Frame 타입의 두 인스턴스에 layer-1과 layer-2를 각각 지정하고 아래에 container alias 소비자를 배치 → build-time CSS는 인스턴스별 층을 구분할 수 없어 DOM 자식은 상위 컨테이너 또는 루트 fallback을 읽는 반면, 설계대로 노드별 resolved 배경을 읽는 Canvas는 서로 다른 층을 읽는다. **수정 방향:** 공통 판정 결과를 노드별 DOM binding의 custom property 또는 동등한 동적 속성으로 전달하는 경로를 설계에 추가한다. authored fill의 토큰 역할을 해석 후에도 식별하고, 층 변경·해제와 Undo 시 후손 `_containerLayer` 재계산도 함께 연결해야 한다. G2에는 서로 다른 배경의 Frame 두 개와 편집 전후 전환을 포함한다. 정적 rule variant의 선언만으로 처리하는 범위와 runtime 선언이 필요한 범위를 명시해야 한다.

3. **[HIGH h3] alias의 명시된 CSS 출력이 등록되지 않은 변수를 읽는다.** 본문 `:93`·breakdown `:65`는 `{color.container}`를 `var(--container-bg, var(--base))`, 컨테이너 선언을 `var(--layer-2)` 등으로 고정한다. 현 단일 매핑(`tokenResolver.ts:222-238`)은 `{color.base}` → `var(--bg)`, `{color.layer-2}` → `var(--bg-inset)`, `{color.elevated}` → `var(--bg-elevated)`이다. shared/rendering 소스에는 `--base:`·`--layer-2:` 정의가 없으며 ADR-302 breakdown의 CSS 계획도 pasteboard 추가·raised 삭제이지 이 변수들의 rename이 아니다. **입력 → 결과:** 컨테이너 없는 루트의 alias 소비자 → DOM의 `var(--base)`는 유효 색을 만들지 못하지만 Canvas는 base hex를 출력한다. 컨테이너가 있어도 `--container-bg: var(--layer-2)`를 그대로 쓰면 같은 문제가 난다. CSS에서는 미정의 변수와 유효한 fallback이 없는 선언이 computed-value 시점에 무효화된다 ([W3C CSS Variables §3.1](https://www.w3.org/TR/css-variables-1/#invalid-variables)). **수정 방향:** 역할을 문자열로 변수명에 붙이지 말고 기존 `tokenToCSSVar`/`colorTokenCssValue` 매핑으로 선언값과 base fallback을 생성한다. 의도적으로 새 변수명을 쓰려면 theme emitter의 정의와 소비처 전환까지 별도 계약에 포함해야 한다.

4. **[MEDIUM m4] quiet Card 그림자의 대상 상자가 틀리다.** breakdown `:29`와 본문 `:92`는 quiet Card의 hover·focus·selected 그림자를 Card 배정으로 서술한다. 설치 S2는 루트 quiet `boxShadow: none`(`Card.tsx:111-126`)을 유지하고 `preview` 스타일에만 elevated 그림자를 둔다(`:263-268`). 이 스타일은 `CardPreview`에 실제 바인딩된다(`:599-614`). 현 catalog도 press 효과를 `.react-aria-CardPreview` part에 두어 같은 구분이 있다(`componentRulesTable.ts:2606-2613`). **입력 → 결과:** 이미지 preview와 아래 제목·설명을 가진 quiet Card를 hover → 루트에 shadow.md를 배정하면 이미지뿐 아니라 텍스트 영역까지 감싸는 큰 그림자가 생긴다. **수정 방향:** quiet 루트는 그림자 없이 유지하고 preview part의 hover·focus·selected에 배정한다. G0 fixture와 G1은 속성값뿐 아니라 대상 part도 대조해야 한다.

검증: 실제 설치 소스의 선언과 사용처 및 현재 consumer 경로를 읽어 대조했다. 위 결과는 설계 정적 판정이며 미래 구현의 실행 결과가 아니다. 테스트·생성 CSS 재생성·typecheck·번들 측정·Builder/Preview/Publish 브라우저·픽셀 parity·실제 끌기 동작은 **UNVERIFIED**다. ADR-302가 아직 선행 조건이므로 ADR-303 구현 gate 통과를 주장하지 않는다.

### m1 — quiet Card의 CardPreview 상태 그림자가 DOM에만 배선됐다

- 위치: `packages/shared/src/catalog/generated/componentRulesTable.ts:2566`, `apps/builder/src/builder/catalogRuntime/canvasBinding.ts:1371`, `packages/shared/src/catalog/runtime/rulePaint.ts:443`.

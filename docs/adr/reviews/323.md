# ADR-323 Review Log

## Round 1 — 2026-11-26 (reviewer: codex)

**판정 · 설계 보완 후 재검토**

### HIGH · 단일 날짜 between 조회는 화면에 걸친 일정까지 가져오지 못한다

11월 23일 이상 30일 미만 주를 보는 중 11월 21일~12월 2일 일정은 한 주 내내 보인다. 시작·끝 어느 쪽도 `between`을 통과하지 않고, 반대로 11월 30일에 시작한 일정은 포함된다. 기존 date 비교는 날짜·시각 값의 순서도 일 단위로 줄인다.

조회 계약을 `start < windowEnd && effectiveEnd > windowStart`로 명시하고 종일·시간대·끝 생략 규칙을 적용한다. 정확한 시각 비교가 불가능한 요청 형식은 완전한 상위집합을 받아 정밀하게 거르는 등 누락 없는 경로를 정한다. G3에 로컬·페이지 단위 원격의 경계 일정 id를 고정한다.

근거는 `docs/adr/design/323-timeline-event-calendar-gantt-breakdown.md:123` 및 `packages/shared/src/collections/view/comparison.ts:638`이다.

### HIGH · 기간 이동에서 일부 필드만 저장될 수 있다

`updateMany`는 셀별 거절을 집계한 뒤 유효한 필드를 커밋한다. 끌기 시작 후 끝 필드가 삭제되거나 쓰기 불가가 된 상태에서 놓으면 시작만 바뀔 수 있다. 편집 기록 한 건과 `ok:true`는 이 경우에도 가능하다. ADR-317 배치 쓰기 테스트가 부분 성공을 확인한다.

놓는 시점에 같은 세션 쓰기 안에서 대상 key와 기간 필드를 전부 검증하고, 하나라도 거절되면 기간 전체를 보존한다. 성공 알림과 When은 전체 커밋 뒤에만 실행한다. G5·G7에서 부분 거절 시 기록·이벤트 0건을 확인한다.

근거는 `docs/adr/design/323-timeline-event-calendar-gantt-breakdown.md:142` 및 `packages/shared/src/catalog/runtime/catalogPreviewSession.ts:1563`이다.

### HIGH · 빈 주·일 보기에서 키보드로 일정 만들기를 시작할 수 없다

빈 기간에는 편집을 열 일정 Button이 없다. §4.1의 머리에는 이동·보기 전환만 있고 생성 폼을 여는 이벤트는 빈 자리 누르기·끌기다. 키보드 사용자는 날짜·시간을 입력하는 Dialog에 도달할 수 없다.

머리에 RAC ‘일정 만들기’ 버튼을 두거나 동일한 폼을 여는 키보드 진입점을 정의한다. G5에서 일정 0건인 주·일 보기에서 키보드로 첫 일정을 저장한다.

근거는 `docs/adr/design/323-timeline-event-calendar-gantt-breakdown.md:127` 및 `docs/adr/323-timeline-event-calendar-gantt.md:52`이다.

### MEDIUM · 포인터 handler만으로는 약속한 Escape 취소가 전달되지 않는다

설치된 react-aria의 `dist/private/interactions/useMove.mjs:195`는 포인터 이동·해제·취소만 구독하고 자체 키 handler도 화살표만 처리한다. 끌던 중 Escape를 누르고 놓아도 §4.2에 날짜 쓰기를 막을 이벤트 경로가 없다.

Escape 취소를 담당할 기존 취소 경로나 D1 예외 범위를 정합하게 확정한다. G5·G7에서 취소 후 놓았을 때 원래 위치, 편집 기록 0건, When 0회를 확인한다.

근거는 `docs/adr/design/323-timeline-event-calendar-gantt-breakdown.md:81` 및 `docs/adr/323-timeline-event-calendar-gantt.md:114`이다.

### 검증 범위

기존 날짜 비교기로 주 양끝과 당일 시각 경계를 실행했다. Preview 세션을 사용하는 `adr317BatchWrite.test.tsx` 6건이 통과했다. 생성 진입점과 Escape는 설계의 조작 목록 및 설치된 `useMove` 소스에서 판독했다.

UNVERIFIED — 신규 컴포넌트의 Builder·Preview·Publish 통합 동작, VoiceOver, 번들 크기 및 성능은 구현 단계의 검증으로 남는다.

## Round 2 — 2026-11-26 (reviewer: codex)

**설계 수리 3건 확인, HIGH 1건 잔존.**

- **h1 · pending.** 반개방 구간의 겹침식은 원래의 장기 일정 및 창 끝 반례를 해결한다. 일 단위로 미리 줄이는 조건에는 누락이 남는다. `Pacific/Kiritimati`의 2026-11-23 시작 주를 열고 `2026-11-21T22:05:00-12:00`부터 `22:15-12:00`까지인 일정을 넣었다. 저장소의 `coerceDateText`는 오프셋을 보존하고, 실제 화면 시간은 11월 23일 00:05~00:15이며 겹침은 참이다. `viewDay(end)`는 11월 21일이고 `viewCompare("after", end, "2026-11-21")`는 거짓이다. 정밀 판정에 도착하기 전에 누락된다. 요청이 비교하는 날짜의 기준을 고정해 보수적 상·하한을 유도하거나, 그 기준을 모를 때 안전하게 넓혀 받는다. G3에 두 시간대의 실제 경계 입력을 둔다. [조회식](../design/323-timeline-event-calendar-gantt-breakdown.md)
- **h2 · fixed.** 놓기와 Dialog 저장 시점에 대상과 모든 기간 필드를 한 쓰기에서 재검증하고, 거절이면 변경·편집 기록·When 모두 0이다. 기존 붙여넣기의 부분 성공은 옵션 없는 경로에 유지한다. G5·G7이 필드 소실과 부분 거절을 검사한다.
- **h3 · fixed.** 빈 주·일에서 머리의 ‘일정 만들기’ Button이 컴포넌트 소유 폼을 연다. 작성자 규칙 없이 키보드로 생성·저장하는 흐름이 G4에 있다.
- **m4 · fixed (설계).** 끌기 동안만 owner document에서 Escape를 받고 capture·임시 스타일을 정리한 뒤 후속 놓기를 무시한다. G5·G7은 기록·When 0회를 본다. 이전 §4.2에도 Escape 취소 약속은 있었고 document 키 구독은 이번에 추가한 수단이다. Accepted 시 인용할 D1 목록에는 이 수단과 적용 기간을 그대로 남긴다.

끝 필드가 있고 OR를 전달할 수 없는 suffix에서 전량 조회·10,000행 상한·초과 시 명시적 거절은 부분 결과를 피하는 보수적 정책이다. 전량 수신이 해결하는 전송 한계와 수신 뒤 로컬 날짜 비교의 누락은 별개의 문제다. 실제 endpoint, 기간 쓰기, 끌기와 취소는 UNVERIFIED.

## Round 3 — 2026-11-26 (reviewer: codex)

**Round 2 h1 설계 수리 확인. 잔여 이슈 0건으로 설계 리뷰 승인 가능.**

breakdown §5.4.1의 이틀 여유와 반개방 구간 정밀 판정에 독립적으로 적은 일정 id를 대조했다. 저장소의 `coerceDateText`가 양쪽 오프셋을 보존하는지 확인하고 `viewCompare`로 후보를 거른 뒤 실제 순간으로 겹침을 판정했다.

- `Pacific/Kiritimati`의 11월 23일 00:05~00:15 일정은 저장 날짜가 11월 21일(−12:00)이어도 남았다.
- `Etc/GMT+12`의 11월 29일 23:45~23:55 일정은 저장 날짜가 12월 1일(+14:00)이어도 남았다.
- 11월 23~30일 창을 가로지르는 장기 일정은 포함됐고, 창 끝인 30일 00:00에 시작한 일정은 정밀 판정에서 제외됐다. G3에 양방향 경계의 기대 결과가 명시돼 있다. [보이는 기간의 조회](../design/323-timeline-event-calendar-gantt-breakdown.md)

이 검증은 수정된 조회식과 기존 날짜 비교기의 결과다. 실제 원격 페이지 수집과 Event Calendar 렌더링은 구현 단계의 검증으로 남는다.

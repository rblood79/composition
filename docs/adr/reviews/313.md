## Round 1 — 2026-11-16 (reviewer: codex)

판정: **수정 필요 — HIGH 2 pending, LOW 1 deferred**. main `3b9d7fb45`의 Proposed 설계 리뷰다. 제품 구현 판독이나 ADR 상태 승격이 아니다.

### H1 — 기존 동작 보존과 진입 간 동일 결과가 같은 입력에서 충돌한다

- 위치: `docs/adr/313-external-data-intake-standard.md:86` (HC5), `:206` (G2); `docs/adr/design/313-external-data-intake-standard-breakdown.md:47`, `:55-57`.
- 실제 소비: `apps/builder/src/builder/panels/datatable/utils/importPlan.ts:83-88`은 모든 셀을 문자열로 바꾸고 `grid/cellValue.ts:17-32`로 강제한다. 생성 JSON은 `DataTableCreator.tsx:399`에서 원본 행을 저장한다.
- 실행 반례: encoding 없는 boolean/number 필드에 `[{active: "Y", amount: "42"}]`를 기존 표로 가져오면 현재 `[{active: true, amount: 42}]`가 된다. 같은 JSON의 생성/API 경로는 문자열이다. G2가 요구하는 네 진입의 동일 결과와 경로별 기존 결과 보존을 함께 만족할 출력은 없다. no-encoding identity를 적용하면 기존 표 가져오기의 boolean/number 타입이 바뀌며 필터·정렬 회귀가 생긴다. 기존 강제를 모든 진입에 적용하면 HC5가 깨진다.
- CSV도 `dynamicTyping: false`로 바꾸면 기존 `42`·`true`가 `"42"`·`"true"`가 된다. 사용자가 encoding 후보를 확정하지 않은 경우 새 선언 없는 통과 규칙은 원래 값을 복원하지 않는다. 큰 정수만 예외라는 HC5와 R1 설명보다 영향 범위가 넓다.
- 해결: 외부 표현 decoding과 UI 문자열 입력 강제의 경계를 명시하고, 동일 결과 gate를 encoding이 확정된 입력에 한정하거나 기존 동작 변경을 명시적으로 수용해야 한다. 선언 없는 경우의 경로별 전후 기대값을 G1/G2 정답표로 고정한다.

### H2 — 원문 정보를 잃는 정규 값으로 원래 표현의 왕복을 보장할 수 없다

- 위치: `docs/adr/design/313-external-data-intake-standard-breakdown.md:20-29`; 본문 HC7 (`:88`), Decision 5, G2의 원래 글자 왕복 (`:189`).
- `numberText`의 `"4500000.00"`와 `"4500000"`은 같은 number `4500000`으로 합쳐진다. encoding에는 kind 외 인자가 없으므로 같은 입력 상태에서 원래 소수 자릿수를 구분해 되돌리는 함수는 존재할 수 없다.
- `compactDate`는 숫자 `20261106`과 문자열 `"20261106"`을 같은 ISO 값으로 읽고 출구를 문자열로 고정한다. 숫자 날짜를 받는 API에 재제출하면 JSON 타입이 달라진다. 이 항목은 원문 표현을 보존한다고 한 HC7의 직접 반례다.
- 더 심하게 `numberText`로 안전 범위 밖 정수 문자열 `"9007199254740993"`을 받으면 JS number 저장은 `9007199254740992`가 된다. G1의 큰 정수 JSON literal 보존만으로 quoted 숫자의 변환 손실을 막을 수 없다. 현재 문서는 numberText의 허용 범위·실패 조건을 규정하지 않는다.
- 현재 출구도 `packages/shared/src/collections/executeCollectionEndpoint.ts:166`의 `JSON.stringify(body)`와 `view/serialize.ts:149-153`의 문자열화를 사용한다. 새 계약은 표현 복원뿐 아니라 JSON body의 타입·큰 정수 literal까지 구체화해야 한다. 이는 아직 구현되지 않은 모듈의 런타임 버그 판정이 아니라 저장 계약의 정보 손실 반증이다.
- 해결: HC7을 값 동등성/원문 표현/JSON 타입 가운데 무엇으로 정의하는지 정하고, 필요한 wire type·scale·dateParts 길이를 필드 계약에 추가하거나 지원 범위를 제한한다. 손실 나는 numberText는 문자열 유지 또는 명시적 실패 정책을 둔다. 원문 형태가 서로 다른 대조쌍과 큰 숫자 문자열을 G1/G2에 넣는다.

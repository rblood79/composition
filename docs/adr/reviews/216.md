## Round 1 — 2026-09-11 (reviewer: codex)

판정: **수정 후 재리뷰**. HIGH 2 · MEDIUM 4 · LOW 1(deferred). 기준 HEAD `6f580f8c3`. 제품 코드·ADR 본문·breakdown은 수정하지 않았다. 기존 translations.ts 변경은 보존했다.

### 구조 및 코드 검증

필수 섹션과 3개 대안의 4축 평가는 모두 존재한다 (본문:7,25,37,70,80,95,97,108). 구조는 PASS, 계약 및 Gate 품질은 PARTIAL이다. Generator 확장 없음과 분리 4질문은 본문:11 및 breakdown:9에 명시되어 있다.

핵심 현행 주장 확인: band 배치(computeChartScene.ts:451), 예산용 ISO 감지(budget.ts:236,271), 고정 창 clamp(budget.ts:624), DOM의 명시 domain(RechartsChart.tsx:618-630), shared Slider의 다중 thumb(Slider.tsx:148-160)는 VERIFIED. 문자열 순 정렬 주장은 불일치(l7). G0가 예정한 번들 기준선과 thumb 실측은 아직 수행하지 않았으므로 수치/동작 PASS로 승계하지 않는다.

### 발견 사항

**h1 [HIGH] 집계 후 시간 좌표 보존 계약이 없다**

aggregate는 첫 ~ 끝 문자열만 반환한다. time + aggregate 또는 extrema fallback에서 transformed 점의 epoch를 결정할 수 없다. 근거: `docs/adr/design/216-chart-time-axis-format-window-breakdown.md:17,34-35; packages/specs/src/chart/budget.ts:355-399,722-741`.

**h2 [HIGH] 기존 scene byte 보존과 모든 창의 2-thumb 전환이 충돌한다**

미설정 기존 문서에도 가변 창을 적용하지만 기존 scene은 thumb 하나다. 두 번째 thumb를 넣으면 HC1이 깨지고 유지하면 두 leg 초기 컨트롤이 달라진다. 근거: `docs/adr/216-chart-time-axis-format-window.md:27-28; docs/adr/design/216-chart-time-axis-format-window-breakdown.md:32-37; packages/specs/src/chart/marks/windowTrack.ts:34-51`.

**m3 [MEDIUM] d3 파싱 규칙 및 왕복 오라클 명세가 실제 d3와 다르다**

%y 68은 2068이며 숫자 지시자별 폭 제한이 있다. format/parse 왕복은 손실 형식과 비정규 입력에서 항등이 아니다. 근거: `docs/adr/design/216-chart-time-axis-format-window-breakdown.md:26-28`.

**m4 [MEDIUM] n < fitEff에서 창 불변식을 만족할 수 없다**

0 <= start, end <= n, end-start >= fitEff는 데이터가 적거나 resize로 fitEff가 커지면 동시에 성립하지 않는다. 근거: `docs/adr/design/216-chart-time-axis-format-window-breakdown.md:32,36; packages/specs/src/chart/budget.ts:656-660`.

**m5 [MEDIUM] 파싱 실패 x를 기존 gap sentinel로 취급하는 계약이 성립하지 않는다**

빈 범주 라벨은 값이 있으면 정상 범주로 합산되고 gap은 값 undefined로 판정된다. 유효 epoch가 없는 행의 위치와 제외/단절 정책이 없다. 근거: `docs/adr/design/216-chart-time-axis-format-window-breakdown.md:15-16; packages/specs/src/chart/series.ts:118-147; packages/specs/src/chart/budget.ts:445-449`.

**m6 [MEDIUM] G5 성능 측정 조건과 실패 대안의 판정이 불완전하다**

R/S와 모델 p95만 있고 기기/DPR/visibility/캐시 상태/불리 조작/프레임 A-B 조건이 없다. onChangeEnd로 연기하면 드래그 중 재계산 기준 자체가 사라진다. 근거: `docs/adr/216-chart-time-axis-format-window.md:32,104,117; docs/adr/design/216-chart-time-axis-format-window-breakdown.md:61; .claude/rules/measurement-validity.md:13-23,59`.

**l7 [LOW] 현행 범주가 문자열 순 정렬된다는 Context가 코드와 다르다**

일반 경로는 첫 출현 순으로 categories에 push한다. 시간 간격 문제는 유효하나 현재 정렬 설명은 정정 대상이다. 근거: `docs/adr/216-chart-time-axis-format-window.md:9; packages/specs/src/chart/series.ts:125-134`.

h1 재현 조건은 time line/area에 `overflow=aggregate`를 주고 n>fitEff로 만드는 것이다. 누적 auto 또는 extrema fallback도 집계를 호출한다. epoch를 라벨과 분리해 보존하고 bucket 대표 좌표와 범위, 창 domain 기준을 정해야 한다. 두 leg가 같은 잘못된 값에 동의하는 것만으로 G2가 통과하면 안 된다. 양 끝 timestamp와 기대 x를 손계산한 검사가 필요하다.

h2는 기존 window 문서(n>fitEff, dimensionScale 미설정) 한 개로 반증된다. scene byte 보존 범위를 데이터 기하로 한정할지, 기존 컨트롤을 opt-in 밖에서 유지할지 계약에서 결정해야 한다. 본 리뷰는 HC 예외를 승인하지 않는다.

m3 실측: 설치된 d3-time-format 4.1.0을 pnpm exec node로 실행했다. utcParse('%y')('68') = 2068-01-01; utcParse('%Y%m%d')('20260305') = 2026-03-05. 공식 locale.js의 parseYear는 >68 분기, parseFullYear/parseMonthNumber는 4/2자 slice를 사용한다. 또한 2026-02-30은 2026-03-02로 정규화된다. ISO 기본 경로의 실제 달력 검사와 사용자 format의 d3 정규화 정책을 구별해야 한다. `%Y`로 임의 날짜를 왕복하면 월/일/시간이 소실되므로 날짜 항등 대신 지시자가 보존하는 성분을 대조하고, 문자열 항등은 정규형 입력으로 제한해야 한다. 공식 근거: [d3-time-format locale.js](https://github.com/d3/d3-time-format/blob/main/src/locale.js).

m4는 n=3, fitEff=10 또는 넓은 화면으로 resize하면 즉시 드러난다. 비활성/짧은 데이터에서는 [0,n]과 min(n,fitEff)를 쓰는 등 예외를 명시해야 한다. 현행 코드는 end를 Math.min(n,start+fitEff)로 제한한다.

m5는 valid / invalid / valid dimension 행에 모두 수치 값이 있는 입력으로 확인할 수 있다. invalid 행을 제거할지, 선 단절로 보존할지와 그때의 위치를 정의해야 한다. 기존 y 결측 규약을 이름만 재사용해서는 x 결측이 처리되지 않는다.

m6는 성능 fixture의 출처, 창 이동·확대에 따른 가시 집합 변화, cold/warm, foreground와 기기 조건, 측정 표본 수 및 전체 프레임 비용 A/B를 G5에 명시해야 한다. release-only 대안을 사용하면 별도 release 지연 기준과 표시 중인 데이터/선택 구간의 일치 정책이 필요하다.

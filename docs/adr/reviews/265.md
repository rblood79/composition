# ADR-265 Review Log

## Round 1 — 2026-10-16 (reviewer: codex)

판정: **설계 보완 필요 — MEDIUM 2건 open, HIGH 0건.** Phase 구현 판독이 아닌 Proposed 설계 리뷰다. 제품 코드와 ADR 상태는 변경하지 않았다. 기준 HEAD: `02f6cec67`; 다른 작업자의 Grid dirty 변경은 보존했다.

### M1 — 메뉴 허용 결과를 공유하는 특성 키가 명령의 실제 허용 조건을 구분하지 못한다 (open)

- 위치: `docs/adr/design/265-document-layer-edit-select-cost-breakdown.md:52`, 본문 `265-document-layer-edit-select-cost.md:89`.
- 현재 `canvasMenu.ts:141`의 `allowed`는 실제 명령을 계획하고, `packages/shared/src/catalog/commands/structure.ts:1686`의 Group은 부모의 타입이 아니라 전체 `NodeParent` identity가 같은지 검사한다.
- 실행 반례: 같은 페이지에 Frame F1의 Text A/B, Frame F2의 Text C를 둔다. A+B 선택 → Group 허용; 문서를 바꾸지 않고 A+C 선택 → `GROUP_PARENTS_DIFFER`, Group 제외. 두 선택은 타입·부모 타입·instance/origin/slot 여부·선택 수가 모두 같고 graph revision도 같다. 실제 `CatalogWorkspace.selectRecords`와 `catalogCanvasMenuItems(..., "action-bar", ...)`로 확인했다.
- 제안된 캐시를 적용하면 A+B의 true가 A+C에 재사용되어 거절될 Group이 표시된다. 반대 순서에서는 가능한 Group이 숨겨진다. graph step에서만 비우므로 선택 전환으로는 해결되지 않는다. 이는 현재 메뉴 구현의 결함이 아니라 문서에 제안된 메모화의 반례다.
- 해결: 명령별로 실제 의존하는 선택·부모 identity와 명령 인자를 포함하거나, 안전한 명령에만 캐시를 제한한다. 대안인 선별 술어를 택한다면 같은 반례에서 기존 허용 집합과 거절 사유를 유지하도록 명시한다. 타입이 같은 선택 사이에 결과를 공유하는 현재 문구는 제거해야 한다.

### M2 — 앞부분만 선택하는 드라이버로 기울기 0을 상수 비용이라고 확정한다 (open)

- 위치: `docs/adr/design/265-document-layer-edit-select-cost-breakdown.md:22`–23; 기울기 0인 자리를 제외하는 본문 `265-document-layer-edit-select-cost.md:89`.
- 현행 `apps/builder/scripts/perf-baseline.mjs:2132`–2136은 i=0부터 `ids[i++ % ids.length]`를 고른다. 기본 3초/100ms에서 seed 600과 5,000 모두 첫 30개만 선택한다. export된 실제 `FRAME_CLASSES.select`를 fake page/store와 고정 입력으로 실행해 양쪽 모두 index 0..29, 30회를 확인했다. 타이머만 microtask로 대체했으며 wall-clock 수치는 측정하지 않았다.
- 실행 반례: 현행 `CatalogWorkspace.prototype.selectRecords`와 `findPositionOfRecord`를 그대로 실행하고 read model의 형제 행 입력만 600/5,000개로 격리했다. 앞 30개 선택은 비교 합계 465/465라 G0 식은 기울기 0을 낸다. 같은 코드로 뒤 30개를 선택하면 17,565/149,565회다. `workspace.ts:677`의 선형 find는 그대로인데 측정 정책만 이를 상수로 오분류한다.
- 영향: 실제 큰 문서 뒤쪽 요소를 선택할 때 남는 C8의 문서 크기 비례 비용을 후보에서 제외할 수 있다. Layers 전체 펼침은 선택 대상 index를 바꾸지 않으므로 이 반례를 해소하지 못한다. 단순한 테스트 추가 요청이 아니라, 현행 드라이버와 의사결정식 조합의 잘못된 판정을 실행으로 확인한 것이다.
- 해결: 각 규모의 앞·중간·끝을 같은 비율로 방문하는 결정적 선택열을 G0에 명시하고 두 번의 동일 카운트를 확인한다. 기존 baseline 시나리오는 보존하면서 별도 선택 분포를 등록해도 된다. 기울기 0은 측정한 입력 범위의 결과로만 해석한다.

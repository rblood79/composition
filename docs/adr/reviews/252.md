# ADR-252 Review Log

## Round 1 — 2026-10-03 (reviewer: codex)

판정: 대안 A의 배치 통합·properties id 유지·탭별 D2/D3 및 다중 선택 계약 보존은 현재 코드와 맞는다. HIGH 0, MEDIUM 1, LOW deferred 1. P2의 단축키 등록 방식을 구현 전에 구체화해야 한다. ADR-251 구현과 G0~G5 gate 통과는 별도 조건이다.

1. **MEDIUM — 같은 scope에서 두 복사 정의를 탭 조건으로만 나누는 방식은 현재 dispatcher와 맞지 않는다.** docs/adr/design/252-design-panel-merge-breakdown.md:62와 §2 #5(:22)는 한 정의로 합치는 안과 두 정의+탭 조건 안을 열어 둔다. 현재 apps/builder/src/builder/hooks/useKeyboardShortcutsRegistry.ts:371-379는 canRun을 보지 않고 첫 key/scope 매치를 실행한 뒤 break한다. 정의 두 개를 panel:properties로 옮겨 둘 다 등록하고 canRun으로 Property=false / Style=true를 주면 Property 핸들러만 실행된다. Property 핸들러 내부에서 탭을 검사해 early return해도 키가 소비되어 Style 핸들러로 넘어가지 않는다. 격리 실행은 canRun 방식에서 propertyCalls=1/styleCalls=0, early-return 방식에서 propertyWrites=0/styleCalls=0/consumed=true를 확인했다. 별도 리스너를 그대로 두는 방식도 키보드 dispatcher가 canRun을 검사해 주는 구조가 아니므로 등록 단계의 배타성을 명시해야 한다. CommandPalette.tsx:266-270 및 :342-346 또한 canRun으로 활성/실행을 판정하지 않아 조건 없는 게시를 그대로 유지하면 비활성 탭 명령이 실행 가능으로 보이게 된다(팔레트 동작은 정적 대조이며 이번 격리 테스트에서는 렌더하지 않음). 한 물리 키 핸들러가 활성 view를 읽어 dispatch하는 안을 확정하거나, 비활성 정의를 등록 목록에서 제외하는 배타적 등록 방식으로 정한다. 이름이 분리된 메뉴 명령을 유지할 경우 메뉴/팔레트의 availability와 실제 실행 계약까지 맞춘다. 단순 canRun이나 handler early return만으로 키 충돌 0을 주장하지 않는다.

2. **LOW deferred — G3의 '위치 보존'은 저장된 배치 키와 최종 화면 좌표를 구분해야 한다.** docs/adr/252-design-panel-merge.md:134 / breakdown:20은 registry에서 styles를 제거하고 현재 정규화는 그대로 둔 채 properties 위치·높이를 보존한다고 한다. 현재 solver는 남은 visible rows를 다시 쌓고 cluster 크기로 zone origin을 계산한다(panelWorkspaceLayoutV4.ts:782-814). Styles가 Properties보다 위에 있는 정상 top-right V4 입력에서 제거 전 properties rect는 (967,204,233,200), 제거 후 (967,0,233,200)이었다. row 높이·cluster/zone/column 키는 보존되지만 최종 y는 보존되지 않는다. 제거에 따른 정상 재배치를 제품 결함으로 단정하지 않는다. G3를 placementZone/cluster/column/row height/visibility 보존과 삭제에 따른 row 재배치 허용으로 명시하는 편이 현재 결정에 맞는다. 절대 화면 좌표까지 보존하려면 현재 '정규화 변경 없음·변환 코드 없음'과 다른 설계가 필요하다. 이 항목은 LOW deferred이며 라운드 재개 사유로 두지 않는다.

검증 범위: HEAD db76cc301에서 ADR·breakdown, 패널 registry/UI/CSS, Properties·Styles host/clipboard, scope·shortcut 등록/commandRegistry·전체 메뉴·CommandPalette·agent 호출, V4 정규화/solver, 성능 하니스의 catalog facade 및 선택 driver를 정적으로 대조했다. 임시 격리 반증 3건 + 인접 기존 Vitest 18건 = 21/21 PASS. 이 PASS는 실패/재배치 조건을 확인한 것이며 ADR gate 통과가 아니다. 재현 소스 및 출력은 /private/tmp/adr252-review-probe.test.tsx와 /private/tmp/adr252-review-probe.json에 보관하고 작업 트리의 임시 TS 파일은 제거했다.

1. **[severity HIGH] [category: evidence-missing] Tree 펼침 writeback이 canonical 저장까지 도달한다는 전제가 틀립니다.**

   **근거:** [breakdown:31](/Users/admin/work/composition/docs/adr/design/239-tree-submenu-swatch-item-origins-breakdown.md:31), [breakdown:64](/Users/admin/work/composition/docs/adr/design/239-tree-submenu-swatch-item-origins-breakdown.md:64)는 Preview 토글이 배열을 저장하므로 배열 부재를 “한 번도 토글하지 않음”으로 해석합니다. 그러나 [App.tsx:718](/Users/admin/work/composition/apps/builder/src/preview/App.tsx:718)의 writeback은 Preview runtime을 갱신한 뒤 allowlist만 Builder로 전송하며, [builderPropSync.ts:25](/Users/admin/work/composition/apps/builder/src/preview/messaging/builderPropSync.ts:25)의 허용 값은 `isExpanded`뿐입니다. `expandedKeys`는 canonical·history·DB에 도달하지 않습니다.

   **실패 시나리오:** 중첩 Tree에서 펼침 콜백이 `expandedKeys: ["A"]`를 생성 → Builder 문서는 그대로 → 제안된 Canvas reader도 이전 값을 읽고, 저장·reload 후 토글 결과가 남지 않습니다. 따라서 배열 부재만으로 과거 토글 여부를 구분할 수도 없습니다.

   **해결 방향:** F3의 runtime 갱신과 문서 저장을 구분하고, 펼침을 문서 상태로 삼는 결정에 canonical mutation·history·저장까지의 배선을 포함해야 합니다. 이관 조건에서도 “미토글 문서”라는 잘못된 의미를 제거해야 합니다.

2. **[severity HIGH] [category: other] 펼침 결정과 Canvas 픽셀 동일 조건을 동시에 만족할 수 없습니다.**

   **근거:** [본문:34](/Users/admin/work/composition/docs/adr/239-tree-submenu-swatch-item-origins.md:34)와 [G6:113](/Users/admin/work/composition/docs/adr/239-tree-submenu-swatch-item-origins.md:113)는 기존 Canvas 픽셀 보존을 요구하지만, [Decision:82](/Users/admin/work/composition/docs/adr/239-tree-submenu-swatch-item-origins.md:82)는 펼침에 따라 자식 표시와 chevron 방향을 바꿉니다. 현재 [buildSpecNodeData.ts:1772](/Users/admin/work/composition/apps/builder/src/builder/workspace/canvas/skia/buildSpecNodeData.ts:1772)는 펼침 상태를 주입하지 않고, [skiaPrimitives.ts:2543](/Users/admin/work/composition/packages/specs/src/renderers/skiaPrimitives.ts:2543)는 `isExpanded === true`일 때만 아래쪽 chevron을 그립니다.

   **실패 시나리오:** `A > B`, `expandedKeys` 부재 → 기존에는 B가 보이고 chevron은 오른쪽 → 이관 후 B는 유지되지만 chevron이 아래쪽으로 바뀌어 픽셀 diff가 발생합니다. 기존 `expandedKeys: []` 문서는 배열을 보존하므로, 새 reader 적용 후 B 자체가 사라집니다.

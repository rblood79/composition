- **HIGH — Phase 4의 원자적 저장 계약이 현재 소비 경로와 충돌한다.** breakdown은 ADR-213과 표면이 겹치지 않는 형제라고 고정하면서(`docs/adr/design/212-data-panel-editor-redesign-breakdown.md:8`) Phase 4에서 `define_endpoint`를 같은 `DataChange`로 적용한다(`docs/adr/design/212-data-panel-editor-redesign-breakdown.md:88`). 현재 적용기는 이 op를 ADR-213 범위라며 명시적으로 거부한다(`apps/builder/src/builder/stores/utils/dataChange.ts:408-413`). ADR-212가 endpoint 적용기와 inverse/persistence를 소유할지, ADR-213의 해당 phase를 선행 의존으로 둘지 정해야 G3가 실행 가능하다.
- **MEDIUM — initial bundle 0 전제가 사실과 다르다.** 본문은 편집기가 lazy chunk라고 단정하지만(`docs/adr/212-data-panel-editor-redesign.md:26`), 현재 config와 editor shell은 정적 import다(`apps/builder/src/builder/panels/core/panelConfigs.ts:30`, `apps/builder/src/builder/panels/datatable/DataTableEditorPanel.tsx:35-42`). breakdown 파일 변경표에도 lazy 경계 도입 owner가 없다(`docs/adr/design/212-data-panel-editor-redesign-breakdown.md:117-134`). Phase 0/1에 lazy boundary와 로딩 fallback, G5 기준 chunk를 명시해야 한다.
- **MEDIUM — 성능 Gate가 측정 무결성 계약을 충족하지 않는다.** G1/G5는 p95와 전후 동일만 적고(`docs/adr/212-data-panel-editor-redesign.md:134`, `docs/adr/212-data-panel-editor-redesign.md:138`), 대표 문서, 가시 집합 변경/스크롤 같은 불리한 조작, 변경 전 arm, 기기/DPR/visibilityState/힙 상태를 고정하지 않았다. `.claude/rules/measurement-validity.md:19-25`에 따라 이 상태에서는 수치로 Gate를 통과시킬 수 없다.

### 근본 반론 (hate)

- **load-bearing 가정**: ADR-152 적용기가 Phase 4의 `create_collection + set_source + define_endpoint`를 한 원자적 변경으로 실행할 수 있다 (`docs/adr/design/212-data-panel-editor-redesign-breakdown.md:88`).
- **root**: 스키마 선언을 실제 소비 경로로 간주했지만 `define_endpoint`는 적용기에서 예외를 던진다 — 공격 축: 소비 경로 부재 (`apps/builder/src/builder/stores/utils/dataChange.ts:408-413`).
- **first nail**: 기존 `reduceDataOps` 단위 테스트에 세 op 묶음 1건을 넣어 예외 여부와 inverse를 확인한다. 수 초짜리 테스트로 Phase 4 구현 전체보다 훨씬 싸다.
- **판정**: 이 검사는 G0에 명시돼 있지 않고 G3에서야 늦게 드러난다 — 이슈 h1 (HIGH, pending).

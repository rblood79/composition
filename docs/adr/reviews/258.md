### h1 — HIGH: defaultValue 편집·undo가 Preview 상태에 적용되지 않는다

위치: `docs/adr/258-color-controls-canvas-gradient.md:95` (Decision 1), `docs/adr/design/258-color-controls-canvas-gradient-breakdown.md:56` (ruleDom 경로 유지).

입력·상태 → 결과: 동일 id의 ColorArea/ColorSlider/ColorWheel을 `defaultValue="hsl(0, 100%, 50%)"`로 마운트한 후 `hsl(120, 100%, 50%)`로 바꾸면 Canvas 함수는 새 색을 읽지만 RAC state는 이전 빨강을 유지한다. 같은 방식의 undo도 불일치하며 reload 때만 새 초기값이 들어간다. Preview에서 먼저 끌고 문서 기본값을 바꾸면 끌기 결과가 그대로 남는다.

근거: 설치 `useColorAreaState.mjs:27`, `useColorSliderState.mjs:26`, `useColorWheelState.mjs:56`가 `useControlledState`를 사용하고 `utils/useControlledState.mjs:19`는 최초 값으로 `useState`를 초기화한다. 현재 `runtime/domBinding.tsx:1644`의 Color key는 node.id다. JSDOM + React act로 세 hook 모두 같은 key에서 새 defaultValue 후 `hsla(0, 100%, 50%, 1)` 유지, 새 key 후 `hsla(120, 100%, 50%, 1)` 반영을 재현했다.

해결 방향: 작성 초기값 변경 시 RAC owner subtree를 다시 초기화하는 key/state reset 계약을 명시한다. Preview 자체 끌기와 관계없는 prop 편집에서는 상태를 유지하고, 문서 defaultValue 편집·undo/redo에서는 새 문서 기본값으로 초기화한다. G3에 끌기 후 작성 기본값 변경·undo를 연결한다. `delegatedDom.tsx:1755`의 기존 Slider가 참고 경로다.

### h2 — HIGH: 일반 CSS 색과 편집 중간 문자열이 두 consumer에서 예외를 만든다

위치: `docs/adr/258-color-controls-canvas-gradient.md:95`의 “string — CSS 색”, breakdown `258-color-controls-canvas-gradient-breakdown.md:46`, `:48`.

입력·상태 → 결과: 문서 defaultValue에 유효한 CSS인 `red` 또는 `rgb(255 0 0)`를 넣으면 설치 ColorArea SSR이 각각 `Invalid color value: red`, `Invalid color value: rgb(255 0 0)`를 던진다. `garbage`도 ColorWheel에서 같은 방식으로 던진다. 일반 문자열 필드의 편집·AI/import로 이 값이 commit되면 계획상 shared resolver의 parseColor와 Preview RAC가 모두 그 값을 받는다. 잘못된 값을 저장한 문서의 재열기에서도 반복된다.

근거: 현재 `document/valueType.ts:16`의 string 검사에는 색 파싱이 없다. 계획은 채널 검증만 추가하고, 공용 함수에는 parseColor 사용을 명시한다. 설치 RAC renderToString으로 위 입력들의 예외를 실행 확인했다. RAC가 실제 받는 범위는 [ColorArea 공식 Value 설명](https://react-aria.adobe.com/ColorArea)의 parseColor 기반 값이다.

해결 방향: “설치 parseColor가 받아들이는 색 문자열”로 D2 범위를 한정하거나 지원 CSS 구문을 명시적으로 변환한다. graph/library/default/AI/import 경계에서 같은 파싱 검사를 적용하고 실패는 transaction 전 거부한다. 패널은 입력 중 draft를 유지하고 유효한 값만 commit한다. 빈 값의 의미도 fallback/거부 중 정하고, 실패 시 revision 불변을 확인한다.

### m1 — MEDIUM: 필드별 편집과 조합 거부만으로는 색 공간 전환이 완결되지 않는다

위치: breakdown `258-color-controls-canvas-gradient-breakdown.md:48`, ADR `:137` (G3 실패 대안).

입력·상태 → 결과: 기본 ColorSlider의 `channel=hue` · `defaultValue=hsl(...)`에서 사용자가 rgb/red로 바꾸려 한다. 먼저 colorSpace=rgb를 고르면 hue는 rgb에서 무효, 먼저 channel=red를 고르면 현재 HSL에서 red가 무효다. 조합 검증을 지키면 두 직접 전환이 모두 거부되고, 검증을 생략하면 RAC가 `Unknown color channel: hue/red`를 던진다. alpha 등 임시 채널을 경유하는 우회가 필요하며 “검증기 메시지로 안내”만으로 일반적인 색 공간 선택이 동작하지 않는다. 명시 x/y 축을 가진 ColorArea도 같은 전환 문제를 갖는다.

근거: `CatalogPropertiesPanel.tsx:333`는 `handlePatch({ [key]: value })`로 단일 prop을 쓴다. 설치 ColorSlider SSR에서 (hsl defaultValue + red), (hsl defaultValue + colorSpace rgb + hue)는 예외, (hsl defaultValue + colorSpace rgb + red)는 정상임을 확인했다. 공식 [ColorSlider API](https://react-aria.adobe.com/ColorSlider)의 colorSpace와 channel은 함께 유효한 조합이어야 한다.

해결 방향: colorSpace 변경 시 무효 channel/xChannel/yChannel을 유효한 기본 축으로 바꾸거나 해제하는 하나의 CatalogCommand/transaction을 정한다. 미지정 colorSpace는 parseColor(defaultValue)의 유효 공간으로 검사한다. 저장된 값을 유지할 전환 정책과 undo 단위를 명시한다. 의존 enum 필터를 포기하더라도 원자적 전환은 필요하다.

### m2 — MEDIUM: ColorSlider의 값 출력이 빈 텍스트로 고정된다

위치: breakdown `258-color-controls-canvas-gradient-breakdown.md:55`의 `Label {label} + SliderOutput + SliderTrack > ColorThumb`, `:56`의 기존 DOM 경로 재사용.

입력·상태 → 결과: ColorSlider의 기본 SliderOutput(children="")에 현재 값의 text owner가 붙지 않는다. `valueBindings.ts`는 Slider만 찾으므로 Canvas 출력은 빈 글자이고, `domBinding.tsx:758`가 RAC SliderOutput에 children=""를 명시해 RAC가 제공할 값까지 덮어쓴다. `hsl(120,100%,50%)`/hue의 설치 SSR은 children 생략 시 “120°”, children="" 전달 시 빈 output을 냈다. label도 미작성 상태에 빈 문자열을 전달하면 RAC 기본 “Hue”가 사라진다.

근거: `runtime/valueBindings.ts:164-184`의 RAC_TEXT_OWNERS/포맷은 `Slider` + 숫자 Intl.NumberFormat 전용이며 `:235`의 dependent 갱신도 그 owner 목록을 따른다. 현재 `domain/componentTraits.ts:350-351`의 SliderOutput/SliderTrack owners도 Slider만 허용하므로 새 원본에 맞춰 함께 확장해야 한다. 이는 새 output 노드를 둔 결정이 실제로 글자를 제공하는 소비 계약의 누락이다.

해결 방향: shared 값 소유·포맷·dependent 갱신 경로에 ColorSlider를 추가한다. Canvas는 설치 Color.formatChannelValue(channel, locale)에 맞춰 문서 초기값을 표시하고, DOM은 미작성 output children을 생략해 RAC 실행값을 표시한다. 미작성 label의 기본 채널명과 작성 label 우선순위를 명시하고 두 consumer에 적용한다. Slider의 기존 숫자 포맷과 소유 경계는 보존한다.

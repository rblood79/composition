- **load-bearing 가정**: "격차의 직접 원인이 입력 공급 부재다" (`ADR:93` 수정 전)
- **root**: 소비 경로 부재 — 공급한 값을 읽는 경로가 definite 주축에서 닫혀 있다 (`flex.rs:332`, 측정 케이스는 definite). 이것이 무너지면 Decision·Gate·Phase 구성이 전부 무의미해진다. 공격 축: **소비 경로 부재**
- **first nail**: production ListBox 를 `height` 없이 (주축 AUTO) 제약 flex 안에 두고 `overflow:visible` 로 1회 측정 — 케이스 1줄 vs 프로그램 Phase 0~4 + 커널 조건 확장
- **판정**: 종전 G0 는 "Chrome 이 content 기반인가" 를 물어 이 nail 을 커버하지 못했다 → 이슈 #1 (HIGH) · G0 를 이 nail 로 교체하여 fixed

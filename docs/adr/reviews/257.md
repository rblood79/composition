# ADR-257 Review Log

## Round 1 — 2026-10-10 (reviewer: codex)

## Round 1 — Codex 설계 리뷰 (codex exec read-only, 2026-10-10)

판독: HIGH 3 · MEDIUM 4 · LOW 1 (deferred). 실행자 확인:

- **Chrome 실측** (headless Chromium, box-sizing border-box · padding 0 8px · min-width 0, 폭 300): flex `1 1 0`·`2 2 0` = 105.33 · 194.67 / flex 1·1·1 = 100 · 100 · 100 / colSpan 흉내 flex 2·1 = 194.67 · 105.33 / grid `repeat(3, minmax(0,1fr))` + span 2 = 200 · 100 / grid `minmax(0,1fr) minmax(0,2fr)` = 100 · 200.
- h1: Codex 의 「엔진 ≠ CSS」 는 Chrome 실측과 다르다 (엔진 = Chrome). 그러나 ADR 의 근거 「RAC 와 차이는 정수 반올림 하나」 는 틀렸다 — flex 로는 padding 이 있는 칸의 fr 비율을 낼 수 없다. HIGH 유지, root cause 정정.
- h2 · m3: Chrome 실측으로 확인. 행마다 같은 명시 트랙의 grid 가 h1 · h2 를 함께 푼다 — 대안 재평가 필요.
- h3: resolver.ts:1073 · 1172 (바운드 행 fixed 150) · tableViewChildStyle.ts:64 확인.
- m4: 로컬 S2 1.8.0 원본 (scratchpad s2pkg — package.json version 1.8.0) Cell 의 `showDivider = false` · `align || 'start'` 확인.
- m1 · m2: 코드 인용 확인 (실행 반례는 Codex 의 메모리 실행 — 실행자 재실행 안 함, UNVERIFIED).
- README 개수 (열림 3 · 합계 284) 일치.

종합: **승인 불가** — Decision (대안 A) 의 load-bearing 가정이 h1 · h2 로 깨졌다. 수리 방향: 대안 C 를 「행마다 같은 명시 트랙 grid (Row 상자 유지)」 로 다시 세워 A 와 재비교, 바운드 기본 폭 · TableView intrinsic 폭을 G0 · BC 에 포함, ColumnSize/ColumnStaticSize 타입 분리, align · showDivider 는 S2 대로 (또는 명시 확장).

### H1 — step 1의 child_sizes와 shrink-only 조건으로는 측정 필요 여부를 판정할 수 없음

- 위치: `docs/adr/design/268-flex-row-definite-content-size-suggestion-breakdown.md:37`; 본문 Alternatives A / Decision.
- 현재 `tree.rs:3060-3076`은 nowrap row의 auto 컨테이너 item을 `deferred_to_resolve`로 미루고 step 1 크기를 `(0, 0)`으로 둔다. 실제 max-content는 2-b에서 들어온다. 따라서 step 1 `child_sizes`를 hypothetical main으로 합산하면 필요한 floor 측정이 누락된다.
- 재현: row 300 > A(width 200, 자식 width 150) + B(width auto, 자식 width 200). 제안 pre-scan은 `200 + 0 < 300`이라 A 측정을 건너뛴다. 현재 native engine은 **100/200**, Chrome 155 `getBoundingClientRect`는 **150/200**. B가 뒤에 오는 순서라 2-b 순차 처리로도 A를 측정할 시점에는 B의 intrinsic이 없다.
- 별도 반례: row 500 > width 200, flex-basis 0, grow 0, 자식 width 150인 단일 item. shrink 0/1 모두 Chrome **150**, 엔진 **0**. 행이 줄어들지 않아도 auto minimum이 basis의 hypothetical size를 clamp한다. [CSS Flexbox §9.2 및 §9.7](https://www.w3.org/TR/css-flexbox-1/#algo-main-item)은 이 순서를 정의한다.
- 수정 방향: auto item의 intrinsic과 명시 basis·min/max를 반영한 실제 hypothetical size를 확보한 뒤 판단한다. 측정 생략은 전역 shrink 여부나 `flex-shrink > 0` 대신 auto minimum이 결과에 영향을 줄 수 없는 item인지로 결정한다. 위 두 반례를 G1에 포함한다.

### H2 — with_measure_pass가 임시 style.width를 복원한다는 전제가 틀림

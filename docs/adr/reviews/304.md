### h1 — 고정 grid 열이 접힘·숨김을 따르지 않음 (HIGH)

- 설계 위치: `docs/adr/design/304-app-frame-layout-presets-breakdown.md:101`, `:138`, 본문 Decision 4 (`docs/adr/304-app-frame-layout-presets.md:101`).
- 입력 → 결과: 200px 사이드 열의 app-shell에서 tablet 접힘을 적용하면 패널은 42px이지만 content 시작점은 x=200이라 158px이 빈다. mobile에서 패널을 display:none으로 바꿔도 content 시작점은 x=200이고 390px 화면에서 콘텐츠 폭은 190px뿐이다.
- 실행: Chromium에서 문서의 명시 grid 숫자 선·열·패널 크기 변화만 구성해 측정했다. 1920/768/390에서 트랙은 각각 `200px 1720px` / `200px 568px` / `200px 190px`; contentX는 전부 200이었다. 실제 App frame 구현이나 Builder parity 검증은 아니다. 명시 트랙이 grid-template-columns로 정의되는 계약은 [W3C CSS Grid](https://www.w3.org/TR/css-grid/#explicit-grids)와 대조했다.
- 원인: tablet에는 컨테이너 층을 두지 않고 mobile에는 자식 숨김만 둔다. runtime 접기 버튼·작성 prop으로 접을 때도 같은 문제가 남으므로 단순 breakpoint별 42px 고정만으로는 부족하다.
- 방향: 부모 트랙과 패널 폭이 같은 유효 접힘 상태를 소비하도록 설계하거나, 패널의 유효 폭이 트랙을 결정하게 구성한다. mobile은 콘텐츠가 전폭을 차지하도록 트랙·배치를 함께 바꾼다. G2는 패널 폭 외에 content 시작점·폭도 비교해야 한다.

### h2 — 적용 식별 충돌로 새 preset 클릭이 무시됨 (HIGH)

- 설계 위치: breakdown `:100` (새 세 preset을 PRESET_ORDER 선두), `:102` (app-header의 header/content), `:116` (적용 판정 그대로), 본문 `:99` (기존 10개의 키·슬롯·값 유지).
- 현행 경로: `layoutPreset.ts:75`의 catalogAppliedPreset은 슬롯 이름 열만 비교해 PRESET_ORDER의 첫 일치를 반환한다. `LayoutPresetSelector/index.tsx:120`은 그 값과 클릭한 키가 같으면 적용을 생략한다.
- 입력 → 결과: 기존 vertical-2 layout (header/content)에 계획대로 app-header를 선두에 등록하면 catalogAppliedPreset이 vertical-2 대신 app-header를 반환한다. 사용자가 app-header를 눌러 Frame header를 Nav instance로 바꾸려 해도 클릭 핸들러가 즉시 return한다. app-shell과 app-shell-end도 바깥 슬롯 이름이 같아 같은 식별 충돌이 생긴다.
- 실행: 실제 catalogAppliedPreset에 기존 슬롯 열을 주고 계획의 app-header 정의·선두 순서를 임시 등록했다. 등록 전 vertical-2 → 등록 후 app-header를 확인했다. 임시 메모리 변경은 finally에서 복구했다.
- 방향: 이름 열 외에 슬롯 definitionId·구조·end 내용 등 실제 식별 정보를 판정에 반영하고, 표시용 PRESET_ORDER와 지원 preset의 판정 집합을 분리한다. 결정 1(b)를 선택해 표시 순서에서 기존 키를 빼더라도 기존 layout의 적용 판정은 유지해야 한다.

### m1 — 안쪽 적용이 바깥의 responsive item 배치를 삭제함 (MEDIUM)

- 설계 위치: breakdown `:111`의 명령 무변경, `:115`의 슬롯 Frame에서 적용 허용, 본문 R2/G1의 바깥 grid 선 보존 계약.
- 현행 경로: `layoutPreset.ts:190`은 PRESET_RESPONSIVE_OWNED_KEYS를 전체 정리한다. 그 집합은 `presetStyle.ts:51` → `responsive.types.ts:206`을 통해 gridColumnStart/gridRowStart 및 다른 responsive item 축을 포함한다.
- 입력 → 결과: layout 루트에 dashboard-widgets 적용 → widgets 슬롯을 골라 vertical-2를 안쪽 적용. 바깥이 준 widgets의 tablet gridColumnStart=1 / gridRowStart=3이 삭제되어 base의 3열/2행 배치가 살아난다. 바깥 tablet은 2열이므로 안쪽 편집만으로 widgets가 하단 전폭 위치를 잃는다.
- 실행: CatalogWorkspace.execute를 통해 위 두 실제 명령을 실행했다. 적용 전 tablet gridRowStart=set("3"), 적용 후 해당 키 없음이 확인되었다. 새 UI가 노출할 기존 명령 동작의 결함이다.
- 방향: preset이 자식 배치를 위해 소유하는 container 축과 부모에서 자신의 위치·크기를 정하는 item 축을 분리하고 responsive 정리에도 같은 경계를 적용한다. base grid 선 보존에 더해 tablet/mobile grid item 선을 보존한다.

### 이슈

- **M1 — 기본 한도 기준값 부재.** 한도를 「명시」 하는 결정이 올리는 것인지 내리는 것인지 모르는 채 R3 (낮아서 thrash) 와 HC4 (90 % 초과 0) 가 적혀 있다. Skia 소스의 `GrResourceCache` 기본은 96 MiB 로 알려져 있지만 이 빌드에서 읽지 않았다 (UNVERIFIED). 90 % 규칙은 Skia 가 예산 초과 때만 퇴거하므로 「working set < 0.9 × 한도」 여유 규칙이지 thrash 검출이 아니다. → Phase 0 이 scratch context 로 `getResourceCacheLimitBytes()` 를 읽어 결정 2 의 기준값으로 두고, HC4 · R3 문구를 고쳤다.
- **M2 — 핸들 수명.** 지금은 `resize` 마다 `createGPUSurface` → 새 GL 핸들 · GrDirectContext, 옛 것은 삭제되지 않는다 (코드 사실 표에 없었다). Phase 2 가 「resize 는 같은 grContext 재사용」 을 두면 복원 경로 (`:1553` → `resize`) 에서 abandoned context 를 재사용 → `MakeOnScreenGLSurface` null → `createGPUSurface` 의 SW 폴백으로 조용히 넘어간다 (사용자 가시: context 소실 뒤 성능 절벽, 경고 1 줄). → F3 보강 · R5 를 HIGH 로 올리고 소유자의 abandoned 상태 · `delete()` · `deleteContext` · G2 unit 「복원 뒤 backend GPU · GrContext 1 개 · 옛 핸들 삭제」 + 원복 RED · G0 에 현재 생성 수.
- **L3 — 인용 drift** (breakdown 표 `:566 ~ 571` → `:575 ~ 580`).

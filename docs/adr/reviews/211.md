## 발견 사항

### h1 HIGH — 합계/평균 및 others의 의미

D:40은 값 필드가 퍼센트면 평균을 쓰지만 현행 `series.ts:102-107`은 범주별 sum이고 `presentation.ts:476-511`은 숫자 표시만 소유한다. 같은 원본 0.1/0.9가 decimal이면 집계 1, percent이면 0.5가 된다. 이를 valueFormat으로 판정하면 표시 옵션 변경으로 기하가 달라지고, 별도 메타데이터를 뜻한다면 그 입력 채널이 없다. 평균을 사용하면 G2의 일괄 '집계 합=원본 합'(ADR:115)도 성립하지 않는다. 중복 범주의 행 수가 다르면 '범주 평균'과 '행 평균'도 다르다.

D:47의 '값 내림차순'은 다중 시리즈 radar/pie/radial에서 어떤 값을 정렬할지 없다. 음수 pie는 현행 `marks/pie.ts:194-209`에서 절댓값으로 면적을 낸다. +10/-10을 others로 sum하면 면적이 사라질 수 있다. radial others는 합산 후 domain 재계산 여부가 없고 현행 `marks/radial.ts:145-153`은 domain 밖을 clamp한다.

최소 수정: 집계 연산을 표시 포맷에서 분리하고 sum/mean의 입력 단위·가중치·결측·음수 계약을 명시한다. 극좌표 종류별 ranking key, 시리즈별 합산, others synthetic identity/원본 '기타' 충돌, domain 재계산을 정한다. G2는 sum/mean/선택/others 별 독립 오라클로 나눈다. 자동 의미 추정 대신 명시 설정 또는 지원 제한을 선택할 수 있다.

### h2 HIGH — 공통 x LTTB로 모든 시리즈 극값을 보장할 수 없음

D:41/104는 첫 시리즈 또는 합산 시리즈로 공통 x를 선택하고 D:79/ADR:115는 극값 위치 오차 ≤1 슬롯을 요구한다. 첫 시리즈가 평평하면 다른 시리즈의 좁은 spike는 선택에 영향을 주지 않는다. 합산 방식도 B의 +spike와 C의 -spike가 상쇄되면 동일하다. 선택되지 않은 구간에 spike를 놓으면 중요한 극값이 사라지며 '위치 오차'를 계산할 대상도 없다. 이는 구현 버그 예측이 아니라 제안한 입력 축약의 정보 손실 반례다.

최소 수정: 시리즈별 오차/극값 보존 목표와 허용 손실을 정하고 multi-series 선택 규칙을 다시 설계한다. union이 fit을 초과하는 경우의 우선순위도 필요하다. P0에 평탄 기준 시리즈·서로 다른 위치 spike·상쇄 시리즈·결측 gap fixture를 넣고, 선택 알고리즘과 무관한 원본 극값/픽셀 오라클로 검증한다. 합계 접미는 원본 점 선택인 LTTB에 붙이지 않는다.

### h3 HIGH — 개수 fit이 가독성과 총비용 계약을 보장하지 않음

D:16-23은 종류별 fit만 정한다. 반지름60, minArc6이면 fit62지만 pie 값 [1000,1]의 작은 조각 호는 약0.377px다(`marks/pie.ts:264` 값 비율 sweep). 개수2≤fit이라 개입하지 않는다. 따라서 '최소 호 길이' 보장과 'fit 이하 무변경'은 동시에 주장할 수 없다. 여러 동심 pie 링은 안쪽 반지름과 링 두께도 제한해야 한다. stacked bar/line/area/radar는 fit에 시리즈 수가 없으므로 폭이 같아도 시리즈 수에 따라 점/마크 비용이 증가한다. '컬럼 수와 분리' 주장(ADR:124)을 구조로 증명하지 못한다.

작은 plot 폭4, minSlot8이면 fit0이다. D:40의 ceil(n/fit), D:47의 fit-1, LTTB의 0/1/2점 처리 모두 미정이다. Python 독립 산술로 fit0 및 pie 호0.3766을 확인했다(제품 테스트 아님).

최소 수정: 개수 예산과 최소 실제 크기를 구분한다. 최소 호 보장을 포기할지, 값 비중 기반 묶기를 할지 명시하고 HC를 맞춘다. 다중 시리즈/안쪽 링/부분 sweep/간격 예산과 fit0·1·2의 렌더/진단 정책을 넣는다. 총비용 보장은 시리즈 수를 포함한 제한 또는 측정 범위 한정으로 표현한다.

### m1 MEDIUM — 축 종류 자동 추론의 의미 전환

D:27-30은 파싱 가능한 모든 값을 순서/기간 축으로 취급한다. `series.ts:42-49,112-118`은 문자열화와 첫 출현 순서이며 시간 정렬은 하지 않는다. 숫자형 ID '001','002'도 기간/수량 축처럼 집계될 수 있고, 날짜가 역순이면 '인접 묶음'이 기간을 의미하지 않는다. LTTB x가 timestamp인지 categoryIndex인지, 불규칙 간격을 재현하는지도 없다.

최소 수정: raw 타입 보존, 정렬·동률·결측·엄격 ISO 판정과 x 거리 의미를 명시한다. 숫자형 ID를 자동 집계하지 않는 opt-in 또는 보수적 auto 규칙을 정하고 overflow×종류의 전체 지원표를 추가한다. 현재는 극좌표 window만 금지돼 bar others, line aggregate 등의 의미가 열려 있다.

### m2 MEDIUM — 새 prop 전달 경로 누락

D:60-73에 `Chart.binding.ts` accepts 등록이 없다. `toRacProps.ts:88`은 accepts만 투영한다. shared `Chart.tsx`의 props 추출/memo와 Skia의 `pickChartPresentationProps`(`skiaPrimitives.ts:3330`)도 명시 키 전달이다. types/validator만 추가하면 실제 화면에 전달되지 않는다. 중첩 displayBudget의 ref 전체 교체·reset·동일 값 재적용·Undo/reload 검사도 없다.

최소 수정: catalog kind/accepts/전용 editor mount, shared memo 및 Skia allowlist를 inventory에 넣고 실제 Properties→semantic→canonical→DB→reload→양 renderer→Export 경로를 Gate로 고정한다. helper에 직접 props를 넣는 테스트만으로 통과시키지 않는다.

### m3 MEDIUM — Brush는 고정 폭 창 이동을 자동 제공하지 않음

D:34는 창 크기=fit, D:36은 화살표로 창 이동을 선언한다. 설치된 Recharts3.10.1 `es6/cartesian/Brush.js:386-415`는 startX/endX 손잡이 각각의 index를 움직인다. 그대로 쓰면 창 크기가 변한다. D:54처럼 렌더 행을 창으로 잘라 넘기면 Brush가 전체 index를 어디에서 받는지도 필요하다. resize·source 변경·필터 감소·종류 전환 때 start clamp/reset 규칙과 resolver의 window start 입력도 없다(D:52).

최소 수정: full model/visible model/index 변환, controlled start/end의 고정 길이, 마지막 창, 데이터 교체 및 포커스 정책을 명시한다. Brush 공존 spike는 렌더 여부뿐 아니라 키보드 창 길이 불변·끝까지 접근을 검사한다. Brush가 plot 공간을 차지한다면 Canvas도 동일 공간을 예약하거나 외부 배치를 택해야 동일 size의 fit이 성립한다. 자체 스크롤 fallback은 Recharts accessibilityLayer가 자동 소유하지 않으므로 기존 접근성 primitive를 통한 계약이 필요하다.

### m4 MEDIUM — 호환 범위와 안전 cap

D:97은 fit 초과와 200행 초과를 동일시하지만 다르다. 폭이 좁은 50범주는 200행 미만이어도 바뀐다. 반대로 300행이 같은 범주에 합산돼 범주수1≤fit이면 기존 Canvas 앞200행 합계와 신규 전체300행 합계가 달라진다(`canvasSceneNode.ts:2585-2590`, `series.ts:102-118`). 'fit 이하 scene byte 동일'(D:80)은 그대로는 불가능하다.

D:55의 Canvas 전용 안전 cap은 도입 시 전체 runtime과 합계/domain을 다시 다르게 만든다. D:98의 '구버전 200행으로 복귀'는 Canvas에만 해당하며 runtime은 전체 행이다.

최소 수정: raw 행 수/집계 범주 수/표시 셀 수로 영향 집합을 분리하고 기존 slice 영향 문서는 byte 동일 예외를 명시한다. 안전 cap을 허용한다면 두 leg 의미·안내·동일성 조건을 재정의하고 자동 도입하지 않는다. 데이터 보존과 시각적 rollback 동일성도 분리한다.

### m5 MEDIUM — 번역 export 정본 경로 오인

D:48은 others 문자열을 export 시점에 고정하는 선례로 `CHART_INVALID_SETTINGS_TEXT`를 들지만 실제 `computeChartScene.ts:129`는 영문 상수이고 Recharts도 같은 상수를 직접 렌더한다(`RechartsChart.tsx:227`). 번역을 export에 실어 주는 경로의 근거가 아니다. displayBudget 외 저장 필드가 없다는 D:9와도 연결 방식이 미정이다.

최소 수정: 문서 locale/표시 문자열의 실제 전달 위치와 저장·export 계약을 정하고 Canvas/Preview/독립 Publish ko/en 및 reload 테스트를 추가한다. 기존 상수 동작을 번역 주입 선례로 쓰지 않는다.

### m6 MEDIUM — 위험 평가·Gate 정합

ADR:74-77은 B HIGH0으로 위험 회피 대안 검토를 끝내지만 같은 B의 행 cap 제거와 두 leg 불일치를 R1/R2 HIGH로 선언한다(ADR:99-107). HIGH 경로별 구체 인용도 없어 adr-writing seed(:248)를 충족하지 않는다. 대안 C의 독립 Canvas/DOM 표시 정책을 consumer-to-consumer 의존이라고 단정한 기각 이유도 과하다. 정책 비대칭과 실제 소비자 간 의존은 구분해야 한다.

최소 수정: B의 위험 축을 R1/R2와 맞추고 필요한 회피 대안 또는 위험 수용 근거를 제시한다. 각 HIGH에 코드 경로와 반증 Gate를 연결한다. G4는 engineering/policy를 분리하며 실제 5,000행 모델 시리즈 수·분포·표본수·warm/cold·창 이동 반복 조건을 고정한다. ±2ms 상대 비교만으로 두 arm 동반 악화를 통과시키지 않도록 before 대비 총비용도 기록한다. G1의 CHART_SAMPLE_ROWS 참조0은 역사 문서/리뷰가 아니라 제품 코드 범위로 한정한다.

### H1 — 이동 root의 부모 문맥까지 이동하면 다음 patch의 절대 좌표가 틀린다 (open)

- 위치: `docs/adr/design/264-moved-subtree-translate-page-grid-rebind-breakdown.md:40`.
- 근거: `renderCommands.ts:1482`의 `parentAbsX/Y`는 해당 노드의 부모 절대 좌표다. `renderCommands.ts:1190`의 subtree builder는 이 값을 받아 현재 지역 좌표를 더하며, `canvasBinding.ts:2099`는 후속 편집마다 저장된 문맥을 재사용한다.
- 입력 → 잘못된 결과: 고정된 부모 아래 형제 root의 y가 10→30으로 이동(Δ20). 설계대로 root의 parentAbsY도 0→20으로 옮긴 뒤 그 root를 편집하면 `buildSubtreeCommandStream`의 bounds.y가 50이 된다. 전체 재구축은 30이다. 선택·hover·SpatialIndex가 그림과 어긋나 HC3를 위반한다.
- 실행: 실제 builder 함수로 예상 30 / 제안 문맥 적용 후 50 확인. 즉시 1회 이동 동치뿐 아니라 이동→같은 root 편집 순서가 필요하다.
- 해결 방향: 이동 root의 부모 문맥은 보존하고, 이동 root 아래 자손들의 parentAbs만 갱신한다. page offset과 cmdOffset을 쓰는 root도 별도 계약으로 구분한다.

### H2 — root hit bounds만으로는 overflow 자식의 이전 픽셀을 지울 수 없다 (open)

- 위치: `docs/adr/design/264-moved-subtree-translate-page-grid-rebind-breakdown.md:42` (제외 판정 :38), ADR 본문 :53.
- 근거: `renderCommands.ts:1763`의 unsafe 판정은 transform·effect·shadow 등 개별 paint 특성이지 외부 element 자식이 부모 bounds 안에 있는지의 판정이 아니다. 현재 `subtreeCommandPatch.ts:240`은 모든 자손의 이전·이후 hit bounds를 합친다.
- 입력 → 잘못된 결과: overflow visible인 높이30 root가 y10→30 이동하고, 내부에 local y60·높이20 자식이 있다. unsafe 집합은 전후 모두 비어 있다. root-only damage는 y10..60이나 자식의 이전 픽셀은 y70..90, 이후는 y90..110이다. 제한된 damage 재기록은 자식 영역을 갱신하지 못해 HC1의 잔상0을 위반한다.
- 실행: 실제 command builder에서 unsafe=[]와 위 bounds를 확인. 기존 getSubtreeDamageBounds의 모든 자손 합집합은 y10..110이다.
- 해결 방향: 이미 순회하는 모든 자손의 전후 hit bounds를 damage에 합치거나, 전체 paint가 root bounds 안임을 검증한 경우에만 root-only를 허용한다.

### M3 — 교차가 끝난 clip 맵을 평행이동하면 새로 드러나는 부분이 손실된다 (open)

- 위치: `docs/adr/design/264-moved-subtree-translate-page-grid-rebind-breakdown.md:40`.
- 근거: `renderCommands.ts:1680`에서 내부 clip을 바깥 clip과 먼저 교차시키고, :1493의 clipContext와 :1485의 buildContext.clipRect에 그 결과를 저장한다. 원래 내부 clipping box 자체가 아니다.
- 입력 → 잘못된 결과: 바깥 clip y0..100, 내부 clipping root y90..120, 자식 높이20. 기존 자식 clip은 y90..100(높이10). root를 -20 이동하면 올바른 clip은 y70..100(높이30), 자식 hit 높이는20이다. 기존 clip +Δ는 y70..80(높이10)만 남고 바깥 clip과 다시 교차해도 복구되지 않는다. 보이는 아래10px가 picking에서 빠지고 후속 patch에도 잘못된 문맥이 전달된다.
- 실행: 실제 builder의 이동 전후 clip 10→30 및 hit 높이20 확인.
- 해결 방향: 기존 교차 결과를 이동하지 말고 CHILDREN_BEGIN의 원래 clip 치수·border inset·scroll 순서를 이용해 바깥의 불변 clip부터 교차를 다시 전파한다. clipContext와 subtreeBuildContext.clipRect를 함께 갱신하며 EMPTY_CLIP→부분 가시 전환도 처리한다.

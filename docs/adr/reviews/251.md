## Round 1 — 2026-10-03 (reviewer: codex)

판정: 대안 A의 방향과 contract 2 정책은 유지할 수 있으나, 현재 breakdown은 구현 전 보강이 필요하다. HIGH 3건.

1. **HIGH — P1·P2만 main에 넣으면 DOM 항목이 사라진다.** docs/adr/design/251-radio-checkbox-items-node-restore-breakdown.md:45는 P1·P2를 main 반영 단위로 정하고 DOM 전환은 P3(:69)에 둔다. 현재 apps/builder/src/builder/catalogRuntime/delegatedDom.tsx:993과 :1054는 그룹의 직계 Checkbox/Radio만 모아 렌더한다. 새 구조의 그룹 자식은 Label·Items이므로 배열이 비고 항목이 DOM에 전달되지 않는다. 격리된 새 구조의 RadioGroup 직계 항목 수는 0이었다. P1~P3을 같은 반영 단위로 묶고, 기존 '+' 경로 제거와 대체도 같은 제품 전환 안에서 처리해야 한다. P3·P4 완료 전 개별 구현 커밋은 main 밖에서 관리하는 방식으로 반영 계약을 명시한다.

2. **HIGH — COLLECTION_FAMILIES로 옮기는 것만으로는 '+'의 Radio 계약을 보존하지 못한다.** docs/adr/design/251-radio-checkbox-items-node-restore-breakdown.md:78 / §2 #8(:27). 일반 collection 경로 apps/builder/src/builder/catalogRuntime/itemInsert.ts:268은 항목에 id를 쓰지만 Radio/Checkbox의 현재 definition은 이를 받지 않는다. 동일 경로를 적용한 격리 transaction은 PROP_NOT_ACCEPTED: project:node:r3.id로 실패했다. id만 제거해도 새 Radio 두 개의 value가 모두 radio가 된다. 현행 packages/shared/src/catalog/commands/collections.ts:468의 고유 value 할당과 :517의 선택된 형제 해제·그룹 value 갱신은 insertCollectionItem에 없다. Radio/Checkbox를 일반 RAC key collection과 구분하는 삽입 전략을 두고, 새 Items 위치에 삽입하면서 기존 그룹의 value/isSelected 규칙을 유지해야 한다. G3에 연속 2회 삽입과 선택된 항목 삽입의 회귀 조건을 넣는다.

3. **HIGH — prop 없는 Items는 size 전달을 끊는다.** docs/adr/251-radio-checkbox-items-node-restore.md:112 / docs/adr/design/251-radio-checkbox-items-node-restore-breakdown.md:66. 현재 packages/shared/src/catalog/resolution/resolver.ts:574는 자식 definition이 accepts.size="string"인 경우에만 owner size를 쓴다. 전달 표만 Group→Items→항목으로 바꾸면 Items의 size가 비어 다음 전달이 중단된다. 격리 비교에서 기존 lg 그룹의 Radio는 lg/lg였지만 prop 없는 실제 Items를 추가한 뒤 md/md였다. TagList 선례에는 size contract가 있어 이 부분은 동형이 아니다. 사용자 편집 prop과 내부 상속 값을 구분해 Items가 내부 size를 운반하도록 하거나, resolver에 명시적인 구조 래퍼 통과 계약을 두어야 한다. G1의 비기본 size 조건은 유지한다.

검증: HEAD db76cc301의 ADR·breakdown 및 현재 library/resolver/partRule/traits/nesting/collection 명령/DOM/Styles host/G3 하니스 소비 경로를 대조했다. 코드 변경 없이 메모리에서 wrapper definition과 template, 전달 표, collection family·trait만 구성한 격리 반증 1건 및 인접 Vitest 15건, 총 16/16 PASS. 이 PASS는 위 실패 조건을 확인한 것이며 ADR gate 통과를 뜻하지 않는다. 반증에서는 contract 1을 유지했으므로 contract 2의 저장 정책은 검증하지 않았다. 임시 테스트는 작업 트리에서 제거했다. 재현 소스와 출력은 /private/tmp/adr251-review-probe.test.ts 및 /private/tmp/adr251-review-probe.json.

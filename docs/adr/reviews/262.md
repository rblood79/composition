1. **m1 — 중첩 교체를 Reset all 한 번에 제거하지 못함.** `packages/shared/src/catalog/commands/instanceOverrides.ts:535`는 시작 시점의 replacement만 순회한다. `resetReplacement`가 바깥 교체를 되접으면서 안쪽 replacement를 현재 instance의 override 목록에 추가하면, 마지막 `withoutFields`가 그 replace를 보존한다 (`:545`, `:328`). 재현: Card.icon의 기본 Star를 Heart로 교체 → Heart 안 Glyph의 기본 A를 B로 교체 → Card instance의 Reset all. 바깥 icon은 Star로 돌아오지만 안쪽 B는 남는다. graph transaction probe의 기대 `[A]`, 실제 `[B]`; 실제 패널 Reset 클릭 뒤 Canvas record와 Preview DOM 모두 `Override B`, Overrides에 `Glyph → Review B`, 토스트는 `All changes reset`. 한 번의 Reset 뒤 fresh instance와 같다는 G2 위반이다. 수리 방향: 되접기에서 새로 노출되는 instance-owned replacement까지 같은 stage/transaction에서 처리하되, 유지 대상인 slot 내용과 원본 소유 교체는 보존한다.

2. **m2 — 자식의 responsive sizing/layout만 변경하면 Overrides와 패널 Push·Reset이 사라짐.** `apps/builder/src/builder/panels/properties/catalog/CatalogComponentSection.tsx:120`의 `extraRows`가 breakpoint의 visual/fillSizing만 열거한다. descendant의 tablet width=240, display=flex만 쓰고 instance를 선택하면 저장된 patch가 있음에도 행은 0이고, `:560`의 `rows.length > 0` 조건 때문에 두 작업 버튼도 없다. 실제 브라우저에서 rows=[], push=false, reset=false. 루트 sizing/layout 보존 결정은 descendant patch에 적용되지 않는다. Canvas 메뉴 경로는 남지만, 승인된 Component 절 경로와 자리별 변경 목록은 작동하지 않는다. 수리 방향: root와 descendant의 보존 범위를 구분해 responsive sizing/layout 행 및 개별 reset 축을 지원한다 (`commands/instanceOverrides.ts:603`도 현재 visual만 제거).

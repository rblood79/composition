### H1 — 기본값이 없는 배열 역할을 생략하거나 지우면 표본이 복구되지 않는다

- 위치: `docs/adr/design/312-chart-data-format-standard-breakdown.md:237` (§5.2 해제), `:49` (`valueFields` 기본 열 없음), `:203` (생성 시 역할 prop 생략), `:201` (값 열의 의미 있는 이름 유지). 본문 Decision 8·10 및 G6와 충돌한다.
- 입력·상태 → 결과: parallel 표본의 값 열은 `price, weight, battery, perf, screen`이다. 연결된 컬렉션의 `#id` 목록으로 `valueFields`를 바꾼 뒤 해제하면 §5.2에 따라 표본에 없는 참조를 삭제한다. 하지만 `valueFields`에는 기본 열이 없으므로 표본 행이 남아 있어도 설정 오류가 된다. 생성 시 모든 역할 prop을 생략하는 규칙 역시 같은 조건을 만든다. 표본을 사용자 임의 열로 편집한 경우에는 scalar 역할도 삭제만으로 원래 매핑을 복구할 수 없다.
- 현행 근거: `packages/rendering/src/chart/families/matrix/index.ts:201`이 표본의 값 열 목록을 제공한다. `packages/rendering/src/chart/families/matrix/parallel.ts:34`는 목록을 직접 읽으며 2개 미만이면 `role.missing`을 낸다. 새 정의가 이를 대체할 기본 목록·복구 값을 제공하지 않는다.
- 실행: 기존 matrix family에 같은 표본 행을 넣었을 때 `valueFields` 포함 시 `empty=false`, 삭제 시 `empty=true`, `role.missing: Value Columns needs 2 or more fields`. 새 연결 명령을 실행한 것은 아니며, 설계가 산출하는 유효 props를 현행 consumer에 전달한 프로브다.
- 수정 방향: 기본값으로 복원 가능한 역할과 명시 목록이 필요한 역할을 구별한다. 후자는 생성 시 유지하고, 연결 전 표본 매핑을 복구하거나 원천별 매핑을 따로 보존하는 계약을 정한다. 단순 삭제로 해제의 가역성을 주장하지 않는다. G6에 parallel/columns 및 사용자가 편집한 표본의 연결·해제를 포함한다.

### H2 — 집계 보기는 원본 collection과 다른 schema를 가지므로 자동 연결이 빈 차트를 만든다

- 위치: `docs/adr/design/312-chart-data-format-standard-breakdown.md:232`–`:235` (§5.2 새 원천=schema), `:193` (패널 Collection 칸). 본문 Decision 10 및 G6의 보기 결과 연결과 충돌한다.
- 입력·상태 → 결과: schema가 `status:string, points:number`, 행이 `[{status:"todo",points:3},{status:"todo",points:5}]`인 컬렉션에서 status로 묶고 points 합계를 `total`로 출력하는 보기를 연결한다. 실제 입력은 `[{status:"todo",total:8}]`인데, 원본 schema의 첫 숫자 열을 고르는 규칙은 metric을 `#f-points`로 지정한다. 결과 행에는 points가 없어 빈 차트가 된다. 사용자가 `#total`을 지정했더라도 재연결 시 원본 schema에 없다는 이유로 덮일 수 있다.
- 현행 근거: `packages/shared/src/collections/view/evaluate.ts:431`의 `viewResultSchema`는 그룹 열과 집계 alias로 결과 schema를 만든다. `packages/shared/src/catalog/runtime/dataBinding.ts:294`는 이 결과를 Chart에도 전달한다. 반면 `apps/builder/src/builder/panels/properties/hooks/useOwnerCollectionColumns.ts:55`는 원본 table.schema만 읽는다.
- 실행: 실제 `runViewQueries` 결과는 `{status:"todo",total:8}` 및 `[status,total]` schema. 실제 `computeChartScene`에 `metric:#f-points`를 전달하면 `empty=true`, `metric:#total`이면 `empty=false`. 원본·결과의 필드 ID를 등록해 미등록 참조와 구별했다.
- 수정 방향: 자동 지정·현재 참조 보존 판정·패널 옵션 모두 연결된 보기 체인의 **결과 schema**를 사용하도록 명시한다. 기존 `viewResultSchema` 등 순수 schema 계산을 재사용하면 HC7의 행 실행 경로를 수정할 필요는 없다. 보기 선택·집계 alias 변경 때의 매핑 처리도 정한다. G6에 합계 alias와 재연결 후 유효 매핑 보존을 고정한다.

### M1 — 역할별 형을 전역 고정하면 종류별 자동 지정 계약이 성립하지 않는다

- 위치: `docs/adr/design/312-chart-data-format-standard-breakdown.md:26`, `:34`–`:39`, `:235`.
- `accepts`는 공통 `ChartRoleDef`에만 있고 `ChartRoleUse`에는 라벨·기본 열 이름만 덮을 수 있다. 현재 `dimension`은 범주 차트에서는 string (`authoring.ts:109`), calendar/candlestick에서는 date (`:823`, `:835`)다. 한 뜻의 key를 유지하는 것과 그 종류에서 허용할 값 형을 동일하게 만드는 것은 다르다.
- 입력·상태 → 결과: schema 순서가 `status:string, date:date, points:number`인 컬렉션을 calendar에 연결한다. 전역 dimension.accepts를 string 또는 any로 두면 첫 열 status가 지정되어 날짜 파싱 실패로 빈 차트가 된다. 전역 값을 date로 두면 반대로 status/points만 있는 범주 차트의 정상 자동 연결이 불가능하다.
- 실행: 같은 `[{status:"todo",date:"2026-11-16",points:8}]`를 matrix family에 전달하여 dimension=status는 `empty=true`, dimension=date는 `empty=false` 확인.
- 수정 방향: 형태/종류의 역할 사용 지점에 `accepts` 제약을 둘 수 있게 하고, 자동 지정과 숫자·날짜 검증이 그 유효 제약을 읽도록 한다. key 문법과 라벨의 공통 정의는 그대로 유지할 수 있다.

### L1 — 외부 근거의 기본값 일반화 (deferred)

`docs/adr/312-chart-data-format-standard.md:101`은 핵심 셋의 이름과 기본값이 React Spectrum Charts와 같다고 단정하지만 공식 [Line API](https://opensource.adobe.com/react-spectrum-charts/docs/docs/api/visualizations/Line/)의 dimension 기본값은 `datetime`, [Bar API](https://opensource.adobe.com/react-spectrum-charts/docs/docs/api/visualizations/Bar/)는 `category`다. 공통 역할 이름을 유지하는 결정은 지지하지만 전 종류 기본 열 이름 통일은 Composition의 선택으로 설명해야 한다. 이 사실만으로 production 차단 이슈를 추가하거나 라운드를 재개하지 않는다.

외부 확인 범위: [shadcn Chart](https://ui.shadcn.com/docs/components/aria/chart)의 Recharts 조합·분리된 ChartConfig, [json-render dashboard catalog](https://github.com/vercel-labs/json-render/blob/main/examples/dashboard/lib/render/catalog.ts)의 xKey/yKey/aggregate 예제도 확인했다. 예제 catalog를 프레임워크 전체의 강제 표준으로 해석하지 않았다.

코드 대조: `families/matrix/index.ts:201`의 parallel 값 목록과 `families/category/index.ts:209`의 skyline 값·앞줄 목록은 해제 시 복구할 실제 값이 존재함을 뒷받침한다. `collections/view/evaluate.ts:431`의 `viewResultSchema`는 그룹 열·집계 alias를 산출하므로 HC7의 행 실행 경로 변경 없이 결과 schema를 산출할 수 있다. `chart/authoring.ts:823,835`의 날짜형 dimension과 `useOwnerCollectionColumns.ts:48`의 원본 schema 소비도 수정 문서의 진술과 일치한다. 이 경로들은 Round 1 이후 변경되지 않았다.

외부 기본값 확인: Round 1에서 읽은 Line·Bar 공식 API와 수정 문구를 대조했고, 이번에 추가된 Scatter의 `dimension=datetime`도 [공식 Scatter API](https://opensource.adobe.com/react-spectrum-charts/docs/docs/api/visualizations/Scatter/) Props 표에서 확인했다. S2와 기존 패키지를 혼합해 전 종류의 기본값으로 일반화하지 않는다.

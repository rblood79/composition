# ADR-223 Review Log

## Round 1 — 2026-09-17 (reviewer: codex)

판정: 설계 보완 필요 — HIGH 1 / MEDIUM 2 / LOW 1. 검토 HEAD 73ce6fc3e. ADR 상태는 Proposed 유지.

### h1 — 명시 이관 경로가 지원되지 않음

ADR:41·70과 breakdown:53은 Card cursor, Tab cursor/user-select/transition을 structure.containerStyles로 옮겨 현행 값을 보존한다고 한다. 그러나 generate-css.ts:365-370은 이 객체를 ContainerStylesSchema로 캐스팅하고, spec.types.ts:55-116에는 해당 세 키가 없으며, CSSGenerator.ts:831-892의 emitContainerStyles도 이 키들을 출력하지 않는다. catalog에 값을 적어도 생성 CSS에는 남지 않는다. 또한 Skia fallback이 이 키를 소비하지 않는다는 F7과 ‘Skia도 같은 줄을 읽는다’는 선택 근거가 서로 충돌한다.

해결: 값 보존이 필요한 DOM 상호작용 스타일의 정본 채널을 먼저 결정해야 한다. ContainerStylesSchema/emitter를 확장한다면 Skia가 무시하는 속성의 허용 계약과 테스트를 추가하고, generator-only root style 채널을 택한다면 대칭 근거와 범위를 그 계약에 맞게 다시 써야 한다. 어느 경우든 Card/Tab 생성 CSS에 세 값이 실제 남는 양성 게이트가 필요하다.

### m2 — GridListItem은 실효값 변화 0이 아님

breakdown:39는 수동 GridList.css가 base를 덮어 변화가 없다고 판정한다. 실제 수동 규칙 GridList.css:38-55에는 align-items 선언이 없고, generated GridListItem.css의 align-items:center가 현재 실효값이다. 현재 focused Chromium 오라클은 GridListItem child0.x가 DOM 35, pipeline 17로 18px 발산함을 재현했다. DEFAULT_BASE_STYLES 중립화는 이 값을 제거해 기존 발산을 닫을 가능성이 높지만, 이는 명백한 사용자 가시 배치 변경이며 현재 G2/G3 6종 목록에 없다.

해결: GridListItem을 ‘변화 0’에서 ‘의도된 정합 수리’로 재분류하고, 기존 known failure가 GREEN이 되는 원복 RED 및 실제 GridList 카드 구조 live를 G2/G3에 넣는다. 수동 CSS의 cursor/transition은 뒤 규칙에서 보존된다는 점도 cohort 표에 분리한다.

### m3 — G2의 대표성 선언과 fixture가 불일치

ADR:92는 Q1을 실제 팔레트 컴포넌트, 합성물 없음으로 답하지만 catalogComponentBox는 div host에 react-aria class만 붙이고 고정 크기 div 자식을 넣는 합성 fixture다(test:73-100,123-154). 같은 파일의 제외 계약 test:321-339는 Tab을 direct leaf 렌더, Card를 별도 구조로 분류한다. 따라서 ADR:98의 Card·Tab generic case는 실제 RAC button/Card 트리나 Canvas 소비 경로를 입증하지 못한다.

해결: Toolbar/TableView 같은 순수 컨테이너는 기존 fixture를 쓰되, Card·Tab은 실제 shared React 컴포넌트 DOM과 production Canvas projection을 쓰는 전용 case로 분리하거나 G3 live를 재현 가능한 자동 gate로 승격한다. Q1 설명도 합성 구조 oracle과 실제 사용자 흐름을 구분해야 한다.

### l4 — Body 생성물 집계 오류

breakdown:44는 body를 no-css·변화 0으로, ADR G1은 11 cohort 중 CSS 10파일로 적었다. 그러나 generated/Body.css는 실제 파일이고 root base에 DEFAULT_BASE_STYLES를 포함한다. 로드되지 않는다는 사실과 생성 diff가 없다는 주장은 다르다. G1은 변경 생성물 11파일, runtime loaded 7종, unloaded 4종처럼 축을 분리해야 한다.

검증: ADR·breakdown·catalog·CSS generator·generated CSS·Skia resolver 직접 대조. focused specs CSSGenerator.containerStyles 11/11 PASS. focused Chromium catalogComponentBox 24 PASS / 기존 2 FAIL(GridListItem child x Δ18, Tooltip width Δ20)로 현재 baseline을 확인했다. 제품 코드와 ADR 본문은 수정하지 않았고 live Builder는 실행하지 않았다. 구현 G0~G5는 UNVERIFIED.

### 설계 수리 확인 — 2026-09-18

사용자 요청에 따라 h1·m2·m3·l4를 모두 설계에 반영했다. Round 1 당시 판정은 위에 보존한다.

- h1 fixed: Card cursor와 Tab cursor/user-select/transition을 `ContainerStylesSchema`가 아닌 기존 generator-only `structure.composition.rootSelectors["&"]`로 이관한다. 공통 geometry인 Pagination align만 `structure.containerStyles`에 둔다. `rootSelectors`는 이미 `&` root emit과 임의 CSS property를 지원하고, rootSelectors만 있는 composition은 `compositionOwnsContainerBox`를 활성화하지 않는다. G1 양성 생성 테스트와 G2-B computed-style, 속성별 원복 RED를 추가했다.
- m2 fixed: GridListItem 수동 CSS가 `align-items`를 덮지 않는 사실과 현재 Chrome Δ18을 cohort에 기록했다. 변화 0 판정을 폐기하고 의도된 parity 수리로 분류해 G2-A, G3 live 7종, 원복 RED에 포함했다. 수동 CSS가 cursor/transition은 별도로 보존한다는 cascade도 분리했다.
- m3 fixed: 측정 Q1을 합성 고정-box 구조 오라클(G2-A)과 실제 shared React Card + `Tabs > TabList > Tab` tree(G2-B), 실제 Builder 흐름(G3)으로 분리했다. Generic `div` fixture로 Card·Tab production 구조를 증명한다는 주장을 제거했다.
- l4 fixed: Body를 no-css가 아닌 unloaded generated로 정정했다. G0/G1 집계는 변경 생성물 11, runtime loaded 7, unloaded 4로 고정했다.
- 수리 판정은 설계 누락의 해소다. 제품 코드와 생성 CSS는 아직 변경하지 않았고 G0~G5는 UNVERIFIED, Status는 Proposed다.

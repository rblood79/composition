# ADR-321 Review Log

## Round 1 — 2026-11-26 (reviewer: codex)

**판정 · 설계 보완 후 재검토**

### HIGH · 입력 별점의 표시·폼 값과 이름 붙인 상태가 서로 달라진다

`valueCommitNumber`의 `setValue`는 숫자를 그대로 받고 숫자 미러도 소수와 범위 밖 값을 보존한다. 설치된 RAC Slider에 2.5와 6을 전달한 SSR에서 range input 값은 각각 3과 5였다. 같은 값의 미러 정규화 결과는 2.5와 6이다. 제출한 별점과 후속 규칙이 읽은 별점이 달라질 수 있다.

입력 모드의 정수·범위 처리와 표시 모드의 반점 처리를 정의한다. 작성 값, 바인딩, Do가 같은 유효값을 거치게 하고 G5에서 폼·미러·별 채움을 함께 확인한다.

근거는 `docs/adr/321-steplist-rating-components.md:108` 및 `packages/shared/src/catalog/runtime/catalogPreviewInteractions.ts:1551`이다.

### MEDIUM · 표시 전용 Meter의 기본 접근성 값이 별점 단위를 잃는다

별 2.5개를 `minValue=0, maxValue=5, value=2.5`로 설치본 Meter에 전달한 SSR 결과는 `aria-valuetext="50%"`였다. G5가 값 존재만 확인하면 통과하지만 사용자가 듣기를 기대한 5점 척도의 소수 값은 표현되지 않는다.

Meter 선택 시 지역화된 `valueLabel`로 ‘5점 만점에 2.5점’을 전달하고 G5에서 실제 접근성 값과 표시값의 단위를 함께 확인한다.

근거는 `docs/adr/321-steplist-rating-components.md:138` 및 `packages/shared/src/catalog/runtime/delegatedDom.runtime.ts:3690`이다.

### 검증 범위

설치된 RAC의 실제 SSR과 `normalizeImplicitStateValue`를 각각 실행했다. StepList 선형 모드의 선택 규칙은 설치본 `useStepListState.mjs:60`과 일치한다. 결정 3에서 자유 이동을 채택하면 G2의 v3 대조는 선형 모드에 적용하고 자유 이동에는 별도 정답표가 필요하다.

UNVERIFIED — 신규 컴포넌트의 Builder·Preview·Publish 통합 동작, VoiceOver, 번들 크기 및 성능은 구현 단계의 검증으로 남는다.

## Round 2 — 2026-11-26 (reviewer: codex)

**Round 1의 두 건 모두 설계 수리 확인. 잔여 이슈 0건.**

- **h1 · fixed.** Decision 8과 breakdown §5.5가 입력 모드 정수·표시 모드 반점의 유효값을 정하고 작성 값·바인딩·Do·미러·Canvas·폼의 소비 지점을 연결한다. G5 채점값은 독립적으로 적는다. 설치본 RAC Slider를 SSR한 결과 2.5, 6, −1의 range 값이 3, 5, 0이었다.
- **m2 · fixed.** Meter에 2.5와 지역화한 `valueLabel`을 넘긴 SSR 결과가 `aria-valuetext="5점 만점에 2.5점"`이었다. G5에서 반점 채움과 그 숫자를 함께 확인한다.

기존 Slider의 미러 보정은 같은 오차가 있는 공용 경로에 한정하는 설계가 타당하다. 기존 `catalogSliderRange`는 min·max·step을 이미 소비한다(`packages/shared/src/catalog/runtime/presence.ts:1947`). 설치된 Slider에서 min=1, max=10, step=2, 값=4.6의 range 값도 5로 확인했다. 공용 처리는 컴포넌트별 범위와 step을 사용한다. 자유 이동은 선형 v3와 별도의 정답표로 판정한다.

설계 리뷰 승인 가능. 신규 컴포넌트의 실행, 기존 Slider 미러의 실제 수정, VoiceOver 청취는 UNVERIFIED.

## Round 2 — 2026-09-26 (reviewer: codex)

### 판정

현행 재작성안은 보완 후 재검토가 필요하다. ADR 구조와 선행 ADR-159/234의 큰 경계는 맞지만 아래 입력에서 결정의 핵심 계약이 깨진다. 제품 코드와 ADR 상태는 변경하지 않았다.

1. **HIGH h1 — 가변 높이 행에서 stride 불일치.** 비-slot Text.children을 `{title}`에 연결하고 첫 행은 짧게, 다음 행은 카드 폭을 넘는 긴 값으로 두면 DOM/CSS 카드는 자연 높이로 줄바꿈한다(`packages/shared/src/components/styles/GridList.css:38-43,102-109`). Phase 4는 직전 layout의 _window 첫 행_ 높이만 읽어 모든 행의 stride로 쓰겠다고 한다(`breakdown:75`). window 위치가 바뀔 때도 다른 높이를 얻어 spacer, window index, maxScrollTop이 바뀐다(`collectionVirtualization.ts:389-404`). 이는 `ADR:35`의 높이 단일값 계약과 `G3`의 진동 0을 동시에 보장하지 못한다. 행별 높이를 금지하려면 실제 DOM/Canvas에서 고정 높이·줄수 제한을 명시하고 강제해야 한다. 자유로운 자식 크기를 유지하려면 시각 행별 최대 높이와 누적 offset을 쓰는 가변 높이 가상화로 설계를 바꿔야 한다. 반증 입력은 2열 GridList의 1행 짧은 title, 2행 3줄 title 및 스크롤 중 두 행 교대다.

2. **HIGH h2 — 소유자별 origin이 Preview에 전달되지 않는다.** Canvas는 각 sourceNode의 `slot[0]` 또는 ref master의 slot을 읽는다(`canvasSceneNode.ts:811-820`); 커스텀 slot 테스트도 있다(`canvasSceneNode.test.ts:2253-2268`). Preview는 전역 `component-gridlist`의 slot으로 단일 `gridList` 구성을 만들고(`App.tsx:345-360,427`) 모든 renderer에 하나를 전달한다(`:871`). Phase 3도 그 단일 context 옆에 자식 트리를 추가한다고만 적는다(`breakdown:68-69`). 서로 다른 GridList origin을 참조하는 두 소유자를 한 페이지에 놓으면 Canvas와 Preview가 서로 다른 자식을 그린다. 템플릿 해석·자식 전달을 GridList owner별로 키잉하고, stride도 같은 origin을 읽도록 묶어야 한다. 반증 입력은 기본 origin과 custom origin을 slot으로 가진 데이터 GridList 2개다.

3. **MEDIUM m1 — 기존 Field 경로의 우선순위가 미정이다.** `columnMapping` 또는 property binding에 GridListItem 템플릿 자식이 있으면 Path 1이고(`SelectionRenderers.tsx:921-923`), Field 자식이 하나라도 있으면 slot 콘텐츠 대신 Field만 그린다(`:953-1013`). 새 규칙대로 origin 자식 전부를 렌더하면 기존 Field 표시가 달라지고, 현 분기를 유지하면 Image/Button이 사라진다. `breakdown:68`은 Path 1/2를 함께 바꾼다고 하지만 Field 혼합 카드의 우선순위·이관·BC gate가 없다. Field가 있는 저장 문서를 inventory에서 확인하고, Field와 origin 자식의 병합 또는 legacy 분기를 결정해야 한다. 반증 입력은 `columnMapping` + Field 1개 + origin Image 1개다.

## Round 3 — 2026-09-26 (reviewer: codex)

### 수리 검증 판정

bec75aeda의 설계 수정과 현재 Canvas/Preview/renderer 코드를 대조했다. round 2 h2는 소유자별 shared origin resolver와 Preview owner별 맵을 Phase 1에 배치했고(`breakdown:63`), 기본/custom origin 두 소유자 반례를 G2에 넣어 **설계상 해소**했다. m1은 Field 우선 legacy 분기(`breakdown:41`)와 문서 수 inventory·DOM Δ0 게이트를 명시해 **설계상 해소**했다. 두 항목 모두 구현·live는 아직 UNVERIFIED다.

**HIGH h1 — 가변 높이 대응의 총 높이 계약이 모순된다.** `breakdown:80-86`은 window 밖 시각 행을 템플릿 공식으로 추정하고, 실체화한 행만 실측 캐시에 넣는다. 반면 ADR G3(b)(`ADR:130`)는 가상화 크기에서 끝까지 스크롤한 직후 *content 총 높이 = DOM scrollHeight ±1px*을 요구한다. 2열·200항목에서 3줄 title이 있는 50개 시각 행을 지나치지 않고 스크롤 thumb을 끝으로 끌면, 중간 행은 1줄 공식 추정으로 남는다. 각 긴 행의 추가 두 줄만큼 누적합이 DOM보다 작아지므로 ±1px을 충족할 수 없다. `ADR:145`도 처음 스크롤할 때 scrollbar 길이가 바뀐다고 인정한다. 화면 끝으로 바로 이동해도 마지막 행에 도달할 수 있는지와 보이는 행 y·anchoring을 별도 검증하고, 총 높이 정확 일치는 모든 행이 측정된 경우로 한정하거나 미측정 행의 정확한 높이를 얻는 독립 측정 경로를 설계해야 한다. 이 항목이 닫히기 전에는 HIGH 0 판정이 아니다.

### 검증 범위

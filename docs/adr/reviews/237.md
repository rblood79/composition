# ADR-237 Review Log

## Round 1 — 2026-09-24 (reviewer: codex)

판정: **설계 수정 필요 — HIGH 2 / MEDIUM 1 (pending)**. ADR-234 적용 확장이라는 방향과 승인된 범위는 유지한다. 제품 코드·ADR 본문·상태는 변경하지 않았다.

### h1 — HIGH: 그룹 선택 owner와 Preview 계약이 서로 다르다

- 설계: breakdown:61-71은 Checkbox `value`, ToggleButton `id`를 유일하게 배정하고 Canvas만 owner `value`/`selectedKeys`를 읽게 한다. 특히 71행은 Preview가 이미 RAC context로 처리한다고 단정한다.
- 현재 경로: `packages/shared/src/renderers/FormRenderers.tsx:732-764`는 자식 `isSelected`에서 node id 배열을 만들어 `defaultValue`에 전달하고, 791/821행은 선택 비교와 Checkbox value 모두 node id를 쓴다. `packages/shared/src/renderers/CollectionRenderers.tsx:692-737`도 owner `selectedKeys`를 읽지 않으며, 742/795행의 비교·ToggleButton id는 node id다.
- 최소 입력: owner `value:["a"]` 또는 `selectedKeys:["a"]`, 자식 node id=`node-1`, 자식 `props.value/id="a"`, `isSelected:false`.
- 실행 결과: CheckboxGroup defaultValue=`[]`, Checkbox value=`node-1`; ToggleButtonGroup defaultSelectedKeys=`[]`, ToggleButton id=`node-1`. ADR의 Canvas 판정은 선택됨을 요구하지만 현재 Preview 초기 상태는 비선택이다. Preview 클릭 후 저장되는 key도 새 authoring key와 다르다.
- 해결 방향: 양쪽 선택 key reader와 owner/자식 상태 우선순위를 함께 정의한다. 기존 자식 `isSelected` 문서의 BC, Preview 초기값·상호작용 writeback·재마운트까지 포함해 같은 key를 쓰도록 계약을 보강한다. 단순히 controlled props를 전달하면 현재 runtime store 경로와 충돌할 수 있으므로 기존 uncontrolled 동작도 보존해야 한다.

### h2 — HIGH: collapsed ref의 콘텐츠가 펼쳐도 복원되지 않는다

- 설계: breakdown:79는 `--collapsed`를 `DisclosureContent enabled:false` descendants patch로 저장한다. :64는 Disclosure 변형을 Slot 후보로도 허용한다.
- 현재 경로: `apps/builder/src/resolvers/canonical/index.ts:234`는 ref 자식을 `filter(isResolvedEnabled)`로 제거한다. :244-265의 runtime 상태 projection보다 먼저 제거되며 :647-648에서 false 판정한다. Canvas 역시 `apps/builder/src/adapters/canonical/canonicalRefResolution.ts:1108-1114`에서 자식 생성을 생략한다. `packages/shared/src/renderers/LayoutRenderers.tsx:1802-1842`는 남아 있는 콘텐츠 자식만 panel에 전달한다.
- 최소 입력: Disclosure origin 아래 header/content → collapsed reusable ref에 `descendants.content.enabled=false` → 사용자 instance는 collapsed를 ref하고 `props.isExpanded=true`.
- 실행 결과: resolver 결과의 `isExpanded`는 true이지만 자식 type은 `[DisclosureHeader]`뿐이다. 이 상태에서는 펼침을 true로 바꾸어도 표시할 본문이 없다. 단순 상태 어휘 추가와 style/render props 적용으로는 구조가 복원되지 않는다.
- 해결 방향: runtime collapsed 층과 직접 참조한 변형의 상속 patch를 구분하고, 펼침 시 inherited hide를 되돌리는 규칙 및 상태 해석→pruning 순서를 정한다. instance가 직접 저장한 `enabled:false`는 계속 존중해야 한다. origin 참조와 collapsed 참조 각각에서 닫힘→펼침→닫힘 왕복을 검증한다.

### m1 — MEDIUM: raw isExpanded는 그룹 안의 유효 펼침 상태가 아니다

- 설계: 본문:89 / breakdown:79는 Canvas 상태 원천을 `isExpanded` prop으로 한정한다.
- 반례: `DisclosureGroup allowsMultipleExpanded:false` 아래 A/B 모두 `isExpanded:true`. `packages/shared/src/utils/disclosureGroupExpansion.ts:54-65`의 유효 집합은 A만 남기며 B는 false다. 실제 실행에서도 B raw=true, effective=false를 확인했다.
- 영향: B의 collapsed 변형에서 배경/테두리/헤더 스타일을 편집하면 raw prop 기준 상태 층은 펼침 모양을 고른다. 반면 기존 Canvas layout(`implicitStyles.ts:3842-3868`)·chevron(`buildSpecNodeData.ts:785-804`)·Preview(`LayoutRenderers.tsx:1716-1722`)는 그룹 제약으로 B를 접는다. 상태 모양과 본문/화살표가 같은 화면에서 어긋난다.
- 해결 방향: Canvas 상태 층도 기존 `isDisclosureExpandedInContext`를 소비하도록 명시한다. prop 부재의 기본값 true 및 Components 변형 자기 강제 상태의 우선순위도 동일 경계에서 정의한다.

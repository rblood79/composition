### H1 — 해제 전부터 존재한 instance 주소를 새 사본 주소로 옮기는 계약이 없다

- 대상: `docs/adr/completed/282-library-origin-unlock-fork-and-reset.md:88`, `docs/adr/design/282-library-origin-unlock-fork-and-reset-breakdown.md:22`.
- 입력 → 잘못된 결과: Button instance의 label 자식에 `descendantOverrides.patch`로 "Customized"를 저장한 뒤 원본 루트를 새 사본으로 바꾸면 기존 자식 편집이 사라진다. 유효 정의를 사본 루트로 통일한 주소 검증에서는 옛 경로가 `TEMPLATE_ROOT_MISMATCH`로 거부된다. 해제만으로 기존 instance의 내용을 바꾸거나 후속 편집·재열기를 막을 수 있다.
- 근거: `document/clone.ts:68-85`의 map은 복사한 서브그래프에만 있고, 경로의 `project:node:` ID만 바꾼다. 사본 밖 기존 instance의 `lib:template:` 주소는 바꾸지 않는다. `resolution/address.ts:81-87`은 루트와 각 부모·자식 ID가 정확히 일치해야 한다. 현재 validator는 `address.ts:44-47`에서 원본 library 정의를 직접 읽으므로 resolver만 사본으로 전환하는 것도 검증 기준을 갈라놓는다.
- 실행 근거: 실제 code library의 Button으로 루트 조회만 전환한 probe에서 `["Customized"] → ["Save"]`, 같은 유효 루트를 제공한 주소 검증에서 `TEMPLATE_ROOT_MISMATCH: lib:template:component-button`를 확인했다. 미구현 unlock 명령의 재현이 아니라, 제안된 루트 교체가 요구하는 주소 계약의 반례다.
- 해결 방향: lib template ID → 사본 NodeId 대응표와 affected instance 경계를 정의하고, 해제 transaction에서 기존 instance·중첩 template의 주소 참조를 함께 재작성한다. descendant override뿐 아니라 interaction·showWhen 등 주소 소비자도 포함하고, 명령·검증·resolver가 같은 유효 정의를 읽게 한다. G1에 **해제 전 작성한 자식 편집·slot 채움·중첩 주소 → 해제 → 동일 결과·저장/로드·undo/redo 보존**을 추가한다. 현재 G1의 "사본 descendantOverrides 재작성"은 외부의 기존 instance 주소를 보장하지 않는다.

### H2 — composite defaults를 사본 루트 props로 흡수하면 accepts와 바인딩이 깨진다

- 대상: `docs/adr/completed/282-library-origin-unlock-fork-and-reset.md:87`, `docs/adr/design/282-library-origin-unlock-fork-and-reset-breakdown.md:22`, `:44`.
- 입력 → 잘못된 결과: 유효한 Button 원본 override `defaults.label = "Send"`를 해제 시 사본 루트 `type-Button.props.label`로 옮기면 `PROP_NOT_ACCEPTED`로 transaction이 거부된다. 별도로 `detachInto`의 결과를 사본으로 재사용하면 instance별 "Save"/"Cancel"이 "Save"/"Save"가 된다.
- 근거: `generated/reusableOriginLibrary.ts:492-504`의 composite Button은 `label`·`icon`을 받지만 native Button의 `bindings/Button.binding.ts:56-64`는 `children`을 받는다. 두 namespace는 같지 않다. `commands/materialize.ts:382-396`은 binding을 제공하지 않으면 거부하고 제공하면 placeholder를 값으로 치환한다. `:1089-1095`의 detach는 현재 instance 값을 제공하므로 "그대로" 재사용하면 매 instance에 적용돼야 할 symbolic binding을 고정한다. `cloneNodeSubgraph` 또한 document node만 읽어 현재 graph의 lib 루트 입력은 `NODE_REQUIRED`다 (`document/clone.ts:39-42`).
- 실행 근거: `setLibraryDefault(label="Send")` 성공 후 동일 key의 native 사본 루트 흡수는 `PROP_NOT_ACCEPTED: ...label`. 실제 detach 결과를 유효 Button template으로 조회한 probe에서 "Save"/"Cancel" → "Save"/"Save" 확인.
- 해결 방향: symbolic binding을 보존하는 library → owned template 복사 계약을 별도로 명시한다. composite binding defaults는 composite scope에 유지하거나 이를 보존할 저장 모양을 정해야 한다. 단순 root props 병합 및 현재 detach의 값 고정으로 대체하지 않는다. G1에 서로 다른 label/icon/placeholder의 instance 둘 이상, 기존 composite defaults, 해제 후 prop 변경의 동작 보존을 추가한다. 사용자 결정 2의 선택지와 normative 결정도 이 제약에 맞춰 정리한다.

### H3 — reset에서 fillSlot 참조만 지우면 채움 노드가 소유자를 잃는다

- 대상: `docs/adr/completed/282-library-origin-unlock-fork-and-reset.md:116`, `docs/adr/design/282-library-origin-unlock-fork-and-reset-breakdown.md:45`.

- 근거: `commands/structure.ts:1120-1144`는 삭제된 주소를 참조하는 override를 걸러내면서 `replace.replacementId`의 subtree만 삭제한다. 탈락한 `fillSlot.childIds`를 처리하는 분기가 없다. `document/graph.ts:962-964`의 모든 node 소유자 검증을 통과할 수 없다. 검증기 거부는 원복을 막아 줄 뿐 정상 리셋의 구현이 되지 않는다.
- 실행 근거: ADR이 재사용하는 프로젝트 소유 template 모양으로 유효 graph를 만들고, template 루트 교체와 기존 subtree 삭제를 같은 transaction으로 계획했다. helper 실행 뒤 instance override는 비었고 채움 노드는 남았으며, 실제 commit은 `UNOWNED_NODE: project:node:filled`로 거부됐다. 미구현 reset 명령의 실재 실패로 주장하지 않는다.
- 해결 방향: 사라지는 slot의 instance 소유 콘텐츠를 유지·재배치할지 삭제할지 정하고, 선택한 정책에 맞춰 child subtree와 관련 state/interaction까지 같은 transaction에서 처리한다. G2를 단순 patch 외에 **fillSlot + 자식 subtree + 관련 record**의 reset·undo/redo·저장/로드로 구체화한다.

### H4 — reset이 composite defaults·stateRules를 남겨 기본 원본으로 돌아가지 않는다

- 대상: `docs/adr/completed/282-library-origin-unlock-fork-and-reset.md:87`, `docs/adr/design/282-library-origin-unlock-fork-and-reset-breakdown.md:50`.
- 입력·상태 → 잘못된 결과: Button 원본에 `defaults.label = "Send"`와 hover state override를 설정하고 해제한 뒤 reset한다. 개정 결정 1 및 breakdown의 reset은 override의 `templateRootId`·`templateMap`만 지우며 빈 override일 때만 entry를 삭제한다. 따라서 "Send"와 hover override가 그대로 남는다. 상태를 초기화했다고 표시해도 사용자는 라이브러리 기본 Button으로 돌아가지 못한다.
- 근거: 해제 때 defaults/stateRules를 남기는 것은 h2의 올바른 해결이다. 그러나 이것을 reset 뒤에도 남기면 본문 Status의 사용자 범위(`:10`, 원본 override 전부 초기화), Decision 요약(`:83`, 사본·override 삭제), "Reset to library default" 액션과 충돌한다. 현재 resolver는 잠금 여부와 무관하게 `resolver.ts:1234-1238`에서 override defaults를, `:1191-1193`에서 stateRules를 적용한다.
- 실행 근거: 현재 code library에서 `setLibraryDefault`로 유효한 label·hover override를 만들고, 개정 reset이 명시한 두 필드만 제거한 결과 record를 실제 CatalogGraph로 검증·resolve했다. 결과 label은 `["Send"]`, stateRules의 hover.color는 `red`로 남았다. 이는 미구현 reset 명령의 실재 실행이 아니라 **명시된 reset 결과 모양**에 대한 현재 consumer 검증이다.
- 해결 방향: 해제 시에는 defaults/stateRules를 보존하되, reset 시에는 해당 원본의 definitionOverride 전체를 제거하고 overrideIds를 정리하도록 결정 1·breakdown·G2를 일치시킨다. 원본 사본을 해제한 적 없는 override까지 전체 초기화 범위에 포함하는지도 행의 reset 계약과 함께 명시한다. G2에 기존 defaults·stateRules를 가진 원본의 reset → 라이브러리 기본 결과 → undo/redo 보존을 추가한다.

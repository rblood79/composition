### 이슈

- **m1 MEDIUM — 저장 위치 사실 오류.** `applyCanonicalDataBindingPatch` 는 정상 쓰기에서 `nextProps.dataBinding = write.binding` + `updateNodeExtension({ dataBinding: undefined })` 이다. `x-composition.dataBinding` 은 `restore` 스냅샷(legacy/import 형태) 복원 때만 쓴다. `PROPS_FORBIDDEN_KEYS` 는 `updateNodeProps` 경로에만 걸리고 primary 경로는 props 를 통째 교체한다. 따라서 ADR §Context "canonical extension 저장" · HC3 "canonical extension에 기록 … props 직접 쓰기 경로를 만들지 않는다" · breakdown §0 6행 · §1 `canonicalDocumentStore.ts` 행은 production 형태를 거꾸로 기술했다. 영향: G1 read-back 과 §2-2 기존 바인딩 캡처가 빈 필드를 보고, HC3 을 문자대로 따르면 extension 쓰기로 이탈 (extension 형태는 소비처 3곳이 떨어뜨렸던 legacy — 09-09 수리 이력). **해결**: 저장 위치를 "공통 적용기(`bind_element`)가 쓰는 현행 형태 — `props.dataBinding` (extension 은 legacy/restore)" 로 정정하고 HC3 을 "적용기 밖의 직접 쓰기 경로 신설 금지" 로 재서술. 설계 방향(공통 적용기 경유) 자체는 유효.
- **l2 LOW deferred — G0 축소 사실.** 같은 묶음 create+bind 는 사전 생성 UUID 를 `create_collection.id` 에 싣기만 하면 현재 코드로 성립 (reducer 가 op.id 채택, preflight 가 reduce 후 collections 대조). 공통 준비 API 신설은 불필요; 주석 범위 확장만. Phase 0 에 사실로 기록.
- **l3 LOW deferred — 외부 리서치 근거 0.** 대안 A~D 가 코드 경로에 근거하므로 production 재현 없음. 재개 사유 아님.
- **l4 LOW rejected — Gates `시점` 열.** breakdown §5 가 시점 역할.

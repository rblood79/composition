# ADR-230 Review Log

## Round 1 — 2026-09-21 (reviewer: codex)

## 설계 리뷰 — HIGH 1 · MEDIUM 2, 보완 필요

기준 HEAD `f54a857d1`. ADR-230 Proposed 본문·breakdown을 현재 renderer/Skia 경로와 대조했다. 사용자 확정인 별도 상태 origin 형태, RAC 내부 sub-part 제외, Canvas interaction 미재현 결정은 유지한다. 제품 코드 및 ADR 본문/상태는 수정하지 않았다.

### h1 — disabled opacity 중복 적용 (HIGH)

G2는 Button/Disabled origin의 opacity 편집이 두 leg에 동일하게 적용돼야 한다. 그러나 제안된 “resolved props 위 style overlay”를 현재 production buildSpecNodeData에 대입하면:

```json
[
  { "type": "opacity", "value": 0.5, "source": "style" },
  { "type": "opacity", "value": 0.38, "source": "state" }
]
```

두 opacity가 독립 saveLayer를 열므로 곱은 0.19다. DOM의 inline opacity 0.5는 생성 CSS의 data-disabled opacity 0.38을 대체한다. 따라서 origin opacity 0.5가 양쪽에서 동일하게 표현되지 않는다. seed가 catalog 값 0.38을 그대로 style에 굽는 경우에도 Skia에는 중복 감쇠 위험이 있다.

**보완**: state overlay의 적용 여부/속성 소유권을 보존하고, 해당 키의 catalog 상태 효과는 fallback으로만 적용하도록 단일 유효 상태 스타일을 정의한다. 일반 instance 자체 opacity와 상태 opacity를 어떤 규칙으로 결합할지도 분리해야 한다. isDisabled 자체를 false로 지우는 우회는 다른 상태 표현을 깨뜨린다. buildSpecNodeData/effects 경계를 구현 범위에 명시한다.

검증: 현재 production 함수의 disabled Button + style.opacity=0.5 진단에서 opacity 효과 1개 기대 assertion이 실패했다. 픽셀을 직접 측정한 결과가 아니라 효과 목록과 saveLayer 소비 구현에 근거한 판정이다.

### m2 — inline selected 색이 hover CSS를 가린다 (MEDIUM)

Phase1은 선언적 상태를 inline으로, Phase2는 일반 data-origin/data-hovered stylesheet로 주입한다. selected ToggleButton 배경을 빨강, hover origin 배경을 파랑으로 저작하면 selector가 정확해도 inline 빨강이 남는다. 일반 default origin 배경 편집도 같은 문제를 만든다.

Chromium 최소 CSS fixture 결과:

```json
{
  "actual": "rgb(255, 0, 0)",
  "expected": "rgb(0, 0, 255)",
  "ruleMatches": true
}
```

**보완**: default/selected/hover/pressed/disabled와 instance 명시 style의 cascade/우선순위를 하나로 명시한다. 상태값을 CSS custom property로 공급하고 실제 상태 selector가 최종 속성을 결정하거나 RAC style render-prop에서 최종 상태 스타일을 산출하는 등 충돌하지 않는 전달 방식을 선택해야 한다. 무조건 important 추가는 instance override까지 덮으므로 소유권 설계의 대안이 아니다. selected×hover/pressed의 정책도 결정한다.

검증은 새 브라우저 최소 fixture에서 data-hovered를 부여해 수행했다. 실제 Preview pointer 이벤트나 Builder E2E를 실행한 것은 아니다.

### m3 — authored props와 유효 interaction 상태를 혼동 (MEDIUM)

Phase1의 resolveActiveStateVariant(props)는 self props의 isSelected/isDisabled만 읽는다. 그러나 기존 code는 RadioGroup.value=a + Radio.value=a, Radio.isSelected 미지정이라는 정상 문서에서 **선택된 Radio**를 만든다. Skia는 buildSpecNodeData 내부에서 조상 값을 투영하고, DOM은 RAC RadioGroup이 defaultValue로 결정한다. 앞단 scene ref 분기에서 self props만 읽으면 selected origin을 고르지 못한다. Tab도 selectedKey→_isSelected 투영을 사용한다.

또한 renderToggleButton은 단독일 때 defaultSelected, 그룹일 때 RAC groupState에 선택을 맡긴다. 사용자가 Preview에서 선택을 바꾼 순간에는 정적 canonical props 기반 inline overlay와 RAC data-selected 상태가 달라질 수 있다.

**보완**: authored state, ancestor-derived state, RAC effective state를 구분한다. Canvas는 기존 조상/collection projection 이후의 유효 상태를 공용 resolver에 전달하고 DOM은 RAC의 실제 render state/data 속성에서 overlay를 선택해야 한다. 대표 반증은 RadioGroup.value로 선택된 자식과 Preview ToggleButton 직접 클릭이다. 이는 단순 테스트 커버리지 요구가 아니라 현재 지원하는 상태 소유 모델과 새 selector 계약의 불일치다.

### 확인한 검증과 한계

- 기존 buildSpecNodeData 테스트 **74/74 PASS**.
- 추가 disabled overlay 진단 **1 FAIL** (기대 opacity 효과 1개, 실제 2개). jsdom의 기존 canvas getContext 미구현 경고가 출력됐지만 이 assertion 실패는 반환된 효과 목록에서 발생했다.
- Chromium CSS 최소 fixture는 selector match=true인데 inline 빨강 유지 확인. 실제 제품 UI/픽셀/성능·persist/reload는 미실행이며 구현 gate G0~G4는 UNVERIFIED.
- 임시 진단 테스트는 `/private/tmp/adr230-review-probe.test.ts`에 보관하고 저장소에서 제거했다.
- 결론: 별도 상태 origin 방향은 유지 가능하지만 단순 style overlay만으로는 성립하지 않는다. catalog 상태 효과 대체, DOM cascade, 유효 상태 source를 먼저 확정해야 한다. 일반 커버리지 지적만으로 차단 항목을 추가하지 않았다.

## Round 2 — 2026-09-21 (reviewer: codex)

## Round 1 설계 수리 검증 — 3건 fixed

사용자의 수정 방향 착수 요청에 따라 본문·breakdown·README·CHANGELOG를 보완했다. 별도 상태 origin, sub-part 제외, Canvas interaction 미재현 전제와 Proposed 상태를 유지한다.

- **h1 fixed (설계)**: opacity 상태 소유권을 render-only 정보로 보존하고, state-owned opacity가 catalog disabled 효과를 대체하도록 결정했다. origin 0.5는 한 번만, 명시 instance 0.8은 우선 적용한다. state opacity 부재/plain은 기존 경로 유지. buildSpecNodeData/effects·layout 소비 경계를 범위에 추가하고 G0/G1/G2 반증에 연결했다. isDisabled=false 우회는 금지한다.
- **m2 fixed (설계)**: Phase 1부터 CSS 변수/실제 RAC 상태 selector 한 채널로 공급한다. 관리 속성의 기존 inline도 출처별 변수로 옮겨 경쟁을 없애고, instance 명시값 우선과 selected→hover→pressed·disabled 차단을 명시했다. selected 상태에서 실제 hover/pressed 및 해제 후 복귀를 요구한다. 공통 CSS 채널 실패는 Phase 1도 보류하므로 Phase 2 보류만으로 회피할 수 없다.
- **m3 fixed (설계)**: self props만 받는 상태 판별을 제거했다. Canvas는 RadioGroup/Tab/collection/조상 disabled 투영 이후, DOM은 RAC data 상태가 유효 상태 source다. origin/instance override 출처와 상태 입력을 분리했다. RadioGroup.value만 지정한 자식 및 Preview 직접 선택을 반증 조건에 포함했다.

검증은 위 세 항목의 수리에 한정했다. round 1 본문은 보존하고 frontmatter outcome만 fixed로 갱신했다. 잔존 구현 HIGH를 R6으로 유지하고 G0/G1/G2에 연결했으며 설계 fixed를 구현 위험 소멸로 해석하지 않는다.

제품 코드는 변경하지 않았다. 앞선 opacity 진단 RED를 GREEN으로 만들거나 실제 제품 live/pixel/performance를 검증한 것이 아니다. 구현 gate G0~G4는 UNVERIFIED다. 기존 dirty 문서 및 .out 산출물을 보존했다.

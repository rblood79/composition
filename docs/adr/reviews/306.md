### h1 — HIGH: size 삭제 범위에서 typed 원본이 빠졌고, 구 문서는 무시되지 않는다

- 위치: `docs/adr/design/306-chart-36-types-recharts-size-removal-breakdown.md:175-186`, `docs/adr/306-chart-36-types-recharts-size-removal.md:99`.
- 현재 typed 원본 `packages/shared/src/catalog/document/generated/reusableOriginLibrary.ts:6135`에 `size: "M"`이 있다. `createChartInitialProps` 호출 여부와 무관하게 이미 실리는 값이다. 그런데 §6 삭제 표에는 이 정본이 없고 변경 여부를 Phase 1의 조건부 조사로 남겼다.
- 실행 반례: 현행 `buildCodeCatalogLibrary()`를 만들고 메모리에서 Chart의 size accepts/defaults/파생 시각 규칙을 제거한 뒤 `buildCatalogLibrary`로 검증 → `PROP_NOT_ACCEPTED: lib:template:component-chart.size`. 원본의 size도 제거한 뒤 같은 contract의 기존 Chart `size: "L"` 문서를 `CatalogGraph`로 로드 → `PROP_NOT_ACCEPTED: project:node:chart-review.size`. 전자는 앱 라이브러리 구성 자체를 막고 후자는 기존 문서 열기를 막는다. 원래 라이브러리의 같은 문서는 정상 로드됨을 먼저 확인했다.
- 근거: `packages/shared/src/catalog/document/library.ts:351-356`은 허용하지 않은 원본 prop을 거부하고 `graph.ts:1803-1813`은 문서 prop을 거부한다. 따라서 "accepts에 없으면 무시되어 240으로 표시"는 성립하지 않는다. contract를 올리면 Chart 유무와 무관하게 이전 contract 문서 전체가 `UNSUPPORTED_LIBRARY_CONTRACT`로 거부된다(`graph.ts:584-588`). 이는 기존 저장소 정책이며 변환 기능을 요구하는 지적이 아니다.
- 해결: typed Chart 원본의 size 제거를 Phase 1의 필수 변경으로 넣고 contract 상승·이전 문서 거부를 확정한다. 본문 Decision 7·Consequences·G1의 호환성/로드 판정을 그 계약에 맞춘다. 공개 React 타입의 `packages/shared/src/components/Chart.runtime.ts:85` size 선언도 제거 목록에 포함한다.

### m1 — MEDIUM: 크기에 의존하는 Sankey 배치를 size 없는 모델 memo로 재사용할 수 없다

- 위치: `docs/adr/design/306-chart-36-types-recharts-size-removal-breakdown.md:107-109`, `:217`.
- §4.2는 모델을 rows+의미 prop으로 memo하고 리사이즈 시 KDE와 함께 sankey relaxation도 다시 돌리지 않는다고 고정한다. 이식 대상으로 지정한 pinned 함수는 `width/height/nodePadding/nodeWidth`를 받아 픽셀 간격으로 초기 배치·충돌 해소·relaxation을 수행한다. 크기 변경은 배치 입력 변경이다.
- 실행 반례: 5링크에 nodePadding=12, nodeWidth=10을 유지해 320×240 → 640×360으로 계산. a 노드 y0는 126 → 186이며 이전 좌표를 높이 비율로 늘린 189와 3px 다르다. 노드 x 폭도 양쪽 모두 10px이므로 단순 배율 재사용은 폭을 20px로 잘못 늘린다. 전체 노드의 정규화 y0 최대 차이는 0.0083333이었다. 고정된 이전 배치를 재사용하면 현재 크기의 올바른 배치와 달라지고, 다시 계산하면 문서의 재계산 0 조건을 어긴다.
- 해결: 값 집계·그래프 구성 등 크기 독립 모델과 크기 의존 layout/relaxation을 나눠 memo 키를 정한다. 리사이즈 재계산 0은 크기 독립 단계에만 적용하고 배치에는 실제 크기·간격을 포함한다. 두 consumer는 그 결과를 함께 읽는다.
- 외부 근거: [pinned ztd sankeyLayout](https://github.com/Junhan2/ztd-charts/blob/3c4376cda61361d630ae4cc7bd472af64ba30d2e/packages/ztd-charts/src/layout/sankey.ts#L39-L169). 로컬 checkout SHA 일치 및 원문을 확인했다.

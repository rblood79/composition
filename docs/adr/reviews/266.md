### H1 — 재바인드 해제 순서를 건너뛴 등록 교체 계측·인계 (open)

- 위치: breakdown:18의 `registerSkiaNode` 교체에서 재바인드가 버린 자원을 세는 계획과 breakdown:34–39의 L2; ADR 본문:72.
- 실제 소비 경로: `canvasScene.ts:190–202`의 `rebind`는 `this.binding.dispose()` 뒤 새 `bind()`를 수행한다. `canvasBinding.ts:2448–2450`의 dispose는 모든 등록 ID에 `unregisterSkiaNode`를 호출한다. `useSkiaNode.ts:56–63`에서 paragraph 슬롯을 폐기하고 registry에서 삭제하며 picture도 무효화한다. 이후 `registerSkiaNode:37–43`에 들어올 때 `oldData`는 없다. 같은 내용이라는 비교와 dataRef 갱신을 등록 교체에만 추가해도 재바인드 캐시는 인계되지 않는다.
- 실행 반례: 실제 `CatalogWorkspace`와 Rust 레이아웃으로 Text를 삽입하고 실제 `CatalogCanvasScene`에 바인딩한다. 같은 노드에 retained paragraph와 picture를 붙인 후 문서 변경 없이 `scene.rebuild()`를 호출한다. 텍스트 내용은 같지만 새 원본 노드가 생기며 옛·새 슬롯 모두 비었고 picture도 miss다. disposal drain 뒤 picture 1개·paragraph 1개가 실제 delete되었다. CanvasKit 자원만 delete spy인 대역이며 workspace/binding/registry 수명 경로는 실제 코드다.
- 영향: Phase 0의 `rebindReleasedPictures`/`rebindReleasedParagraphs`/`rebindSameContent`가 주요 재바인드 비용을 0으로 오분류하고 `cold-released`도 누락할 수 있다. G0 go/no-go와 L1 뒤 남는 재바인드에 대한 L2 효과가 함께 무효화된다.
- 해결: 계측은 실제 unregister/dispose 해제 지점에서 재바인드 사유와 함께 수행한다. 재바인드용으로 구·신 노드를 비교할 수 있는 명시적 인계 수명/transaction을 두고, 성공 시 자원을 이동한 뒤 잔여 구 노드를 해제한다. 실패·삭제·root 교체 시 정리와 font/image invalidation을 유지한다. 직접 register→register 테스트에 더해 실제 `scene.rebuild()`/`imageLoaded()`를 통과하는 유지 검증을 계획에 포함한다. 이는 현행 해제가 잘못이라는 지적이 아니라 제안된 최적화의 삽입 지점이 대상 경로에 닿지 않는 문제다.

### M2 — cache miss 수를 working set으로 삼으면 상한이 다시 줄어든다 (open)

- 위치: breakdown:22의 `recordedElementsPerContent` 정의와 :43–45의 L3.
- 입력 → 결과: 1,370개를 그리는 content에서 상한 1,713과 warm cache를 가진다. 다음 content 기록은 1,370개 모두 hit하므로 새 picture record 수는 0이다. 문서의 산식 `max(1024, ceil(recorded × 1.25))`을 기록 끝에 적용하면 상한이 1,024로 줄고 346개가 퇴거된다. 다음 동일 순서 스캔에서 LRU 순차 thrash로 1,370개 전부 miss가 된다. 상한을 그제야 1,713으로 늘려도 반복적으로 전체 재기록이 재발한다.
- 검증: 문서의 상한 산식과 LRU 동작을 그대로 둔 독립 모델 프로브가 warm frame `hit=1370, record=0, cap=1024`와 다음 frame `hit=0, record=1370, cap=1713`을 확인했다. 제안된 정책의 반례이며 아직 존재하지 않는 L3 제품 구현을 실행했다는 뜻은 아니다.
- 해결: 상한은 hit+miss를 포함한 고유 self-draw 수/실제 resident working set으로 산출하고 record 수는 비용 계측으로 분리한다. 부분 damage 기록 한 번이 전체 working set을 축소하지 않도록 full/content 기록 범위와 축소 조건도 명시한다. 같은 visible set을 연속 재기록했을 때 warm 상태가 유지되어야 한다.

### H1 — 실제 해제 지점 계측과 두 단계 교체로 수리 (closed)

- breakdown:18은 `scene.rebind`가 사유 구간을 열고 실제 `unregisterSkiaNode`에서 버린 picture/paragraph를 세도록 수정됐다. 새 등록과의 동일 내용 비교용 데이터는 사유 구간의 dev 맵에 보관한다. 등록 교체에서만 계측하던 초안의 누락이 해소됐다.
- breakdown:34–39는 `retire()`가 구독만 끊고 registry를 남기며, 새 `bind()`에서 oldData를 보고 인계한 뒤 새 등록에서 빠진 id만 `releaseRemaining`으로 정리하는 순서를 명시한다. 실패 시 전량 정리, verify/drag의 인계 금지, image-loaded/root의 내용 비교, owner-drawn/volatile/편집 중 노드 제외와 font/image 무효화 유지도 포함됐다.
- 실제 코드 대조: `canvasBinding.ts:1491–1506`의 새 bind는 등록 id를 모으면서 register를 호출하고, :2448–2450은 unsubscribe와 unregister를 연달아 호출한다. 이 두 동작을 분리하면 oldData를 볼 수 있는 삽입 지점이 실제로 존재한다.
- 실행 프로브: 실제 workspace/엔진/scene에 Text와 자원 대역을 등록한 뒤, 기존 binding.dispose의 unregister만 spy로 억제해 제안된 retire를 흉내 냈다. 실제 `bindCatalogCanvas`가 해당 Text를 재등록하는 순간 옛 노드 identity·retained paragraph·cached picture가 모두 살아 있음을 확인했다. 다시 등록된 id를 잔여 정리에서 제외하면 새 노드도 유지됐다. **이는 인계 지점의 도달성 검증이며 아직 없는 sameDrawData/dataRef/슬롯 이동 구현이 통과했다는 뜻은 아니다.**
- 실제 `pageGridChanged` 강제 재바인드와 `imageLoaded`, verify 및 내용 변경을 통과하는 제품 테스트가 :39에 명시돼 기존 직접 register 테스트의 경계 누락도 보완됐다.

### M2 — miss 수와 working set 분리로 수리 (closed)

- breakdown:22는 touched를 full 기록의 hit+record 고유 수로 정의하고 recorded는 비용 계측으로 분리했다. :44–45의 진입 기준과 동적 상한도 touched를 사용한다. damage/drag subtree 기록은 상한을 줄이지 않고, full 기록에서만 3회 연속 60% 아래일 때 축소하는 히스테리시스가 명시됐다.

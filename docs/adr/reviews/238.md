# ADR-238 Review Log

## Round 1 — 2026-09-24 (reviewer: codex)

merge 차단 문제 4건입니다. 모두 현재 코드와 제안된 계약을 대조한 반례이며, 구현 후 브라우저 재현은 **UNVERIFIED**입니다. 파일은 수정하지 않았습니다.

1. **[severity HIGH] [category: other] `props.id` 우선 규칙이 section 상속 항목의 key 유일성을 깨뜨립니다.**

   **근거:** [breakdown:75](/Users/admin/work/composition/docs/adr/design/238-collection-item-slots-sections-picker-items-breakdown.md:75)는 경로 접두를 붙이면서도 `props.id`가 있으면 그대로 사용합니다. 그런데 [staticCollectionMigration.ts:390](/Users/admin/work/composition/apps/builder/src/builder/components/staticCollectionMigration.ts:390)는 일반 이관 항목에도 `props.id`를 저장하며, [collectionItemInsert.ts:167](/Users/admin/work/composition/apps/builder/src/builder/components/collectionItemInsert.ts:167)의 Slot 삽입도 같은 경로를 사용합니다. 따라서 `props.id`의 존재를 “현재 instance에서 사용자가 지정한 전역 유일 key”로 해석할 수 없습니다. RAC는 section 전체에서 유일한 id를 요구합니다. [공식 계약](https://react-aria.adobe.com/collections#globally-unique-ids)

   **실패 시나리오:** section origin에 Slot “+”로 항목을 추가하여 `props.id="item-a"`가 저장됨 → 같은 origin의 section instance 두 개를 한 ListBox에 삽입 → 두 상속 항목 모두 key가 `"item-a"` → 선택이 두 항목에 걸리고 항목 식별이 충돌합니다. 객체 동일성 조회 수리는 RAC key 충돌을 해결하지 않습니다.

   **해결 방향:** 상속된 id와 collection에서 명시적으로 소유하는 id를 구분하고, 상속 항목에는 일관된 namespace를 적용해야 합니다. 기존 `selectedKeys`와 Menu section 선택값의 대응도 함께 정의해야 합니다.

2. **[severity MEDIUM] [category: evidence-missing] Select/ComboBox의 `id`와 `value`를 독립적으로 보존하는 이관 계약이 없습니다.**

   **근거:** [본문:89](/Users/admin/work/composition/docs/adr/238-collection-item-slots-sections-picker-items.md:89)와 [breakdown:82](/Users/admin/work/composition/docs/adr/design/238-collection-item-slots-sections-picker-items-breakdown.md:82)는 행의 `id`/`value`를 `props.id`로 옮긴다고만 규정합니다. 실제 기본 데이터부터 두 값이 다릅니다([SelectionComponents.ts:25](/Users/admin/work/composition/apps/builder/src/builder/factories/definitions/SelectionComponents.ts:25)). 현재 선택 writeback은 `selectedKey=id`, `selectedValue=value`를 별도로 저장합니다([SelectionRenderers.tsx:1367](/Users/admin/work/composition/packages/shared/src/renderers/SelectionRenderers.tsx:1367)).

   **실패 시나리오:** `{id:"opt-1", value:"KR", label:"대한민국"}`, `selectedKey:"opt-1"` → `value`를 새 id로 사용하면 기존 선택이 끊깁니다. `id`만 보존하고 `value`의 저장·조회 경로를 제거하면 재선택 시 `selectedValue`가 `"KR"` 대신 `"opt-1"`이 됩니다. 초기 선택과 표시 글자만 비교하면 후자는 통과합니다.

   **해결 방향:** `id→props.id`와 업무 값 `value`의 보존 위치를 별도로 명시하고, 클릭·입력 일치 처리의 writeback도 새 항목에서 같은 값을 읽도록 계약을 정해야 합니다.

3. **[severity MEDIUM] [category: other] `textValue=label` 이관은 기존 검색 동작을 변경합니다.**

   **근거:** [breakdown:83](/Users/admin/work/composition/docs/adr/design/238-collection-item-slots-sections-picker-items-breakdown.md:83)는 이관 항목의 `textValue`를 label 글자로 정합니다. 그러나 `textValue`는 사용자가 별도로 편집하는 필드이고([ComboBox.binding.ts:33](/Users/admin/work/composition/packages/shared/src/catalog/bindings/ComboBox.binding.ts:33)), 현재 renderer는 `item.textValue ?? item.label`을 RAC에 전달합니다([SelectionRenderers.tsx:1552](/Users/admin/work/composition/packages/shared/src/renderers/SelectionRenderers.tsx:1552)). RAC 필터의 입력도 `textValue`입니다. [공식 API](https://react-aria.adobe.com/ComboBox#api)

   **실패 시나리오:** `{label:"대한민국", textValue:"대한민국 Korea"}`인 옵션에서 `"Korea"` 입력 → 이관 전에는 검색됨 → 제안대로 이관하면 `textValue:"대한민국"`이 되어 검색 결과에서 사라집니다. Canvas 픽셀과 초기 선택은 동일할 수 있습니다.

   **해결 방향:** 명시된 `textValue`를 보존하고, 부재할 때만 label을 사용해야 합니다. G3의 “label 글자로 필터” 조건도 이 우선순위를 반영해야 합니다.

4. **[severity MEDIUM] [category: other] 선택 항목이 없으면 placeholder를 표시한다는 규칙이 ComboBox 자유 입력을 잃게 합니다.**

   **근거:** [breakdown:82](/Users/admin/work/composition/docs/adr/design/238-collection-item-slots-sections-picker-items-breakdown.md:82)는 Canvas 표시를 “선택 항목의 label, 없으면 placeholder”로 정합니다. 현재 공용 reader는 `inputValue`를 선택값보다 먼저 읽고([selectDisplayValue.ts:34](/Users/admin/work/composition/packages/shared/src/collections/selectDisplayValue.ts:34)), Preview도 이를 `defaultInputValue`로 복원합니다([SelectionRenderers.tsx:1639](/Users/admin/work/composition/packages/shared/src/renderers/SelectionRenderers.tsx:1639)). 자유 입력은 기본 factory에서 허용됩니다.

   **실패 시나리오:** 정적 ComboBox에 목록에 없는 `"서울 지사"`를 입력하여 `inputValue`만 저장 → 이관·reload → 제안된 Canvas reader는 placeholder를 표시하지만 Preview는 `"서울 지사"`를 표시합니다. 해당 입력 상태를 Undo/Redo로 복원해도 같은 불일치가 발생합니다.

   **해결 방향:** 기존 자유 입력 우선순위를 유지하고, 선택 항목 label을 찾는 부분만 canonical 항목 조회로 교체해야 합니다.

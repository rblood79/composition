## Round 2 — 2026-11-25 (reviewer: claude)

## 수리 검증 (round 1 의 HIGH 1 · MEDIUM 2)

- **h1 fixed** — breakdown §5.1: 읽기 실패 = 행마다 부른 `normalizeRows` report 의 `unread` · `precision` · `typeMismatch` (판정 함수 하나, HC2 유지), 그 칸은 쓰지 않고 「읽기 실패」 로 센다. 본문 F4 · HC2 · Decision 2 · R2 · G1 이 같은 내용이고 G1 의 자기모순 (EditableCell 과 같은 값 + 실패 0 건 쓰기) 이 「읽히는 값은 같음 · 읽히지 않는 글자는 원래 값 유지」 로 갈렸다. `update` 경로를 맞출지는 사용자 결정 8 (Phase 1, 권고 「맞춘다」). 근거 재확인: `normalizeRows.ts:164-178` (글자 실패 → `null`) · `:184` · `catalogPreviewSession.ts:1135-1148` (`itemFields` 가 report 를 버림).
- **m1 fixed** — breakdown §5.4: 상태는 replay 가 만든 항목 객체 (WeakMap) 에 붙이고 replay 뒤 `getItemKey` 로 Map 을 만든다. 근거: replay 의 `update` 는 `{ ...item, ...patch }`, `append` · `insert` 는 `edit.item` 으로 새 객체를 만든다 (`catalogPreviewSession.ts:388-394` · `:345-353`). G4 에 id 없는 collection + `insert` · `remove` · `move` 경우를 넣었다.
- **m2 fixed** — breakdown §5.4 · §5.6 · 본문 결정 6 · G4: 편집 번호 + 저장이 보낸 (key, field) 목록, 성공 때 「마지막 편집 번호 ≤ 보낸 번호」 인 칸만 표시를 지우고 실패면 아무것도 지우지 않는다. EditableCell 경로의 순서 확인: RAC `useContextProps` 가 `mergeProps(contextProps, props)` (`react-aria-components/dist/private/utils.mjs:100`) 라 `FormContext` 의 submit (`onSave` → 세션 `update`) 이 Form 규칙 `onSubmit` 보다 먼저 돈다 — 규칙 실행 때 편집 번호가 있다.

새 HIGH 0. round 1 의 LOW 4 는 deferred (production 재현 없음 — 문서 정정, 착수 Phase 0 에서 반영 가능).

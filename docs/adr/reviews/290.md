HIGH — Badge subtle의 실제 글자 바탕 accent-subtle이 대비 제약에서 빠졌다.

- 대상: docs/adr/290-theme-accent-contrast-target-lightness.md:122-128,171; docs/adr/design/290-theme-accent-contrast-breakdown.md:35-39.
- 소비 경로: componentRulesTable.ts:312-322의 Badge accent/subtle은 background=accent-subtle, subtleText=accent이다. 제안된 분류를 적용하면 subtleText=accent-content가 된다. 실제 생성 CSS Badge.css:57-60도 이 바탕/글자 조합을 사용한다.
- 제안된 조건은 base/layer-1/layer-2/elevated에 4.5, neutral-subtle에 3.0뿐이다. accent-subtle은 지금 공식을 유지하면서 제약에는 넣지 않았다.
- 재현 입력: light + neutral + blue + Badge variant=accent, fillStyle=subtle, 일반 크기 글자. accent-content 시작값 #3660f0가 위 조건을 모두 만족해 그대로 유지된다. 하지만 실제 바탕 accent-subtle=#daeeff와는 4.318442:1로 4.5 미달이다. green은 조건에 맞춰 #1f834f로 바뀌어도 실제 바탕 #dcf6e4와 4.152792:1, turquoise는 #277e88/#ddf4f6에서 4.144816:1이다.
- 확인: 원본 oklchToHex, createAccentColorTokens 및 생성 Tailwind palette를 실행했다. 새 solver 구현 결과로 주장하지 않는다. 제안된 조건과 가장 가까운 통과 명도를 독립 0.00001 격자 탐색으로 산출했다. blue는 시작 명도가 이미 조건을 만족하므로 탐색 방식과 무관한 반례다. 참조쌍 black/white=21.
- 해결: accent-content의 실제 인접색에 accent-subtle을 4.5 조건으로 포함하고, 파생 및 명시 accent-subtle 델타를 탐색 전에 해석한다. G1에 이 대비쌍을, G3에 Badge subtle을 포함한다. 토큰 역할을 추가할 필요는 없다.

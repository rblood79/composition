#### H1 (HIGH) — 메뉴 항목 절반의 배선 경로가 실재하지 않는다

HC4 (`ADR:25` "기존 store/단축키 핸들러 배선") 와 §3-2 (`deps 는 액션 핸들러 주입 — BuilderCanvas / LayerTree 가 기존 핸들러를 넘김`) 는 §1 인벤토리가 나열한 핸들러가 호출 가능하다고 전제한다. 실측은 반대다:

- `useGlobalKeyboardShortcuts.ts:99` 훅은 **아무것도 반환하지 않는다** (`:631-640` 이 registry 등록으로 끝, `BuilderCore.tsx:383` 에서 side-effect 호출). `handleCanvasCopy:182` / `handleCanvasPaste:205` / `handleCanvasDelete:250` 은 내부 `useCallback` 클로저다.
- `CanvasSelectionShortcuts.tsx:46` 은 **컴포넌트 1개만 export** 한다 (`CanvasSelectionShortcutsHost`, `BuilderCore.tsx:1161` 마운트). `handleDuplicate:226` / `handleGroupSelection:401` / `handleUngroupSelection:468` / `handleAlign:540` / `handleDistribute:608` 은 전부 비-export 클로저.
- `useKeyboardShortcutsRegistry.ts` 의 export 는 타입·훅·`logShortcuts`·`formatShortcut` 뿐 — **id 로 핸들러를 동작하는 dispatch API 가 없다**.

영향 범위: T1 #1 Copy · #2 Paste · #3 Duplicate · #8 Group · #9 Ungroup · #10 Align▸ 과 T2 #1 Paste here — **14항목 중 7항목**. 하위 유틸(`multiElementCopy.ts` / `elementGrouping.ts` / `elementAlignment.ts` / `elementDistribution.ts`)은 export 되어 있으나, 선택 해소·scope 분기·확인 다이얼로그·히스토리 오케스트레이션은 위 클로저 안에 있다. 나머지 7항목(delete/reorder/component 토글/detach/go-to-origin/zoom/rulers)은 store 액션이라 도달 가능하다 — **비대칭이 이 결함의 신호**다.

따라서 Phase 2·3 은 "provider + 배선" 이 아니라 **핸들러 추출 계층 신설(또는 registry dispatch API 도입)** 을 포함해야 하며, §4 파일 변경표에 `useGlobalKeyboardShortcuts.ts`(640줄)·`CanvasSelectionShortcuts.tsx`(873줄) 가 없다. 권고: Phase 1 에 "액션 계층 추출" 을 명시 항목으로 추가하고 두 파일을 변경표에 등재, HC4 문구를 "기존 유틸 재사용 + 오케스트레이션 공유 계층 추출" 로 정정.

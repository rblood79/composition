#### h1 · HIGH · evidence-missing — §3.1 raw/plot/display 표가 현행 값 라벨 의미와 모순 (expand 값 라벨은 raw 다)

- **설계 주장**: breakdown:66 "일반 축/값 라벨 → plot 값", :68 "expand 축/값 라벨 → 0–100 normalizedPercent", T05 (:116) "expand25 → 25%".
- **코드 사실**: 값 라벨은 stack 모드와 무관하게 **raw 개별값**을 받는다 — `marks/bar.ts:196-210` (stacked/expand 분기에서 `series.values.get(ci) ?? 0` 을 label 로 push), `marks/area.ts:92`, `RechartsChart.tsx:138` (`label${si}` = `labelText(ci, raw)`), `computeChartScene.ts:351-354` (`formatTick(raw)`). 정규화(0–100)는 **축 눈금** (`runtimeData.ts:29,36` `valueExtent(grid,"expand")` → `niceTicks`) 과 마크 기하 (`series.ts:154-160`) 에만 적용된다. tooltip 도 raw (`RechartsChart.tsx:255-258`).
- **실패 시나리오**: 사용자가 expand + `valueFormat:"percent"` + `valuePercentUnit:"percentagePoints"` 를 켠다. 설계대로 값 라벨 context 를 `normalizedPercent` 로 주면 raw 120 이 "120%" 로 찍히고 (ratio 면 "12000%"), 축은 "25%". 반대로 구현자가 값 라벨을 정규화 값으로 바꾸면 **auto/미설정 문서의 라벨 문자열이 바뀐다** — HC ADR:21 "기존 문자열 보존" 위반. T05 는 어느 쪽이 정본인지 판정하지 못한다 (측정 leakage #3 — 설계 표와 설계 fixture 가 서로 확인).
- **최소 수정**: §3.1 표를 "expand 축 눈금 = normalizedPercent(비율로 변환해 Intl percent)" 와 "expand/stacked 값 라벨 = raw 집계값 (현행 유지, tooltip 과 같은 context)" 로 분리. `formatChartNumber(value, config, context)` 의 context 를 마크 빌더가 아니라 `computeChartScene` 의 `labelText` 한 곳과 축 tick 한 곳에서 고정. T05 기대값을 "expand **축** 25 → 25% · expand **값 라벨** raw 120 → currency/decimal 문자열" 로 고친다. 값 라벨을 정규화로 바꾸고 싶다면 그것은 **동작 변경**이므로 HC 재판정 + 별도 fixture.

#### m1 · MEDIUM · evidence-missing — "200행×4시리즈 p95≤100ms" 의 workload 가 ADR-209 기준 (200 마크) 과 다르다

- ADR:25 / breakdown:145,147 은 "200행 × 4시리즈" 를 static 상한 조건으로 둔다. ADR-209 의 ≤100ms 는 `209-runtime-performance-harness.txt:39-42` 의 **200행 × `series: S${i%4}` = 4 시리즈 × 50 범주 = 200 마크** 에서 나온 수치다. columns 모드 "200행 × 4필드" 는 **200 범주 × 4 시리즈 = 800 마크** 다. breakdown:149 는 "같은 마크 수" 로 별도 비교한다고 쓰지만 HC 의 ≤100ms 가 어느 마크 수에 붙는지 정해지지 않았다 — 800 마크에서 100ms 를 요구하는지, 200 마크 동등 데이터인지에 따라 G4 의 PASS/FAIL 이 갈린다 (measurement-validity Q1·Q3).

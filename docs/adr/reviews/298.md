## Round 1 — 2026-11-01 (reviewer: codex)

판정: **설계 수정 필요 — HIGH 2 · MEDIUM 2, pending 4**. 채택 대안 B 의 방향은 유지. 제품 코드 · ADR 상태 변경 없음. 검토 기준: main `dd7a12602` + untracked ADR-298 본문 · breakdown · 분석 문서. 브라우저 실행 결과는 UNVERIFIED (코드 경로 판정).

실행자 (Claude) 가 네 건의 인용을 직접 열어 확인했다 — `codeViewFillsCss` 가 `layer.color` 를 그대로 합침 (`styles.ts:355-370`) · `codeViewFillColor` 는 hex 만 (`:424`) · `tokenOf` → `SET({kind:"token"})` 복원은 `if (token && visual)` 로 visual 만 (`codeViewStyles.ts:399`) · rule 행간은 `sourcePixels(lineHeight) / sourcePixels(fontSize)` 배율 (`codeCatalogLibrary.ts:179`) 뒤에 `applyWrites(visual, node.visual)` (`resolver.ts:1468`) · `deviceTypography` 는 배율이 짝과 같을 때만 변수로 (`:49-57`) · library `tokens` 와 revision 해시에 토큰 배열 포함 (`codeCatalogLibrary.ts:976-1001`) · 검증기 `library.tokens.get` 직접 조회 (`graph.ts:1721`) · computed 는 수치 (`switchDomPaint.browser.test.ts:57`).

### H1. D8 「코드 보기 변경 0」 ↔ Phase 3 fills · inset 왕복
Phase 3 에서 fill 색에 `TokenUse` 저장 → `codeViewFillsCss` 가 `background: [object Object]`. `background: var(...)` 입력은 `codeViewFillsOf` 가 파싱하지 못한다. inset 의 `var(...)` 도 `tokenOf` 가 layout 으로 복원하지 않는다. 수정 방향: D8 의 변경 0 을 visual 범위로 한정하고 Phase 3 에 fill · gradient stop · inset 의 출력 · 역파싱을 명시.

### H2. 행간 배율 계약
기본 Text M = `{typography.text-base}` / `--line-height` (16/20 → 배율 1.25, `componentRulesTable.ts:13326`). 노드에 제목 M 22 토큰만 저장하고 행간을 비우면 1.25 가 남아 27.5px — 설계 표의 짝 26 이 아니다. DOM 도 배율이 짝과 일치할 때만 변수로 바꾼다. 수정 방향: 명시 행간과 자동 행간을 구분하고, 자동 행간은 최종 fontSize 토큰의 짝에서 배율을 계산. length 토큰 px 를 배율 필드에 그대로 전달 금지.

### M3. G1 투영 동일 ↔ D2 토큰 추가
토큰 하나만 더해도 `tokens` · `revision` 이 달라져 G1 실패. 수정 방향: 기존 참조의 해석값 · 기존 Page.css · 생성 CSS 동일성과 신규 토큰 · 별칭 표의 정확성을 분리. 별칭은 `library.tokens.get` (검증기 · Code) 에서도 성립해야 한다.

### M4. G2 computed `var()` 참조
`gap: var(--catalog-token-spacing-md)` 가 정상 적용되면 computed 는 `12px`. 수정 방향: inline 선언의 변수 참조 확인과 테마 · 모드 전환 전후 computed 값 확인을 분리.

### 그 밖의 판정
- F1 · F9 · F10 · F12 인용 맞음. F9 접미사는 활성 모드 재해석값에 영향 없지만 ID 조회에는 필요 (`themedToken.ts:36`). F12 DOM 미갱신은 추정 유지.
- D5: 노드 토큰이어도 최종 inline 값과의 일치 검사를 일괄 제거하면 안 된다 — paddingX 토큰과 별도 paddingLeft 값이 공존할 수 있고 현재 검사가 후자의 덮어쓰기를 막는다 (`deviceTypography.ts:193`). 색 · 그림자 확장 때 기본 light 로 읽는 `resolveToken(ref)` 비교를 그대로 복사하면 안 된다 (`tokenResolver.ts:31`).

- 사용자 결정 1 · 4 · 5 는 D1/D2/D3 경계 · 승인 scope 변경이 아닌 구현 · 표시 계약 — Phase 진입 때 재질문 불필요. 2 · 6 · 7 은 범위 변경, 3 은 기존 사용자 결정 변경이라 질문 가능.

**LOW deferred**: 295 G2 하니스는 박스 차이 판정 + DOM 스크린샷 저장만이라 paint 픽셀 oracle 추가 필요 (`adr295PaletteSymmetry.browser.test.ts:390,405`) · G1~G5 의 pre-push 배선 없음 (`.githooks/pre-push:69`) · G5 A/B · 부하 · 측정 조건 구체화. production 재현 없는 커버리지 지적이라 라운드 재개 사유 아님.

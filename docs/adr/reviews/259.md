### HIGH — r1-h1: 도움말 Button은 field ButtonContext에서 명시 해제해야 한다

대상: `docs/adr/259-s2-contextual-help-prefix-item-links.md:77,140`, breakdown `:43-44`.

- 재현 입력: `ComboBox[isDisabled=true] > div(Label + DialogTrigger(Button[aria-label=Help] + Popover))`, Button의 slot 미지정.
- 결과: 도움말과 picker Button이 모두 `disabled=true`. 도움말이 picker의 `aria-labelledby`도 상속한다. 사용자는 비활성 field의 도움말을 열 수 없고, 도움말 이름이 picker 버튼의 이름 경로에 연결된다.
- 대조: 도움말만 `slot={null}`이면 도움말 `disabled=false`, picker `disabled=true`; 실제 S2 disabled ComboBox도 같은 결과다. 이름은 별도로 field Label id + 도움말 자신의 id를 연결해야 한다.
- 원인 근거: `runtime/racSlot.ts:43-50,78-87`의 plain context는 미지정 slot을 그대로 연결한다. `runtime/racSlotScope.tsx:45-49`가 이를 읽는다. RAC `Dialog.mjs:47-93`의 DialogTrigger는 외부 ButtonContext를 지우지 않는 PressResponder이며, RAC `ComboBox.mjs:215-224`는 picker ButtonContext를 제공한다. S2 `ContextualHelp.tsx:195-205`는 `slot={null}`을 명시한다.
- 해결 경계: 새 ContextualHelp 원본의 trigger Button에 catalog `slot:false`(RAC null)를 명시하거나 ContextualHelp binding에서 같은 연결 해제를 보장한다. Label context·도움말 이름 연결 및 DialogTrigger의 PressResponder는 유지한다. G3에 disabled ComboBox 도움말 열기와 picker 독립성 검증을 넣는다. 일반 Button의 context 처리를 전역 변경할 필요는 없다.

### MEDIUM — r1-m1: Popover의 제목 ID를 실제로 연결해야 한다

대상: 본문 `:140,176`, breakdown `:18,43`.

- 재현 입력: `DialogTrigger[defaultOpen=true] > Button[slot=null,aria-label=Help] + Popover > Heading[slot=title]('Help title')`.
- 결과: `role=dialog`는 생성되지만 `aria-labelledby`는 trigger Button을 가리켜 `Help`가 된다. Heading에는 제목 ID가 없고, `slot=title`만으로 연결되지 않는다.
- 독립 S2 oracle: 같은 제목을 둔 S2 ContextualHelp는 dialog가 Heading id를 참조해 `Help title`로 명명된다. RAC Popover에 제목 id와 `aria-labelledby`를 명시한 대조도 동일하게 정상이다.
- 원인 근거: catalog `domBinding.runtime.ts:685-697`은 Heading의 slot을 전달할 뿐이고, `:1769-1780`의 제목 처리는 Dialog에 한정된다. RAC Popover는 HeadingContext를 제공하지 않는다. S2 `ContextualHelp.tsx:54-59,79-87`는 Popover의 `aria-labelledby`와 title slot의 id를 직접 연결한다.
- 해결 경계: ContextualHelp 내부에 한정하여 Popover와 title Heading의 안정된 DOM id를 연결하거나 S2와 같은 HeadingContext provider를 제공한다. 일반 Popover에 Dialog를 강제로 추가하면 기존 picker·menu의 구조와 칠에 영향을 주므로 이 수정의 경계로 삼지 않는다. 제목 교체·편집 후에도 참조가 유효하고 작성 이름 우선순위가 유지되는지 G3에서 확인한다.

### MEDIUM — r1-m2: prefix를 눌렀을 때 input에 포커스가 가야 한다

대상: 본문 `:92,141`, breakdown `:35-39`.

- 재현 입력: `TextField > Label + Group(span('$') + Input)`, 앞 글자에 mouse `pointerdown`.
- 결과: `document.activeElement !== input`; 같은 입력의 실제 S2 TextField prefix는 `document.activeElement === input`.
- 원인 근거: `components/Group.tsx:88-102`는 RAC Group을 전달할 뿐이다. 기존 field wrapper DOM 경로에도 이 포커스 전달이 없다. S2 `Field.tsx:258-273`는 비대화형 prefix·padding에 pointerdown 및 touchend 처리를 명시한다. CSS·상자 칠·aria-labelledby 변경만으로 동작이 추가되지 않는다.
- 해결 경계: prefix를 가진 field control Group에 한정해 비대화형 앞 글자·상자 padding의 포인터/터치를 input 또는 textarea로 전달한다. Button·입력·편집 가능한 자식의 동작과 disabled field의 상태는 보존한다. 일반 Group 전체에 이 동작을 추가하지 않는다. G2에서 앞 글자 클릭 후 입력 및 포커스 상태를 확인한다.

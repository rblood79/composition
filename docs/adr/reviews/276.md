# ADR-276 Review Log

## Round 1 — 2026-10-20 (reviewer: codex)

판정: **설계 승인 보류 — HIGH 3건, pending 3건**. 세 이슈는 모두 open이다. 제품 코드와 ADR 본문·Status는 수정하지 않았다.

1. **[HIGH · h1 · open] 글자 없는 중첩 Button의 변경 0 지침을 수정해야 한다.**

   대상: `docs/adr/design/276-button-text-child-iconbutton-merge-breakdown.md:31` 및 본문 R1 (`docs/adr/completed/276-button-text-child-iconbutton-merge.md:95`). Phase 1은 Button에 기본 `label: Button`과 `Text{label}`을 추가하지만, Phase 0은 글자 없는 호스트를 변경 0으로 규정한다. 현재 NumberField 증감 (`packages/shared/src/catalog/document/generated/reusableOriginLibrary.ts:3920`, `:3945`)과 Select trigger (`:4548`)는 `origin-component-button`을 참조하며 `children: ""`로 기존 자체 글자만 비운다. resolver의 `templateBindings` (`packages/shared/src/catalog/resolution/resolver.ts:810`)는 새 `label` 기본값을 별개 키로 공급하고, nested root와 호스트의 자체 자식은 함께 해석된다 (`:1937`, `:2022`; `packages/shared/src/catalog/runtime/compositionRoot.ts:495`).

   입력·상태 → 잘못된 결과: 새 라이브러리에서 NumberField/Select를 팔레트로 생성 → 원래 Icon 또는 SelectValue만 있어야 할 trigger에 기본 Text `Button`이 추가된다. 이는 옛 문서와 무관한 새 프로젝트 회귀다. ButtonGroup의 Cancel/Save 등 `children`으로 라벨을 쓰는 중첩 origin도 `label` 쓰기로 옮기지 않으면 기본 라벨이 생긴다 (`reusableOriginLibrary.ts:3549`).

   해결 방향: 인벤토리를 type-Button 직접 참조뿐 아니라 `origin-component-button`과 중첩 origin 참조까지 포함하고, 글자 없는 호스트는 새 Text의 부재를 명시해야 한다. 단순 빈 라벨은 빈 Text의 flex 자리·gap이 남을 수 있으므로 노드 생략 계약도 정한다. 글자 있는 호스트의 `children`도 새 바인딩으로 옮기고, NumberField·Select·ButtonGroup의 유효 자식과 글자를 G1/G2 완료 조건에 포함한다.

2. **[HIGH · h2 · open] template 라벨과 owned Icon이 서로 다른 목록이라 기본 순서와 편집 대상이 맞지 않는다.**

   대상: `docs/adr/design/276-button-text-child-iconbutton-merge-breakdown.md:46` 및 `:47`. 제안은 Text를 origin template에 두면서 Icon을 기존 방식의 `index: 0`으로 삽입한다. 현재 `catalogButtonChildren`는 `node.children`과 `reader.getEntry`만 읽고 (`apps/builder/src/builder/catalogRuntime/buttonChildren.ts:41`), 삽입 부모는 `{ kind: node, id: nodeId }`다 (`:117`). `childList`는 이 경우 소유 children만 반환한다 (`packages/shared/src/catalog/commands/context.ts:287`). resolver는 template root부터 해석하고 그 뒤 소유 children을 붙이며 (`packages/shared/src/catalog/resolution/resolver.ts:1233`, `:1292`), consumer의 `collapsedChildren`도 안쪽 template 자식을 먼저 유지한다 (`packages/shared/src/catalog/runtime/compositionRoot.ts:495`).

   입력·상태 → 잘못된 결과: 새 Button origin instance 생성 → Icon 선택 → 소유 목록 index 0의 Icon은 실제 화면에서 template Text 뒤에 놓여 Decision 4의 앞 배치가 성립하지 않는다. 같은 상태에서 기존 조회는 Text 자리를 찾지 못하므로 `ownText`를 제거한 Label 칸도 새 Text를 읽지 못한다 (`apps/builder/src/builder/panels/properties/catalog/CatalogButtonChildFields.tsx:53`). template Icon이 있는 preset/호스트까지 확장하면 NodeId 전용 변경·제거 역시 해당 자리를 대상으로 삼지 못한다.

   해결 방향: 조회는 유효 자식 position과 EditTarget/address를 식별하고, 쓰기는 catalog 명령으로 처리하도록 계약을 명시한다. Icon 삽입 위치는 template Text와 함께 정렬되는 목록/slot 기준으로 정의해야 한다. fillSlot materialize를 선택한다면 `{label}` 바인딩을 잃지 않는지도 명시한다. G1에 실제 해석된 자식 순서 Icon→Text, Properties 라벨 읽기·쓰기, template/owned 대상의 변경·삭제와 Undo/Redo를 포함한다.

3. **[HIGH · h3 · open] 옛 문서 유지와 origin 삭제의 허용 조합을 닫아야 한다.**

   대상: `docs/adr/completed/276-button-text-child-iconbutton-merge.md:78`, `:86`, `:88` 및 breakdown `:53`~`:54`. 문서는 IconButton origin 삭제와 옛 문서 그대로 렌더를 독립 선택지로 두고, 기존 instance는 구조가 같아서 그려진다고 설명한다. 실제 문서의 IconButton node는 `definitionId: lib:definition:origin-component-iconbutton` 참조다. 해당 정의가 없으면 graph 참조 검증은 즉시 `DANGLING_DEFINITION`을 던진다 (`packages/shared/src/catalog/document/graph.ts:996`). 라이브러리 Button template도 같은 ID 아래 바꾸므로, 익명 글자 읽기만 남기는 것은 옛 템플릿 보존이 아니다.

   입력·상태 → 잘못된 결과: 선택 1(a)+3(a) 후 저장된 IconButton 프로젝트 재열기 → Button으로 표시되지 않고 정의 참조 오류로 로드 실패. 기존 plain Button의 `children: Saved` override도 같은 버전에서 열면 옛 문자열과 새 기본 Text label `Button`이 함께 남을 수 있다.

   해결 방향: 현재 구조 변경 계약 (`.agents/skills/composition-patterns/rules/domain-structure-change-audit.md`, Step 3)에 따라 contract 증가·구버전의 명시적 거부를 기본 경로로 확정하고, 실제 구현 시 현재 상수에서 다음 버전을 정한다. 호환 유지를 새 결정으로 택하려면 삭제 정의 및 옛 Button template의 보존·버전 선택 정책이 별도로 필요하다. 최소한 정의 삭제+옛 문서 유지 조합을 허용하지 말고, G3가 plain Button과 IconButton의 지원/거부를 모두 확인하도록 수정한다.

검토 범위: ADR-276 본문과 breakdown, Button/ToggleButton origin·중첩 호스트, 자식 명령과 Properties, template binding·자식 순서·position 명령, Canvas Button binding·pending, DOM 및 graph/storage 계약. `codeCatalogLibrary.ts`의 Button 자식 크기·색 part rule도 확인했으며, 자식 typography 전달 전체를 부재로 단정하지 않았다.

## Round 2 — 2026-10-20 (reviewer: codex)

판정: **설계 승인 보류 — 기존 HIGH 3건은 설계상 해소, 수리에서 생긴 신규 HIGH 1건(h4) open/pending**. 제품 코드 및 ADR 본문·Status는 수정하지 않았다. 실행자가 적은 Round 1 frontmatter의 fixed 상태는 현재 설계 수리 내용과 일치하므로 유지한다. 구현 완료 또는 runtime 검증을 뜻하지 않는다.

이전 이슈 수리 대조:

- **h1 — fixed (설계).** Decision 5 및 breakdown Phase 0~1이 중첩 origin 참조를 포함하고 `children`→`label` 전환을 명시했다. `presentWhen: nonEmptyText`는 빈 Text를 생략하는 기존 공통 경로와 맞는다 (`packages/shared/src/catalog/runtime/presence.ts:711`, `runtime/domBinding.runtime.ts:2856`, `runtime/compositionRoot.ts:2174`). 원래 지적한 무라벨 호스트의 기본 `Button` 노출은 설계상 방지된다. 다만 수리본의 호스트 분류에 별도 회귀 h4가 생겼다.
- **h2 — fixed (설계).** Decision 1~3은 Icon도 template Text 앞에 고정하고 `icon` prop으로 편집하므로, owned 목록 index 0의 순서 문제와 NodeId 전용 자식 명령에 의존하지 않는다. `defaults.icon`이 없는 미치환 `{icon}`은 `bindTemplateValue`에서 placeholder로 남고 (`packages/shared/src/catalog/resolution/resolver.ts:360`, `:810`), Canvas는 path 없는 glyph를 숨기며 (`runtime/presence.ts:725`), DOM Icon도 path가 없으면 null을 반환한다 (`runtime/domBinding.runtime.ts:596`, `packages/shared/src/components/Icon.tsx:47`).
- **h3 — fixed (설계).** Decision 7은 contract +1을 필수로 바꾸고 옛 문서 유지 선택지를 삭제했다. 저장소 로드는 contract 불일치를 `UNSUPPORTED_PROJECT_FORMAT`으로 먼저 거부한 뒤 graph를 구성한다 (`packages/shared/src/catalog/runtime/storage.ts:369`, `:387`). G3에 plain Button과 IconButton 문서의 거부를 모두 넣었다.

**[HIGH · h4 · open] Pagination·Menu·Popover·Tooltip을 글자 없는 호스트로 처리하면 현재 보이는 내용을 잃는다.**

- 설계 위치: `docs/adr/completed/276-button-text-child-iconbutton-merge.md:82` (Decision 5)에서 Pagination·Menu·Popover·Tooltip을 글자 없는 호스트 목록에 포함해 `label: ""`를 쓰도록 했다. breakdown Phase 1의 완료 조건 (`docs/adr/design/276-button-text-child-iconbutton-merge-breakdown.md:51`)도 Pagination 항목의 Text 0을 요구하므로 잘못된 결과를 통과 기준으로 삼는다.
- 현재 코드 사실: Pagination의 다섯 Button은 별도 Icon 자식 없이 `children: ← / 1 / 2 / 3 / →`를 가진다 (`packages/shared/src/catalog/document/generated/reusableOriginLibrary.ts:3139`, `:3151`, `:3162`, `:3174`, `:3186`). Menu trigger는 `children: Menu` (`:3580`), Popover trigger는 `children: Open Popover` (`:6592`), Tooltip trigger는 `children: Hover me` (`:6774`)다. 이들은 자기 글자가 없는 Icon-only trigger가 아니다.
- 입력·상태 → 잘못된 결과: 수리본대로 template의 `children`을 지우고 해당 자리에 `label: ""`를 작성한 새 라이브러리에서 Pagination/Menu/Popover/Tooltip을 팔레트로 추가 → `presentWhen: nonEmptyText`가 Text를 생략하고 미설정 Icon도 숨겨져, 번호·화살표 및 trigger 문구가 없는 빈 Button이 된다. Canvas와 Preview가 똑같이 비어도 사용자 가시 회귀다. 구버전 거부로 해결되지 않는 새 프로젝트의 실패다.
- 해결 방향: 호스트 이름 대신 자리별 실제 `children` 값과 자기 자식 구조를 기준으로 분류한다. Pagination 다섯 값은 각각 `label: ← / 1 / 2 / 3 / →`, Menu·Popover·Tooltip은 기존 문구를 label로 옮겨 보존한다. Text 0은 실제로 글자가 없는 NumberField 증감·Select trigger·SearchField 지우기 등에만 적용한다. Decision 5와 Phase 1 완료 조건을 함께 고쳐야 한다.

검증 범위: Round 1 수리본 본문·breakdown·실행자 기록과 수정된 호스트 매핑, template binding·선택적 Text 존재·미설정 Icon 존재·contract 거부 경로를 현재 코드로 대조했다. 이전 라운드의 포괄 검토를 처음부터 반복하지 않았다. 커버리지 부족만으로 신규 차단 이슈를 만들지 않았다.

**UNVERIFIED:** h4는 현재 template 값과 제안한 변환의 정적 대조 결과이며 실행 재현하지 않았다. 제품 테스트·typecheck·build·브라우저·Canvas/Preview 픽셀·저장 재열기·성능·번들·원복 RED는 미실행이다. 구현은 미착수 상태이며 ADR은 Proposed를 유지한다. 기록 schema/format 검사는 별도 로컬 인수인계에 남긴다.

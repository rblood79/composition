판정: **설계 보완 필요 — HIGH 1 · MEDIUM 3 · pending 4**. 검토 기준 HEAD `da04845c2`. 사용자 결정 두 건과 문서 단위 분리 방향은 유지할 수 있으나 아래 계약을 구현 전에 고쳐야 한다.

1. **h1 — HIGH: context 밖 portal의 이관 규칙이 매치하지 않는다.** ADR Decision 3 (`305-...md:104`)와 breakdown Phase 1은 모든 chrome 시트를 `[data-context="builder"]` 아래에 둔다. 실제 context는 `BuilderViewport.tsx:14`의 앱 div이며, `PropertyRowMenu.tsx:59`와 `PropertySelect.components.tsx:361`의 Popover는 context 표지나 portal container를 지정하지 않는다. 설치 RAC 1.22.1의 Popover → react-aria Overlay 기본값은 `document.body`다. 실제 `PropertyRowMenu`를 사용한 headed Chrome 최소 fixture에서 메뉴와 Popover 모두 context 조상 없음 확인. 현재 Menu/Popover 규칙 44개에 제안 범위를 적용하자 Menu `display:flex → block`, `flex-direction:column → row`, `max-height:300px → none`, Popover `display:flex → block`으로 변했다. 즉 열림 상태에서 G1은 옛 CSS에 가려 통과할 수 있어도 G2의 Δ 0은 성립하지 않는다. **수정 방향:** builder 문서 루트에 표지를 두어 body portal까지 포함하거나, 문서 분리를 전제로 chrome selector의 해당 조상 제한을 없애는 계약을 정한다. portal 재배치는 DOM/접근성 무변경 제약과 별도 검토가 필요하다.

2. **m1 — MEDIUM: G2의 시트 교집합 조건이 공통 폰트와 충돌한다.** Decision 1 (`:102`) 및 G2 (`:148`)는 공통 시트를 root 원시 변수 시트만으로 제한한다. `main.tsx:37`, `preview/index.tsx:14`, `publish/App.tsx:38`은 모두 `pretendard/dist/web/static/pretendard.css`를 import한다. 실제 파일은 `@font-face` 선언이며 이관 대상으로도 지정되지 않았다. import graph를 실제 진입에서 펼치면 컴포넌트 CSS 분리가 끝나도 G2 FAIL이다. **수정 방향:** font-face 등 중립 자산 시트의 공유 허용 범위와 정적 검증을 명시하거나 진입마다 소유할 계획을 추가한다. CSS 배럴만 비교해 폰트를 숨기는 것으로 교집합 검증을 통과시키지 않는다.

3. **m2 — MEDIUM: publish URL이 배포 base를 버린다.** Decision 6 (`:107`)은 현재와 같은 `/publish` URL이 `publish/index.html`로 간다고 한다. 현재 `openCatalogPublish.ts:19`는 `new URL("/publish", window.location.origin)`을 사용하지만 Vite build base는 `/composition/` (`vite.config.ts:304`)다. 따라서 gh-pages의 새 파일은 `/composition/publish/index.html`이며 origin의 `/publish`에 생기지 않는다. `/composition/publish/index.html`을 둔 무 rewrite 정적 fixture에서 `/publish?project=probe`는 HTTP 404, `/composition/publish?project=probe`는 query를 보존해 `/composition/publish/` HTTP 200이었다. 현재 구현의 기존 결함을 새 진입 설계가 그대로 보존하는 문제다. GitHub 공식 문서도 project Pages 파일이 repository prefix 아래에 배포된다고 명시한다: [Creating a GitHub Pages site](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site). **수정 방향:** dev `/`와 production `/composition/`을 반영한 canonical publish URL을 정의하고, G4에 base prefix 아래 정적 서빙과 query 보존·재로드를 명시한다. `publish.html` 대안만으로는 base 누락이 해결되지 않는다.

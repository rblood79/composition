# ADR-326 Review Log

## Round 1 — 2026-11-27 (reviewer: codex)

**설계 승인 보류. HIGH 4건과 MEDIUM 1건을 보완해야 한다.** 현재 작업 트리(HEAD `23f61112e`, 미커밋 Value·검색 변경 포함)에서 확인했다.

1. **h1 · 같은 값에서 다른 단계가 열린다.** ADR-322 G4의 평면 데이터와 같이 120개 부모 각각에 자식 하나를 두고 `defaultValue="R120-1"`을 사용했다. 실제 resolver와 `cascaderTableOf`를 거친 Builder 표는 부모 100개, 키 판정 `missing`, drill 시작 부모 `null`이었다. Preview 창 설정은 120개, `item`, 부모 `R120`이었다. 시작 함수가 같아도 입력이 다르다. 전체 계층에서 선택 경로·중복을 먼저 판정하고, Canvas 표본에 필요한 조상과 현재 단계 행을 포함하는 규칙을 정한다. G5는 이 입력에서 행 키와 위치를 함께 비교한다.
2. **h2 · 원본 경로 행을 생성할 수 없다.** 실제 Library Breadcrumb 템플릿에 `repeat: true`를 추가하자 검증기가 `UNKNOWN_FIELD` (`library.template.repeat`)를 냈다. 필드만 허용해도 `repeatRows`는 `lib:` ID에서 조기 반환한다. P6의 DOM 직접 전달 대안도 Canvas에 같은 경로 행을 요구한다. Library 위치에서 경로를 투영하는 계약, 또는 팔레트 삽입 시 소유하는 project 반복 노드를 선택해 양쪽이 같은 행 키를 읽게 한다.
3. **h3 · 공통 행 CSS로는 개별 편집이 반영되지 않는다.** 팔레트 Cascader의 `Books` 항목에 catalog 명령으로 배경색 `#123456`을 썼다. record의 배경색은 바뀌었고 항목 표의 내용은 편집 전과 같았다. 현재 열린 RAC 행에는 catalog ID와 인라인 배경색이 모두 없었다. §4.3의 공통 class를 더해도 두 입력을 구별할 수 없다. 항목의 `pathId`에서 resolved record를 찾을 수 있게 하고 보이는 RAC 행에 기존 DOM 스타일 적용 경로를 연결한다. G5에서는 한 항목의 편집과 Undo를 이웃 행과 함께 비교한다.
4. **h4 · drill 부품 조건을 그대로 등록할 수 없다.** §4.1의 `cascaderDrill.from = "mode"`를 현재 composite 원본에 적용하자 `validateLibraryDefinition`이 `BINDING_MAP_FROM`을 냈다. 같은 probe에서 원본 `accepts.mode`에 `string`을 추가한 정의는 검증을 통과했다. 원본의 mode 입력과 기본값, 인스턴스에서 방식을 바꿀 때 두 drill 부품이 나타나고 사라지는 조건을 Phase 1에 명시한다.
5. **m5 · 접힌 경로에서 조상 이동이 끊긴다.** `BreadcrumbsRun`에 경로 5개와 RAC `Breadcrumbs.onAction`을 연결했다. 보이는 링크를 누르면 콜백이 1회 호출됐고, 폴더 메뉴에서 접힌 `Category`를 누르면 0회였다. drill 경로는 URL을 열지 않고 현재 단계를 바꿔야 한다. 일반 링크와 접힌 메뉴 항목이 같은 경로 키로 단계 이동을 호출하게 하고 P6에서 두 동작을 모두 확인한다.

**집행 경로.** l6은 LOW deferred다. ADR 본문 180행의 Cascader 단위·정적 검사와 번들 Δ는 실행자가 별도로 돌린다. 저장소 pre-push hook은 변경 경로에 따른 성능 ratchet과 CSS 경계를 검사하고, `push: main` 배포는 initial JS 절대 상한을 검사한다. 이 문구 수정은 승인 보류 건수에서 제외했다.

**실행 근거.** 기존 ADR-322 data·wiring·levels·run·form 테스트 36개 통과. 현행 resolver·검증기·DOM 소비 경로를 사용한 검토용 사례 7개 통과. 이 중 drill의 검색·목록을 하나의 Autocomplete 아래에 둔 대조에서도 기존 키보드 흐름이 통과했다. 로컬 실행 로그는 `.agent/runs/adr326-review-r1/artifacts/comparison.log`와 `window.log`에 있다.

**UNVERIFIED.** ADR-326은 Proposed다. 새 구조의 Chrome·WebKit 실화면, Canvas 행 rect, VoiceOver, 번들·성능은 이번 설계 리뷰의 측정 대상에서 제외했다.

## Round 2 — 2026-11-28 (reviewer: codex)

1. **h1 · 표본에 남긴 항목이 가지인지 잎인지 달라진다.** 잎만 고를 수 있는 단계 표에서 루트 가지 `X`와 `P` 아래 잎의 값이 모두 `X`다. 하위 표의 첫 100행은 다른 가지의 자식이고, 101행은 선택할 잎, 102행은 루트 `X`의 유일한 자식이다. 전체 표에서는 잎 하나만 선택 가능해 `item`이고 drill은 `P`에서 열린다. §4.7대로 두 `X`와 조상, 열릴 단계의 행을 모두 남겨도 102행이 빠진다. 실제 항목 표 함수는 루트 `X`도 선택 가능한 잎으로 보아 `duplicate`를 반환하고 시작 부모가 `null`이 된다. §4.5에서 표의 판정을 재사용하려면 표본 행에 원래의 자식 유무를 보존하거나 전체 계층에서 정한 판정과 경로를 시작 상태와 닫힌 필드에 직접 넘겨야 한다. P8·G5에서 선택 키의 판정과 시작 부모를 함께 비교한다. 근거는 breakdown 133·160–166행과 `runtime/cascader.ts:112–145`다.
   - **단계별 로드에서도 같은 구분이 필요하다.** 같은 캐시 루트 `11=서울`, `36=세종`에서 서울에 미로딩 자식이 있고 시작 값이 `11`이면, 현재 Builder 표는 `item`으로 판정해 ‘서울’을, 실제 Preview 세션은 `branch`로 판정해 ‘11’을 표시했다. 양쪽 행 키는 같았다. Preview는 endpoint 행에서 만든 `branchKeys`를 표에 넘긴다. Builder에도 같은 캐시 행의 자식 유무를 전달하는 조건이 필요하다. 근거는 `runtime/catalogPreviewSession.ts:3114`, `runtime/delegatedDom.runtime.ts:4749`, `runtime/presence.ts:4843`이다.
2. **m5 · 콜백을 연결해도 바로 위 조상을 누를 수 없다.** 경로 `root > A > B > C > D > E`, crumb 폭 60px, 간격 8px, 폴더 폭 32px로 기존 접힘 함수를 실행했다. 폭 310px에서는 끝의 `D, E`가 보이고 메뉴는 `A, B, C`다. 180px에서는 끝의 `E`만 남아 메뉴에 `D`도 들어가야 한다. §4.4의 고정 `hidden`은 두 폭 모두 `A, B, C`여서 두 번째 폭에서는 `D`로 이동할 수 없다. 그릴 자리 넷은 충분하다. 메뉴 키는 전체 논리 경로와 실측 후 보이는 끝 항목 수로 정하고, P6에서는 두 폭에서 기준 메뉴의 **모든** 키가 같은 조상으로 이동하는지 비교한다. 근거는 breakdown 114–122행과 `runtime/breadcrumbsCollapse.ts:82,120–125`다.

**종결한 항목.** h2의 고정 자리 넷은 기존 접힘 함수에 경로 길이 1~12와 폭 여섯 개를 조합한 72개에서 표시 수 상한을 충족했다. h3은 resolved record ID로 조회한 DOM 입력에서 `Books`의 배경색만 `#123456`으로 바뀌고 Undo로 복원됐다(breakdown §4.3). h4는 제안한 `accepts.mode`와 기본값 `columns`를 등록한 원본에서 조건부 템플릿 자리 둘의 수가 기본 → drill → columns → Undo 순으로 `0 → 2 → 0 → 2`였다(§4.1). l6은 ADR 202행의 설명이 실제 pre-push hook과 배포 검사의 분담에 맞는다.

**첫 열기의 단계 로드.** 미로딩 시작 키 `11-1`로 실제 필드와 RAC를 마운트했다. columns·tree·drill 모두 처음 열 때 루트 세 행을 보였고 자식 단계의 `levels.load` 호출은 0회였다. drill에서 ‘서울’로 들어가자 `load("11")`가 1회 호출됐다. 루트 컬렉션을 받아오는 네트워크 요청은 이 측정 범위 밖이다.

**검증 범위.** 검토용 Vitest 4개 파일, 9건 통과. 표본 보존 규칙과 고정 `hidden`은 수정안대로 구성해 현재 resolver·항목 표·접힘 함수와 대조했다. 실행 로그와 입력은 `.agent/runs/adr326-review-r2/artifacts/`에 보관했다. 새 구조의 Canvas·Chrome·WebKit 실화면과 행 위치, 세 방식과 검색 결과의 개별 스타일(P9), VoiceOver, 번들·성능은 UNVERIFIED다.

### Round 2 이후 결정 (2026-11-28)

설계 판독은 두 라운드로 마친다. ADR은 Proposed이며, h1과 m5의 다음 판정은 Phase 0 시제품에서 한다. 두 outcome은 해당 시제품의 실행 근거가 생길 때까지 `pending`이다.

- **h1 → P8.** 표본과 전체 표에서 `X`의 판정이 모두 `item`이고 시작 부모가 `P`인지, 원래의 자식 유무 표식을 제거하면 `duplicate`로 돌아가는지 확인한다. 자식 단계를 읽기 전에는 Builder·Preview 모두 `11`을 `branch`, `11-1`을 `missing`으로 판정해야 한다. 세 데이터 모양과 여러 창 크기에서 고정 seed로 시작 키의 판정·조상 사슬·경로 이름도 비교한다. [P8 판정 조건](../design/326-cascader-open-content-nodes-breakdown.md#47-시작-경로-보존--builder-의-표본-창-round-1-h1)
- **m5 → P6.** 같은 경로를 폭 310px와 180px에서 열어 기준 Breadcrumbs와 보이는 crumb의 위치, 메뉴의 모든 키와 클릭 결과를 비교한다. 180px에서는 메뉴의 `D`를 눌러 그 조상으로 이동해야 한다. [P6 시제품](../design/326-cascader-open-content-nodes-breakdown.md#6-phase-0-시제품-g0)

각 시제품을 통과하면 실행자가 해당 항목의 근거를 남기고 Round 1·2의 같은 ID를 `fixed`로 갱신한다. 실패하면 재현 입력과 실제 결과를 기록하고 해당 항목을 열어 둔다. Phase 1 진입은 ADR의 G0 조건을 따른다.

# ADR-301 Review Log

## Round 1 — 2026-11-05 (reviewer: codex)

판정: 설계 보완 필요 — HIGH 2, MEDIUM 1, pending 3. 현재 작업 트리의 개정안(조립형 6가족)을 HEAD a64bd530d의 소비 코드 및 동시 변경 파일과 정적으로 대조했다. 제품 구현 결함이 아닌, 제안된 구현 규칙의 충돌을 기록한다.

1. **HIGH h1 — 요소 삭제와 재생성 동일 조건이 양립하지 않는다.** ADR Decision 4 (`301-code-view-library-instance-expansion.md:92,95`), breakdown:91. template 요소 전체를 지우면 편집본에는 그 요소가 없지만, 설계가 지시한 enabled:false patch의 재생성본에는 `{false && <X/>}`가 남는다. 기존 `apps/builder/src/builder/catalogRuntime/codeViewEdit.ts:3504-3525`는 자식 수와 visibleState를 비교하므로 `notInCode`로 거절한다. slot 소유 노드의 removeTargets와 구분되는 template 자리(예: OverlayArrow) 삭제로 재현 가능하다. 자리 키의 deterministic 여부로는 해결되지 않는다. 해결: 삭제 입력을 숨김 표현으로 정규화하는 명시적 계약과 비교 단계를 설계하거나, 삭제 대신 false wrapper 편집만 지원하도록 사용자 결정·G2를 맞춰야 한다. 단순히 재생성 검사를 우회해서는 안 된다.

2. **HIGH h2 — 기존 patch가 있는 바인딩 자리는 root prop 쓰기로 편집할 수 없다.** ADR Decision 4 (`301-code-view-library-instance-expansion.md:90`), R2 및 G2. Popover root props.size=L이고 overlay 자리에 기존 descendant props.size=S patch가 있으면 생성 값은 S다. 이를 M으로 편집할 때 설계대로 root props.size=M만 쓰면 기존 patch가 계속 S로 덮어써 Apply가 거절된다. `packages/shared/src/catalog/resolution/resolver.ts:2241-2243`의 바인딩보다 `2261-2269`의 patch가 뒤이며, 기존 `apps/builder/src/builder/catalogRuntime/codeViewEdit.ts:1641-1687`의 planOverrides는 이 patch를 생성할 수 있다. 해결: template 바인딩 유무 외에 유효 값의 작성 주체와 우선순위를 판정하고, 기존 patch 수정/해제 정책을 확정해야 한다. root 값과 patch가 동시에 있는 문서에서 편집·제거·Undo 및 패널 동일성 반례를 G2에 넣는다.

3. **MEDIUM m3 — slot 클래스와 CSS 경로가 서로 다르다.** ADR Decision 1 (`301-code-view-library-instance-expansion.md:86`), breakdown의 styles 무변경 행 및 예제:78,86. Popover content frame에 시각 patch를 작성하면 기존 `packages/shared/src/codeView/files/styles.ts:679-688`은 codeViewAddressKey를 사용해 `.popover .frame`을 출력한다. 반면 제안된 JSX는 `<div className="content">`다. `packages/shared/src/codeView/files/overrides.ts:127-142`는 이 차이를 명시적으로 구분한다(codeViewAddressKey=frame, codeViewSlotKey=content). 따라서 CSS와 JSX가 같은 자리를 가리킨다는 주장이 성립하지 않는다. 해결: slot 표시 이름과 스타일 identity를 구분해 frame 클래스를 함께 유지하거나, CSS emit/read와 위치 anchor를 같은 규칙으로 변경한다. content frame patch의 CSS selector가 생성 JSX에 매칭하고 CSS 편집이 같은 주소로 왕복하는 조건을 gate로 고정한다.

검증 범위: ADR·breakdown, 선행 B 수리 테스트와 생성/역문법, resolver의 binding→patch 우선순위, CSS 주소 emit/read, identity 삭제 판정, overlay open 판정을 정적으로 확인했다. 6가족 범위 결정과 Library 파일 유지 결정을 다시 열지 않았다.

UNVERIFIED: ADR-301은 Proposed이며 새 생성기·자리 역문법을 실행하지 않았다. 위 시나리오는 코드 흐름에 근거한 설계 반례이며 실행 RED/GREEN이 아니다. Builder/Preview live, 번들, 생성 시간 및 G0~G5 통과 여부는 미검증이다. 제품 코드·ADR 상태·커밋 변경 없음.

## Round 2 — 2026-11-05 (reviewer: codex)

판정: 설계 수리 검증 완료 — HIGH 0 · MEDIUM 0 · pending 0. round 1의 h1·h2·m3는 설계상 fixed다. 제품 구현과 G0~G5 통과 판정은 포함하지 않는다.

- **h1 fixed (설계)** — 본문 Decision 4:93,96은 통째 삭제를 enabled:false로 정규화하며, hiddenPositions에 등록된 자리의 owner/체인 포함 identity와 재생성본의 visibleState=false가 맞을 때만 예외를 허용한다. false wrapper를 직접 작성한 편집은 그대로 비교하고, 통째 삭제로 재생성본에만 남은 요소를 한정해서 비교에서 제외하는 계약으로 읽었다. 기존 compareRegenerated의 자식 수·visibleState 비교(codeViewEdit.ts:3504-3525)와 충돌하던 예외가 명시됐다. R9:128과 G2:139에 삭제·다른 편집 동시 Apply, 이미 숨긴 다른 자리 유지, 키 대조 제거 원복 RED가 있다. Apply 후 false wrapper가 나타나는 동작은 사용자에게 보고된 명시적 정규화다.
- **h2 fixed (설계)** — Decision 4:90-91 및 G2:139에 기존 patch가 있으면 이 파일 instance patch에 쓰고 root는 유지하는 규칙이 들어갔다. root L + patch S → M 편집은 patch M/root L이므로 resolver.ts:2241-2269의 우선순위에서도 표시 M이다. 제거는 G2가 명시한 patch·root 동시 해제를 기준으로 판정했다. 본문:91의 조건부 root 제거 표현 역시 root에 기존 작성값이 있으면 함께 제거한다는 G2 및 사용자 설명에 맞춰 구현해야 한다. 공유 key는 읽는 자리 수에 따라 단일 자리 patch로 분기하고, 안쪽 template의 작성값은 해당 파일에서 편집하는 경계가 명시됐다.
- **m3 fixed (설계)** — Decision 1:86과 breakdown:80,88이 slot frame을 codeViewAddressKey의 마지막 segment인 frame으로 출력한다. styles.ts:679-688의 기존 .popover .frame과 일치한다. position 역변환은 class 경로 전용으로 규정하고, 기존 codeViewAddressOf의 slot 이름 우선 분기(overrides.ts:186-190)를 Slot 문법에만 남기므로 이름 충돌 반례도 설계에서 처리한다. G2에는 slot frame CSS 왕복이 있다.

**LOW l4 deferred — breakdown 경로표의 이전 설명.** breakdown:38에는 여전히 `<div className="<slot>">`, :42에는 역변환 그대로 재사용, :44에는 바인딩 자리는 instance prop이라는 요약이 남았다. 본문 Decision 1·4와 G2, breakdown 예제의 새 계약이 이를 대체하므로 새 correctness 반례로 올리지 않는다. 구현할 때 본문·G2를 기준으로 표를 정리한다. 이 문서 정리 항목은 라운드 재개 조건이 아니다.

검증: 수정된 본문·breakdown과 현재 resolver, 주소 역변환, CSS 경로 생성, compareRegenerated를 정적으로 대조했다. 제품 코드나 설계 결정을 추가로 수정하지 않았다. 기존 round의 본문은 보존하고 frontmatter outcome만 round 2 근거로 갱신했다. ADR은 Proposed 유지, 커밋하지 않았다.

UNVERIFIED: hiddenPositions 및 유효 값 층 planner는 아직 구현되지 않았다. 실행 RED/GREEN, 실제 Builder/Preview, Undo·저장/로드, 번들·생성 시간, G0~G5 및 구현 완료는 미검증이다. 설계의 fixed와 제품 실행 PASS를 구분한다.

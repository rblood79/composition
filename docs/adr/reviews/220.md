### h1 — HIGH: 컴파일러 경계 보장 불성립

breakdown:52와 본문:57,134는 library tsconfig + include:[src]가 apps 역참조를 막는다고 명시한다. 실제 config에는 rootDir/composite/import 경계 검사가 없다. 임시 src/index.ts에서 실제 apps/builder/src/services/mockData/random.ts의 hashSeed를 재수출하고 동일 library config를 상속해 TypeScript program(noEmit)을 검사했다. **diagnostics=[] · builderImported=true**였다. 상대 경로 import는 dependencies 0이어도 가능하다. 따라서 G1이 통과해도 이 ADR의 핵심 목적인 역참조 차단은 보장되지 않는다.

수정 방향: 상대 경로·alias·type-only import/re-export를 포함해 해소된 대상 경로를 검사하는 경계 gate를 명시하고, Builder import를 주입한 음성 검사가 실제 실패하도록 한다. 컴파일 옵션으로 해결한다면 현재 제안 설정이 아닌 실제 실패하는 구성의 증거를 남긴다.

### m2 — MEDIUM: rename gate와 저장 계약 충돌

breakdown:93의 전체 src grep은 `mockData`를 어디서든 검출하며 workflow만 제외한다. 그러나 DataTable.mockData(data.types.ts:83), Preview store 타입(types.ts:92), collectionReadModel.ts:93은 생성기 이름과 별개인 기존 데이터 계약이다. 모듈 rename을 완료해도 이 필드 때문에 G2는 실패한다. 이를 0으로 만들려고 바꾸면 본문의 collections 계약 무변경 범위를 넘는다.

수정 방향: 이동 대상 모듈 import와 공개 심볼만 검사하고 collection.mockData/useMockData는 유지 대상으로 명시한다. 인벤토리를 이 범위로 다시 산출하고, 실제 export인 Mock/CreateMockOptions도 대응표에 포함한다.

### m3 — MEDIUM: seed만 고정한 스냅샷은 재현되지 않음

generators.ts:297은 기준 날짜를 startOfTodayUtc()에서 얻고, birthDate(:329)와 cardExpiry(:457)는 날짜/로컬 시간대에 의존한다. 실제 생성기 코드를 그대로 transpile해 seed=adr220, 같은 birthDate 규칙을 실행하면 clock 2026-09-16에서 **1975-05-20**, 2026-09-17에서 **1975-05-21**이 나왔다. 이 규칙은 people preset과 AI MOCK_RULE_TYPES에 실제 포함된다. G0/G3가 자정을 사이에 두면 무변경 코드도 실패한다.

수정 방향: 동작 변경 0을 유지하면서 비교 harness의 clock/TZ/locale/번역 입력을 고정하고 fixture metadata에 남긴다. HC1은 동일한 생성 컨텍스트에서의 동일 출력으로 정확히 기술한다. preset 실제 API는 generateSampleData(count,t,options)이므로 Phase 0 호출 예시도 맞춘다. 제품의 날짜 동작 수정은 요구하지 않는다.

### m4 — MEDIUM: 번들 게이트 false PASS

본문 G4는 양쪽 initial gzip의 abs(delta)<=512와 presetStrings lazy 유지다. 지정 스크립트는 Builder delta<=3584, Preview delta<=0만 검사(:58-59)하며 lazy 대상도 AIPanel/runCommand뿐(:61-62)이다. 동일 sha/lockfile 및 상한 내 fixture에서 Builder 1,300,000→1,301,000 B, Preview 591,000→591,000 B를 전달한 결과 **exit 0 / pass:true**였다. ADR-220 위반 +1,000 B를 통과시킨다. 이는 판정기 입력 반증이며 실제 번들 측정값이 아니다.

수정 방향: ADR-202 조건을 보존하면서 ADR-220 전용 wrapper 또는 명시적 모드를 추가하고 양방향 512 B와 presetStrings initial closure 제외를 검사한다. workspace 추가로 lockfile이 바뀌므로 A/B가 같은 최종 lockfile을 사용하는 절차도 명시한다. breakdown 명령에는 필수 before-preview/after-preview 인자도 포함해야 한다.

### 검증 범위와 한계

ADR/분해 문서, 실제 package config, 생성기·preset 소비 API, AI tableSpec 및 collection 소비 경로, 번들 판정기를 대조했다. 임시 디렉터리에서 경계·날짜·번들 판정 반증을 수행했다. 제품 구현, 전체 build/성능, Builder/Ollama live는 수행하지 않았고 G1~G5 통과를 주장하지 않는다. 리뷰 로그만 저장하며 Accepted/Implemented 승격 및 commit/push는 하지 않는다.

### m1 — MEDIUM: 경계 검사가 정상 테스트의 vitest import를 거부

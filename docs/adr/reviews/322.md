# ADR-322 Review Log

## Round 1 — 2026-11-26 (reviewer: codex)

**판정 · 설계 보완 후 재검토**

### HIGH · 다른 부모 아래의 같은 key를 선택하면 원래 경로를 복원할 수 없다

중첩 데이터에서 A와 B 아래에 각각 `id=01`인 잎을 두면 기존 항목 key가 둘 다 `01`이다. B 아래 잎을 골라도 폼·변수에는 `01` 하나만 남아 재열기 때 어느 조상을 펼쳐야 할지 판별할 수 없다. Design 패널 알림은 게시 화면의 선택을 막지 않는다.

전체 계층에서 key의 유일성을 검증하고 모호한 선택을 거절하거나, 안정적인 복합 식별자와 외부 제출값의 관계를 정의한다. G4에서 서로 다른 부모의 중복 key를 선택·복원하는 입력을 검증한다.

근거는 `docs/adr/322-cascader-hierarchical-picker.md:144` 및 `packages/shared/src/collections/resolveCollectionItems.ts:340`이다.

### HIGH · 서버 응답 오류 경로로는 필수 Cascader의 빈 제출을 막을 수 없다

현재 Form의 `validationErrors`는 `submitEndpoint`가 거절된 뒤에 반영된다. Button과 값을 싣는 hidden input만 있는 최소 폼을 Chrome에서 실행하면 `required`와 빈 값에도 `checkValidity()`가 true이고 `requestSubmit()`이 submit을 한 번 발생시킨다.

사용자 결정 6에서 필수를 채택하면 Form의 검증 방식에 참여하는 필드와 데이터 제출 연결을 명시한다. G6는 빈 필드 오류·focus, endpoint 호출 0회, 유효값으로 고친 뒤 제출 1회를 검사한다.

근거는 `docs/adr/design/322-cascader-hierarchical-picker-breakdown.md:88` 및 `packages/shared/src/catalog/runtime/catalogPreviewInteractions.ts:703`이다.

### 검증 범위

`getItemKey`에 두 행을 넣어 같은 key를 확인했다. Chrome의 최소 폼에서 빈 hidden input 제출을 재현하고 endpoint 응답 처리는 소스로 대조했다. 다중 선택·단계별 로드·필수 검증의 채택 여부는 사용자 결정으로 남는다.

UNVERIFIED — 신규 컴포넌트의 Builder·Preview·Publish 통합 동작, VoiceOver, 번들 크기 및 성능은 구현 단계의 검증으로 남는다.

## Round 2 — 2026-11-26 (reviewer: codex)

**두 건 모두 정적·단일 입력의 원래 반례는 해소됐다. 아래 입력에서는 HIGH가 남는다.**

- **h1 · pending.** 전량이 있는 A/01·B/01을 동시에 비활성화하면 단일 key 계약을 지킬 수 있다. 단계별 원격 로드를 선택하면 현재 항목 표에서 01의 개수는 첫 응답 뒤 1, 다음 응답 뒤 2다. 그 사이 이미 01로 제출할 수 있다. 같은 부모 A 아래 중복 01 둘은 경로 id도 둘 다 `["A","01"]`이다. 설치된 행 key 함수로 두 입력을 확인했다. 원격에서 유일성이 보장되는 식별자/검증 계약을 요구하거나 보장 전 선택을 막고, 형제 충돌은 RAC collection을 만들기 전에 처리해야 한다. G4·G6에 늦게 도착한 충돌과 형제 충돌을 포함한다.
- **h2 · pending.** 설치된 RAC Form·Button 및 `useFormValidationState`·`useFormValidation`으로 문서의 입력 구성을 만들었다. Chrome과 WebKit 모두 빈 단일 native 필드에서 submit 0회·오류 표시·버튼 focus, 유효 key에서 submit 1회였다. 다중 선택이 비면 input이 0개여서 submit 1회였다. 비활성 필드의 빈 input은 제출을 막았고, 값이 있으면 FormData에 포함됐다. 설치본 `react-aria/dist/private/select/HiddenSelect.mjs:122`는 빈 배열에도 최소 한 input을 남기며 132행에서 disabled를 전달한다. §3·§4.5와 G6에 빈 다중 선택의 검증 input, 비활성 필드의 검증·제출 제외, native/aria별 검증 동작을 명시한다.

D1 판단에서는 단일 필드의 실험 성공과 예외 승인 여부를 구분해야 한다. DatePicker가 자체 input에 부여하는 속성 전체와 검증 동작이 다르고, 현재 안은 이 DOM을 직접 생성한다. 역할·키 핸들러가 없다는 사실만으로 기존 프로젝트의 ‘RAC가 출력하는 DOM을 사용’ 요건 충족을 확정할 수 없다. RAC가 제공하는 폼 컨트롤을 소비하거나 직접 생성하는 요소와 역할을 D1 결정에 명시하는 방법이 있다. [D1 정본](../../../.claude/rules/ssot-hierarchy.md)

실제 Cascader의 게시 화면과 원격 endpoint는 UNVERIFIED. 브라우저 결과는 설계대로 조립한 최소 폼의 결과다.

## Round 3 — 2026-11-26 (reviewer: codex)

**Round 2 h1·h2의 반례는 설계 수리 확인. 이름 없는 필수 필드에서 별도 HIGH 1건이 남는다.**

- **h1 · fixed.** §4.2·§4.3과 G4·G6에서 형제 중복을 RAC collection 작성 전에 구별해 두 항목의 선택을 막는다. 단계별 로드는 서버의 전역 유일성 선언을 요구한다. 이후 선언 위반이 발견되면 충돌 항목을 비활성화하고 해당 선택을 비우며 알린다. 발견 전에 끝난 제출까지 소급할 수 없다는 경계도 명시했다.
- **h2 · fixed.** 닫힌 D1 예외 1건과 확정된 필수 검증 정책을 확인했다. 설치본 RAC Form·Button·검증 hook으로 §3.1의 최소 폼을 구성했다. 이름 있는 필드의 다섯 상태 × native·aria × Enter·requestSubmit을 Chrome과 WebKit에서 각각 20건 통과했다. native의 빈 다중 선택은 제출 0회·오류 표시·버튼 focus, 비활성은 값의 유무와 관계없이 제출 1회·FormData 항목 0건이었다.
- **h3 · pending.** §3.1은 `name`이 있어야 input을 만든다. 사용자가 필수만 켜고 Name을 비워 두면 Decision 6의 native 검증이 사라진다. 두 브라우저에서 이 구성으로 빈 값을 `requestSubmit()`한 결과 모두 submit 1회였다. 같은 폼에 **이름 없는 검증 input**을 유지하면 submit 0회, 버튼 focus, FormData 항목 0건이었다. §3.1에서 native 검증 참여와 제출용 이름을 분리하고 G6에 이름 없는 필수 입력을 넣는다. 이 수정은 예외 목록의 요소 종류를 늘리지 않는다. [상세 설계 §3.1](../design/322-cascader-hierarchical-picker-breakdown.md)

검증 대상은 최소 폼과 설계 계약이다. 게시된 Cascader·실제 endpoint·VoiceOver는 UNVERIFIED.

## Round 4 — 2026-11-27 (reviewer: codex)

**Phase 0~6 구현 판독 · HIGH 4건 수리 필요**

원격 main의 최종 커밋은 9f59fedaf다. 문서 상태는 Implemented이며 VoiceOver는 사용자 확인 기록이 있다.

1. **필수 Cascader의 폼 모듈이 도착하기 전 빈 값이 제출된다** Chrome·WebKit에서 폼 모듈 응답만 지연하고 나머지 필수 입력을 채웠다. 화면에 보이는 필수 Cascader가 비었는데 input 0개, checkValidity() true, requestSubmit()의 submit 1회였다. 필수 검증과 값 전송에 쓰는 요소를 첫 렌더부터 제공해야 한다. 근거 `packages/shared/src/catalog/runtime/cascader.components.tsx:263`.

2. **값 넣기 규칙이 미로드 원격 가지를 끝 항목으로 수락한다** Chrome·WebKit에서 끝 항목만 허용하고 hasChildren=true인 A를 한 번도 열지 않은 채 버튼의 setValue("A")를 실행했다. 첫 단계 요청 1회뿐인 상태에서 명명된 input에 A가 기록됐다. 필드와 규칙에서 같은 가지 판정을 사용해야 한다. 근거 `packages/shared/src/catalog/runtime/catalogPreviewInteractions.ts:1039`.

3. **연결한 값 필드와 컬렉션 키가 다르면 원격 가지를 펼칠 수 없다** Chrome에서 같은 원격 표의 컬렉션 키는 id, Cascader 값 필드는 name으로 지정했다. id=11, name=서울, hasChildren=true인 행이 menuitemradio가 됐고 누르자 하위 요청 없이 input에 서울이 기록됐다. 가지 식별·자식 요청에 쓰는 행 키와 제출값의 대응을 보존해야 한다. 근거 `packages/shared/src/catalog/runtime/catalogPreviewSession.ts:3085`.

4. **중복 형제에 붙이는 순번이 실제 key와 충돌해 Preview 전체가 오류 화면이 된다** Chrome에서 가지 C의 응답에 07, 07, 07#1을 주고 C를 열었다. RAC가 Duplicate key 오류를 내고 화면 전체에 ‘프로젝트를 불러올 수 없습니다’가 표시됐다. 단순 중복인 07, 07만 주면 두 항목이 정상 비활성화됐다. 실제 key와 순번을 독립적으로 인코딩해야 한다. 근거 `packages/shared/src/catalog/runtime/cascader.ts:101`.

전용 Vitest는 shared 27/27, Builder 33/33이다. 로컬 Builder에서 만든 Preview와 모의 원격 응답으로 확장한 G6에서 기존 8개 판정은 Chrome·WebKit 각각 8/8이었다. G0~G5 전체, 번들, VoiceOver 청취는 이번 판독에서 재실행하지 않았다.

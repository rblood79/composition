# ADR-229 Review Log

## Round 1 — 2026-09-21 (reviewer: codex)

## 설계 리뷰 — HIGH 1 · MEDIUM 2 · LOW deferred 1

대상: ADR-229 Proposed 본문과 breakdown. 기준 HEAD `7c1cb78e3`. 작성 중인 ADR 두 파일, README 및 `apps/builder/scripts/.out/`는 기존 dirty 상태 그대로 보존했다. 제품 구현·ADR 수정·상태 승격은 수행하지 않았다.

### h1 — 일반 origin 자식 ref는 인용한 경로로 해소되지 않는다 (HIGH)

F5는 `canonicalRefResolution.ts:546`의 “중첩 ref는 자신의 origin propsSchema 기준” 주석을 근거로 seed/생성 경로만 활성화하면 된다고 판단한다. 그러나 이 코드는 **override.children로 삽입하는 노드**를 처리하는 `materializeOverrideChildren` 내부다. Phase 2가 제안하는 **origin.children에 들어 있는 ref**는 `materializeSyntheticDescendants:682`의 별도 경로를 탄다.

production resolver에 Button origin + Toolbar origin + Toolbar 자식 Button ref + Toolbar instance 네 노드를 넣은 진단 결과:

```json
{
  "id": "toolbar-instance/toolbar-action",
  "type": "ref",
  "ref": "component-button",
  "props": { "children": "Action 1" }
}
```

기대 Button 타입과 origin의 variant:accent가 해소되지 않는다. 기존 resolver 테스트 18개는 통과하지만 이 반례는 실패한다. 현재 제품 화면의 결함을 새로 주장하는 것이 아니라 **제안된 seed 모양을 현재 production 함수에 넣었을 때의 실행 결과**다.

**보완**: F5/위험 수용 근거를 수정하고, 일반 origin-child ref 실체화를 명시 구현 대상으로 포함한다. G0는 기존 plain Form을 그대로 배치하지 말고 proposed nested-ref 문서를 먼저 구성해 해소→편집→저장/reload를 검증해야 한다. Form/Toolbar로 줄여도 이 경로는 같으므로 현재 축소안은 이 실패를 회피하지 못한다. 깊은 override/바인딩 소유권과 순환 방어는 그 구현 경계에서 확정한다.

### m2 — Avatar slot은 현재 resolver에서 사라진다 (MEDIUM)

Phase 1은 Icon/Avatar/Text 자식을 `resolveSlotComposition`으로 읽겠다고 하지만 공용 `SLOT_ROLES`에는 avatar가 없다. Avatar(metadata.slotRole=avatar, src={avatar}) + Text(label) 입력 결과는:

```json
{
  "order": ["label"],
  "slots": { "label": { "role": "label", "text": "{label}" } }
}
```

**보완**: `packages/shared/src/catalog/slotRoles.ts`의 vocabulary/reader와 양 consumer의 avatar 존재·스타일·순서 처리를 파일 범위에 추가한다. 또는 avatar를 기존 role로 나타내는 명시 계약을 선택해야 한다. DOM의 기존 avatar > icon 우선순위와 “icon 없으면 leading 전체 skip” 제안도 함께 정렬해야 avatar-only chip이 제거되지 않는다.

### m3 — originIds는 dependency seeder가 아니다 (MEDIUM)

breakdown:53 및 본문 R4는 참조 origin id를 `originIds`에 넣으면 한 pass에서 먼저 보장된다고 한다. 하지만 helper는 그 집합으로 기존 노드를 찾고, **callback이 반환한 origins만** append한다. 빈 문서에서 originIds=[Toolbar,Button], callback=[Toolbar(ref Button 자식)] 조건으로 실행하면 Button origin은 생성되지 않는다(진단 실패).

이는 최종 전체 ensurer 실행 후 항상 dangling이라는 주장이 아니다. generic ensurer가 뒤에서 Button을 생성할 수 있지만, **Toolbar seed의 diffAgainstOrigin 시점에 Button 기본값이 확보된다는 보장은 없다**는 문제다.

**보완**: 기본 origin seed/index 생성과 조합 ref 변환을 2단으로 나누거나 dependency별 ensure를 명시 실행한다. 각 origin repair 소유자는 단일하게 유지하고, callback 반환 집합과 의존 집합을 혼동하지 않는다.

### l4 — BC 수치의 비교 범위 (LOW deferred)

G4의 기존 문서 reload Δnode 0은 신규 Tag item root 2개+slot 자식 보충과 충돌한다. “기존 저작 subtree/순서 불변”, “최초 seed 예상 Δnode/Δbyte”, “두 번째 hydration Δ0”으로 구분하면 된다. 아직 구현된 229 기능의 production 회귀는 아니므로 게이트 표현 보완으로만 기록하며 라운드 재개 사유로 삼지 않는다.

### round 1 정정 요지

초판의 핵심 오류는 **"같은 함수를 호출한다" 를 "같은 허브를 경유한다" 로 읽은 것**이다. `recordInvalidation` 은 mutation 알림이 아니라 **진단 기록기**이고, 그 절반 이상은 프레임이 폴링으로 변경을 발견한 *뒤* 실행된다. 이 오판은 ADR 의 핵심 선택 근거("배선 비용이 낮다")를 직접 지탱하고 있었으므로, 정정 없이 Phase 1 을 진행하면 "허브 2곳 후킹 완료" 상태에서 콘텐츠 편집·선택 변경이 stale 로 남는 결과가 나왔을 것이다. 반면 카메라 축은 실측 결과 오히려 초판보다 강한 보증이 확인됐다 — `viewportState` 쓰기가 listener 발화와 같은 함수 안에 있어 구조적으로 누락이 불가능하다.

| 팬/줌 상호작용 (21 샘플) | 62~120Hz | 최대 **884ms/s** | **88%** |

### 기각 근거 3

1. **효과 크기 미달** — 0.67% 는 R1/R1a(wake 누락 → stale) 버그 클래스를 신설하는 대가에 미치지 못한다.
2. **HC3 달성 불가** — `performanceMonitor` 무게이트 rAF 루프 잔존으로 "wake 0" 이 성립하지 않아 전력 이득 논거가 무너진다.
3. **질량 위치 상이** — 상호작용 884 vs 유휴 6.7 = 132배. 렌더 CPU 개선은 ADR-153 소관.

### CPU 감속 실측은 미확보 (한계 기록)

DevTools 4x throttle 을 5회 시도했으나 끝까지 적용되지 않았다 (교정 루프: 1억 회 205.7ms = 무감속 기대치 215ms, 4배라면 820ms). 원격 디버깅 포트 미개방으로 CDP 직접 설정도 불가. 다만 순간 6배 지연 샘플에서 **fps 120.2 가 유지**되어, rAF cadence 는 CPU 속도와 무관하게 유지된다는 방향성 근거는 얻었다 (n=2) — 선형 환산 시 4배 감속에서도 약 2.7% 로, 기각 판정을 뒤집지 못한다.

### 보존 자산 (재개 시 출발점)

- **wake 소스 인벤토리 실측 확정본** (design breakdown §3): 프레임 내/외 분류 16/9, 상류 2 경로(`StoreRenderBridge.resync` / `invalidationPacket` effect), 카메라 축은 `notifyUpdateListeners` 단일 지점 완결.
- **R1a/G1a 가 포착한 오판 패턴**: "`recordInvalidation` 호출 = 허브 경유" 는 거짓 — 호출 함수의 동일성이 아니라 호출 **위치**(mutation-side vs 프레임 내 폴링)가 wake 자격을 결정한다.

### 재개 조건

(a) 저사양 기기 실측에서 유휴 비용 ≥ 코어 3%, 또는 (b) `performanceMonitor` 무게이트 루프 해소 후 "wake 0" 이 실제 달성 가능해져 전력 이득 논거가 성립할 때.

# ADR-221 Review Log

## Round 1 — 2026-09-16 (reviewer: claude)

## ADR-221 리뷰 round 1 (claude, 2026-09-17)

### 판정: 승인 보류 — HIGH 2 수리 후 재판독 1회

결정 자체 (DOM 층 + 제스처 게이트 + 단일 drag 추종) 는 코드 재료와 맞는다 — `subscribeCanvasFramePresentation` 이 매 프레임 camera/page snapshot 을 transform-only 소비자에게 준다는 계약 (`SkiaCanvas.tsx:1151-1158`), 액션바가 그 소비자라는 선례 (`useActionBarPlacement.ts:84-105`), drag 는 `publishPagePositionPresentation` 델타만 쓰고 카메라를 안 건드린다는 사실 (`usePageDrag.ts:425-445`) 모두 확인. 대안 B 기각 근거 (N 노드 프레임 쓰기) 와 D 기각 근거 (렌더 경로 2개) 도 타당.

문제는 R1 (히트 이관) 의 대응이 코드 사실 한 줄을 빠뜨렸다는 것과, 게이트 신호가 '있다' 고 쓴 사실이 틀렸다는 것.

### HIGH

- **h1 capture 선판정** — `BuilderCanvas.tsx:1466` 의 capture 리스너가 헤더 노드 핸들러보다 먼저 실행된다. target 가드 (`:1193`) 는 input/textarea/contenteditable 만 건너뛴다. Decision 4 에 "capture 핸들러는 `[data-page-header]` 자손 target 을 즉시 return" 을 추가하고 breakdown §2 BuilderCanvas 행 · §7 정적 가드에 그 가드를 잠그지 않으면 G1 ①② 는 DOM 핸들러가 돌기 전에 Skia 가 요소를 선택한 뒤라 실패한다. dblclick capture (`:1467`) 도 같다 — 헤더 dblclick 은 헤더가 처리하고 capture 는 return.
- **h2 게이트 신호 미배선** — `ViewportControlBridge` 는 `onInteractionStart/End` 를 받지만 (`:25-56`) 유일한 마운트 `BuilderCanvas.tsx:1633-1639` 가 전달하지 않는다. 콜백 호출 지점 4개 (`useViewportControl.ts:228 · 266 · 300 · 329 · 384 · 422`) 는 살아 있으므로 배선하면 되지만, 본문 코드 사실 표 '제스처 신호 (재료)' 와 Decision 2 를 "현재 소비자 0 인 prop 을 배선한다" 로 정정하고 R2 대응에 이 배선 자체를 넣어야 한다.

### MEDIUM

- **m1 G2 측정 수단** — `perf-baseline.mjs` 는 페이지 2장만 전제 (`:771-773 · 1675-1689`). 22 페이지 시드는 `--pages N` 옵션 추가 또는 전용 `adr221-*-live.mjs` 를 Phase 0 산출물로 명시.
- **m2 occlusion 문구** — DOM 층은 캔버스 위라 가려진 헤더를 위 페이지 **body** 아래 둘 방법은 clip 뿐. §6 의 clip 기준을 "위 페이지 body rect ∪ 헤더 rect" 로 고정하고 Decision 4 의 'DOM 순서 = z-order' 를 '헤더 간 순서' 로 한정.

### LOW

- **l1** 편집기 500 vs 헤더 700 (`Workspace.css:35-53`, 정적 테스트 `:31`) — 이관 시 700 으로 맞추고 테스트 갱신.
- **l2** auto-pan 없음 확인 → §4 실측 항목 닫음 (fixed).

### 검증 범위 · 한계

- 읽음: 본문 전체 · breakdown 전체 · `BuilderCanvas.tsx` 1180-1470 · 1556-1676 · `useViewportControl.ts` 86-96 · 220-330 · 396-424 · `ViewportControlBridge.tsx` · `usePageDrag.ts` 425-445 · `SkiaCanvas.tsx` 1150-1162 · `perf-baseline.mjs` 771-790 · 1675-1690 · 2069 · `Workspace.css` 22-53 · `canvas-interaction.md:34-35`.
- UNVERIFIED: `.canvas-container` 가 `[data-context="builder"]` 자손인지 (BuilderCore.tsx:1403-1506 마운트 구조상 그럴 것으로 보이나 렌더 트리 직접 확인 안 함 — G4 가 잡는다). `clip-path: inset` 이 pointer-events 를 함께 막는지는 표준 동작이나 live 로 확인 필요 (G1 ④).

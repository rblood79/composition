# ADR-222 Review Log

## Round 1 — 2026-09-17 (reviewer: codex)

판정: 설계 보완 필요 — HIGH 1 / MEDIUM 1 / LOW deferred 1. 검토 HEAD ec2bd37b2. 최신 Figma·Framer 조합 상태표를 기준으로 읽었다. ADR 상태는 Proposed 유지.

### h1 — hug/auto 영향 범위 누락

breakdown:16은 hug/auto를 지원한다. 현행 createPresentationLayoutPlan의 containerSpacingMutation 분기는 자식이 있으면 크기와 무관하게 부모 승격을 막는다(LayoutLane:186,265). 직접 현재 planner를 실행한 root→[hug,following], hug→[a,b] 입력에서 paddingTop와 rowGap 둘 다 roots=[hug], parentChain=[], affected=[hug,b,a], followingIncluded=false였다. PersistentLayoutTree:507은 이 집합만 반환하고 Skia bridge:354도 그 집합만 publication에 넣는다. 세로 흐름에서 hug 높이가 커지면 following 위치도 바뀌어야 하므로, 현재 경로 재사용만으로는 드래그 중 형제 배치가 따라가지 않는다. 기존 테스트 LayoutLane.test.ts:158은 fixed-size 컨테이너만 확인한다.

해결: used-size 변화를 기준으로 부모/형제를 포함하는 spacing plan 확장을 명시하고, 중첩 hug→외부 형제의 드래그 중/commit 후/Preview geometry 대조를 gate로 추가한다. 고정 크기에도 padding이 콘텐츠 폭·줄바꿈을 바꾸는 영향 경계를 확인한다. 지원 범위 제한을 선택한다면 hug 지원 문구와 capability를 함께 맞춰야 한다.

### m2 — 적용 완료 revision의 의미 불일치

breakdown:160은 적용 완료 descriptor를 패널과 값 표시의 정본으로 삼는다. Runtime:684-686은 classify 후 applied/revision을 갱신하지만 bridge:353(계산 null),390(canonical revision 불일치),428(command patch 실패)은 조용히 return한다. 현재 session.applied가 Skia 적용 성공을 보장하지 않는다. 최초 capability probe 뒤에도 후속 frame에서 실패할 수 있다.

해결: sessionId+descriptor revision+layout publication revision을 묶은 소비 완료 신호를 설계하고, 실패 시 세션 취소/마지막 성공 표시/commit 차단 중 명확한 정책을 정한다. 패널은 성공한 publication에 대응하는 값을 읽게 한다. 이는 실제 브라우저에서 발생 빈도를 실측한 결함 보고가 아니라 현재 API 의미와 설계 계약의 불일치다.

### l3 — 성능 측정 조건 (deferred)

G4의 ≤2ms/16.7ms에 fixture 출처, 불리한 편집, A/B arm, 기기/DPR/visibilityState, 워밍업·샘플 수와 총 frame 비용 범위를 붙여야 재현 가능하다. production 실패 없는 coverage 지적이므로 LOW deferred이며 단독 재판독 사유가 아니다.

검증: 현재 소스와 ADR/breakdown 직접 대조, production planner 함수 2입력 실행. 첫 probe는 상대 import 경로 오류로 실패했고 경로 수정 후 성공했다. 신규 테스트 파일·제품 코드·ADR 본문 수정 없음. Builder/Figma/Framer live 재실행과 성능 측정은 하지 않았으며 구현 G0~G5는 UNVERIFIED. 기존 관찰을 이번 리뷰 실측으로 재표기하지 않았다.

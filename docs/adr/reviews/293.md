### HIGH — 전체 출력이 명시 on-negative 델타를 덮는다

- 위치: docs/adr/design/293-theme-color-single-source-breakdown.md:32, ADR Decision 1 (:120).
- 현재 colorTokenToCss.ts:31,47에서 on-negative와 white는 모두 --color-white다. colors.ts의 seed에서 on-negative는 white보다 먼저 삽입되며, resolveThemeSnapshot.ts:234-238의 기존 키 값 대입은 삽입 순서를 바꾸지 않는다. 같은 이름을 마지막 값으로 대체하는 put (:190-194)에 전체 맵을 순회해 넣으면 white가 명시 델타를 덮는다.
- 입력: color.on-negative=#123456, white 미지정. 현재 DOM 명시 출력은 --color-white:#123456이다. 제안 루프 적용 뒤에는 #ffffff가 된다. Skia on-negative는 #123456 그대로다. 실제 catalog negative 버튼은 componentRulesTable.ts:1203에서 color.on-negative를 사용한다.
- 검증: 현재 소스의 매핑과 seed 키 순서를 읽어 제안 루프를 실행한 설계 모델에서 위 덮어쓰기 확인. 근거: .agent/runs/2026-10-30-review-adr293/probe.json. 신규 runtime 구현이나 브라우저 재현으로 주장하지 않는다.
- 해결: 서로 독립적으로 델타 가능한 토큰에는 고유한 semantic 변수를 부여한다. on-negative/white/elevated의 --color-white 공유와 disabled의 primitive --color-neutral-200 공유를 함께 조사한다. 단순 순서 변경으로는 서로 다른 값 두 개를 한 변수로 표현할 수 없다. G1에 서로 다른 최종 값의 이름 충돌 검사, G3에 on-negative/white 독립 델타를 추가한다.

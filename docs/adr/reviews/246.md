# ADR-246 Review Log

## Round 1 — 2026-09-27 (reviewer: codex)

## ADR-246 round 1 — 코드 대조 리뷰

판정: **HIGH 4 / MEDIUM 2 pending.** Proposed 유지. 제품 코드·ADR 본문·상태는 수정하지 않았다.

### HIGH

1. **pre-push 블록 삽입 위치가 실행 불가능** — [design/246:105]는 ADR-198 블록 뒤에 삽입하도록 하지만, 현재 hook은 모든 처리 뒤 [\.githooks/pre-push:80]에서 `exit 0` 한다. 그대로 추가하면 스코프 안의 회귀 push도 246 블록에 도달하지 않아 G1/G4 차단 실증이 성립하지 않는다. **수리 방향:** 종료 전에 공통 경로 판정을 호출하거나 기존 최종 exit를 옮기고, 실제 설치된 hook에서 246 블록 도달·차단을 확인한다.
2. **서버 부재·서버 불일치가 차단 지점을 제거** — [design/246:105]는 5173 서버가 없으면 경고 후 통과다. 기존 하니스는 [perf-baseline.mjs:45,400-401]의 URL로 현재 서버의 Builder를 연다. 서버가 없는 일반 push는 측정 없이 통과하고, 5173이 다른 worktree/오래된 빌드를 서빙해도 잘못된 코드의 카운트를 현재 push의 값으로 판정한다. **수리 방향:** 게이트가 현재 push SHA의 빌드를 소유·검증하거나, 준비되지 않은 환경은 명시적 skip만 허용하는 차단 조건으로 둔다. 서버 정체성 검증을 G1/G4에 넣는다.
3. **idle에서 240 render.frame은 현재 Canvas 모델과 모순** — [ADR-246:34,122]와 [design/246:141]은 idle·pan에 240 beginFrame → `render.frame` 240을 요구한다. 현재 [frameScheduler.ts:24-32]는 dirty일 때만 rAF를 요청하고 [SkiaCanvas.tsx:1214-1224]는 애니메이션 등이 없으면 후속 frame을 예약하지 않는다. idle에서 240개 화면 tick이 와도 Canvas render는 0 또는 소수여야 정상인데 G3는 이를 no-go로 판정한다. **수리 방향:** 브라우저의 beginFrame 전달/rAF probe와 Canvas의 실제 제출 수를 분리하고, 연속 240 render를 기대한다면 별도 지속 갱신 fixture를 명시한다.
4. **begin-frame 제어 경로의 플랫폼·파라미터가 틀림** — [design/246:140-141]은 기본 Playwright 페이지에 launch flag만 주고 `frameTicks`를 보낸다. CDP 정본은 `Target.createTarget.enableBeginFrameControl`이 필요한 타깃 옵션이며 macOS에서는 아직 지원되지 않는다고 하고, `HeadlessExperimental.beginFrame` 시간 인자는 `frameTimeTicks`다. 이 로컬 macOS에서 현재 절차는 기능 검증 전에 실패하거나 시간이 현재 시각으로 대체돼 잘못된 no-go를 낼 수 있다. **수리 방향:** 지원 플랫폼/타깃 생성 경로를 Phase 0에서 확인하고 정확한 인자를 사용하며, macOS 대체 측정 경로 또는 명시적 범위 축소를 결정한다. 정본: https://chromedevtools.github.io/devtools-protocol/tot/Target/ 및 https://chromedevtools.github.io/devtools-protocol/tot/HeadlessExperimental/.

### MEDIUM

5. **90초 상한이 재실행 경로에 적용되지 않음** — [ADR-246:32,115,120]은 push 총 ≤90초를 요구하지만 [design/246:39,123]은 정상 1회 시간만 재고 초과 때 같은 하니스를 1회 더 돈다. 첫 실행이 60~~90초면 회귀가 있을 때만 120~~180초가 된다. **수리 방향:** 부팅·재실행 포함 최악 시간으로 G0/G1을 판정하거나 명시적 timeout·축소 절차를 둔다.
6. **pre-push 스코프가 성능 의존 경로를 빠뜨림** — [design/246:83-94]의 목록은 현재 hotspot과 shared만 담고 `packages/engine/`, `packages/specs/` 등을 제외한다. 레이아웃 엔진 또는 spec 소비 경로가 변경된 push는 Canvas 비용을 바꿀 수 있어도 게이트가 즉시 통과한다. **수리 방향:** runtime import/caller 기준으로 scope를 만들고, 대표 경로 변경 fixture로 hook 실행을 확인한다.

### 검증 범위

ADR·breakdown·연구 §8, 기존 pre-push, perf-baseline, Canvas scheduler, 공식 CDP 계약을 정적으로 대조했다. 실측 3회, 90초 계측, 120Hz beginFrame, 실제 push 차단은 **UNVERIFIED**. 현재 단계는 리뷰이며 G0~G4 PASS를 판정하지 않았다. 외부 블로그의 240 프레임 사례는 연속 갱신 화면에 관한 것이며 이 Builder idle의 render count 계약을 뒷받침하지 않는다 (https://claude.dev/blog/how-we-made-claude-ai-faster/).

## ADR-246 round 2 — round 1 수리 검증 1회

판정: **HIGH 2 pending; round 1의 h3·h4·m5·m6 문서 수리 확인.** 제품 코드·ADR 본문·Status 변경 없음. 본 판독은 약속된 수리 검증 1회이며 자동 추가 라운드는 하지 않는다.

### HIGH

1. **h1 pending — `SKIP_VISUAL_PARITY=1`가 ratchet까지 건너뛴다.** [design/246:107]은 D3 미매칭의 `exit 0`과 마지막 `exit 0`만 재구성 대상으로 적었다. 그러나 기존 [\.githooks/pre-push:22-25]의 visual skip도 `exit 0`이다. 스코프 안의 Canvas 변경을 `SKIP_VISUAL_PARITY=1 git push`로 밀면 이 분기에서 hook 전체가 종료되어 246 측정·차단에 닿지 않는다. 사용자가 지정한 ratchet 탈출구가 아닌 visual 탈출구가 ratchet을 우회한다. **수리 방향:** skip은 ADR-198 실행만 끄는 플래그로 처리하고, hook 전체 조기 종료를 없앤 뒤 visual skip + ratchet scope 조합을 G1에 넣는다.
2. **h2 pending — 자체 서버가 지정 포트에서 실행되지 않는다.** [design/246:133]은 `DEV_PORTS=5179 pnpm dev`로 서버를 띄우고 `BUILDER_URL=localhost:5179`로 측정하도록 한다. 현재 [package.json:7]의 `dev`는 `turbo run dev`, [apps/builder/package.json:7]은 인자 없는 `vite`다. `DEV_PORTS`는 [package.json:9]의 `dev:kill`에만 쓰인다. 따라서 이 명령은 5179를 설정하지 않는다. 5173이 비면 5173에서, 점유 중이면 Vite의 다른 가용 포트에서 뜰 수 있어 게이트가 자체 서버를 확보하지 못한다. 같은 root의 기존 5173을 재사용할 때도 dirty 차단을 perf scope에만 적용하면 vite.config 등 scope 밖 미커밋 런타임 변경을 측정할 수 있어 push SHA 정체성이 보장되지 않는다. **수리 방향:** Vite에 `--port 5179 --strictPort`를 실제 전달하고 ready URL을 검사하며, 측정에 영향을 주는 config/의존 파일의 dirty 여부와 서버가 제공하는 revision을 검증한다.

### 해소 확인

- **h3 fixed:** [ADR-246:34,123]과 [design/246:154]가 브라우저 rAF tick과 Canvas render를 분리했다. 현재 [frameScheduler.ts:24-32]의 dirty 기반 예약과 맞는다.
- **h4 fixed:** [design/246:153-154]가 `Target.createTarget({enableBeginFrameControl:true})`와 `frameTimeTicks`를 쓰고 Linux 조건/Deferred를 명시했다. [CDP Target](https://chromedevtools.github.io/devtools-protocol/tot/Target/)와 [HeadlessExperimental](https://chromedevtools.github.io/devtools-protocol/tot/HeadlessExperimental/) 계약과 일치한다.
- **m5 fixed:** [ADR-246:32,120]이 통과 90초와 재실행 포함 180초를 각각 G0 실측 대상으로 정했다.
- **m6 fixed:** [design/246:94-95,107]이 engine/specs를 scope에 포함하고 wasm 신선도 차단 조건을 넣었다.

### 검증 범위

수정된 ADR·breakdown·리뷰 frontmatter와 기존 hook, root/builder dev 스크립트, Canvas scheduler, CDP 정본을 정적으로 대조했다. 실제 hook push, 자체 서버 기동, 카운트 반복성, 시간 예산, Linux begin-frame은 **UNVERIFIED**이며 G0/G1/G3의 실행 게이트로 남는다. 최신 pending HIGH가 2건이라 Phase 0 착수 조건은 충족하지 않는다.

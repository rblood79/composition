# ADR-219 Review Log

## Round 1 — 2026-09-14 (reviewer: codex)

현재 판정: 수정 필요 — HIGH 3 / MEDIUM 2. main 9f80621e2 및 작업 중 ADR 본문·breakdown 기준. 제품 코드·ADR 상태는 변경하지 않았다.

1. **HIGH — 저장 정규화가 편집 의도를 보존하지 않는다.** §2.2 규칙을 그대로 계산하면 코너 [8,4,2,6] 상태에서 shorthand 12를 써도 기존 네 longhand가 남고 12는 삭제된다. 카탈로그 반경 8, props.style={}에서 TL만 12로 편집하면 [12,0,0,0]이 되어 나머지 코너까지 변한다. §2.4는 한 칸 편집을 해당 longhand 쓰기로 규정하므로 import 전용 문제가 아니다. 변경 property/value, 편집 전 effective geometry, 삭제/그룹 reset 의도를 받는 연산 계약이 필요하다. shorthand 전체 덮어쓰기와 단일 코너 편집, catalog fallback, 삭제 및 배치 순서 독립성을 G3에 명시해야 한다. 수치 반례는 ADR 규칙의 독립 계산이며 아직 없는 제품 구현을 실행한 결과가 아니다.

2. **HIGH — responsive 지원 전제가 현재 계약과 다르다.** shouldWriteBreakpointOverride는 isResponsiveEligibleStyleProp가 false인 border를 base에 기록한다. buildResponsiveElementCss도 같은 필터로 border override를 버린다. 기존 responsiveCss.test.ts:19-28,55-64가 이 동작을 명시한다. 따라서 buildResponsiveStyleOverride 끝의 정규화만으로 tablet 코너 편집은 구현되지 않는다. 전역 범위를 유지할지, ADR-154 eligibility·picker·resolve·CSS emit까지 확장할지 결정하고 비용과 변경 파일에 반영해야 한다. 확장한다면 breakpoint별 배타성만으로 충분하지 않으며 base longhand와 tier shorthand의 합성 우선순위도 정의해야 한다.

3. **HIGH — 기존 Skia 기하가 CSS와 같다는 전제가 틀리다.** 100×100, 반경 [80,0,0,0]은 CSS에서 겹치지 않아 80을 유지하지만 clampCornerRadii는 50으로 자른다. 새 코너 패널에서 바로 만들 수 있는 입력이다. partial_border도 top/right 각각 TR 전체 호를 그리므로 분할 완료라는 문서 설명과 다르고 반투명 stroke가 겹칠 수 있다. CSS 비례 축소 및 외곽/내곽 기하, 코너 소유권을 정의하고 큰 비대칭 반경·인접 변·반투명 stroke를 G0/G2에 넣어야 한다. 기존 shorthand 픽셀 무변경 HC1과 기존 오류 수리 사이의 경계도 명시해야 한다. CSS oracle: [W3C CSS Backgrounds §4.5](https://www.w3.org/TR/css-backgrounds-3/#corner-overlap). 픽셀 parity 점수는 측정하지 않았다.

4. **MEDIUM — 스타일 강등이 대칭 계약에서 빠졌다.** §2.3은 임의 폭의 double/groove/ridge/inset/outset을 solid로 렌더하도록 한다. 기존 문서에서 이 스타일을 가진 요소에 변별 폭을 적용하면 Preview는 원래 스타일, Skia는 solid가 된다. 구현 경계에는 색·타원·자식 clip만 제외되어 있다. 지원 기하를 추가하거나 이 조합의 범위 제한/정규화 정책을 본문 Decision과 HC2에 명시하고 G2에 사례를 넣어야 한다.

5. **MEDIUM — 성능 gate 재현 조건이 부족하다.** G4의 before/after와 요소 수는 유효한 출발점이지만, 연속 반경/폭/크기 편집처럼 경로 캐시가 무효화되는 동작 및 기기·DPR·visibilityState·힙 조건이 없다. 동일 fixture/동작/환경의 전후 총 프레임 비용을 비교하도록 고정해야 한다. 아직 측정되지 않은 성능 저하를 주장하는 것은 아니다.

검증: ADR·breakdown, 저장/카탈로그/반응형 CSS/Skia 소비 경로를 정적 대조했고 정규화 두 사례와 반경 한 사례를 독립 수치 계산했다. 신규 기능 구현, 브라우저 픽셀 실측, build/perf/typecheck는 수행하지 않았으며 해당 gate는 UNVERIFIED다. 리뷰만 수행하여 제품 회귀를 단정하지 않는다. 기존 dirty ADR/README는 보존했다.

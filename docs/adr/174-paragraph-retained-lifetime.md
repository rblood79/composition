# ADR-174: Paragraph 수명 retained 전환 — 전역 LRU 폐지와 안전 폐기

## Status

Accepted — 2026-07-31 (리뷰 round 1 승인 — 이슈 3건 전건 fixed, HIGH/CRITICAL 0, `reviews/174.md`). 이력: Proposed 2026-07-30

**진행**:

- Phase 0 (메모리 축 실측) — **G1 미통과, 재측정 필요**. 1차 측정에 쓴 문서가 소수 텍스트를 복제해 요소 수만 부풀린 합성물이라(2026-07-31 사용자 확인) 중복 계수·고유 키 수·보유 프로젝션이 무효다. 그 수치로 내렸던 소유 모델·스코프 결정은 **철회**했고, 소유 모델은 본 ADR 채택안(per-node retained)으로 복귀했다. 유효 산출은 계측 도구 · paragraph 단가 · 프레임 중 delete 6 지점 · 수명 지도 · 측정 함정 3종. 상세: [breakdown §실측 결과](design/174-paragraph-retained-lifetime-breakdown.md).
- Phase 1 (안전 폐기 프리미티브) 완료 2026-07-31 — 프레임 중 WASM `.delete()` 를 전부 지연 폐기 큐 경유로 전환 (`fa4439739`). 측정 결과와 무관하게 성립하는 변경이라 위 철회의 영향을 받지 않는다.
- Phase 2 (retained 소유 전환) 구현 2026-07-31 (`d7b68a2e7`) → **당일 되돌림 (`954c17532`)**. 구현 자체는 계약을 만족했으나 (**G3 통과** — 계약 테스트 16, **G2 스래싱 A/B 통과** — 상한 20 서버 2대에서 RED `evictions 33 / hitRate 5.71%` vs GREEN `evictions 0 / hitRate 100%`), **실사용 문서에서 R2 가 그대로 발현해 텍스트가 소실**됐다. 사용자 보고 (2026-07-31) → 22 페이지 실문서에서 재현 → 런타임 플래그 A/B: `retained ON` 은 CanvasKit WASM 힙이 **2,147 MB (wasm32 주소공간 상한)** 에 닿아 `RuntimeError: Aborted()` 로 할당이 전부 실패 (프레임 다수 텍스트 소실 → 렌더 루프 정지), `retained OFF` 는 줌아웃·전 페이지 팬 내내 **1,090 MB 평탄** + 전 프레임 정상. 되돌림 후 실물 재확인 — 22 페이지 전체 렌더 · 힙 1,194 MB · 콘솔 에러 0. 상세: [breakdown §Phase 2 되돌림](design/174-paragraph-retained-lifetime-breakdown.md).
  - **원인은 채택안을 절반만 구현한 것**이다. Decision 은 대안 C (retained + **walk 스코프 정책**) 인데 Phase 2 는 보유만 넣고 스코프를 Phase 3 으로 미뤘다 — 그 중간 상태가 정확히 **대안 B** 이고, B 의 유일 HIGH ("무스코프 보유는 대형 문서에서 상한 없는 증가") 가 그대로 실현됐다. 스코프 없는 retained 는 착지 가능한 중간 상태가 아니다.
  - **"노드 소유면 상한 질문이 사라진다" 는 이 캔버스에서 성립하지 않는다.** 보유 상한 = 살아 있는 텍스트 노드 수인데, composition 캔버스는 22 페이지 프레임을 **동시에** 그리므로 그 집합이 곧 문서 전체다. 기존 경계인 `clearSkiaRegistry`(페이지 전환)는 여기서 아무것도 회수하지 않는다 — Pen 은 한 번에 한 화면을 그려 이 차이가 없었다 (대안 C 의 "composition 의 전 페이지 전역 등록 구조 차이 보정" 이 바로 이 지점).
  - 따라서 **G1 은 Phase 2 의 선행 게이트**다 (권고가 아니라 차단 조건). G1 미통과 상태로 Phase 2 를 진행한 것이 이번 회귀의 절차적 원인이며, 재개는 G1 통과 + 스코프 정책 동반 구현이 조건이다.
- Phase 1 은 되돌림 대상이 아니다 — 지연 폐기는 소유 모델과 독립적으로 성립하며 main 에 유지된다.

## Context

Skia 렌더의 텍스트 paragraph 는 전역 LRU 캐시 (고정 상한 1,000, `nodeRendererState.ts:14-21`) 로 관리되고, 퇴거 시 **프레임 도중 즉시** WASM `.delete()` 를 호출한다 (`nodeRendererText.ts:80-85`). 이 구조는 잠재 결함 2단을 내장한다 — ① 한 프레임 walk 의 **고유 텍스트 수** (캐시 키 기준 — content 키라 동일 텍스트·스타일·폭은 노드 간 공유, `nodeRendererText.ts:130`) 가 상한을 넘으면 프레임마다 전량 스래싱 ② 프레임 중 delete 된 paragraph 의 WASM 힙 주소가 같은 프레임의 새 paragraph 에 재사용되면 CanvasKit(Ganesh) 텍스트 blob 캐시가 stale 히트하여 **글리프만 조용히 소실**된다. ADR-173 P1 (컬링 반경 512) 이 이 문턱을 넘겨 실버그로 드러났고 (walk 텍스트 draw 1,416 > 1,000 — **필러 5,046 문서 측정치**: 기제 격리(`49d71dbd3`)는 유효하나 bench-\* 텍스트는 고유 문자열이라 중복 계수 ≈ 1 이어서 경계 수치로는 실문서 일반화 불가, 실문서 문턱은 Phase 0 중복 계수 실측이 확정 — 2026-07-31 오염 점검 정정), 되돌림은 문턱을 넘게 한 원인만 제거했을 뿐 **문턱 자체와 프레임 중 즉시 폐기는 main 에 잔존**한다. 텍스트 밀도·고유도가 높은 문서를 줌아웃하면 반경 200 에서도 넘을 수 있다. 문제 정의 정본: `docs/explanation/research/BUILDER_FRAME_DROP_BASELINE_5K.md` §8.

사용자 지시 (2026-07-30): 소실 기제만 끊는 최소 수리(폐기 지연 단독)가 아니라 **결함 부류의 구조 제거** — "단순한 눈가리기식 처리를 원하는게 아니다 완성도가 더 중요하다".

참조 구현 실측: Pen v1.2.1 은 paragraph 를 노드 필드로 소유 (수명=노드, 전역 캐시/상한/퇴거 0건) 하여 같은 결함 부류가 구조적으로 성립하지 않음을 상용 앱으로 검증했다 (`PEN_V1.2.1_RENDERING_UIUX_ANALYSIS.md` §3-4-1).

**SSOT 3-domain 판정**: D1/D2/D3 어느 스키마도 확장하지 않는다 — Skia consumer **내부** 자원 수명 문제 (builder 런타임). D3 시각 결과 불변이 통과 조건이다. 단 canvas-rendering.md §3 의 "WASM Paragraph 객체 캐싱 금지" 문구는 측정 경로 맥락 규칙이라 렌더 측 규칙 정정이 범위에 포함된다.

**Hard Constraints**:

1. 글리프 소실 0 — 문턱 초과 재현 절차 (`VITE_PARAGRAPH_CACHE_SIZE=50` + 줌 왕복, G2) 에서 소실 0.
2. 프레임 중 (record 시작 ~ flush 완료 사이) paragraph / nodePicture WASM `.delete()` 호출 0.
3. 성능 비회귀 — 기준선 문서 §1 의 전 경로 (유휴/팬 2종/스크롤/줌/편집) frame gap 비회귀, **불리 경로 + 프레임 총비용 포함 측정**.
4. 메모리 — retained 증가분이 Phase 0 실측 프로젝션 이내 (수치는 Phase 0 에서 freeze, G1).
5. 측정 경로 불변 — "Layout = Canvas 2D = CSS 정합" 원칙과 측정기의 "결과값만 LRU" 계약 유지 (렌더 측 한정 전환).

**Soft Constraints**:

- `49d71dbd3` (되돌려진 처치 커밋) 이 폐기 지연 구현·계약 테스트의 검증된 계보로 존재 — 재작성 비용 소.
- ADR-173 재시도 선결 조건 3개는 전부 컬링 반경 거래 대상 — 본 ADR 은 반경 불변(200) 이라 비해당.

## Alternatives Considered

### 대안 A: 캐시 정책 패치 — 동적 상한 + 폐기 지연 (`49d71dbd3` 재도입)

- 설명: 전역 LRU 유지. 상한을 `max(1000, 프레임 피크 draw × 1.25)` 로 동적화 + 퇴거의 WASM delete 를 flush 후로 지연.
- 근거: 원 커밋의 live 검증 계보 (수정 전 소실 재현 / 후 유지, 5,046 요소 문서 ×2 왕복).
- 위험:
  - 기술: L — 검증된 구현 재적용.
  - 성능: M — 소실은 끊지만 수명이 캐시 정책에 결합된 채 남음. 상한이 피크 추종 (세션 단조 증가 = 사실상 무상한인데 정책은 암묵) + 문턱 근처 진동 시 재생성 비용 잔존.
  - 유지보수: M — "왜 1,000인가 / ×1.25 인가" 류 튜닝 상수와 퇴거 로직 존속. 수명 규율이 캐시 정책과 이중.
  - 마이그레이션: L — 국소 재적용.

### 대안 B: retained 전환 — 전 페이지 무스코프 보유

- 설명: paragraph 소유를 전역 LRU 에서 skia node (registry entry) 로 이관. 재생성은 데이터 dirty 때만, 삭제는 unregister/dirty 때만 (deferred). 스코프 퇴거 없음 — 전 텍스트 노드 상시 보유.
- 근거: Pen v1.2.1 실측 동형 (노드 소유, 캐시 0건 — §3-4-1).
- 위험:
  - 기술: M — 수명 배선 (invalidate 신호를 registry data identity 로 단일화) 신규.
  - 성능: **H** — composition 은 비가시 페이지 포함 4,969 노드 전역 등록. 전 텍스트 paragraph 상시 보유의 메모리 총량이 **미실측** — 대형 문서에서 상한 없는 증가 가능.
  - 유지보수: L — 수명 규율 단일 (dirty/destroy), 튜닝 상수 소멸.
  - 마이그레이션: M — 전환 중 전역 LRU 와 이중 경로 관리 필요.

### 대안 C: retained 전환 + walk 스코프 정책 (B 의 메모리 위험 회피)

- 설명: B 와 동일한 노드 소유 수명 + **스코프 정책**: 가시(walk) 페이지 이탈 시 해당 페이지 노드의 paragraph 를 일괄 deferred 폐기 (프레임 밖). Phase 0 실측에서 총량이 작으면 스코프 퇴거는 no-op 으로 수렴 (= B 와 동치).
- 근거: Pen 모델 + composition 의 전 페이지 전역 등록 구조 차이 보정. 일괄 폐기는 페이지 전환 시점 (프레임 밖) 이라 프레임 중 delete 부재 원칙 유지.
- 위험:
  - 기술: M — B 의 배선 + 스코프 퇴거 1경로.
  - 성능: M — 메모리 상한 = 가시 페이지 텍스트 총량 (Phase 0 실측으로 확정). 페이지 재진입 시 lazy 재생성 비용은 첫 draw 1회.
  - 유지보수: M — 스코프 퇴거 로직 추가 (단 퇴거는 "페이지 단위 일괄" 하나 — LRU 식 항목별 퇴거 아님).
  - 마이그레이션: M — B 와 동일한 이중 경로 구간.

### Risk Threshold Check

| 대안 | 기술 | 성능 | 유지보수 | 마이그레이션 | HIGH+ 개수 |
| ---- | ---- | ---- | -------- | ------------ | :--------: |
| A    | L    | M    | M        | L            |     0      |
| B    | M    | H    | L        | M            |     1      |
| C    | M    | M    | M        | M            |     0      |

루프 판정: B 의 HIGH (메모리 미실측) 를 회피하는 대안 C 가 이미 포함 — 추가 루프 불요. CRITICAL 없음.

## Decision

**대안 C: retained 전환 + walk 스코프 정책**을 선택한다.

선택 근거:

1. 결함 부류 3개 (글리프 소실 / 스래싱 문턱 / 프레임 중 대량 delete 위험면) 를 **구조적으로 제거**한다 — 사용자 지시 (완성도 우선) 정합. A 는 소실만 끊고 문턱·퇴거·튜닝 상수를 남긴다.
2. B 의 유일 HIGH (메모리 미실측) 를 스코프 정책으로 회피하면서, Phase 0 실측 결과 총량이 작으면 스코프가 no-op 으로 수렴해 B 의 단순성도 잃지 않는다.
3. A 의 폐기 지연 부품은 기각이 아니라 **Phase 1 프리미티브로 흡수**된다 — composition 은 React 커밋이 프레임과 겹쳐 unregister 가 프레임 도중 올 수 있으므로, retained 모델에서도 남는 삭제 지점의 안전장치로 필요하다 (Pen 은 destroy 가 렌더 밖이라 불요했던 부분).
4. 잔존 위험이 전부 MED 이하이고 각각 Gate 로 관리된다.

기각 사유:

- **대안 A 기각**: 수명이 캐시 정책 (상한/퇴거) 에 결합된 채 남아 문턱 개념이 존속 — 문턱 진동 시 재생성 비용과 튜닝 상수가 남고, "왜 이 상한인가" 가 다음 문서 규모에서 재론된다. 완성도 요구 미달. (폐기 지연 부품만 Phase 1 로 흡수.)
- **대안 B 기각**: 메모리 총량 미실측 상태의 무스코프 보유는 대형 문서에서 상한 없는 증가 위험 (HIGH). 단 Phase 0 실측에서 총량이 작으면 C 의 스코프가 no-op 으로 수렴하므로 실질 포함된다.

## Consequences

### Positive

- 텍스트 소실 결함 부류의 구조 제거 — 문턱 (walk 텍스트 수 > 상한) 개념 자체가 소멸하여 문서 규모·줌 수준과 무관하게 성립 불가.
- 문턱 초과 시의 스래싱 (프레임마다 paragraph 전량 재생성) 소멸 — 대형 문서 줌아웃 경로의 잠재 성능 절벽 제거.
- 수명 규율 단일화 (dirty/unregister) — 튜닝 상수 (`1,000`, `VITE_PARAGRAPH_CACHE_SIZE`) 와 퇴거 로직 제거로 `nodeRendererText.ts` / `nodeRendererState.ts` 단순화.
- 안전 폐기 프리미티브 (`deferredDisposal`) 가 nodePicture 경로에도 적용 — 동류 use-after-free 위험면 동반 제거.

### Negative

- 메모리 프로파일 변화 — LRU 상한 (최대 1,000개) 에서 가시 페이지 텍스트 총량 비례로. Phase 0 실측과 G4 메모리 조건으로 관리하나, 초대형 단일 페이지 (텍스트 수만 개) 는 스코프 정책의 한계 밖 (재론 조건).
- `useSkiaNode` registry 와 렌더 자원의 결합 증가 — registry entry 가 WASM 자원 부착점이 되므로 unregister 경로의 폐기 누락이 곧 누수 (계약 테스트로 감시).
- 전환 구간 (Phase 2) 동안 이중 경로 유지 비용.
- canvas-rendering.md §3 규칙 문구 정정 필요 (측정 경로 한정 명시) — 규칙 문서 1건 동반 갱신.

## Context

### 도메인

**D3 시각 스타일** — preset 이 컨테이너와 슬롯에 쓰는 레이아웃 값 (`display` · grid 트랙 · 폭 · breakpoint 층) 과 Nav · SideNavPanel rule 의 값. **D1 관찰** — 랜드마크 요소 (`nav` · `main` · `aside` · `region`) 는 rule `structure.element` 로 type 마다 고정이고 노드별 덮어쓰기 필드가 없다 (`componentRulesTable.ts:10016` Nav `element: "nav"` · `:6613` frame `element: "div"` · `domBinding.runtime.ts:924` `frame: element("div")`). RAC · S2 가 주는 ARIA (S2 SideNavPanel 은 `aria-label` 이 있을 때 `role="region"` — `SideNavPanel.tsx:166 ~ :171`) 는 그대로 쓴다. **D2 읽기만** — SideNavPanel 의 `isCollapsed` · `defaultCollapsed` (S2 prop, `sideNav.ts:47 ~ :55`) 를 읽는다. 문서 스키마 · 명령 신설 0.

### Spectrum Hub App frame (design-data 3.8.2 guideline 원문 — 5 지침)

- **overview**: App frame = header + side navigation + content area 의 틀. 내비게이션은 한 곳에만 둔다. 랜드마크 — 내비는 이름 붙인 `navigation`, header 는 `banner`, 내용은 `main` (둘 이상이면 `region`), skip link 와 F6 영역 이동, `h1` 은 main 안.
- **header (browsing context)**: 높이 56. lock-up (로고 · 제품명) · 검색 · **CTA 는 하나** · 전역 동작 (도움말 · 알림 · 계정).
- **side navigation**: 최소 폭은 단계 수에 따라 160 / 200 / 240. 1단 항목은 아이콘 필수 (접힘 때 라벨 대신). end 섹션 (설정 · 도움말) 은 구분선 위, 높이가 모자라면 start 섹션에 이어 붙어 함께 스크롤. 라벨 표시 제어 「Show / Hide menu labels」. **≤ 768 은 overlay tray** (hamburger 가 연다).
- **content area**: 배치 네 가지 — 단일 · 가로 분할 (고정 상단 + 스크롤) · 세로 분할 (관련 없는 내용, 한쪽은 접을 수 있음) · 격자 (사용자 배치). **스크롤은 한 곳**. 그라데이션은 content area 안에만.
- **creating bluelines**: 치수 표기 — 이 ADR 밖.

### 제약

- **Hard**: 문서 스키마 · 명령 신설 0 — preset 의 슬롯이 instance 가 되는 것은 `insertNodes` 의 `definitionId` 와 `ownSlotContents` (`materialize.ts`) 로, 중첩 적용은 `catalogLayoutPresetCommand(rootId = 컨테이너)` 로 끝난다. breakpoint 별 **prop** 층을 문서에 더하지 않는다 (마이그레이션 코드 0 원칙 · contract 유지).
- **Hard**: D3 대칭 — tablet 접힘 · mobile 숨김 · 중첩 트랙이 Canvas (tablet 프레임 768 · mobile 390) 와 Preview (viewport) 에서 같은 모양. 판정은 함수 하나를 두 consumer 가 읽는다 (ADR-303 `containerLayer` 와 같은 모양).
- **Hard**: 값 정본 — SideNavPanel 42 · Nav 56 은 rule 값 (ADR-300 · ADR-295 원칙) 이고 preset 은 **배치만** 쓴다 (header 행 `auto` · sidenav 열 `auto` — 높이 · 접힘 폭을 preset 이 다시 적지 않는다). 사이드 폭 기본값은 Hub 수치 (160 / 200 / 240) 중 하나 (사용자 결정 2) 를 **sidenav 슬롯 노드의 폭** 으로 쓴다 — 트랙이 아니다.
- **Hard**: 접힘 · 숨김의 한 가지 경로 — tablet 판정 · 작성 `isCollapsed` · Preview 접기 버튼 (runtime) · mobile `display: none` 네 가지가 모두 패널의 유효 폭 (200 · 42 · 0) 하나로 모이고, 부모 트랙은 그 폭을 따른다. 트랙에 breakpoint 별 고정값 (`42px 1fr`) 을 쓰면 runtime 접기가 트랙에 닿지 않는다 (리뷰 round 1 h1).
- **Hard**: 번들 — Builder ≤ 1,414,000 · Preview ≤ 327,000 (ADR-201 재승인, 만료 2026-11-25). 직전 실측 Builder 1,412,437 · Preview 325,046 추정 (303 종결 공지의 Δ 합산 — **G0 에서 재측정**). 공용 판정 함수 (`sideNav.ts`) · 내용 슬롯 경로 (`project.ts`) 는 Preview 번들에 들어간다.
- **Hard**: 기존 문서 무변경 — 기존 10 preset 의 키 · 슬롯 이름 · 값은 그대로 (적용된 layout 의 `catalogAppliedPreset` 이 계속 맞아야 한다). 카테고리 · 표시 범위 (scope) 만 달라진다.
- **Soft**: Hub 의 mobile overlay 는 이 ADR 밖 — 이 ADR 의 mobile 층은 sidenav 슬롯 숨김까지. hamburger · Sheet 는 후속 상호작용 ADR 이 header 슬롯에 넣는다.
- **Soft**: 린트성 지침 (CTA 1 · 내비 한 곳 · 라벨 길이 · skip link · F6 · `h1` 위치) 은 내용 저작 규칙이라 preset 으로 강제할 수 없다 — 범위 밖 (breakdown §5).

## Alternatives Considered

### 대안 A: preset 추가만 — App frame 묶음을 빈 Frame 슬롯으로

- 설명: 카테고리 하나 (App frame) 와 preset 3 을 지금 모양 그대로 (슬롯 = 빈 Frame) 더한다. 중첩 · 접힘 · 랜드마크는 손대지 않는다.
- 위험: 기술(L — 정의 추가뿐) / 성능(L) / 유지보수(**H** — 사용자가 Nav · SideNavPanel 을 매번 넣어야 하고, content 안 분할은 여전히 불가라 sidebar-left + vertical-2 같은 조합마다 preset 이 늘어난다. Hub 의 「header 56 · 접힘 42」 가 preset 값이 아니라 사용자 손에 달린다) / 마이그레이션(L).

### 대안 B: 두 겹 모델 — instance 슬롯 + 컨테이너 단위 중첩 적용 + 판정 함수 접힘 + 랜드마크 type

- 설명: ① App frame preset 의 슬롯이 **컴포넌트 instance** (header → Nav · sidenav → SideNavPanel 원본, 내용 기본값은 `ownSlotContents`) 이고 content 만 Frame. ② preset 에 표시 범위 `scope` (frame · content) 를 두고, layout template 안 **어느 컨테이너를 골라도** 그 컨테이너 단위로 preset 격자 · Slots 목록 · 적용 표시가 나온다 (명령은 `rootId` 를 이미 받는다 — UI 와 내용 슬롯 경로만 컨테이너 단위로). 페이지 내용은 **가장 안쪽** 내용 슬롯으로 (content → 안쪽 preset 의 content · 첫 required · 첫). ③ tablet 접힘 = 판정 함수 `catalogSideNavPanelCollapsed` 의 가지 하나 — 작성한 `isCollapsed` · `defaultCollapsed` 가 없고 그 패널이 App frame 의 sidenav 슬롯이면 활성 breakpoint 가 tablet 일 때 접힘 (Canvas 는 세션 breakpoint, Preview 는 같은 경계의 `matchMedia`). mobile 층은 sidenav 슬롯 `display: none` (지금 `responsive.layout` 으로 저장 가능). ④ 랜드마크는 rule `structure.element` 를 가진 type (사용자 결정 3 의 방식).
- 위험: 기술(M — preset 정의 TS 형 확장 · UI 자리 확장 · 판정 함수 가지 · 내용 경로 재귀. 전부 기존 경로의 확장, 새 저장 형식 없음) / 성능(M — Preview 여유 ≈ 1.9 KB, shared 두 파일 변경 → G3) / 유지보수(L — 「슬롯은 instance 일 수 있다 · preset 은 컨테이너 단위」 두 규칙) / 마이그레이션(L — 문서 0 · 기존 preset 키 유지).

### 대안 C: App frame 을 페이지 · 프로젝트 설정으로 (shell 을 layout 밖에)

- 설명: header · sidenav 를 `ProjectEntry` 의 앱 shell 설정으로 두고 페이지 layout 은 content 만.
- 위험: 기술(M) / 성능(L) / 유지보수(M — layout 과 shell 두 체계) / 마이그레이션(**H** — 스키마 신설 · contract bump · 「page body = layout instance」 모델 (ADR-248 4e, 사용자 결정 2026-10-01) 과 충돌). Page Layout 은 Builder 설정이라는 사용자 결정 (2026-10-28) 과도 다른 층이다.

### 대안 D: 한 겹 조합 preset — (shell 3) × (content 4) 를 카드로 펼침

- 설명: 조합마다 preset 하나 (예: 「Header + Side nav + 가로 분할」).
- 위험: 기술(L) / 성능(L) / 유지보수(**H** — 12 카드가 시작이고 content 배치가 늘 때마다 곱으로 는다 · 안쪽만 바꾸는 편집이 없다) / 마이그레이션(L).

### 대안 E: B + mobile overlay 까지 한 ADR

- 설명: B 에 hamburger Button · Sheet 안 SideNav · 열림 상태 · focus 반환을 더한다.
- 위험: 기술(**H** — D1 오버레이 상호작용 (trigger · open 소유 · esc · focus) 이 레이아웃 ADR 에 섞인다 · 사용자가 보드에서 분리를 정했다) / 성능(M) / 유지보수(M) / 마이그레이션(L).

## Decision

**대안 B — 두 겹 모델.** 위험 수용 근거: 두 M 은 모두 기존 경로의 확장이고 (명령은 `rootId` 를 받고, 슬롯 노드는 `definitionId` 를 갖고, breakpoint 판정은 ADR-303 과 같은 「함수 하나 · 두 consumer」 모양), 번들은 G3 가 상한을 잰다. 스키마 · 명령 신설 0 이라 되돌리기는 preset 정의와 UI 자리를 지우는 것으로 끝난다.

1. **App frame preset 묶음 (카테고리 `appframe`, 표시 범위 `frame`)** — `app-header` (header → Nav · content → Frame), `app-shell` (기본 — header → Nav · sidenav → SideNavPanel · content → Frame), `app-shell-end` (sidenav → **별도 원본** `SideNavPanel/End` — end 섹션을 가진 Library 원본. 원본이 다르므로 적용 판정 서명 (Decision 3) 이 app-shell 과 갈린다). 컨테이너는 grid `"header header" / "sidenav content"`, 열 **`auto 1fr`**, 행 `auto 1fr` — header 높이는 Nav rule M 56, sidenav 폭은 **sidenav 슬롯 노드의 작성 폭** (사용자 결정 2 — 200) 이고 preset 컨테이너는 둘 다 적지 않는다. 접힘 때 SideNavPanel rule `stateStyles.width.isCollapsed` 42 가 작성 폭을 이기고 (`componentRulesTable.ts:16186`), `display: none` 이면 열이 0 — 부모 트랙이 **패널의 유효 폭을 따른다** (리뷰 round 1 h1 수리: 고정 `200px` 트랙은 접힘 뒤 158 · 숨김 뒤 200 의 빈 열을 남겼다). header 는 두 열을 걸치지만 `1fr` 을 지나는 item 은 `auto` 열의 intrinsic 크기에 기여하지 않는다 (CSS Grid §12.5 — Chromium · 엔진 `tree.rs:5345` 같은 규칙, G2 가 content 시작점으로 잰다). 슬롯 정의에 `instanceOf` (TS 형, preset 정의 파일 안) 를 두고, 명령은 그 슬롯 노드를 `definitionId = 원본 id` + `ownSlotContents` 로 만든다 (Frame 슬롯과 같은 `slot: { name, required }`).
2. **콘텐츠 영역 preset (표시 범위 `content`)** — 기존 preset 중 Hub 의 네 배치에 대응하는 것 (단일 fullscreen · 가로 vertical-2 · vertical-3 · 세로 sidebar-right · 격자 — 사용자 결정 4) 에 `scope: "content"` 를 표시한다. 키 · 슬롯 · 값은 무변경. sidebar-left · dashboard · holy-grail 의 운명은 사용자 결정 1.
3. **컨테이너 단위 적용** — Properties 의 preset 격자 · Slots 목록 · 적용 표시는 layout template 루트뿐 아니라 **그 template 안의 슬롯 Frame** 에서도 나온다 (명령 `rootId` = 그 컨테이너 · 표시 범위 — 루트는 `frame` + `content`, 안쪽은 `content` 만). `catalogLayoutSlots` 의 「바깥 슬롯에서 멈춤」 은 그대로다 (컨테이너마다 자기 직속 슬롯만). **적용 판정 서명** = 직속 슬롯의 (이름 · `definitionId`) 열 — `CatalogLayoutSlot` 에 `definitionId` 를 더하고 `catalogAppliedPreset` 은 preset 슬롯의 (`name` · `instanceOf ?? frame`) 열과 비교한다. 판정 집합은 `LAYOUT_PRESETS` **전체** (표시 순서 `PRESET_ORDER` 가 아님 — 결정 1 (b) 로 표시에서 뺀 키도 기존 layout 의 판정을 지킨다). 서명은 preset 마다 유일해야 한다 (정적 검사, G1) — vertical-2 (`header`·frame · `content`·frame) ≠ app-header (`header`·Nav · `content`·frame) · app-shell (`sidenav`·SideNavPanel) ≠ app-shell-end (`sidenav`·SideNavPanel/End) (리뷰 round 1 h2 수리). 페이지 내용 슬롯 (`layoutContentSlotPath`) 은 **가장 안쪽** 까지 내려간다 — 단계마다 `content` → 첫 required → 첫 슬롯, 그 슬롯이 또 슬롯을 가지면 계속. Page 의 Properties 가 그 경로 (「content ▸ bottom」) 를 보여 준다. 중첩은 두 층까지 설계 대상이다 (세 층은 막지 않지만 검증하지 않는다).
4. **좁은 폭** — tablet: 판정 함수 `catalogSideNavPanelCollapsed` 에 가지 하나 — 작성한 `isCollapsed` · `defaultCollapsed` 가 없고 패널이 App frame 의 sidenav 슬롯 (슬롯 선언 이름 `sidenav`, layout template 또는 그 instance 안) 이면 활성 breakpoint 가 tablet 일 때 접힘. Canvas 는 세션 breakpoint, Preview 는 `BREAKPOINTS` 의 같은 경계 (768) 를 `matchMedia` 로 읽는다. 접기 버튼의 runtime 상태 (ADR-300 `onCollapsedChange`) 가 그 위에서 이긴다. mobile: preset 이 sidenav 슬롯의 mobile 층에 `display: none` 을 쓴다 (지금 저장 가능한 층) — `auto` 열이 0 이 되어 content 가 전폭 (Decision 1). hamburger · overlay 는 후속 ADR. 네 경로 (tablet 판정 · 작성 prop · runtime 접기 · mobile 숨김) 가 모두 패널 폭 → 트랙 한 길로 모인다.
5. **랜드마크** — 방식은 사용자 결정 3. 권고 (a): rule `structure.element` 를 가진 type `Main` · `Aside` 를 catalog 에 더해 (Nav 와 같은 자리 — `componentCatalog.ts` layout 카테고리 · rule 은 frame 과 같은 container · `skipCSSGeneration` · `d2Provenance` `composition`) App frame preset 의 content 슬롯은 `Main` instance, 세로 분할의 보조 슬롯은 `Aside`. header 슬롯은 Nav (`<nav aria-label>` — Hub 의 `banner` 가 아니라 `navigation`; S2 에 앱 header 컴포넌트가 없다). SideNavPanel 은 S2 대로 `aria-label` → `region`. skip link · F6 · `h1` 은 범위 밖.
6. **스키마 · 명령 신설 0** — 저장되는 것은 지금 모양의 노드 (`definitionId` · `slot` · `responsive.layout`) 뿐. 「breakpoint 별 prop 층」 은 만들지 않는다 (기각 — 아래).
7. **preset 소유 키 = 컨테이너 축만** — 적용 명령이 지우는 키는 자식을 배치하는 컨테이너 축 (`display` · `flexDirection` · `gridTemplateAreas` · `gridTemplateColumns` · `gridTemplateRows`) 이고, 부모 안에서 자기 자리를 정하는 item 축 (`gridColumnStart` · `gridRowStart` · flex longhand) 은 base 에서도 (`layoutPreset.ts:89 ~ :95` 이미 그렇다) tablet · mobile 층에서도 지우지 않는다 — `PRESET_RESPONSIVE_OWNED_KEYS` 를 `PRESET_OWNED_CONTAINER_KEYS ∩ eligible` 로 줄인다 (`PRESET_AUTHORED_RESPONSIVE_STYLE_PROPS` 의 item 키 제외 — 그 집합은 eligibility 판정용으로 그대로). 기존 동작 변화 0 — layout 루트에는 preset 이 item 키를 쓴 적이 없다 (`presetCss(responsive)` 는 컨테이너 style 만, 슬롯 item 키는 새 노드에 쓴다). 안쪽 컨테이너 (바깥 preset 의 슬롯) 에 적용할 때 바깥이 준 tablet 자리 (dashboard-widgets `widgets` 의 `gridColumnStart 1` · `gridRowStart 3`) 가 남는다 (리뷰 round 1 m1 수리).

기각 사유 — A: Hub 값이 사용자 손에 남고 조합이 preset 수로 터진다. C: 스키마 신설과 「page body = layout instance」 와 충돌. D: 카드가 곱으로 는다. E: D1 상호작용이 섞이고 사용자가 분리를 정했다. **breakpoint 별 prop 층 (schema)**: 접힘 하나를 위해 contract 를 올리고 모든 prop 에 층 의미를 열게 된다 — 판정 함수 가지 하나로 같은 결과.

> 구현 상세: [304-app-frame-layout-presets-breakdown.md](design/304-app-frame-layout-presets-breakdown.md)

### 사용자 결정 (6 건 — `/execute-adr` 가 닿을 때 묻는다)

1. **sidebar-left · dashboard · holy-grail** — (a) 남긴다 (빈 Frame 슬롯이 필요한 경우용, 표시 범위 `frame`) **권고** / (b) App frame 묶음에 흡수하고 `PRESET_ORDER` 에서 뺀다 (키는 남겨 기존 layout 의 적용 표시를 지킨다).
2. **사이드 폭 기본값** — (a) 200 (Hub 2단 최소) **권고** / (b) 160 / (c) 240. sidenav **슬롯 노드의 폭** (`sizing.width`) 이고 컨테이너 열은 `auto` 다 (Decision 1). tablet 층은 접힘 (42, rule 이 작성 폭을 이김) 이라 폭 층을 쓰지 않는다.
3. **랜드마크 요소 부여 방식** — (a) type `Main` · `Aside` 신설 (rule `element`) **권고** / (b) DOM binding 이 슬롯 이름 (`content` → `main`) 으로 요소를 바꾼다 (숨은 결합 — 권고하지 않음) / (c) 이 ADR 밖.
4. **콘텐츠 영역 preset 집합** — (a) fullscreen · vertical-2 · vertical-3 · sidebar-right · dashboard-widgets (보드) **권고** / (b) 격자는 feed (header + 4열) 로.
5. **번들** — G0 실측 여유 안이면 진행, 넘으면 ADR-201 재승인 (사용자) 이 Phase 1 착수 조건.
6. **tablet 접힘의 Preview 판정 = viewport 폭** (Canvas 의 tablet 프레임 768 과 같은 경계) — (a) 그대로 **권고** / (b) 접힘은 작성 prop 만 (preset 이 tablet 에서 아무것도 안 함).

## Consequences

### Positive

- Layouts 탭에서 App frame 을 **한 걸음** 으로 — header (Nav 56) · sidenav (SideNavPanel 200 / 접힘 42 / mobile 숨김) · content 가 instance 로 서고, Hub 값이 사용자 손이 아니라 preset 에 있다.
- content 슬롯 안에 Hub 의 네 배치를 **중첩** 으로 — 조합 수가 곱이 아니라 합 (3 + 4).
- 페이지 내용이 가장 안쪽 스크롤 슬롯으로 가서 「스크롤은 한 곳」 이 기본 결과가 된다.
- 랜드마크 (결정 3 (a)) 가 type 으로 생겨 다른 layout · 손 배치에서도 쓸 수 있다.

### Negative

- preset 격자 · Slots 목록이 「고른 컨테이너」 단위라, 루트를 고른 사용자는 안쪽 슬롯을 보려면 content 슬롯을 골라야 한다 (Page Properties 의 경로 표시가 보완).
- 사이드 폭이 트랙이 아니라 sidenav 슬롯 노드의 폭이라, 사용자가 폭을 바꾸려면 컨테이너가 아니라 그 노드 (SideNavPanel instance) 의 Width 를 고친다 — 다른 preset (holy-grail `200px 1fr 200px`) 과 어법이 다르다. 대신 접힘 · 숨김이 한 길로 끝난다.
- tablet 접힘이 작성 prop 이 아닌 **판정** 이라 Properties 의 `isCollapsed` 칸은 비어 있는데 화면은 접혀 있다 — Properties 에 「breakpoint 가 접음」 안내 한 줄 (Phase 3).
- mobile 에서 sidenav 가 숨고 hamburger 가 없다 — 후속 ADR 전까지 mobile 은 내비 없음 (header 의 Nav 항목으로 보완 가능).
- Header type 이름이 S2 Menu section header 라는 사실은 그대로 — App frame 의 header 는 Nav 다 (이름 혼동은 팔레트 라벨 「navigation」 으로 가른다).

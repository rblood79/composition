# ADR-256: RAC 수준의 조립 — 노드 트리를 RAC 부품 그대로 그리고, 넣는 자리를 레퍼런스에서 가져온다

외부 빌더의 slot:

- **Plasmic**: code component 의 slot prop 에 `allowedComponents` 로 허용 목록을 적는다 ([문서](https://docs.plasmic.app/learn/registering-code-components)). 허용 목록이 컴포넌트 작성자의 선언이다.
- **Webflow**: Component Slot 이 처음에는 컴포넌트만 받다가 2025 년에 모든 요소를 받게 바뀌었다 ([변경 기록](https://releases.sh/release/rel_NPLtElsFfOtyLT42-FCDu-component-slots-open-to-any-element-type)). 자유도를 넓히는 방향이다.
- **pen.dev**: 원본의 frame 을 slot 으로 지정하면 instance 가 그 자리를 아무 내용으로 채운다.
- **RAC**: 「slot」 은 넣는 구멍이 아니라 context 가 알아보는 이름 붙은 자리다 (`slot="title"` · `slot="description"` · `slot="increment"`). 넣을 수 있는 것은 부품의 `children` 종류가 정한다 — collection 은 항목만, 나머지는 자유 내용.

### Domain (SSOT 3-domain)

- **D1 DOM/접근성 (본체)**: Preview 가 RAC 부품을 노드 트리대로 조립한다. RAC 의 DOM · ARIA · 키보드는 그대로이고, 우리 renderer 가 끼어들어 구조를 정하던 것을 걷어낸다. 넣을 수 있는 자식의 판정을 「우리 renderer 가 그릴 수 있는가」 (F6) 에서 「RAC 부품의 `children` 종류」 로 바꾼다 (결정 지점 ③ — 사용자 지시가 근거).
- **D2 Props/API**: 새 prop 0. Card 의 S2 구조 전환은 D2 참조 원천 (RSP) 을 따르는 것이다. 상태별 표시 (Decision 7) 는 prop 이 아니라 노드의 표시 조건이다.
- **D3 시각 스타일**: 정본은 catalog 그대로다. 부모 rule 이 그리던 부품 (F9) 을 노드로 만들 때 모양 선언을 그 부품의 rule 로 옮긴다 (ADR-253 · DisclosureChevron 과 같은 방식). Generator 선언 (ADR 작성 규칙 #2): 생성기는 자식 selector 를 이미 낸다 (`packages/rendering/src/renderers/CSSGenerator.ts` `generateCompositionCSS`). 새 부품 type 은 rule 하나씩 추가한다.

### 제약

- **hard — 시각 계약**: ADR-248 G3 수치. Canvas ↔ DOM geometry ≤ 1 CSS px, 비텍스트 픽셀 차이 ≤ 0.001. 레퍼런스 구조로 바뀌어 달라지는 화면은 G0 목록에 고정하고 목록 밖 변화 0.
- **hard — 저장 포맷 (BC 수식)**: template 구조를 바꾸는 병합마다 contract +1 (7 → 8 …). 옛 개발용 프로젝트는 **전부** 열리지 않는다. 변환 0 파일. 보존 대상 프로젝트 0 이 전제다 (사용자 확인 1).
- **hard — 성능**: ADR-246 ratchet A등급 증가 0. 부품 노드가 늘어 `scene.build` 가 는다 — 컴포넌트 100개 격자에서 편집 한 번의 증가를 G6 에서 잰다.
- **hard — 번들**: Builder initial ≤ 1,421,000 · Preview ≤ 623,000 (ADR-201 재승인, 만료 2026-10-25 — 만료 뒤에는 그때의 상한). shared 합성 컴포넌트 30개를 Preview 경로에서 빼면 줄어드는 쪽이다.
- **hard — 접근성**: 조립을 자유롭게 열어도 RAC 가 요구하는 짝 (Select 의 Button + Popover > ListBox, ComboBox 의 Input, collection 의 항목) 이 없으면 RAC 가 오류를 내거나 이름이 사라진다. 필수 부품은 지울 수 없어야 한다.
- **soft**: Skia 전용 시각 효과 0. family 단위 worktree · phase 별 커밋 · Gate 통과 뒤 main 병합 (ADR-251 Decision 7).

## Alternatives Considered

### 대안 A: slot 만 레퍼런스에 맞춘다

- 설명: slot 25자리를 레퍼런스의 자식 종류로 다시 정하고 (collection → 항목, 그 밖 → 자유 내용), 넣을 수 있는 목록을 그 종류에서 만든다. Preview renderer 와 중첩 규칙 F6 은 그대로 둔다.
- 위험: 기술 L / 성능 L / 유지보수 H (자유 내용이라 선언해도 F5 의 18개 renderer 가 그리지 않으므로 F6 가 다시 막는다 — 선언과 실제가 갈린 채 남는다) / 마이그레이션 L
- 목표 판정: **미달**. field · Slider · Switch · Calendar 안의 조립, context 조립 (F11), 상태별 내용 (F12) 이 안 된다.

### 대안 B: 노드 트리를 RAC 부품 그대로 그린다 + 넣는 자리를 RAC 의 children 종류에서 가져온다

- 설명: ① Preview 가 노드 하나를 RAC 부품 하나로, 자식 순서대로, 부모의 RAC context 안에 그린다. 합성 renderer (F5 의 props 15 · 선별 8 · 무시 3) 를 RAC 부품의 노드 트리로 바꾼다. ② 원본 template 을 레퍼런스 예제의 조립으로 다시 쓴다. ③ 부품마다 받는 자식 종류 (항목 목록 / 자유 내용) 를 RAC API 에서 가져와 중첩 규칙 · 넣을 수 있는 목록 · slot 표시가 같은 판정을 쓴다. ④ 부모 rule 이 그리던 조립 가능 부품 (F9) 을 노드로 만든다. ⑤ catalog 에 없는 RAC 부품 (F11) 을 추가한다. ⑥ 상태별 표시를 노드에 둔다.
- 위험: 기술 H (RAC 의 context 조립을 일반 경로로 — 조건부 부품 · 필수 짝 · collection 내부 규칙) / 성능 M (노드 수 증가 · 해석 비용) / 유지보수 L (그리기 경로가 하나 — 컴포넌트별 renderer 가 준다) / 마이그레이션 H (원본 template 대부분 · G3 승인 기록 · 테스트 경로)

### 대안 C: pen.dev 식 자유 slot

- 설명: 모든 frame 성 부품을 slot 으로 열고 무엇이든 넣게 한다. Preview 는 지금 renderer 를 유지하고, 그리지 못하는 자식은 renderer 옆에 덧붙여 그린다.
- 위험: 기술 H (RAC 부품 밖에 덧붙인 요소는 context 를 받지 못한다 — 예: TextField 옆에 붙인 Button 은 field 의 disabled 를 모른다) / 성능 L / 유지보수 H (renderer 47개마다 덧붙임 규칙) / 마이그레이션 L
- 목표 판정: **미달**. 자유도는 넓지만 RAC 의 조립이 아니다 (D1 침범 — 접근성 연결이 끊긴다).

### 대안 D: shared 합성 컴포넌트에 slot prop 을 추가 (Plasmic 식)

- 설명: 지금 renderer 를 두고, 각 합성 컴포넌트에 `prefix` · `suffix` · `footer` 같은 ReactNode slot prop 을 더해 허용 목록을 선언한다.
- 위험: 기술 M / 성능 L / 유지보수 H (컴포넌트마다 slot prop 설계 · RSP 에 없는 prop — D2 위반) / 마이그레이션 M
- 목표 판정: **미달**. 우리가 정한 자리만 열린다. RAC 예제의 임의 조립은 여전히 안 된다.

### Risk Threshold Check

| 대안 | HIGH+                   | 목표 (RAC 예제 재현) |
| ---- | ----------------------- | -------------------- |
| A    | 유지보수 H              | 미달                 |
| B    | 기술 H · 마이그레이션 H | 충족                 |
| C    | 기술 H · 유지보수 H     | 미달                 |
| D    | 유지보수 H              | 미달                 |

모든 대안이 HIGH 1개 이상이다. 1차 루프: 목표를 충족하는 것은 B 뿐이므로 B 의 HIGH 를 줄이는 방법을 찾았다 — family 단위로 나눠 각 family 가 자기 Gate 와 후퇴안 (그 family 만 옛 renderer 유지) 을 갖게 하면 기술 위험이 한 family 범위로 묶인다. 마이그레이션 H 는 줄지 않는다 — 보존 대상 프로젝트 0 (F14 · 사용자 확인 1) 이 수용 근거다. 2차 루프에서 다른 대안 (A 를 먼저 하고 B 를 나중에) 을 따졌으나 A 의 slot 선언은 B 에서 다시 쓰이므로 이중 작업이다 — Phase 순서로 흡수한다 (breakdown).

## Decision

**대안 B** 를 선택한다. 사용자 원칙 「RAC 수준이 되지 않는다면 빌더를 하는 의미가 없다」 를 충족하는 유일한 대안이다.

1. **기준**: RAC 컴포넌트는 react-aria.adobe.com 예제와 API, D1 정본은 설치된 RAC. RAC 에 없는 S2 컴포넌트는 react-spectrum.adobe.com. 두 곳 모두 있으면 구조는 RAC, 이름 붙은 자리 · props 만 S2 참고. 두 곳 모두 없는 Nav · Pagination · FileUpload · Chart 는 지금 구조 (사용자 확인 3).
2. **Preview 는 노드 트리를 그린다**: 노드 하나 = RAC 부품 하나 (또는 RAC 가 요소를 주지 않는 자리의 plain 요소), 자식 순서대로, 부모의 RAC context 안에서. 컴포넌트별 위임 renderer 는 RAC 가 요구하는 것만 남긴다 — collection 의 `id` · `textValue`, Select · ComboBox 의 Popover 연결, 펼침 · 선택 같은 실행 값 (ADR-250). shared 합성 컴포넌트는 Builder UI 가 쓰는 3개 (F13) 만 남기고 Preview 경로에서 뺀다.
3. **원본 template = 레퍼런스 예제의 조립**: 예) TextField = `TextField > Label + Input + Text[slot=description] + FieldError` · Checkbox = `CheckboxField > CheckboxButton (indicator + 글자) + Description + FieldError` (F8) · NumberField = `NumberField > Label + Group > (Button[slot=decrement] + Input + Button[slot=increment])`. 지금의 wrapper type (`SelectTrigger` 등) 은 RAC 의 `Group` 으로 바꾼다. 예제의 CSS class 가 아니라 우리 catalog rule 이 모양의 정본이다 (D3 무변경).
4. **넣는 자리 = 부품의 children 종류**: 부품마다 `항목 목록 (받는 항목 type)` 또는 `자유 내용` 을 type 특성 표 (`S/domain/componentTraits.ts`) 에 둔다. 중첩 규칙 · Properties 의 「넣기」 목록 · Components page 의 빈 slot 표시가 이 하나를 읽는다. `SELF_COMPOSED_CONTAINER_CHILD_TYPES` (F6) 는 「아직 전환하지 않은 family 의 제한」 으로 뜻을 바꿔 판정에 교집합으로만 남기고, family 가 전환될 때마다 그 행을 지워 끝에 없앤다. template 의 `slot` 선언은 이름 (Components page 표시) 만 남고, 넣을 수 있는지는 종류가 정한다. 컴포넌트 자신에 걸린 자리 (F4) 도 instance 에서 채울 수 있다.
   - **이름 붙은 자리 (RAC `slot`) 의 지정**: 넣기 판정과 slot 연결은 별개다. 제공자 표는 설치 RAC 의 `TextContext` · `ButtonContext` · `HeadingContext` 등 **consumer context 별 실제 제공 노드**에서 추출한다 (파일명이나 family 루트를 제공자로 쓰지 않는다). RAC 1.21.0에서 Text — ListBoxItem · MenuItem = 기본 · `label` · `description`, GridListItem · Dialog = 기본 · `description`, Toast = 기본 · `title` · `description`, field 계열 = `description` · `errorMessage` (기본 없음), Calendar = `errorMessage`. Button — NumberField `increment` · `decrement`, Calendar · RangeCalendar `previous` · `next`, Dialog · Toast 기본 · `close`, Disclosure 기본 · `trigger`, **Tag `remove`, TreeItem · Row 기본 · `chevron` · `drag`**, GridListItem 기본 · `drag`; Select 는 이름 목록 없는 일반 ButtonContext 를 준다. Heading — Dialog 기본 · `title`. Tag 는 TextContext 를 새로 주지 않는다. 가장 가까운 **같은 consumer context** 제공자를 찾으며, 다른 context 제공자는 그 탐색을 막지 않는다. 전체 표는 G0 ⑧ 에 고정했다 ([evidence](evidence/256-g0-inventory.md) — 설치 RAC 를 실제로 마운트한 결과. 위 행 외에 RadioField `description` · ColorSwatchPickerItem `label` · `description` · 기본 · GridListItem · TreeItem · Row 의 `Checkbox[selection]` · Column 의 `Checkbox[selection]` · DateRangePicker 의 `DateField[start · end]`, 그리고 context 를 비우는 자리 3 — Select 의 Popover · DisclosurePanel · DatePicker 안 Calendar).
   - **slot 연결의 네 경로**: ① 명시 `slot={null}` 은 context 연결을 해제한다. ② 제공자에 `slots` 표가 있고 명시 이름이 유효하면 그대로 전달한다. ③ slot 미지정(빈 slot 문자열은 작성 시 미지정으로 정규화)은 기본 slot (`DEFAULT_SLOT`) 이 있으면 **생략한 채** 전달해 기본 연결을 유지한다. ④ `slots` 표가 없는 일반 context 는 미지정 또는 명시 문자열을 그대로 전달해 RAC 의 context 병합을 유지한다 (`utils.mjs:77-91`). 제공자가 없어도 RAC 요소를 그대로 그린다. **slotted context 에서 기본 slot 이 없거나 명시 이름이 잘못된 경우에만** 렌더링 시 `slot={null}` 로 처리하고 Properties 에 「연결 안 됨」 을 표시한다. 잘못된 작성 이름은 저장 상태에서 보존하므로 유효한 제공자 아래로 이동하면 다시 연결된다. slot 제거는 미지정으로 돌아가는 동작이며, 명시 연결 해제와 다르다. 저장·validation 은 이 키의 미지정 · 문자열 · 명시 null 을 구분한다. 필수 부품의 slot 변경·해제·이동은 Decision 5 의 결과 트리 검증을 먼저 거쳐, 필수 trigger/context 연결을 끊는 명령을 거부한다. 정상 기본 연결에는 「연결 안 됨」 을 표시하지 않는다.
5. **필수 부품**: RAC 가 동작에 요구하는 짝 (Select 의 trigger Button · Popover · ListBox, ComboBox 의 Input, Slider 의 Track · Thumb, Calendar 의 Grid, collection 의 항목 …) 은 **존재와 context 관계** 가 계약이다 — 지울 수 없고, 그 context 밖으로 옮길 수 없다. 같은 context 안에서의 재배치 · 사이에 Group · Frame 끼우기 · 같은 type 의 다른 원본으로 교체 (Button → 다른 Button 원본) 는 허용한다. 거부는 결과 트리가 RAC 요구 관계를 깰 때만 한다 (중첩 규칙이 조상 사슬로 판정 — `N` 의 owners 층과 같은 방식). 최초 template 위치에 고정하지 않는다. 짝 목록은 RAC 실행으로 G0 ⑨ 에 고정했다 — 부모 밖에서 throw 하는 부품 (context 관계) 과 빠지면 역할이 사라지는 부품 (존재) 을 나눈다. collection 의 항목은 **존재가 아니라 context 관계**다 (RAC 는 빈 collection 을 허용한다). Table 은 Column 수와 각 Row 의 Cell 수가 같아야 한다 (어긋나면 throw — 열 추가 · 삭제는 모든 Row 의 Cell 을 같은 명령에서 바꾼다). 그 밖의 부품 (Label · Description · FieldError · 아이콘 …) 은 지우고 · 옮기고 · 다른 것을 끼울 수 있다.
6. **조립 가능한데 부모 rule 이 그리던 부품을 노드로 (F9)**: 선택 표시 (`SelectionIndicator`) · Tag 지우기 (`Button slot="remove"`) · Slider 채움 (`SliderFill`) · overlay 화살표 (`OverlayArrow`) · ProgressBar · Meter 채움 · TreeItem 선택 checkbox. Canvas 는 그 노드를 자기 rule 로 그린다 (DisclosureChevron 선례). RAC 가 스스로 만드는 내부 (Calendar 칸 · DateInput 조각) 는 그대로 부모가 그린다.
7. **상태별 표시**: 노드가 「어느 상태에서 보이는가」 (`showWhen`) 를 가진다 (사용자 확인 2).
   - **상태의 주체 — 조건마다 따로 찾는다**: 기본 주체는 **그 키를 render props 로 주는 가장 가까운 조상**이다. 다른 키만 가진 조상은 통과한다. `Disclosure > Button > Icon` 의 `isExpanded` 는 Disclosure, `isPressed` 는 Button 이 주체다. Group 은 자기 render props 의 `isHovered` · `isFocusWithin` · `isFocusVisible` · `isDisabled` · `isInvalid` 키에서 주체가 된다. 키 표는 설치 RAC 의 `useRenderProps` `values` 로 G0 ④ 에 고정한다. 명시 `from: { type: T }` 는 **그 키를 주는 T 타입 중 가장 가까운 조상**만 뜻한다. 더 바깥의 같은 타입을 선택할 때는 `from: { ancestor: 주소 }` 로 **특정 조상 노드의 저장 주소**를 지정한다. 화면 이름·type·조상 몇 번째인지로 동일 노드를 대신 식별하지 않는다. 예: `Group A > Group B > Text` 에서 A의 주소와 B의 주소는 다른 참조이고 두 상태가 독립적이다. 주소 형식과 복사·이동 계약은 breakdown §1-1을 따른다.
   - **참조 실패**: 명시 주체가 조상에서 사라지거나 요구 키를 제공하지 않으면 다른 조상으로 자동 대체하지 않는다. 새 작성·이동·삭제 명령은 전체 변경 후의 참조 무결성을 검사해 거부하고, 외부 입력에 남은 잘못된 참조는 「상태 연결 안 됨」 으로 진단하며 조건 전체를 false 로 판정한다 (부정 조건도 true 로 뒤집지 않는다).
   - **조건**: 고정 목록 — `isSelected` · `isIndeterminate` · `isExpanded` · `isInvalid` · `isDisabled` · `isReadOnly` · `isRequired` · `isPressed` · `isHovered` · `isFocusVisible` · `isOpen` · `isCurrent` · `hasSubmenu` · `allowsRemoving` · `allowsSorting` (뒤 4개는 G0 ④-1b — 레퍼런스의 Breadcrumb 구분 아이콘 · MenuItem submenu chevron · Tag 지우기 Button · Column 정렬 표시가 쓴다). 형식은 `{ all: [조건, …], from?: 주체참조 }` 이며 조건은 `isX`, `{ not: "isX" }` 또는 같은 조건에 `from` 을 붙인 `{ key: "isX", from: 주체참조 }` / `{ not: "isX", from: 주체참조 }` 다. 조건별 `from` 이 전체 `from` 보다 우선하고, 둘 다 없으면 키별 기본 탐색을 한다. 한 조건식에 바깥 Checkbox 의 선택 상태와 안쪽 Button 의 pressed 상태를 같이 쓸 수 있다. 조건은 3개 이하이고 `any` · 중첩 · 임의 표현식은 없다. 체크 아이콘 = `{ all: ["isSelected", { not: "isIndeterminate" }] }`, 가로선 = `{ all: ["isIndeterminate"] }`. 노드별 조건은 독립이다.
   - **값의 비어 있음 — 바인딩은 노드를 없애지 않는다**: Decision 12 의 값 바인딩은 텍스트·속성 값만 치환한다. 빈 값이라는 이유로 노드나 자식을 제거하지 않는다. 원본의 **선택적인 Label · Description 텍스트 부품(설명 역할의 `Text slot="description"` 포함)에만** 명시 `presentWhen: "nonEmptyText"` 를 선언해 기존 빈 label/description 생략을 보존한다 (상태 boolean인 `showWhen` 과 별개, 둘 다 있으면 모두 충족해야 표시). 판정값은 모든 텍스트 바인딩을 치환한 최종 문자열 `String(value ?? "")` 이며 길이 0만 빈 값이다. `0` · `false` · 공백은 각각 `"0"` · `"false"` · 공백으로 유지하고 trim 하지 않는다. 여러 바인딩과 리터럴이 섞이면 최종 텍스트 전체를 판정한다. 이 선언이 없으면 빈 텍스트도 노드를 유지한다. 자식 노드가 있으면 텍스트가 비어도 컨테이너를 유지하고 자식은 각자의 조건으로 판정한다. 필수 부품에는 이 값 존재 조건을 허용하지 않는다 (Decision 5). Phase 2 전에 이 제한된 존재 계약을 넣는다.
   - **FieldError는 별도**: authored `errorMessage` 가 비어도 **FieldError 노드를 마운트**하고 빈 children을 `undefined` 로 전달해 RAC의 `validationErrors` 기본 문구를 보존한다 (`domBinding.tsx:642-648`, `FieldError.mjs:21-41`). FieldError에는 `presentWhen` 을 적용하지 않는다. Preview 의 invalid 여부·최종 문구는 RAC가 결정한다. Canvas도 동일한 비교 상태의 `isInvalid` 와 유효 메시지 (명시 문구가 있으면 그것, 없으면 해당 상태의 validationErrors)를 받아 존재를 판정하며, 문서의 빈 errorMessage만으로 숨기지 않는다. G2는 빈 사용자 문구 + 실제 validation 오류의 양쪽 상태를 비교한다. 아이콘 자식이 있는 증감 Button 등 다른 부품에는 텍스트 값에 따른 자동 생략을 적용하지 않는다.
   - **거짓일 때**: DOM 에 없고 레이아웃 자리도 없다 (`catalogHiddenAtRest` 와 같은 처리). 자리를 남기려면 사용자가 상태마다 다른 노드를 둔다.
   - **Canvas 판정**: 주체의 유효 상태 = displayState (Components page 상태 칸 · 상태 변형 원본) + 파생 값 (`X/presence.ts` `derivedProps` — `_isSelected` · `isExpanded` …). hover · pressed · focus-visible 은 Preview 만 (ADR-230 과 같은 경계). G0 ④ 가 조건 × 파생 값 표를 고정한다.
8. **catalog 에 없는 RAC 부품 (F11)** 을 레퍼런스 예제가 쓰는 만큼 추가한다 — Autocomplete · Group · OverlayArrow · SelectionIndicator · SubmenuTrigger · SliderFill · CheckboxField · CheckboxButton · SwitchField · SwitchButton · RadioField · RadioButton · CalendarHeading · CalendarMonthPicker · CalendarYearPicker · TreeItemContent · Keyboard. CalendarMonthPicker · CalendarYearPicker 는 2026-10-09 사용자 지시로 Phase 9 에 추가한 부품이다. TokenField · NavigationTree · PreviewTrigger 는 G0 목록에서 쓰임이 확인될 때만.
9. **Card 를 S2 구조로**: `Card > CardPreview + Content (Text[slot=title] + Text[slot=description] + 자유 내용) + Footer (자유 내용)`. CardHeader 를 없앤다 (사용자 결정 2026-09-29 「ADR-248 완료 뒤」 — ADR-248 은 2026-10-05 Implemented). ADR-240 이 「영역별 새 type (RSP 식)」 을 유지보수 부담으로 기각했으나, 그 부담의 근거였던 영역별 renderer 가 Decision 2 로 사라지므로 이 ADR 이 그 기각을 뒤집는다.
10. **저장 포맷**: template 이 바뀌는 병합마다 contract +1, 옛 문서 거부, 변환 0 (ADR-253 Decision 9 와 같다 — 사용자 확인 1).
11. **완료 판정 = 레퍼런스 예제 재현**: G0 에서 확정하는 예제 세트 (코드 · 레퍼런스 조회일 · 설치 RAC 버전 · 비교할 상태 목록 · Builder 조립 절차) 를 Builder 의 UI 만으로 만들고, 저장 뒤 다시 열어도 구조 · slot · 표시 조건이 같고, Preview DOM 이 예제를 설치 RAC 로 마운트한 DOM 과 **구조가 같다**: 요소 종류 (태그) · 부모 - 자식 관계 · 형제 순서 · 텍스트 · `slot` · role 과 aria 속성 · aria 연결 (`aria-labelledby` · `aria-describedby` · `aria-controls` 가 가리키는 요소가 같은 자리). 제외하는 차이: 자동 생성 id 값 · `data-catalog-id` · `data-*` 식별 속성 · class 이름 · inline style. 이 구조 비교는 Canvas ↔ Preview 시각 비교 (G3 수치) 와 별개로 둘 다 통과해야 한다. RAC 에 없는 S2 컴포넌트는 `@react-spectrum/s2` 를 테스트 전용 devDependency 로 마운트한 DOM 이 기준값이다 (번들 영향 0 — 테스트 밖 import 0 을 정적으로 고정).
12. **부모의 계산 값을 자식에게**: RAC render props 가 주는 값 (ProgressBar · Meter 의 `percentage` · `valueText`, Slider 의 `state` 값, Calendar 의 `formattedDate`, DateSegment 의 `text` · `placeholder`, Tab 의 `isSelected` …) 은 자식 노드가 template 바인딩 `{percentage}` · `{valueText}` 로 글자 · 시각 속성 (`width: {percentage}%`) 에 받는다 — 같은 `{key}` 바인딩 (ADR-254 Decision 5) 의 기존 composite accepts 출처는 유지하고, render props 출처를 선택한 바인딩은 Decision 7의 키별 주체 탐색·명시 주소 참조를 사용한다. 바인딩 값의 치환은 노드 존재 여부를 바꾸지 않는다. Preview 는 render props 값으로, Canvas 는 파생 값 (`derivedProps` — Progress track 의 `value` 가 선례) 으로 푼다. 주체별 값 목록은 G0 ④ 표에 같이 둔다. 이것으로 부모 renderer 를 지워도 채움 · 값 글자가 같은 결과를 낸다.
13. **반복 부품 template**: RAC 가 항목 데이터를 스스로 만드는 collection (CalendarGrid 의 날짜 칸 `CalendarCell`, DateInput 의 조각 `DateSegment`, CalendarGridHeader 의 요일 칸) 은 노드 하나를 **반복 template** 으로 둔다 — Preview 는 RAC 의 children 함수가 항목마다 그 template 의 노드 트리를 그리고 (Decision 12 의 값 바인딩으로 `{formattedDate}` · `{text}`), Canvas 는 지금처럼 grid · segment 를 그리되 칸의 모양을 template 노드의 rule · 자식에서 읽는다. 데이터 생성은 RAC 내부 그대로 (D1). 이것이 없으면 칸 안에 내용을 더하는 레퍼런스 조립 (Calendar 예제의 칸 안 표시) 이 안 된다. Phase 9 의 G2 가 통과하지 못하면 「반복 template 없음」 을 이 ADR 의 명시 제한으로 남긴다.
14. **Calendar 표시 기간과 월·연도 선택** (2026-10-09 사용자 지시 · Round 24 수리): Calendar · RangeCalendar 는 `CalendarMonthPicker` · `CalendarYearPicker` 아래 Select 를 노드로 조립해 표시할 월·연도를 바꾼다. RAC 가 제공하는 항목 · 현재 값 · 변경 callback · 접근성 속성을 runtime 에서 연결하며 문서에 함수를 저장하지 않는다. 레퍼런스 Display options 의 조작 패널 prop 4개 — `visibleDuration` · `pageBehavior` · `firstDayOfWeek` · `weeksInMonth` — 를 Properties 에서 작성한다. 표시 기간의 정본은 `visibleDuration` 이고, 양의 정수 수량과 Day · Week · Month Select 를 조합해 `{days: N}` · `{weeks: N}` · `{months: N}` 중 하나를 설정한다 (기본 `{months: 1}`). 저장 값은 임의 객체가 아니라 전용 `calendar-duration` 계약으로 다룬다. 단위 키 하나와 양의 안전 정수만 허용하며, Inspector kind → typed accepts/default 생성 → authored/resolved 값 타입 → 문서·graph·library 검증을 함께 확장한다. 이 확장은 UI 전환보다 선행하고 명령·history·저장/로드 경로에서 같은 객체를 보존한다. `firstDayOfWeek` · `weeksInMonth` 는 기존 scalar kind 이고 미설정 = locale. 현재 월 전용 `maxVisibleMonths` 표면을 이 계약으로 전환한다 — DatePicker · DateRangePicker 의 `maxVisibleMonths` 는 삭제하고, picker 안 Calendar 의 소유는 RAC calendar context 와 같다 (`firstDayOfWeek` · `pageBehavior` = picker, `visibleDuration` · `weeksInMonth` = 안 Calendar 노드). 여러 달은 레퍼런스 starter 처럼 한 달 블록 (`CalendarMonth` — `div.month`, RAC 구조 밖 · prop 0) 을 반복 template 으로 두어 months 수만큼 그리고, 블록마다 CalendarHeading · CalendarGrid 의 offset 을 runtime 이 준다 (previous 는 첫 블록 · next 는 마지막 블록 — `showWhen`). Canvas · Preview 모두 같은 날짜 기간 · 블록 수 · pagination 을 소비하며, 표시 기간 변경은 날짜 선택 방식이나 선택 값을 바꾸지 않는다. Preview 실행 중 보기 전환은 레퍼런스에 없어 범위 밖이다. [공식 Month and year pickers](https://react-aria.adobe.com/Calendar#month-and-year-pickers) · [Display options](https://react-aria.adobe.com/Calendar#display-options) 가 기준이며, 구현 범위와 완료 기준은 breakdown §3-1 에 둔다.

> 구현 상세: [256-rac-composition-level-breakdown.md](design/256-rac-composition-level-breakdown.md)

**위험 수용 근거**: 기술 H 는 family 단위 Phase 와 Phase 별 후퇴안 (그 family 만 옛 renderer) 으로 한 family 범위로 묶는다. ADR-253 이 field 부품에서 같은 전환 (부품을 자기 binding 으로 RAC context 안에 그림) 을 이미 했으므로 경로는 검증돼 있다 — 남은 것은 배치를 shared 컴포넌트에서 노드 순서로 옮기는 것이다. 마이그레이션 H 는 보존 대상 프로젝트 0 이 전제다.

**기각 사유**

- A: slot 을 「자유 내용」 이라 선언해도 Preview 가 그리지 않으면 중첩 규칙이 다시 막는다 (F5 · F6). 목표 미달이고, 그 선언은 B 에서 그대로 다시 쓰이므로 먼저 할 이유가 없다.
- C: 덧붙인 요소가 RAC context 밖이라 접근성 · 상태 연결이 끊긴다 (D1). 자유도는 RAC 조립이 아니다.
- D: 우리가 고른 자리만 열리고 RSP 에 없는 prop 이 생긴다 (D2 위반). Plasmic 의 `allowedComponents` 는 code component 작성자가 자기 컴포넌트를 선언하는 방식이라, RAC 부품 자체를 조립하는 우리 목표와 다르다.

## Consequences

### Positive

- 빌더로 만들 수 있는 구조가 RAC 예제와 같아진다 — field 안의 아이콘 · 버튼, 항목 안의 두 줄 글자와 Avatar, Popover 안의 Autocomplete, Dialog 의 닫기 버튼 slot.
- 「넣을 수 있는가」 의 판정이 하나가 된다 — slot 25자리 손 지정 · 5종 목록 · renderer 한계 표가 RAC children 종류 하나로.
- Preview 의 컴포넌트별 renderer 가 준다 — 그리기 경로가 하나라 새 RAC 부품 추가 비용이 binding 과 rule 하나다.
- Card 가 S2 구조가 되고 CardHeader 가 사라진다.

### Negative

- template 대부분과 G3 승인 기록 · 테스트 경로를 다시 쓴다. 옛 개발용 프로젝트는 열리지 않는다.
- 노드 수가 늘어 해석 비용이 는다 (G4 에서 상한 관리).
- 자유 조립을 열면 사용자가 RAC 가 의도하지 않은 조합도 만들 수 있다 — 필수 부품 외의 조합은 RAC 와 같이 허용한다 (RAC 도 막지 않는다).

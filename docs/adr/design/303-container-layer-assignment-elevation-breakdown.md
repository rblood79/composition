# ADR-303 Design Breakdown — 컨테이너 배경 층 배정 · 떠 있는 요소의 그림자 · 테두리 · `{color.container}` 상속

> 본문: [303-container-layer-assignment-elevation.md](../303-container-layer-assignment-elevation.md). 구현 상세 (Phase · 파일 · 게이트 절차) 는 여기가 정본이다. 숫자는 2026-11-08 설계 시점 실측이며 Phase 0 이 다시 재서 freeze 한다.

## 1. 전제 lock-in (fork 4 질문 — adr-writing.md §ADR Fork)

1. **base / 응용**: [ADR-302](../completed/302-theme-color-two-axis-spectrum-ladders.md) 가 base (층 **토큰의 값** — pasteboard · layer-2 재분류 · elevated · popover-outline alias · 모드별 단), 이 ADR 이 응용 (그 토큰을 **어느 컴포넌트가 어느 자리에 쓰는가** + 자식이 컨테이너를 따르는 파생 참조). 302 가 선행이다.
2. **schema 직교성**: 302 는 resolver 출력 (snapshot 의 역할 → hex) 이고, 이 ADR 은 rule 값 (`backgroundColor` · `boxShadow` · `borderColor` 의 TokenRef) 과 파생 prop (`_containerLayer`) 이다. 저장 스키마는 둘 다 0 — 직교한다. `{color.container}` 는 snapshot 키가 아니라 rule 값 언어의 alias 라 302 의 172 키 표에 들어가지 않는다.
3. **선행 ADR 전제 reverse 검증**: 302 본문 · breakdown 을 `Card` · `Modal` · `Popover` · `boxShadow` · `container` 로 grep — 배정 · 그림자 · 상속에 대한 결정이 없다 (302 는 「rule 참조 이름 무변경 + status 66 · raised 7 재분류」 만). 반대로 이 ADR 은 302 의 `layer-2` 값 · `popover-outline` alias 없이는 G1 fixture 를 쓸 수 없다. 의존 방향 302 → 303 이 맞고, 303 → 302 역방향 의존은 없다.
4. **판독 전 전제**: 위 세 줄이 여기 있으므로 판독 (phase 당 1 + 수리 1) 은 본문 정합만 본다. 사용자 confirm = 2026-11-08 `/create-adr` 요청 (302 와 합치지 않는다는 답 뒤).

### 2c. 기준선 · 측정 5-질문 (measurement-validity §1)

- **Q1 출처**: fixture 는 설치 S2 소스에서 생성기가 뽑는다 (외부). before/after diff 는 기본 테마 (blue · neutral) × light/dark 의 resolver 출력 + rule 값 — 사용자 문서가 아니라 rule 자체.
- **Q2 불리 케이스**: `{color.container}` 는 중첩 (Popover 안 Card 안 Tag) · 컨테이너 없는 루트 · Frame 임의 hex 배경 · Portal 로 옮겨진 Popover 를 parity 에 넣는다.
- **Q3 대조군**: before = HEAD (302 종결 커밋) 의 생성 CSS · Canvas 스냅샷, after = Phase 1 · 2 — 같은 문서 · 같은 뷰포트.
- **Q4 소비 경로**: `--container-bg` 는 컨테이너 **노드** 의 inline style (`domBinding.runtime.ts` `authoredStyle` `:3369` — 호출처 `:891 · :1790 · :1807 · :2486`, Frame 의 사용자 배경이 DOM 에 닿는 경로) 이 쓰고 자식의 `var(--container-bg, var(--bg))` 가 읽는다. 생성 CSS 는 관여하지 않는다 — Frame 은 `skipCSSGeneration: true` 라 정적 CSS 로 노드별 층을 구분할 수 없다 (리뷰 h2). Canvas 는 `presence.ts` 파생 → `rulePaint.ts` → `resolveCatalogPaint` 순서를 단위로 확인한다.
- **Q5 oracle 독립성**: G1 은 S2 소스 (외부), G2 는 Canvas 픽셀 ↔ DOM `getComputedStyle` (서로 다른 consumer — 한쪽이 다른 쪽의 재생성이 아니다).
- **번들 기준선**: 302 종결 커밋에서 `adr201-bundle-gate.mjs` 로 Builder · Preview initial gz 를 재고 여유를 G0 표에 적는다 (설계 시점: 302 전 Preview 여유 1,090 B · 302 ≤ +256 B → ≤ 834 B 예상).

## 3. `{color.container}` 설계

### 3a. 판정 함수 하나

- `packages/shared/src/catalog/runtime/containerLayer.ts` (신설) — `containerLayerOf(node, resolved): LayerRole | undefined`. 「컨테이너」 = rule 의 `paint.backgroundColor` 가 층 역할 (`base` · `layer-1` · `layer-2` · `elevated` · `pasteboard`) 로 풀리는 노드 (Popover · Modal · Card · Table · Dialog · Sheet · 층 토큰을 배경으로 가진 Frame). 임의 hex 배경은 컨테이너가 아니다 (층만 상속).
- Canvas: `presence.ts` 의 조상 파생 (`:2416` `_inPopover` 와 같은 자리) 에 `_containerLayer` 추가 — 가장 가까운 컨테이너 조상의 역할 이름. `resolveCatalogPaint` 는 `{color.container}` 를 만나면 `props._containerLayer ?? "base"` 의 snapshot hex.
- DOM: 컨테이너 **노드** 의 inline style 에 `--container-bg` 를 쓴다 (`authoredStyle` `:3369` — rule 컨테이너 · Frame 둘 다). 값은 `COLOR_TOKEN_TO_CSS[containerLayerOf(node)]` 조회 — 기존 등록 이름 그대로: base `var(--bg)` · layer-1 `var(--bg-overlay)` · layer-2 `var(--bg-inset)` · elevated `var(--bg-elevated)` (`tokenResolver.ts:222 ~ :238`) · pasteboard 는 302 가 등록하는 이름. 손으로 쓴 변수 이름은 0 (미등록 변수는 선언 전체를 무효로 만든다 — 리뷰 h3). `tokenToCSSVar` 가 `{color.container}` → `var(--container-bg, var(--bg))`. 정적 생성 CSS 는 선언하지 않는다 (리뷰 h2).
- Popover 는 RAC Portal 이라 DOM 조상이 `body` 지만 Popover **자신이** 컨테이너라 자식 (Menu · ListBox) 은 둘 다 layer-2 — R3 의 대표 케이스.

## 5. 열어 둔 것 (이 ADR 밖)

- **편집 · 탐색 맥락** (Hub background-layers · app-frame) — 페이지 성격에 따른 층 배정 두 벌. Page 스키마가 필요해 대안 D 로 기각. 사용자 페이지는 탐색 맥락 고정, 편집 맥락은 Builder chrome (D3 밖).
- **주목 위계 (attention-hierarchy · containers)** — 「한 페이지에 강조 컨테이너 한 묶음 · accent 채움 한 요소」 는 문서 검사 (빌더 린트) 후보. 토큰 · rule 로 강제할 수 없다.
- **`emphasized-hover` 그림자** — Hub 에는 있으나 S2 1.8.2 `createTheme` 에 토큰이 없다 (hover 는 `elevated`). S2 가 추가하면 ADR-166 토큰 4번째로.
- **ActionBar** — S2 `elevated` 배경 + 그림자 + outline. rule 이 없어 등록 (ADR-280 계열) 뒤 2a 에 추가.
- **Hub 두 색 조합 (two-tone 100 + 900)** — 아이콘 · 일러스트 배경 규칙. `*-subtle` (200|300) 과 다른 개념, 아이콘 ADR 대상.

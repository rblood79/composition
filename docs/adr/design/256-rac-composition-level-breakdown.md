# ADR-256 breakdown — RAC 수준의 조립

> 본문: [ADR-256](../256-rac-composition-level.md). 이 문서는 Phase · 파일 경계 · 순서 · 시작 인벤토리를 둔다. 결정은 본문이 정본이다.

경로 약어: `S/` = `packages/shared/src/` · `D/` = `S/catalog/document/` · `X/` = `S/catalog/runtime/` · `R/` = `apps/builder/src/builder/catalogRuntime/` · `N` = `S/catalog/nesting/nestingRules.ts`

## 1. 전제 점검 (ADR 작성 규칙 4 질문)

1. **base / 응용**: 이 ADR 은 ADR-253 (부품 = 원본 instance, 부품을 자기 binding 으로 RAC context 안에 그림) 의 응용이 아니라 그 일반화다. 253 이 field 부품의 「그리기」 를 노드로 옮겼고, 이 ADR 은 「배치 · 넣기 판정」 까지 노드 트리로 옮긴다. 253 의 결정은 그대로 유효하다 (뒤집지 않는다).
2. **schema 직교성**: children 종류·consumer context 제공자 표는 코드 특성 표다. 문서에는 `showWhen`과 주체 참조, 선택적 텍스트 부품의 `presentWhen: "nonEmptyText"`, slot의 미지정/이름/명시 null 구분을 저장한다. 값 바인딩은 노드 존재를 바꾸지 않으며 기존 `slotFills` · `descendantOverrides` 주소 경로를 보존한다.
3. **선행 전제 재검증**: ADR-240 의 「영역별 새 type 기각」 은 영역별 renderer 비용이 근거였다 — Decision 2 로 그 비용이 사라지므로 Card 에서 뒤집는다 (본문 Decision 9). ADR-251 의 RadioItems · CheckboxItems 묶음 노드는 RAC 구조 밖 (`div.radio-items`) 이다 — G0 ⑦ 판정: **유지**. 레퍼런스 RadioGroup · CheckboxGroup 예제가 같은 `div.radio-items` · `div.checkbox-items` 로 항목을 묶는다 (처음 이 문장의 「레퍼런스 예제에는 없으므로」 는 틀렸다).
4. **판독 시점**: Phase 0 인벤토리 고정 뒤 판독 1회 (전제 · 범위), 각 Phase 는 판독 1 + 수리 검증 1 (`.claude/rules/review-loop-closure.md`).

## 1-1. 상태 주체 주소와 제한된 존재 조건 (round 3 수리)

- `from: { type: T }`는 해당 조건 키를 주는 T 타입 중 가장 가까운 조상이다. 같은 type의 더 바깥 조상은 `from: { ancestor: StateOwnerRef }`로 선택한다. UI는 조상 경로를 표시하지만 저장값은 이름/순번이 아닌 주소다.
- `StateOwnerRef`의 page 작성 노드는 `{ nodeId: NodeId }`, instance 하위 노드는 `{ address: InstanceAddress }`를 사용한다. 원본 template 안에서는 `{ local: { instances: TemplateId[], templatePath: TemplateId[] } }`로 저장한다. local 주소는 그 원본의 template root를 기준으로 하며, instances는 중첩 instance template 노드 경로, templatePath는 마지막 원본 안 root-to-target 경로다. 사용 시 현재 원본 instance의 주소 prefix를 붙인다. 반복 template 안의 local 참조는 현재 반복 항목의 주체로 해석하며 동적 항목 키를 저장 주소로 고정하지 않는다. 라이브러리 원본에 프로젝트 NodeId를 박거나 파생 런타임 id를 저장하지 않는다.
- 원본 instance를 복제해도 local 참조는 복제된 instance 안의 동일 조상을 가리킨다. 프로젝트 서브트리 복사 시 복사 범위 안 node/address 참조는 복사 ID map으로 함께 바꾼다. 외부 참조는 원래 주소를 유지하되 새 위치에서도 실제 조상이어야 한다. wrapper 삽입 등 조상 정체성을 유지하는 편집은 같은 transaction에서 주소 경로를 갱신한다. 대상 소실/비조상/키 미지원은 대체 탐색 없이 명령을 거부한다. 저장·undo/redo·재열기는 이 참조를 보존한다.
- 조건별 `from`이 전체 `from`보다 우선한다. 동일 type 중첩 및 서로 다른 키의 주체 조합을 Phase 4에서 검증한다. 참조가 잘못된 외부 입력은 조건 전체 false와 상태 연결 진단으로 처리한다.
- `presentWhen`은 원본에서 선택적인 텍스트 Label/Description(설명 역할 Text 포함)에만 명시한다. 전체 바인딩 치환 후 텍스트 `String(value ?? "")`의 길이를 판정하고, 자식 노드가 있으면 컨테이너를 유지한다. FieldError·필수 부품에는 적용하지 않는다. 값 치환 자체는 모든 부품을 유지한다. Phase 2 앞부분에서 이 계약을 구현하고 FieldError의 undefined children → RAC validationErrors 경로를 유지한다.

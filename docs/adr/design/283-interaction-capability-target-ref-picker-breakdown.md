# ADR-283 design breakdown — capability 대상 참조 · 실행 record 기준 해소 · 검색 선택기 · Canvas 지정

> 본문: [../283-interaction-capability-target-ref-picker.md](../283-interaction-capability-target-ref-picker.md). 이 문서가 Phase · 파일 · 검증의 정본이다. `docs/adr/evidence/` 는 로컬 전용이라 실측 결론은 여기에 둔다. 시안: [Design artifact](https://claude.ai/artifact/QhLirtifNa4oLdWSrFHFxz) (① 검색 선택기 · ② Canvas 지정 · ③ 기능 변경 안내 · ④ 현재 목록).

## 0. 전제 lock-in (분리 아님 — ADR-281 모양의 적용)

1. **base / 응용**: [ADR-248](../completed/248-unified-catalog-document.md) (`InstanceAddress` · `CatalogStateOwnerRef` 세 모양) → [ADR-280](../280-interactions-rac-surface-registry-controlled-runtime.md) (등록표 · dispatcher) → [ADR-281](../281-interactions-panel-vocabulary-inheritance-form-destination.md) (규칙 **주인** 쪽의 instance 주소 · `recordsOfOwner` · `effectiveInteractionsOf`) 가 base. 이 ADR 은 같은 주소 모양을 규칙 **대상** 쪽에 적용하는 응용 — 의존 방향 248 → 280 → 281 → 283.
2. **schema**: capability action `targetId: NodeId` → `target: CatalogNodeRef | { unset: true }` (`{ nodeId } | { address } | { local }` — `CatalogStateOwnerRef.ancestor` 에서 꺼낸 공용 타입 · `unset` 은 자리가 사라진 규칙의 저장 모양, capability 전용). `LIBRARY_CONTRACT_VERSION` 48 → 49, 변환 0. 그 밖 `InteractionEntry` 무변경.
3. **리뷰 Round 1 (2026-10-25) 반영**: 해소 비교 단위 = 반복 조상 record (`parentId` 체인, 경로 문자열 아님) · 색인 = 주소의 모든 project id · 복사 = 세 모양 모두 재매핑 · `unset` 모양. 상세는 본문 Decision 1 ~ 3 · [../reviews/283.md](../reviews/283.md).
4. **선행 전제 reverse 검증**: 281 이 주인 쪽에 address 층을 둔 사유 (instance 마다 다른 record · 끄기 · 바꾸기) 는 대상 쪽에도 같다 — 대상도 instance 마다 다른 record 다. dispatcher 는 record id 를 받으므로 (`dispatcher.ts:598`) 해소가 Preview 변환 층에서 끝나면 280 · 281 코드는 바뀌지 않는다.
5. **판독**: 사용자가 요청할 때 `/review-adr 283`.

### 1b. 해소 설계 — 반복 조상 record (R5 · 리뷰 H1)

**사실**: 소유 자식 record 의 `instancePath` 는 자기 id 로 끝난다 (`resolution/resolver.ts:1427-1429`) — 같은 행의 Delete `[…, row, delete]` 와 Text `[…, row, target]` 는 경로가 다르다. instance 안 template 노드 record 의 path 만 instance 사슬이다 (`compositionRoot.ts:3980`). 따라서 「경로 전체 일치」 는 같은 행 형제를 전부 탈락시킨다 (리뷰 probe: 3 행 투영에서 0 개).

**`resolveCapabilityTarget(root, firingRecordId, ref)`**:

1. 후보 = 참조가 가리키는 source 의 record 전부 — `nodeId` 는 `recordsOfSource(nodeId)` · `address` · `local` 은 `recordsOfSource(templatePath.at(-1))`. `unset` → `undefined` + `TARGET_UNSET`.
2. 이름 붙인 instance 사슬로 좁힌다 — `address`: `recordsOfOwner` (`catalogPreviewInteractions.ts:66-70`) 의 instancePath tail 비교를 helper 로 꺼내 `instances` 와 · `local`: 실행 record 의 `instancePath` (template record 면 instance 사슬) 에 `local.instances` 를 이은 사슬과 tail 비교 · `nodeId`: 0.
3. **반복 조상**: record R 의 `parentId` 체인 (`compositionRoot.ts:226 · 815`) 에서 `rowIndex !== undefined` 인 행 record 와 source 가 instance 노드 (`definitionId` 있음) 인 instance 루트 record 를 모은 집합 `repeaters(R)`. 후보 T 가 남으려면 `repeaters(T) \ named(ref, T)` 가 모두 `ancestorsOrSelf(firing)` 에 있어야 한다 — **세 모양 같은 식, 면제 없음**. `named(ref, T)` = `repeaters(T)` 중 instance 루트 record 이고 source 가 `address.instances` 또는 `local.instances` 에 든 것 (`nodeId` 는 ∅). 행 record 는 어느 모양도 이름 붙이지 않는다 → 항상 공유 검사. **Why**: 행 반복은 record identity 의 `#row:<key>` (`compositionRoot.ts:494-498` · `resolver.ts:260-267` `withRowKey`) 에만 있고 `instancePath` 는 행마다 같다 — Local 컴포넌트를 행 template 으로 3 번 반복하면 `local` 후보 3 이 step 2 를 전부 통과한다 (리뷰 Round 2 probe). 행 조상 identity 비교 뒤 1.
4. 남은 후보 1 → 그것 · 0 → `undefined` + `TARGET_OUT_OF_CONTEXT` · 2+ → 테스트가 단언하는 설계 위반.

**Phase 0 에서 잴 것**: record 종류별 (page 노드 · 행 record · 행 자손 · instance 루트 · template 노드 · overlay 본체 · 열린 목록 · portal) `parentId` 체인이 행 record · instance 루트 record 에 닿는지 표 (`:1618` `tagRows` · `catalogPreviewSession.ts:1385` 의 「record on the chain」 패턴 참고). 닿지 않는 종류가 있으면 Phase 1 에서 그 record 에 조상 표지를 더한다 — 「record 하나일 때만」 폴백은 쓰지 않는다.

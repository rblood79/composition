# ADR-217 Design Breakdown — Chart 기준선 (ReferenceLine) · 산점도 (Scatter)

> 상위: [ADR-217](../217-chart-reference-line-scatter.md) · Proposed 2026-09-12 · 선행: [ADR-194](../completed/194-chart-component-headless-geometry.md) (기하 SSOT) · [ADR-211](../completed/211-chart-display-budget-pixel-fit-window-decimation.md) (표시 예산 · 창) · [ADR-216](../completed/216-chart-time-axis-format-window.md) (연속 x 스케일 `positions` · `resolveCategoryBand`). D2 원천: react-spectrum-charts `vega-spec-builder` (`ReferenceLine` · `Scatter`, 2026-09-12 shallow clone 정독 — 인용은 파일:줄).

## 1. 범위 · 선행 관계 (분리 4질문 lock-in)

- **범위**: (A) 값 축 기준선 — `referenceLines[]` (RSC `ReferenceLine`: `value` · `label` · `lineType` · `layer`) 를 scene 이 `LineMark role:"reference"` + 라벨 `TextMark` 로 낸다, domain 은 scene 이 넓힌다 (두 leg 같은 눈금). (B) 새 `chartType:"scatter"` — 행 = 점 (같은 x 합산 없음), x = 숫자 (`dimensionScale` 미설정 = `linear`) 또는 `time` (216 재사용), 마크 = 시리즈당 점 path 1개 (`buildDotMarks`), 예산 = 211 (window · extrema), DOM = Recharts `ScatterChart` + `Scatter`.
- **범위 밖**: 산점도 반투명 점 (두 leg 합성 단위가 다르다 — round 1 m3; line `showDots` 의 같은 차이는 기존 LOW deferred) · 밀도 표현 (binning) · 범주/시간 축 위의 세로 기준선 (RSC `position` before/after/center — band 전용; "오늘" 선은 후속) · `ReferenceArea`/`ReferenceDot` · 기준선 아이콘 (RSC `icon`) · Scatter `size` 매핑 (버블 — RSC `SymbolSizeFacet`) · `ScatterPath`/`Trendline`/`ScatterAnnotation` · Scatter 의 `colorScaleType:"linear"` (연속 색) · bar 의 `linear` 스케일 · Skia 상호작용.
- **분리 4질문** (adr-writing.md §Fork): (1) base/응용 — 194 (기하 SSOT) · 211 (예산) · 216 (`positions` + `resolveCategoryBand`) 이 base, 본 ADR 은 그 위의 응용 두 가지 (마크 종류 1 + 장식 마크 1). 역방향 의존 없음 — 216 의 `positionBand` 는 이미 "epoch" 가 아니라 "숫자 위치" 로 쓰여 있어 (`timeAxis.ts positionBand(positions, scale)`) scatter 의 linear x 가 그대로 탄다. (2) schema — 새 저장 props 는 `referenceLines?` (객체 배열, `seriesConfig` 와 같은 `items-manager` kind — `Chart.binding.ts:104-116` 선례) 와 `chartType` enum 값 1 (`scatter`) 뿐. 210 `seriesConfig` · 211 `budget*` · 216 `dimension*` 을 specialization 하지 않는다 — 다만 `dimensionScale` 의 **해석** 이 scatter 에서 달라진다 (§2.3: 미설정/`category` = `linear`). 직교. (3) 선행 전제 reverse — 216 이 "시간축은 line/area 만" 으로 `time` 을 막은 것은 bar 가 band 여서였다 (`presentation.ts:585-612`); scatter 는 연속 x 가 본질이라 그 거부 목록에 **넣지 않고** 허용 목록에 넣는다 — 216 의 결정 자체 (bar 거부) 는 유지. 211 의 "R7 신규 chartType 은 컴파일 오류로 잡는다" (`computeChartScene.ts:479-483 assertNever` · `budget.ts:174-177 throw`) 가 본 ADR 의 첫 RED 다. (4) 3차 리뷰까지 미루지 않음 — round 1 에 낸다. **사용자 confirm**: 2026-09-12 ADR-216 create-adr 의 AskUserQuestion 에서 사용자가 "ReferenceLine · Scatter 는 후속" 을 선택 ([216 breakdown §1](216-chart-time-axis-format-window-breakdown.md#1-범위--선행-관계-분리-4질문-lock-in)) + 2026-09-12 `/create-adr ReferenceLine·Scatter 후속` 직접 지시 (하나의 ADR — 사용자 지정). 종결 계약상 재질문하지 않는다.

### 2.2 기준선 (ReferenceLine)

- **props (D2)**: `referenceLines?: readonly ChartReferenceLine[]` — `{ value: number; label?: string; lineType?: "solid" | "dashed" | "dotted"; layer?: "back" | "front" }`. 기본 `lineType:"solid"` · `layer:"front"` (RSC 와 같다). 값 축 (metric) 전용 — bar/line/area/scatter (직교 4종). pie/radar/radial 은 진단 `referenceLines.unsupportedChartType` (radar 의 값 링 기준선은 후속). 개수 상한 4 (진단 `referenceLines.tooMany`) — 마크 2/개 (선 + 라벨) 로 M 에 영향 없음. `value` 비유한 → 진단 `referenceLines.invalid` (설정 오류 = 그리지 않음, 210 규약).
- **domain (RSC 와 다른 점, 명시)**: RSC 는 domain 을 넓히지 않아 범위 밖 기준선이 보이지 않는다. 우리는 `valueExtent` ∪ `{value}` 로 domain 을 넓힌 뒤 `niceTicks` — **scene 이 정한다** (`model.ts:247-251` 한 자리). expand (0–100) 는 값 단위가 정규화라 기준선도 0–100 으로 읽는다 (문서화). 두 leg 는 같은 `ticks.domain` 을 이미 읽으므로 (`RechartsChart.tsx:640-647`) Recharts `ReferenceLine`/`ifOverflow` 를 쓰지 않는다.
- **마크**: `LineMark { role: "reference", dash?: readonly number[] }` — dash 표: dashed `[6, 4]` · dotted `[2, 3]` (Skia `strokeDasharray` · DOM `stroke-dasharray` 같은 배열). 좌표: 세로 차트 `y = value(v)`, `x1 = plot.x`, `x2 = plot.x + plot.w`; 수평 차트는 x. 라벨 `TextMark { role: "reference", anchor: "end", baseline: "bottom" }` 를 선의 끝 (오른쪽/위) 안쪽에 `fontSize × 0.3` 띄워 둔다 — RSC 의 "축 위 라벨 + 눈금 숨김" 은 채택하지 않는다 (여백 재계산 + 충돌 규칙 2개가 늘고 Skia 대칭 비용만 크다; 라벨은 plot 안 (Recharts 관행) 이 값싸고 같은 그림). 색 `chart.reference` 토큰 → `--chart-reference` (기본 `{color.neutral}` = RSC gray-800 상당), 라벨은 같은 토큰. 순서: `layer:"back"` 은 grid 뒤에 (grid → back 기준선 → 마크), `front` 는 마크 뒤 축선 앞 — Skia 는 `skiaPrimitives.ts:3597-3600` 순서에 그대로 끼운다. **DOM (P0 spike 정정)**: pinned Recharts 3.10.1 은 `Customized` 를 자식 순서와 무관하게 **그래픽 항목보다 먼저** 렌더한다 (`adr217ScatterSpike.browser.test.tsx` — ScatterChart · LineChart 둘 다 `back, front, marks`; production 의 축선/tick `foreground` 도 사실은 마크 아래다). 따라서 `back` 은 `backdrop` Customized 에 얹고, `front` 는 Recharts svg 의 **형제 overlay `<svg class="chart-decoration-front">`** (같은 크기 · 같은 좌표계 · `pointer-events: none`, 창 트랙 host 와 같은 absolute 배치) 에 그린다 — 좌표는 scene 값 그대로라 byte 동일 (HC4). 축선/tick 을 overlay 로 옮기는 것은 범위 밖 (기존 동작 유지).
- **채널**: rule `chart.reference?` (spec.types `chart.reference?` + CSSGenerator `--chart-reference` + Skia `channel.reference` — 211 `others` 와 같은 3곳). fallback `CHART_REFERENCE_FALLBACK_TOKEN = "{color.neutral}"`.
- **패널**: `ChartReferenceLineControls.tsx` — items-manager 목록 (값 · 라벨 · 선 종류 · 층), Content 섹션 시간축 컨트롤 아래. 문자열 `chart.referenceLines` · `chart.referenceValue` · `chart.referenceLabel` · `chart.referenceLineType` · `chart.referenceLayer` + 옵션 라벨 (실선/파선/점선 · 뒤/앞) ko/en.

### 2.3 산점도 (Scatter)

- **모델**: `chartType:"scatter"` 는 직교 종류 (bar/line/area 와 같은 cartesian 분기). 격자 = **행 하나가 범주 하나** (`buildSeriesGrid` scatter 분기: key 합치기 없이 push — 같은 x 두 행 = 점 두 개), `positions[ci] = x`. x 파싱: `dimensionScale` `time` 이면 216 파서, 그 외 (`linear` = 미설정/`category`) 는 `toFiniteNumber` — 실패 행은 216 과 같은 정책 (범주 push 전 제외 + `dimension.parse.failed` 경고). x 정렬 오름차순 (`sortByPosition` 재사용 — 창/극값이 x 순서를 전제한다). 라벨 = x 표시 문자열 (linear 는 `formatValue` 계열 숫자 형식, time 은 216 라벨).
- **`dimensionScale` 해석**: scatter 에는 범주 스케일이 없다 — 미설정 (`toRacProps` 가 채우는 `"category"` 포함) = `linear`. chartType 전환은 `{chartType}` 만 patch 하므로 (`ChartAuthoringControls.tsx:60`) line → scatter 전환 문서가 오류 상태에 빠지지 않게 하는 유일한 길이다. 명시 `"category"` 와 미설정을 구분할 수 없으므로 (기본값 fill) `"linear"` 라는 새 enum 값은 **두지 않는다** — `ResolvedDimensionSettings.scale` 에 `"linear"` 를 더해 해석 결과만 셋으로 늘린다 (저장 값은 그대로 2). 패널 (`ChartTimeAxisControls`) 은 scatter 에서 옵션 라벨을 "숫자 / 시간" 으로 바꾼다.
- **스케일 · 축**: x = `linearScale(niceTicks(xmin, xmax).domain)` (linear) 또는 216 `timeScaleFor` (time) — `resolveCategoryBand` 에 linear 분기 1개 추가 (`model.linear?: { domain, ticks }` — 216 `model.time` 과 같은 자리, transformed 전체). x 축 눈금 = 값 축과 같은 `niceTicks` + `formatValue` (linear) · 216 2단 라벨 (time). `axisKind` 는 `"ordinal"` 고정 (216 과 같은 이유).
- **마크**: 시리즈당 `buildDotMarks(points, seriesIndex, dotRadius(strokeWidth))` 1개 — 선 없음, **불투명** (`PathMark.fillOpacity?: number` 신설, scatter 는 1 · 미지정 = 현행 0.85 — round 1 m3: Skia 의 path union 과 DOM 의 점별 합성은 반투명에서만 갈린다; RSC Scatter 기본 opacity 1), 값 라벨 (`showValueLabels`) 은 line 과 같은 `pointValueLabel`. `showDots` · `curve` 는 scatter 에서 휴면 (패널 숨김). 색 = 시리즈 (colorBy 휴면). `stackType` 휴면 (dodged 고정 — validator 가 stacked/expand 를 진단 `stackType.unsupportedChartType` 으로 거부하지 않고 **무시** 한다: 기존 문서 전환 시 조용히 깨지지 않게, 패널 숨김).
- **예산 (211 희소 계약 — round 1 h1, HC9)**: 산점도 격자는 희소하다 (점 하나 = 시리즈 하나의 값). 211 의 조밀 계수 (`S × |U|`) 와 집계 fallback 을 그대로 쓰면 600행 × 60시리즈 (600점 ≤ P) 가 7,200 으로 계수돼 집계로 떨어지고 x 가 bucket 첫 위치로 옮겨진다 (codex 반증). 산점도 계약:
  - **슬롯 = 점**: `slotFit(scatter) = P` (`pointBudget`) — 점은 겹쳐도 되므로 px 간격 제약이 없다. `markFactor(scatter)` = `labels` (값 라벨만; 점 path 는 시리즈당 1 = S ≤ M). `resolveFitEff(scatter)` 는 `min(fit, floor(M/(S·k)) if k>0, P)` — 관측점 수로 P 를 잰다 (`floor(P/S)` 아님).
  - **계수 = 실제 관측점**: `selectExtrema(grid, fitEff, k, budget, count = "dense" | "sparse")` — scatter 는 `sparse`: `pathPoints = Σ_series |values ∩ U|` (선택 index 안의 실제 값 수). line/area 는 기본 `dense` (현행 식 그대로 — HC1 byte 동일). 극값 선택 자체 (bucket · 시리즈별 min/max **원본 index**, gap 은 희소에서 무의미하므로 sparse 는 `gapI` 를 더하지 않는다) 는 원본 점만 남긴다.
  - **fallback = 솎기, 집계 0**: `sparse` 에서 B=1 까지 줄여도 넘치면 (`2·S > P`, 즉 시리즈 2,500 초과) `aggregateBuckets` 대신 **시리즈별 stride 솎기** (`thinSeries(grid, P)`: 각 시리즈의 점을 x 순서로 `ceil(size / floor(P/S))` 간격 샘플 — 원본 점) + 진단 `budget.thinned` (warning). 넓힌 창 재추출 (`budget.ts:870-873`) 도 scatter 는 같은 sparse 극값 → 솎기 순서. **모든 결과 `(x, y, series)` ⊆ 입력** — G2 소속 테스트 3 fixture (codex 600×60 → overflow 0 · 12,000×60 → 극값 ⊆ 입력 · 6,000 시리즈 × 2 → 솎기 ⊆ 입력 + 진단 1).
  - `defaultBudgetMode(scatter, ordinal)` = `extrema`, 지원 = window · extrema (aggregate/others 는 validator 거부). n > P 일 때만 overflow (창 길이 = P 점). rowCap 20k 그대로. 창 트랙 · thumb 2 는 216 그대로 (categories = x 순서 점).
- **DOM**: `ScatterChart` + 시리즈당 `<Scatter data={[{x, y}]} shape={PlainDot}>` (반지름 = `dotRadius`, **`fillOpacity 1`** — 불투명이라 점별 요소와 Skia 의 단일 path 가 겹친 자리에서 같은 픽셀; G3 합성 프로브) · `XAxis type="number" dataKey="x" domain={model.linear.domain | time.domain}` · `YAxis domain={ticks.domain}` · `backdrop`/`foreground` 그대로. 툴팁 = Recharts `Scatter` 의 점 단위 hover (D1 runtime) — content 는 기존 custom content 에 scatter payload 분기 (x 는 dimension 라벨, y 는 `formatValue`). Recharts `Scatter` 는 lazy `RechartsChart` 청크에만 든다 (initial 0 — G5 가 잰다).
- **Skia**: `PathMark.fillOpacity` 읽기 1줄 (`skiaPrimitives.ts:3551-3553` 의 고정 0.85 → `mark.fillOpacity ?? 0.85`) — 그 외 변경 0 (path 마크 · 축 텍스트 마크는 이미 소비한다). DOM `svgDecorations.tsx:79-83` 도 같은 기본값. 신규 chartType 은 `CHART_PRESENTATION_KEYS` 무관 (`chartType` 은 이미 읽는다).
- **저작**: descriptor `scatter` ("Scatter Chart", 아이콘 `ScatterChart` (lucide), 검색어 산점도/분포/점), defaults `{ showDots: true, showLegend: true }`, preset 없음. `createChartInitialProps("scatter")` 는 숫자 sample (`{ x, y, series }` 8행 — legacySample 은 범주라 전부 파싱 실패 → "No data" 가 된다) + `dimension:"x"` · `metric:"y"`. 패널: chartType 옵션 +1, `ChartDataMappingControls` 의 범주 라벨 = "X" (scatter), columns 모드 허용 (값 필드마다 시리즈 — y 여러 개), `ChartBudgetControls` 종류 목록 +1, `ChartSeriesControls` 무변경.

### 2.4 두 leg 대칭 검증

- 기준선: `chartParity` 에 (a) 값 축 domain 이 기준선으로 넓어진 눈금 문자열 (b) 기준선 `y` (c) 라벨 `x,y` 가 Skia scene 과 DOM `<line>`/`<text>` 속성에서 byte 동일 — 4 종류 × layer 2.
- 산점도: 점 path `d` (Skia `PathShape.d` = DOM `Scatter` 점 좌표 — DOM 은 Recharts 가 그리므로 `cx/cy` 를 scene 점과 대조, 216 `chartParity` +2 와 같은 방식) · x 축 눈금 문자열 · 창 초기 상태.
- 합성 (G3, round 1 m3 방법): 같은 시리즈 겹친 점 2 (`(4,40)` × 2) 를 Skia 캡처 (Compare Mode 전) 와 Preview 캡처에서 중심 픽셀 대조 — 불투명이면 두 값이 같다. 반투명 회귀 (기본 0.85 를 잘못 물려받음) 가 여기서 잡힌다.
- 소속 (G2, HC9): 결과 격자의 모든 `(positions[ci], values.get(ci), series.key)` 가 입력 행 집합에 있는지 (Set 대조) — 극값 · 솎기 · 넓힌 창 3 경로.
- 손계산 oracle (G2): 기준선 `value 120` 에 데이터 max 100 → domain `[0, 120]` (niceTicks 5) · `y = plot.y` (맨 위); 기준선 `value -20` 에 bar → domain `[-20, 100]`; scatter 5 점 `(1,10) (1,30) (2,20) (4,40) (4,40)` 1 시리즈 → categories 5 (합산 없음, 중복 점 2), positions `[1,1,2,4,4]`, x domain `[0, 4]` 또는 `[1, 4]` (niceTicks 규칙대로 손계산), 마크 subpath 5.

### 2.5 미지원 chartType 안전 경로 · 호환 · rollback 경계 (round 1 h2)

- **현재 사실**: 미지원 `chartType` 은 validator 가 아니라 `slotFit`/`markFactor` 의 `throw` 가 먼저 만난다 (`budget.ts:174-177` · `:200-201` — 모델 `computeChartScene.ts:325` 가 설정 오류 검사 `:351` 보다 앞). 두 leg 모두 catch 가 없어 `chartType:"scatter"` 문서는 **구버전 (현재 main 포함) 에서 캔버스 scene 빌드 · Preview 렌더가 중단** 된다 (codex 실측: 현재 소스 · 로컬 dist 둘 다 `Error: unhandled chartType: scatter`). 저장 데이터는 남는다 (canonical 은 그대로) — "설정 오류로 표시" 는 현재 코드에 없는 동작이다.
- **P1 = 안전 경로 commit (본 ADR 의 첫 코드 commit, scatter 이전)**: `resolveChartPresentation` 이 `chartType ∉ CHART_TYPES` (신설 상수 — `ChartType` 유니온과 같은 자리, 6 → 7) 를 진단 `chartType.unsupported` (error) 로 내고 `resolveChartModel` 은 `presentation.ok === false` 면 layout/budget 을 건너뛰어 (`slotFit`/`markFactor` 도달 0) 설정 오류 scene ("Check chart settings", `computeChartScene.ts:351` 경로) 을 반환한다 — `slotFit`/`markFactor` 의 default `throw` 는 남긴다 (도달 불가 = 방어선 유지). 두 leg 동일 (DOM 도 같은 모델). 테스트: `chartType:"scatter"` (아직 없는 종류) 문서 → 두 leg throw 0 + 설정 오류 scene; 6종 byte 동일.
- **rollback 경계**: 되돌림 대상 = **P1 commit 이후**. P1 이전 revision 으로 되돌리려면 scatter 차트를 먼저 다른 종류로 바꾼다 (패널 chartType 전환 → 산점도 전용 props 는 휴면 보존, `referenceLines` 는 무시됨). 이 절차와 "P1 이전은 지원하지 않는 경계" 를 ADR Status/CHANGELOG 에 기록한다. G3 T12 프로브 대상 = P1 dist (기준선 무시 · scatter 설정 오류 · 데이터 보존) — P1 이전 dist 의 예외는 사실로만 기록.
- `referenceLines` 는 구버전이 무시한다 (모르는 prop = passthrough 0) — 선 없이 렌더, 데이터 보존.

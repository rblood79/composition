# ADR-217 Design Breakdown — Chart 기준선 (ReferenceLine) · 산점도 (Scatter)

> 상위: [ADR-217](../217-chart-reference-line-scatter.md) · Proposed 2026-09-12 · 선행: [ADR-194](../completed/194-chart-component-headless-geometry.md) (기하 SSOT) · [ADR-211](../completed/211-chart-display-budget-pixel-fit-window-decimation.md) (표시 예산 · 창) · [ADR-216](../completed/216-chart-time-axis-format-window.md) (연속 x 스케일 `positions` · `resolveCategoryBand`). D2 원천: react-spectrum-charts `vega-spec-builder` (`ReferenceLine` · `Scatter`, 2026-09-12 shallow clone 정독 — 인용은 파일:줄).

## 1. 범위 · 선행 관계 (분리 4질문 lock-in)

- **범위**: (A) 값 축 기준선 — `referenceLines[]` (RSC `ReferenceLine`: `value` · `label` · `lineType` · `layer`) 를 scene 이 `LineMark role:"reference"` + 라벨 `TextMark` 로 낸다, domain 은 scene 이 넓힌다 (두 leg 같은 눈금). (B) 새 `chartType:"scatter"` — 행 = 점 (같은 x 합산 없음), x = 숫자 (`dimensionScale` 미설정 = `linear`) 또는 `time` (216 재사용), 마크 = 시리즈당 점 path 1개 (`buildDotMarks`), 예산 = 211 (window · extrema), DOM = Recharts `ScatterChart` + `Scatter`.
- **범위 밖**: 범주/시간 축 위의 세로 기준선 (RSC `position` before/after/center — band 전용; "오늘" 선은 후속) · `ReferenceArea`/`ReferenceDot` · 기준선 아이콘 (RSC `icon`) · Scatter `size` 매핑 (버블 — RSC `SymbolSizeFacet`) · `ScatterPath`/`Trendline`/`ScatterAnnotation` · Scatter 의 `colorScaleType:"linear"` (연속 색) · bar 의 `linear` 스케일 · Skia 상호작용.
- **분리 4질문** (adr-writing.md §Fork): (1) base/응용 — 194 (기하 SSOT) · 211 (예산) · 216 (`positions` + `resolveCategoryBand`) 이 base, 본 ADR 은 그 위의 응용 두 가지 (마크 종류 1 + 장식 마크 1). 역방향 의존 없음 — 216 의 `positionBand` 는 이미 "epoch" 가 아니라 "숫자 위치" 로 쓰여 있어 (`timeAxis.ts positionBand(positions, scale)`) scatter 의 linear x 가 그대로 탄다. (2) schema — 새 저장 props 는 `referenceLines?` (객체 배열, `seriesConfig` 와 같은 `items-manager` kind — `Chart.binding.ts:104-116` 선례) 와 `chartType` enum 값 1 (`scatter`) 뿐. 210 `seriesConfig` · 211 `budget*` · 216 `dimension*` 을 specialization 하지 않는다 — 다만 `dimensionScale` 의 **해석** 이 scatter 에서 달라진다 (§2.3: 미설정/`category` = `linear`). 직교. (3) 선행 전제 reverse — 216 이 "시간축은 line/area 만" 으로 `time` 을 막은 것은 bar 가 band 여서였다 (`presentation.ts:585-612`); scatter 는 연속 x 가 본질이라 그 거부 목록에 **넣지 않고** 허용 목록에 넣는다 — 216 의 결정 자체 (bar 거부) 는 유지. 211 의 "R7 신규 chartType 은 컴파일 오류로 잡는다" (`computeChartScene.ts:479-483 assertNever` · `budget.ts:174-177 throw`) 가 본 ADR 의 첫 RED 다. (4) 3차 리뷰까지 미루지 않음 — round 1 에 낸다. **사용자 confirm**: 2026-09-12 ADR-216 create-adr 의 AskUserQuestion 에서 사용자가 "ReferenceLine · Scatter 는 후속" 을 선택 ([216 breakdown §1](216-chart-time-axis-format-window-breakdown.md#1-범위--선행-관계-분리-4질문-lock-in)) + 2026-09-12 `/create-adr ReferenceLine·Scatter 후속` 직접 지시 (하나의 ADR — 사용자 지정). 종결 계약상 재질문하지 않는다.

### 2.2 기준선 (ReferenceLine)

- **props (D2)**: `referenceLines?: readonly ChartReferenceLine[]` — `{ value: number; label?: string; lineType?: "solid" | "dashed" | "dotted"; layer?: "back" | "front" }`. 기본 `lineType:"solid"` · `layer:"front"` (RSC 와 같다). 값 축 (metric) 전용 — bar/line/area/scatter (직교 4종). pie/radar/radial 은 진단 `referenceLines.unsupportedChartType` (radar 의 값 링 기준선은 후속). 개수 상한 4 (진단 `referenceLines.tooMany`) — 마크 2/개 (선 + 라벨) 로 M 에 영향 없음. `value` 비유한 → 진단 `referenceLines.invalid` (설정 오류 = 그리지 않음, 210 규약).
- **domain (RSC 와 다른 점, 명시)**: RSC 는 domain 을 넓히지 않아 범위 밖 기준선이 보이지 않는다. 우리는 `valueExtent` ∪ `{value}` 로 domain 을 넓힌 뒤 `niceTicks` — **scene 이 정한다** (`model.ts:247-251` 한 자리). expand (0–100) 는 값 단위가 정규화라 기준선도 0–100 으로 읽는다 (문서화). 두 leg 는 같은 `ticks.domain` 을 이미 읽으므로 (`RechartsChart.tsx:640-647`) Recharts `ReferenceLine`/`ifOverflow` 를 쓰지 않는다.
- **마크**: `LineMark { role: "reference", dash?: readonly number[] }` — dash 표: dashed `[6, 4]` · dotted `[2, 3]` (Skia `strokeDasharray` · DOM `stroke-dasharray` 같은 배열). 좌표: 세로 차트 `y = value(v)`, `x1 = plot.x`, `x2 = plot.x + plot.w`; 수평 차트는 x. 라벨 `TextMark { role: "reference", anchor: "end", baseline: "bottom" }` 를 선의 끝 (오른쪽/위) 안쪽에 `fontSize × 0.3` 띄워 둔다 — RSC 의 "축 위 라벨 + 눈금 숨김" 은 채택하지 않는다 (여백 재계산 + 충돌 규칙 2개가 늘고 Skia 대칭 비용만 크다; 라벨은 plot 안 (Recharts 관행) 이 값싸고 같은 그림). 색 `chart.reference` 토큰 → `--chart-reference` (기본 `{color.neutral}` = RSC gray-800 상당), 라벨은 같은 토큰. 순서: `layer:"back"` 은 grid 뒤에 (grid → back 기준선 → 마크), `front` 는 마크 뒤 축선 앞 — 두 leg 같은 위치 (`skiaPrimitives.ts:3597-3600` · `RechartsChart.tsx backdrop/foreground` 의 Customized 두 그룹에 그대로 얹는다).
- **채널**: rule `chart.reference?` (spec.types `chart.reference?` + CSSGenerator `--chart-reference` + Skia `channel.reference` — 211 `others` 와 같은 3곳). fallback `CHART_REFERENCE_FALLBACK_TOKEN = "{color.neutral}"`.
- **패널**: `ChartReferenceLineControls.tsx` — items-manager 목록 (값 · 라벨 · 선 종류 · 층), Content 섹션 시간축 컨트롤 아래. 문자열 `chart.referenceLines` · `chart.referenceValue` · `chart.referenceLabel` · `chart.referenceLineType` · `chart.referenceLayer` + 옵션 라벨 (실선/파선/점선 · 뒤/앞) ko/en.

### 2.3 산점도 (Scatter)

- **모델**: `chartType:"scatter"` 는 직교 종류 (bar/line/area 와 같은 cartesian 분기). 격자 = **행 하나가 범주 하나** (`buildSeriesGrid` scatter 분기: key 합치기 없이 push — 같은 x 두 행 = 점 두 개), `positions[ci] = x`. x 파싱: `dimensionScale` `time` 이면 216 파서, 그 외 (`linear` = 미설정/`category`) 는 `toFiniteNumber` — 실패 행은 216 과 같은 정책 (범주 push 전 제외 + `dimension.parse.failed` 경고). x 정렬 오름차순 (`sortByPosition` 재사용 — 창/극값이 x 순서를 전제한다). 라벨 = x 표시 문자열 (linear 는 `formatValue` 계열 숫자 형식, time 은 216 라벨).
- **`dimensionScale` 해석**: scatter 에는 범주 스케일이 없다 — 미설정 (`toRacProps` 가 채우는 `"category"` 포함) = `linear`. chartType 전환은 `{chartType}` 만 patch 하므로 (`ChartAuthoringControls.tsx:60`) line → scatter 전환 문서가 오류 상태에 빠지지 않게 하는 유일한 길이다. 명시 `"category"` 와 미설정을 구분할 수 없으므로 (기본값 fill) `"linear"` 라는 새 enum 값은 **두지 않는다** — `ResolvedDimensionSettings.scale` 에 `"linear"` 를 더해 해석 결과만 셋으로 늘린다 (저장 값은 그대로 2). 패널 (`ChartTimeAxisControls`) 은 scatter 에서 옵션 라벨을 "숫자 / 시간" 으로 바꾼다.
- **스케일 · 축**: x = `linearScale(niceTicks(xmin, xmax).domain)` (linear) 또는 216 `timeScaleFor` (time) — `resolveCategoryBand` 에 linear 분기 1개 추가 (`model.linear?: { domain, ticks }` — 216 `model.time` 과 같은 자리, transformed 전체). x 축 눈금 = 값 축과 같은 `niceTicks` + `formatValue` (linear) · 216 2단 라벨 (time). `axisKind` 는 `"ordinal"` 고정 (216 과 같은 이유).
- **마크**: 시리즈당 `buildDotMarks(points, seriesIndex, dotRadius(strokeWidth))` 1개 — 선 없음, 값 라벨 (`showValueLabels`) 은 line 과 같은 `pointValueLabel`. `showDots` · `curve` 는 scatter 에서 휴면 (패널 숨김). 색 = 시리즈 (colorBy 휴면). `stackType` 휴면 (dodged 고정 — validator 가 stacked/expand 를 진단 `stackType.unsupportedChartType` 으로 거부하지 않고 **무시** 한다: 기존 문서 전환 시 조용히 깨지지 않게, 패널 숨김).
- **예산 (211)**: `slotFit` scatter = `axis / minPointGap` (line 과 같음), `defaultBudgetMode(scatter, ordinal)` = `extrema` (비누적 line 과 같음 — bucket 별 min/max 점 보존이 산점도에도 옳다: 이상치가 남는다), 지원 = window · extrema (aggregate/others 거부). 점 ≤ P(5,000) · rowCap 20k 그대로. 창 트랙 · thumb 2 · 넓힌 창 재추출은 216 그대로 (categories = x 순서 점).
- **DOM**: `ScatterChart` + 시리즈당 `<Scatter data={[{x, y}]} shape={PlainDot}>` (반지름 = `dotRadius`, `fillOpacity 0.85` — Skia 점과 같은 값) · `XAxis type="number" dataKey="x" domain={model.linear.domain | time.domain}` · `YAxis domain={ticks.domain}` · `backdrop`/`foreground` 그대로. 툴팁 = Recharts `Scatter` 의 점 단위 hover (D1 runtime) — content 는 기존 custom content 에 scatter payload 분기 (x 는 dimension 라벨, y 는 `formatValue`). Recharts `Scatter` 는 lazy `RechartsChart` 청크에만 든다 (initial 0 — G5 가 잰다).
- **Skia**: 변경 0 — path 마크 · 축 텍스트 마크는 이미 소비한다. 신규 chartType 은 `CHART_PRESENTATION_KEYS` 무관 (`chartType` 은 이미 읽는다).
- **저작**: descriptor `scatter` ("Scatter Chart", 아이콘 `ScatterChart` (lucide), 검색어 산점도/분포/점), defaults `{ showDots: true, showLegend: true }`, preset 없음. `createChartInitialProps("scatter")` 는 숫자 sample (`{ x, y, series }` 8행 — legacySample 은 범주라 전부 파싱 실패 → "No data" 가 된다) + `dimension:"x"` · `metric:"y"`. 패널: chartType 옵션 +1, `ChartDataMappingControls` 의 범주 라벨 = "X" (scatter), columns 모드 허용 (값 필드마다 시리즈 — y 여러 개), `ChartBudgetControls` 종류 목록 +1, `ChartSeriesControls` 무변경.

### 2.4 두 leg 대칭 검증

- 기준선: `chartParity` 에 (a) 값 축 domain 이 기준선으로 넓어진 눈금 문자열 (b) 기준선 `y` (c) 라벨 `x,y` 가 Skia scene 과 DOM `<line>`/`<text>` 속성에서 byte 동일 — 4 종류 × layer 2.
- 산점도: 점 path `d` (Skia `PathShape.d` = DOM `Scatter` 점 좌표 — DOM 은 Recharts 가 그리므로 `cx/cy` 를 scene 점과 대조, 216 `chartParity` +2 와 같은 방식) · x 축 눈금 문자열 · 창 초기 상태.
- 손계산 oracle (G2): 기준선 `value 120` 에 데이터 max 100 → domain `[0, 120]` (niceTicks 5) · `y = plot.y` (맨 위); 기준선 `value -20` 에 bar → domain `[-20, 100]`; scatter 5 점 `(1,10) (1,30) (2,20) (4,40) (4,40)` 1 시리즈 → categories 5 (합산 없음, 중복 점 2), positions `[1,1,2,4,4]`, x domain `[0, 4]` 또는 `[1, 4]` (niceTicks 규칙대로 손계산), 마크 subpath 5.

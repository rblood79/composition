# ADR-260 design breakdown — 원본이 page 에 남는 컴포넌트

> 본문: [../260-component-origin-in-place.md](../260-component-origin-in-place.md). 이 문서가 Phase · 파일 · 검증의 정본이다. `docs/adr/evidence/` 는 로컬 전용이라 실측 결론은 여기에 둔다.

## 0. 전제 lock-in (fork 4 질문 — 분리가 아니라 ADR-248 판정 ② 의 개정)

1. base / 응용: 이 ADR 은 ADR-248 문서 모델 (base) 의 **소유 edge 한 종류** 를 바꾸는 응용이다. ADR-248 은 Implemented 라 fork 가 아니라 후속 ADR 이다.
2. schema: `DefinitionEntry.originRef?: boolean` (선택 필드) 하나 추가 — `CatalogClipboard` 의 선택 필드 셋 (Decision 13) 은 문서 schema 가 아니다. 옛 문서는 필드가 없어 소유 모양 그대로 — 직교.
3. 선행 전제 reverse 검증: 2026-09-30 판정 ② 「그 자리 origin 불가」 의 근거는 「정의의 template 소유와 동시 소유」 였다. 그 근거는 소유 edge 가 하나뿐일 때만 성립한다 — 참조 edge 를 두면 소멸. 사용자 confirm = 2026-10-14 「선택 노드가 ORIGIN 으로」 + 「ADR 먼저 작성」.
4. 판독: Codex 1차는 Phase 0 inventory 뒤 (사용자 요청 시 `/review-adr 260`).

## 1. Phase 0 — inventory · oracle (G0)

- `templateRootId` 를 읽는 34 파일 (2026-10-14 grep, 테스트 제외) 과 `kind === "definition"` 판정 53 파일을 세 묶음으로 분류한다: **(a)** id 로 template 을 읽는다 (resolver · positions · address · fieldSource · materialize · itemInsert · rowTemplate · slots · textBinding — 소유 edge 변경으로는 바뀌지 않는다. 단 리뷰 H1 로 「template 노드 자신의 override 를 읽는가」 를 따로 표시한다 — Decision 11 이 그 조회를 바꾼다) · **(b)** 소유 사슬로 정의를 만난다 (`graph.ts` 소유 검증 · 재검증 트리거 `:600-608` · `transaction.ts` `ownedChildIds` · `clone.ts` · `structure.ts` `topLevel` · `locate` · `removeWithReferrers` · `compositionRoot` 영향 root · `componentConfirm` · `workspace.ts` `ownerOfRecord`) · **(c)** 정의 편집 view 를 전제한다 (`compositionRoot.ts` `pageRoots` · `workspace.showDefinition` · `CatalogComponentsPanel` · `CatalogDefinitionsSection` · `CatalogDefinitionBar` · `layerTree.ts` · `componentActions.ts` · `canvasMenu.ts` · `shortcuts.ts` · `actionBar.ts`).
- pen.dev 동작 확인 3건 (2026-10-14 대조 — 문서에 있으나 composition 코드로 확정 못 함): detach 해도 중첩 instance · 변수 참조는 링크 유지 (`detachInto` 가 중첩 project instance 를 instance 로 남기는지) · instance 안의 원본 유래 레이어는 다른 부모로 옮길 수 없음 · instance slot 에 드래그 · 붙여넣기로 채움. 다르면 Phase 2 에 수리 행을 더한다.
- 그래프가 존재를 검증하는 참조 종류 전수 (definition · token · stateVariable 소유자 · interaction 대상 …, `graph.ts` 검증부) 와 다른 프로젝트 붙여넣기 정책 (의존 집합 · 값 고정 · 그대로) 표 — Decision 13 (Round 2 H5).
- 문서 수: 저장소 fixture (`document/fixture.ts` · `__tests__`) 와 로컬 프로젝트 (IndexedDB) 의 `project:definition:` 컴포넌트 · layout 수.
- oracle 대조표 (pen.dev docs · Figma help, 2026-10-14 조회 — 본문 Context): 만들기 (둘 다 그 자리) · 편집 전파 (둘 다 흐름, override 유지) · detach (instance 하나) · 해체 (pen.dev ⌘⌥K 토글 / Figma 없음 — undo 또는 instance 떼고 원본 삭제) · 원본 삭제 (Figma instance 유지 + Restore / pen.dev 미문서) · 복제 (pen.dev instance / Figma 새 컴포넌트) · 이동 (둘 다 자유) · 중첩 (둘 다 지원).
- 사용자 결정 5건 모두 2026-10-14 답 (본문 Status). oracle 표에 Figma 「Restore main component」 의 실제 자리 (instance 옆 — 문서 미명시) 를 실물로 확인해 적는다 — 다르면 1회 보고.

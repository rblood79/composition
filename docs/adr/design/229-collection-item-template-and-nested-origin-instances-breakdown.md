# ADR-229 Design Breakdown — TagGroup item template origin + 저작 조합층의 origin 안 instance

> 본문: [229](../229-collection-item-template-and-nested-origin-instances.md). 상태 Accepted (2026-09-21, Phase 0 완료 — §7). 이 문서가 Phase·파일·게이트 절차의 정본이다 — ADR 본문에는 포인터만.

## 1. 전제 lock-in (fork 4 질문)

1. **base / 응용**: base = ADR-147/148/161 (collection item template · ref-composite 컨테이너) + ADR-228 (팔레트 전 항목 origin · instance 계약). 이 ADR 은 그 **응용** — 같은 모델을 TagGroup 과 조합 origin 의 자식에 적용한다. 새 추상 0.
2. **schema 직교성**: canonical 스키마 변경 0 — `type:"ref"` · `slot: string[]` · `metadata.slotRole` 은 148/161 의 것. 새 필드 없음. 공용 slot vocabulary에 avatar를 additive 확장하며 D2 PropContract는 유지한다. 228 의 instance 계약 (명시 initialProps = origin 과 다른 키) 을 자식 ref 에도 그대로.
3. **선행 ADR 전제 reverse 검증**: 148 의 "template origin 은 컨테이너 origin `slot[0]`" 방향 그대로 (TagList 가 slot 보유자). 228 의 "sub-part 는 origin 화하지 않는다 (RAC 컴포넌트만)" 그대로 — 사용자 판정 (a) 가 재확인 (2026-09-21 AskUserQuestion).
4. **codex 1차 진입 시점**: 이 breakdown §2 inventory 가 확정된 뒤 (Phase 0 착수 전) — 전제 결함은 §2 표에서 잡힌다.

사용자 confirm 기록: 2026-09-21 AskUserQuestion "(a) 저작 조합만 먼저 (Recommended)" 선택 — 메모리 `project-origin-instance-composition-scope-2026-09`.

## 3. Phase

### Phase 0 — inventory freeze + 2단 override 실측 (G0)

- §2 U1~U3와 리뷰 반증을 인접 회귀로 고정한다. 기존 plain Form을 배치하는 것으로 대체하지 않는다. Button origin + Toolbar/Form origin의 **실제 자식 ref** + outer instance인 proposed fixture를 구성한다.
- `canonicalRefResolution.ts` 일반 source-child 경로에 nested master 해소를 구현한다. nested master props → 조합 자식 patch → 바깥 instance descendant patch 순으로 적용하고, 자식 master propsSchema로 재바인딩한다. 기존 override.children 경로와 결과를 대조한다. 깊은 descendant path의 주소 안정성·원본 불변·순환 참조의 유한 종료를 같은 경계에서 검증한다.
- 타입 Button 및 origin 속성 상속을 확인한 뒤 실제 Builder(headed)에서 안쪽 Button 편집 → instance 저장 위치/IndexedDB 확인 → reload → 두 leg 값 → Undo/Redo를 검증한다. outer instance 편집이 조합 origin이나 Button origin을 오염시키지 않아야 한다.
- 이 공통 경로가 GREEN이 되기 전에는 Phase 2의 신규 ref seed를 활성화하지 않는다. 공통 해소 실패 시 §5의 전체 보류 조건을 적용한다.

### Phase 1 — TagGroup item template origin

- `components/taggroup/tagGroupTemplateOrigins.ts` 신설: `TAG_ITEM_DEFAULT_ORIGIN_ID = "component-tag-item-default"` · `TAG_ITEM_SELECTED_ORIGIN_ID` · slot 자식 Icon `{icon}` (optional) · Avatar `{avatar}` (optional) · Text label `{label}` · `metadata.type:"tag-template-origin"` · `ensureTagGroupTemplateOrigins` (ListBox 동형). `component-taggroup` 의 TagList 자식 (`__2`) 에 `slot: [default, selected]` — generic seed (`catalogOrigins.ts`) 가 TagGroup 을 만들 때 TagList 에 slot 을 붙이도록 `pickCanonicalExtras` 확장 또는 TagGroup 을 `TEMPLATE_ORIGIN_REUSABLE_TYPES` 에 넣고 손 ensurer 로 (ListBox/GridList 와 같은 길 — 후자 권장, 근거: slot 보유자가 origin 자식이라 generic 경로가 표현 못 함).
- `REUSABLE_ORIGIN_ENSURERS` 에 등록, `componentRegistrationContract.test.ts` 불변식.

### Phase 2 — 저작 조합층 자식의 ref 화

- 규칙 하나: `toOriginChildSeed(node)` — `getReusableCompositeOriginId(node.type)` 이 있고 node 가 sub-part 가 아니면 (`isDelegatedSubpartChild` false) `{ id, type:"ref", ref: originId, name, props: diffAgainstOrigin(node.props), metadata }`. `diffAgainstOrigin` = 228 의 명시 initialProps 규칙 (origin 과 다른 키만).
- 적용 지점: 손 seed (Form `__action-{n}` · `__field-{n}` TextField · Toolbar Button · IconButton 은 root 가 Button 이라 제외) · generic seed `flattenDefinitionChildren` (ButtonGroup · Pagination · 그 외 definition 자식 중 reusable 타입) · 생성 경로 `useElementCreator` 의 같은 변환.
- **2단 seed (m3)**: 진입 시 existing origin ID 집합을 먼저 보관한다. ① 각 단일 소유 ensurer가 기존 plain 기본 seed 및 Tag template을 보충한 뒤 문서 전체 유효 origin index를 완성한다. ② 진입 시 없었던 조합 origin의 자식만 index를 읽어 ref로 변환한다. 처음 보충된 plain 자식을 사용자 기존 자식으로 오인해 변환을 건너뛰지 않는다. 기존 origin의 자식은 일절 변환하지 않는다.
- `diffAgainstOrigin`은 ①의 완성된 props를 사용한다. 순회 순서가 달라도 같은 결과여야 한다. 참조 누락/순환 dependency는 조용히 props:{}로 대체하지 않고 진단해 해당 ref 전환을 차단한다. `originIds`는 각 ensurer의 수집·배치 대상만 유지하며 다른 owner의 origin을 생성·repair하기 위한 집합으로 확장하지 않는다.
- 전환은 children/descendant override·fills/sizing/responsive 등 기존 canonical 의미도 보존해야 한다. 조합 자식의 독자 subtree를 target origin 기본 subtree로 조용히 대체하지 않는다. Phase 0 inventory에서 해당 차이를 확정하고 기존 override 형식으로 표현하지 못하면 전환을 보류한다.
- 기존 origin: repair가 children과 배치를 보존 (F8). 신규 여부는 문서 전체가 아니라 진입 시 origin ID 존재 여부로 판단한다. 테스트는 기존 origin과 신규 보충 origin이 섞인 문서도 포함하며 G4의 비교 범위를 따른다.
- 2단 override: Phase 0 실측 결과에 맞춰 `diffRefPropsAgainstMaster` 가 중첩 instance 의 master 를 (조합 origin 의 자식 ref 가 가리키는) Button origin 으로 잡는지 unit — 원복 RED.
- Navigator/Properties: 중첩 instance 선택 시 필드 = plain Button 과 같음 (HC). instance 배지는 표시. **F15 (Phase 0 실측)**: synthetic 자식은 1-level 부터 Properties/Styles 가 빈 상태라 HC 를 만족하려면 패널의 selected 파생 (`getActiveCanonicalSelectedElement` · `useCanonicalPropertyElement*`) 이 `<instance>/<path>` 를 resolved synthetic 노드 (origin ⊕ 자식 patch ⊕ 바깥 patch) 로 읽고, 쓰기는 ref-descendant target (`resolveEditorPresentationTarget`) 과 같은 `descendants` 경로로 가야 한다 — 이 phase 의 실제 범위 (신규 InspectorFieldKind 0 은 그대로).

## 5. 축소안 (G0 실패 시)

- 일반 origin-child ref 해소/2단 소유권이 실패하면 **모든 조합 자식 ref 전환을 보류**한다. Form/Toolbar도 같은 경로라 축소만으로 회피할 수 없다. TagGroup 축은 독립 gate를 충족할 때만 진행하며 ADR 전체 완료로 보고하지 않는다.
- 공통 경로는 통과하고 generic 고유 seed 변환에서만 실패한 경우에 한해 Form/Toolbar 손 seed **2종**으로 범위를 축소한다. 남은 generic 대상은 미완료로 기록하고 승인된 전체 범위의 완료와 구분한다.

## 6. 함정 (선행 ADR 에서 승계)

- 228 h1: ref 의 유효 타입은 문서 index (`findCanonicalNodeType`) 로 — 중첩 ref 자식의 nesting guard (Button ⊂ ButtonGroup) 도 같은 경로.
- 228 h2: origin 보존 테스트는 사용자가 실제로 바꾼 상태 (역순 · frame 안 · 자식 편집) 로.
- 228 parity 함정: Skia 픽셀 leg 는 stage 를 뷰포트 안에 (`focusStage`) + 빈 캡처 가드 + 선택/hover 해제.
- 09-21 chip 상자: Tag rule 은 hand CSS 와 자동으로 안 맞는다 — DOM 실측을 같은 하니스에서 읽는다 (`taggroup-chip-text-live.mjs`).
- ADR-923 P5: sub-part 판정은 `isDelegatedSubpartChild` 하나로 — Phase 2 의 ref 화 제외 조건도 이 술어.

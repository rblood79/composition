## 별도 영역 — DOM/Skia cutover 분리 (value-fill 군 발효 선행 조건)

> **위상**: 본 섹션은 value-fill standalone 군(SliderTrack/ProgressCircle/ProgressBar/Meter) 발효를 막는 **구조적 차단**을 기록한다. **ADR-912 안에서 다룰지 별도 설계로 분리할지는 사용자 결정 대기** — 본 섹션은 결정을 내리지 않고 차단의 본질·범위·선택지만 surface 한다(실행 중 파생 ADR/단계 분할 금지: `feedback-no-derived-adr-mid-execution` / `feedback-execute-adr-surface-minimization`).

### 차단의 본질 (2026-06-05 ProgressBar+ProgressCircle 2 slice 실측)

현재 catalog cutover 게이트는 **DOM·Skia 발효를 단일 source 로 묶는다**:

- `componentCatalog` entry 의 `cutover === "catalog"` → `getCatalogCutoverTypes()` 단일 집합.
- Skia: `isCatalogSkiaCutover(type)` = `isCatalogCutover(type)` (cutover.ts — 단계 5 step1 에서 `skiaLegacy` 0건 도달 후 **의도적 collapse**, dead gate 제거).
- DOM: `cutoverPrimitives` = `CATALOG_CUTOVER_TYPES` (App.tsx:908) = 동일 `getCatalogCutoverTypes()` 파생.

→ 한 type 을 `cutover:"catalog"` 로 등록하면 **DOM 과 Skia 가 동시에 generic 경로로 전환**된다. "Skia 만 generic, DOM 은 rendererMap/RAC 전용 유지" 는 **현 아키텍처에서 표현 불가**.

### 왜 value-fill 군에서 문제가 되나

value-fill 군은 DOM 이 **generic fallback(div + box+text)으로 재현 불가능한 전용 렌더**에 의존한다:

| type           | DOM 전용 렌더                                               | Skia 경로 (준비 상태)                                              |
| -------------- | ----------------------------------------------------------- | ------------------------------------------------------------------ |
| ProgressBar    | RAC `<ProgressBar>` + child-label (renderProgressBar)       | shell-only 가능(rule fill transparent → 빈 box, 자식이 시각 담당)  |
| Meter          | RAC `<Meter>` + child-label (renderMeter, ProgressBar 동형) | ProgressBar 동형 (MeterTrack escape 발효됨)                        |
| ProgressCircle | SVG `<circle stroke-dasharray>` (renderProgressCircle)      | `value_fill_arc` primitive 준비됨(track+indicator arc 자체 생성)   |
| SliderTrack    | RAC `<Slider>` (thumb + range 모드)                         | `value_fill_bar` `[]` 반환(자식 thumb) + thumb 별도 primitive 필요 |

Skia 측은 (일부) 준비됐으나, catalog 등록이 DOM 까지 끌고가 **DOM 시각이 generic box+text 로 깨진다**(원형 ring/RAC track 소실). generic 억지 재현은 시각 깨짐이므로 회피(`feedback-no-fallback-thinking`).

### 선택지 (사용자 결정 영역 — 본 문서는 제안만, 결정 안 함)

1. **DOM/Skia cutover 채널 재분리**: 단계 5 step1 이 collapse 한 dead gate 를 value-fill 한정으로 재도입(Skia-only cutover set). 단계 5 의도(채널 단일화)와 역방향 → ADR-912 본문 결정 재검토 필요 가능성.
2. **전용 DOM INTERNAL_RENDERERS wrapper 신설**: ProgressBar/Meter/ProgressCircle 의 RAC/SVG 렌더를 `INTERNAL_RENDERERS` React.ElementType 형식 wrapper 로 격상 → catalog cutover 경로(CanonicalNodeRenderer L193)가 generic box 대신 wrapper 호출. child-label 의존(renderProgressBar) 재구현 범위.

영역 B 14(보류 13 + List)를 **단일 generic projector 로 억지 흡수하지 않는다**. 실측(Explore agent + main file:line 확증)상 데이터 소스가 3가지로 갈리고, 단계 4 발효 선례 projector(`getListBoxProjectionRows`/`getTableProjectionRows`, `collectionRowProjectionModel.ts`)는 **collection items 에 닫혀있어** controller render-prop·chevron 을 같은 데이터 모델로 표현할 수 없다. 따라서 **고수준 projection 골격은 공유, 데이터 소스 어댑터만 3가지로 분리**한다.

#### 공유 골격 (3 메커니즘 공통 — 선례 단계 4 인프라 재사용)

선례(`canvasSceneNode.ts` `appendListBoxRowProjection` / `appendGridListRowProjection` / `appendTableRowProjection`)가 확립한 render-space 골격을 그대로 승계. 메커니즘별 신규 발명 아님:

- **projection id**: `projection:` prefix (예: `projection:listbox-row:{ownerId}:{key}` / `projection:table-cell:{ownerId}:{itemKey}:{columnId}`). `isRenderProjectionId` 가드. canonical document/IndexedDB 미저장.
- **projection metadata union**: `CanvasProjectionMetadata` 의 `kind` discriminant + `isCollectionRowProjectionKind`/`isCollectionCellProjectionKind` **단일 handler** 로 family 분기 회피(no-classification — `feedback-container-generic-box-no-classification` 정합).
- **3-route write-target**: `resolveCollectionWriteTarget(projection, intent)` — `template`(origin master, 모든 행) / `data`(collections/binding, content) / `override`(`RefNode.descendants[key]`, per-row). `assertCanonicalWriteTarget` boundary guard(출력에 projected id 혼입 시 throw).

#### 핵심 통찰 — "데이터 동형, 렌더 구조 비대칭"

Tag 는 ListBox 와 **데이터 모델(items SSOT)·container shell·boundary guard 는 직접 동형**이나, **item 렌더 구조가 다르다**: ListBox 는 처음부터 projection 노드였고, TagList 는 spec 내부 self-render(이미 작동 중). 따라서 Tag proof slice 는 단순 어댑터 추가가 아니라 **작동 중인 TagList self-render seam 을 제거하고 projection 으로 교체**하는 작업 — kill criteria 의 "seam 제거"에 정확히 해당.

**좌표 재계산 난점 해소 (Taffy 위임)**: 사용자 경고("wrap/maxRows 좌표를 projector에서 재계산")는 ListBox 선례의 좌표 처리 방식을 보면 회피 가능하다. ListBox projector 는 좌표를 **직접 계산하지 않고** rowsGroup `flexDirection:column` + row `width:100%` 로 Taffy 에 위임(`canvasSceneNode.ts:554-588`). Tag 의 wrap-flow(가로 흐름 + 행 줄바꿈)는 **rowsGroup `display:flex flexWrap:"wrap" flexDirection:"row"` + chip `width:fit-content`** 로 Taffy flex-wrap 위임 가능 → `TagList.spec.ts:299-333` 의 수동 Phase 1 wrap 시뮬레이션 전량 제거. `maxRows` 만 window limit 동형으로 projector 에서 별도 처리(`getFlatProjectionRows` windowLimit 패턴 재사용, "Show all" chip 은 후속).

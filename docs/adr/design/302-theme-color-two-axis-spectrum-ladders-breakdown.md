## 1. 전제 lock-in

fork 가 아니라 새 결정이다 — 선행 ADR 의 의존 방향을 확인만 한다.

1. **base / 응용**: ADR-227 (테마 컬렉션 · delta · 축) = base. **ADR-302 = 그 축 중 색 축의 값 생성기 교체** — 스키마 · 명령 변경 0. ADR-295 (값은 S2, 이름은 저장소, oracle fixture) 의 색 확장.
2. **schema 직교성**: `ThemePreset` (tint · neutral · radius · darkMode) · `TokenEntry` · `TokensSnapshotEntry` 무변경. alias 표는 코드 (`packages/shared/src/catalog/runtime/`) 다. 대안 E (문서 alias 토큰) 는 범위 밖.
3. **선행 ADR 전제 reverse 검증**: ADR-290 (accent = 역할 둘 · 실제 바탕에 대한 목표 대비 · 두 렌더러 같은 hex) 중 「역할 둘 (`accent` · `accent-content`)」 과 「두 렌더러 같은 hex」 는 유지, 「oklch 탐색 (`solveAccentRoles`)」 은 사다리 생성으로 **대체** — 290 본문 Status 에 「Superseded in part by ADR-302 (Decision 2 탐색 → 302 Decision 1 사다리)」 한 줄. ADR-191 (Tailwind 생성 팔레트) 은 팔레트 CSS · 사용자 피커 묶음에서 유지, 테마 경로 (`semanticPaletteMap` 좌표 · `NEUTRAL_PALETTES`) 에서만 빠진다 — 191 본문에 「테마 경로는 ADR-302」 한 줄. ADR-227 §6 유보 (테마별 light/dark 이중 세트) 는 그대로.
4. **판독 전 전제**: 위 세 줄이 여기 있으므로 판독 (phase 당 1 + 수리 1) 은 본문 정합만 본다.

## 3. 생성식 (사용자 결정 1 — (a) 권고안의 상세)

입력: 기준 사다리 `R` (gray 13단 또는 blue 16단, light · dark 각각, design-data 값) · 목표 (c, h) (tint preset 의 oklch 또는 사용자 hex 의 oklch) · 바탕 `bg` (그 모드의 gray-25).

1. 단 `i` 마다 `L_i` = `R[i]` 의 oklch L. 후보 = `oklch(L_i, c, h)` 를 sRGB gamut 안으로 c 만 줄여 맞춘다 (hue 유지).
2. 목표 대비 `T_i` = `R[i]` 와 `bg` 의 WCAG 대비 (Hub colors 페이지의 단별 대비 — blue 1.06 ~ 19.5:1 이 이 값이다). 후보의 대비가 `T_i` 에서 ±5 % 를 벗어나면 L 을 이진 탐색으로 조정 (gamut 안에서).
3. 사다리 단조성 검사 — light 에서 L 이 단 순서로 감소, dark 에서 증가. 어긋나면 그 단을 이웃 중앙으로.
4. 역할 검사 (alias 표 적용 뒤) — 글자 역할 4.5 · 면 3.0 · rule 전경 쌍 (color × backgroundColor, 같은 가지) 은 default · hover · pressed · focus 전 상태 4.5 (S2 Button fill 명시 단은 기본 preset 에서 4.81 ~ 6.64 로 통과 — 3.0 완화 없음). 실패한 역할만 **바탕과의 대비가 커지는 방향으로 이동** (사다리 안에서 최대 2단 — 모드별 사다리가 이미 반전돼 있어 두 모드 모두 index 증가 = 바탕에서 멀어짐; 전경 on-\* 은 바탕 L 에 따라 gray-25 / white · black) 하고 그래도 실패면 G3 FAIL (warnings 아님). 「다음 단」 과 다르다 — hover/pressed 의 다음 단은 상태 진행이고, 여기는 대비 수리다.
5. Tone 사다리는 같은 식에 `R` = gray, (c, h) = Tone preset 의 색조 (slate 등은 지금 Tailwind 500 의 oklch c · h 를 입력으로 — 값은 생성, 이름만 유지).

기본 preset 은 1 ~ 5 를 거치지 않고 `R` 그대로다 (G1 동일).

- 문서 override 의 모드별 값 (ADR-227 §6 · 대안 E) — 사용자가 「dark 에서 다른 override」 를 요구할 때.
- Spectrum 의 `transparent-neutral*` · `transparent-overlay-N` · HCM 색 (`ButtonFace` …) — forced-colors 는 ADR-290 의 `LinkText` 처리 그대로.
- 색 토큰의 component 층 (Spectrum component-specific) — 이 ADR 은 semantic 역할 층만.
- 문서 저장 스키마에 alias 타입 — 대안 E.

## 1. 전제 lock-in

1. base/응용: 이 ADR 은 단일 실행 ADR — fork 없음. Decision 1 (DOM/Skia 경계 규칙) 이 이후 chrome 의 base 규칙이 되지만 후속 ADR 을 지금 만들지 않는다.
2. schema: 저장 스키마 무변경. `pagePositions` · `pages[].title` 은 그대로, 헤더는 표시 층만.
3. 선행 ADR 전제: ADR-178 (shift-클릭 body 토글) 의 **결과 계약** 은 유지 — 진입 경로만 Skia 캡처 → DOM 핸들러. 2026-08-12 occlusion 계약 (`canvas-interaction.md:34-35`) 은 "가려진 헤더는 보이지도 잡히지도 않는다" 로 재서술, 수단은 clip → DOM 순서 + `clip-path`.
4. 헤더 층 배치 (사용자 판정 2026-09-17, 성능·완성도 기준): **`.canvas-container` 안** + 컨테이너 capture 가드. 형제 `.workspace-overlay` 배치는 휠/pan 리스너가 `containerEl` 소유라 헤더 위 카메라 조작이 죽어 기각 (본문 Decision 4).
5. 병행 세션: task-state goal 은 ADR-013 (미커밋 sweep 대기). 교집합 후보는 `BuilderCanvas.tsx` 뿐 — G0 에서 `git status` 로 확인, 013 커밋 뒤 착수.

## 4. 단일 drag 추종

- drag 대상 pageId 는 `usePageDrag` 세션이 안다. 프레임 콜백은 `pagePositionSnapshot` 에 델타가 있는 pageId **하나** 만 `readPagePositionDelta` 로 읽어 그 노드 transform 을 쓴다 (문자열 비교 후 변경 시만).
- drag 중 다른 헤더는 정지 상태 — 카메라가 안 움직이므로 배치 유효.
- drag 종료 시 §6 clip 재계산 (겹침 관계가 바뀔 수 있다) + 대상 노드 최종 배치 1회.
- drag 중 카메라 auto-pan: **없음** (실측 2026-09-17 — `usePageDrag.ts:425-445` 는 RAF 스로틀로 `publishPagePositionPresentation` 만 호출, 카메라 무변경). drag 는 게이트 밖으로 확정.

## 5. settle 1회 배치

`placeAll(camera, frames)`: 모든 페이지에 대해 `pageHeaderGeometry` 로 화면 px 계산 → `style.transform = translate3d(left, top, 0)` · `style.width` · `data-active` · §6 clip. 뷰포트 밖 페이지는 `display: none` (컬링 — G2 실패 시 대안이 아니라 기본).

배치 트리거: 게이트 OFF 전환 · 프로그램 zoom/setPosition (`addUpdateListener`) · 페이지 추가/삭제/이름 변경 (`pages` 구독) · drag 종료 · `visiblePageFrames` 변경.

## 6. occlusion — DOM 순서 + clip-path

- 렌더 순서 = `orderPagesForPaint(pages, currentPageId)` → 활성 페이지 헤더가 DOM 마지막 = **헤더끼리의** 최상단. DOM 층 자체는 항상 Skia 캔버스 위라 위 페이지 **body** 와의 가림은 순서로 해결되지 않는다 — 아래 clip 이 유일한 수단 (round 1 m2). `pagePaintOrder.ts` 주석의 "소비자 3경로" 가 4경로가 된다 — 주석 갱신.
- 페이지 P 의 헤더 rect 와 **P 보다 뒤 (위) 인 페이지들의 body rect ∪ 헤더 rect** (화면 px) 교집합이 있으면 그 페이지 헤더 노드에 `clip-path: polygon(...)` 대신 **가려지지 않은 구간 rect 하나** 를 `clip-path: inset(...)` 로 준다. 위 페이지가 헤더의 좌·우 한쪽만 가리는 것이 전형 (페이지는 축 정렬 rect) — 양쪽을 가리면 남는 가운데 구간, 전부 가리면 `display: none`.
- 3 겹침 이상은 위 페이지 각각에 대해 inset 을 순차 적용해 남는 구간을 좁힌다 (rect ∩ 연산, polygon 차집합 금지 — R3).
- clip 된 구간은 `pointer-events` 도 자동으로 안 받는다 (clip-path 밖은 히트 대상 아님) → G1 ④.
- 활성 페이지 헤더는 위 페이지가 없으므로 clip 없음 — "어느 쪽에서도 잘리지 않는다" 유지.

## 10. 범위 밖 (후속 판정)

- 프레임 타이틀 (`FrameAreaGroup`) DOM 이관 — 히트 없음, Skia `renderPageTitle` 유지. 옮기면 `selectionRenderer` 의 Paragraph 캐시 전체를 걷어낼 수 있다.
- 헤더 안 미니 툴바 (Framer 의 breakpoint 라벨 · 페이지 액션) — Decision 1 의 층 규칙 위에서 별도 ADR.
- 이름 편집 UX 를 in-place `contenteditable` 로 — 현행 input 이동까지만.

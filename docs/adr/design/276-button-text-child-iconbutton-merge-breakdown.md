# ADR-276 breakdown — Button 글자를 Text 자식으로 · IconButton 통합

> 본문: [ADR-276](../completed/276-button-text-child-iconbutton-merge.md). 이 문서는 Phase · 파일 · 검증의 구현 상세다. 인벤토리 수치는 2026-10-20 grep 실측이고 Phase 0 에서 다시 센다. Round 1 (2026-10-20) 의 HIGH 3 (h1 중첩 호스트 기본 라벨 · h2 owned Icon 순서 · h3 origin 삭제 + 옛 문서 유지) 과 Round 2 의 h4 (Pagination · Menu · Popover · Tooltip 을 글자 없는 호스트로 잘못 분류 — §2b 자리별 값 표로 정정) 를 반영했다.

## 1. 전제 lock-in

- **분류**: 새 결정이다. 기존 ADR 의 fork · 분리가 아니고 의존 방향 변화도 없다. ADR-254 Decision 5 (`{label}` 바인딩 글자 = 부모 prop 정본) · ADR-256 (RAC 조립 · Icon div · Text span 유지 · Decision 7 `presentWhen`) · ADR-260 (origin = page 노드) 위에서 Button 의 origin template 과 명령 · 소비자만 바꾼다.
- **schema**: 문서 스키마 변경 0. 바뀌는 것은 code-catalog 의 origin template (`reusableOriginLibrary.ts`) 과 명령 · 소비자다. origin template 구조 변경이므로 `LIBRARY_CONTRACT_VERSION` +1 (구조 변경 계약 Step 3 — 변환 없음, 옛 개발용 프로젝트 거부; 당시 42 → 구현 43 (`09a72805f`), 이후 ADR 로 현재 50).
- **사용자 확정** (본문 Status 원문 인용): 「button컴퍼넌트에 text를 처음부터 넣게되면 문제가 해결되지않나」 · 「button컴퍼넌트와 iconbutton 컴퍼넌트 를 통합」.
- **사용자 결정 3건** (본문 §Decision) 은 Phase 0 끝에 묻는다 — 1 IconButton 남김 방식 · 2 icon-only 표현 · 3 Icon 기본 위치.

## 3. Phase

### Phase 0 — 인벤토리 (G0)

- §2b 표 (중첩 Button 27 + ToggleButton 7) 를 다시 센다: 자리 id · 현재 `children` 값 · 자기 Icon 자식 / SelectValue 유무 · **쓸 `label` = 현재 값** · `icon` 으로 옮길 후보 여부 (범위 밖, 표기만). 호스트 이름으로 분류하지 않는다 (Round 2 h4 — Pagination `← 1 2 3 →` · Menu · Popover · Tooltip trigger 는 글자 있는 자리). `type-Button` 직접 root 9 는 변경 0 임을 재확인 (composite instance 아님).
- 자체 `children` 문자열을 읽는 지점: `textOf(node)` (`canvasBinding.ts` · `domBinding.runtime.ts`) · `catalogTextKey` · AI write (`phase4eAiWrite`) · clipboard (`phase4eClipboard`) · 원본 반영 (ADR-262 `pushChanges`) · 데이터 바인딩 행 템플릿 (`interpolateCollectionRowTemplate`) · Layers 라벨. Button 에 닿는 것만 표에 올리고, 각각 「`label` prop 으로 읽는다」 가 되는지 적는다 (IconButton 이 오늘 어떻게 읽히는지가 oracle).
- `withComposedText` · `composedPartInputs` 를 Button · ToggleButton 밖에서 쓰는 type 이 있는지 (있으면 Button 호출만 삭제).
- IconButton 참조: 카탈로그 쪽 (`componentCatalog.ts` · `reusableOriginLibrary.ts` · `reusablePropsSchemas.ts` · `paletteItems.ts` · `componentsPage.ts` · `originView.ts` · rules table 주석 1107행) 과 테스트 (§4). 빌더 크롬의 `IconButton` UI 컴포넌트 (`@composition/shared/components`) 는 **무관** — 이름만 같다.
- 사용자 결정 1 ~ 3 을 묻고 본문 Status 에 기록.

### Phase 1 — origin template · 호스트 · Canvas (G1 · G2)

- `lib:template:component-button`: 자식 `component-button__icon` (`type-Icon`, `slot: "icon"`, `iconName: "{icon}"`, IconButton `__icon` 과 같은 visual) · `component-button__label` (`lib:definition:text`, `slot: "label"`, `children: "{label}"`, **`presentWhen: "nonEmptyText"`**, IconButton `__label` 과 같은 visual). `props.children` 삭제. definition `origin-component-button` 의 `accepts.label: "string"` · `accepts.icon: "string"`, `defaults.label: "Button"`, `defaults.icon` 없음. 상태 변형 4 는 그대로.
- `lib:template:component-togglebutton` 도 같은 꼴 (`defaults.label: "Toggle Button"`).
- 중첩 자리 27 + 7: §2b 표대로 `children` 값을 그대로 `label` 로 옮기고 `children` 을 지운다 (글자 17 은 문구 보존 · `""` 8 은 `""` · 상태 변형 9 는 쓰지 않음). 자기 Icon 자식은 그대로.
- `LIBRARY_CONTRACT_VERSION` +1 (`types.ts` — 42 → 43) + 헤더 주석 한 줄 (ADR-276).
- Canvas: `bindings.button` 의 익명 글자 분기 삭제 · `withComposedText` 의 Button · ToggleButton 호출 삭제 (다른 type 이 없으면 함수째) · 정적 가드 (옛 ① 글자를 쓰는 명령 0).
- DOM: RAC Button 안 `Icon` + `span.react-aria-Text` 는 IconButton 과 같은 경로 — 변경 0 예상 (G2 로 확인). `icon` 없음의 DOM Icon 이 요소를 남기지 않는지 (gap, R5) 확인.
- 단위 (RED 먼저): 새 Button instance 의 해석 자식 = Icon (hidden) + Text · `label` · `icon` 쓰기 1 step 씩 · `icon` 제거 → Icon hidden · 글자를 바꾼 뒤 `icon` 을 써도 글자 1 (원복 RED — 옛 `setIcon` 으로 2) · 중첩 34 자리 전수 — 해석된 글자 = 이관 전 `children` 값 (Pagination `← 1 2 3 →` · Toolbar `Action 1~3` · Menu `Menu` · Dialog `Open Dialog · Close` · Popover `Open Popover` · Tooltip `Hover me` · ButtonGroup · ToggleButtonGroup 보존, NumberField 증감 · SearchField · Select · Calendar picker · ContextualHelp · FieldButton 은 Text 0 · 폭 변화 0) — 원복 RED 둘 (`label` 미기재 → "Button" · 글자 자리에 `""` → 문구 소실) · IconButton 과 Button origin 의 template 구조 동일 · ToggleButton 같음.

### Phase 2 — Properties · 소비자 (G1 · G2)

- `buttonChildren.ts` 삭제 (`catalogButtonChildren` · `catalogButtonChildCommands`). `CatalogButtonChildFields.tsx` 삭제. `CatalogPropertiesPanel.components.tsx` 274 ~ 330 · 473 ~ 480행의 `buttonChildFields` · `ownText` 분기 삭제 — Content 섹션은 definition `accepts` 의 `label` · `icon` 칸 (오늘 IconButton 경로). Icon 칸 (`kind: "icon"`) 에 「없음」 = prop 제거 (`setFields` `{ kind: "remove" }`).
- `reusablePropsSchemas.ts`: `ICONBUTTON_PROPS_SCHEMA` 를 Button 스키마로 (사용자 결정 1 (a) 면 이름 변경, (b) 면 preset) — `icon.default` 삭제.
- 인라인 편집: Button 더블클릭 → Text 자식 상자 (ADR-254 경로). RED: 루트 record 의 `catalogTextKey` 가 `label` 을 잡아 Button 상자에 편집기가 열리면 Text 자식 우선 (bound text 자식이 있는 record 는 루트 편집 대상 아님).
- 자체 `children` 소비자 (Phase 0 표): AI write · clipboard · 원본 반영 · 데이터 바인딩 · Layers 라벨이 Button 글자를 `label` 로 읽는다 — IconButton 과 같은 결과가 oracle.
- icon-only (사용자 결정 2): `label: ""` → Text 없음 + Properties `aria-label` 안내.
- RED 테스트: 글자를 바꾼 instance 에 `icon` 설정 → 글자 1 · `icon` 「없음」 → Icon hidden · 글자 유지 · history 1 step 씩 · Undo/Redo.

### Phase 1 ~ 3 — 2026-10-20 (G1 · G2 단위 통과, G3 live 는 아래)

- 계획과 달라진 것 (사후 보고):
  - **FieldButton** (§2b 「글자 없음 · 자기 Icon 자식」): 그대로 두면 FieldButton 의 `icon` 이 Button 의 template `{icon}` 에도 묶여 글리프가 둘 (ComboBox · DatePicker · DateRangePicker 의 trigger). 자기 Icon 자식 (`component-fieldbutton__icon`) 을 지우고 Button 의 Icon 자리를 쓴다.
  - **ToggleButton 의 Text 자식 크기 · 색**: Button 은 hand 정의의 child part rule 이 Text 의 fontSize · lineHeight · Icon 의 iconSize 를 size 별로 주지만 ToggleButton (generic rule 정의) 은 없어 Text 가 16px 였다 → `buttonChildScaleRules` 를 둘이 같이 쓴다. 색은 `catalogToggleButtonGlyphOwner` 가 Icon 만 소유해 Text 가 `--fg` 였다 (선택 상태 흰 글자 위에 검정) → Text 도 소유 (DOM 은 `utilities.css` `.button-base > :is(.react-aria-Icon, .react-aria-Text …) { color: inherit }` 이 이미 그렇다).
  - **Text 의 `width: 100%`** (Text rule containerStyles, ADR-151 B22): Button 안 Text 가 버튼을 채워 Layout 정렬이 보이지 않았다 → template `__label` 에 `width: fit-content`.
  - **typography**: Button · ToggleButton 에 쓴 letterSpacing · textAlign · textDecoration 이 Canvas 에서 `CATALOG_CANVAS_VISUAL_UNSUPPORTED` 를 던졌다 (옛 익명 글자가 받던 값) → `CATALOG_TEXT_STYLE_CONTAINERS` 에 둘을 넣고 `textDecoration` 을 전파 키로 (CSS Text Decoration §1.2 — 버튼은 atomic inline box 라 조상의 것은 멈춘다, `ownsTextDefault`).
  - **template 자리의 명시 색**: 「기본값과 같은 명시 Icon 색도 저작 선택」 (2026-10-14) 판정이 소유 노드의 entry 만 봐서 template Icon 자리의 override patch 를 못 봤다 → `catalogHasAuthoredColor` 가 patch 도 읽는다 (`templatePositionWrites`).
  - **accepts**: definition `defaults` 의 키는 `accepts` 에 있어야 한다 (`PROP_NOT_ACCEPTED`) — root passthrough (variant · size · fillStyle · staticColor · type · isDisabled · isPending / ToggleButton 의 size · staticColor · isEmphasized · isQuiet · isSelected · isDisabled) 를 옛 IconButton 처럼 `accepts` + `defaults` 에 둔다 (팔레트 insert 가 기본값과 같은 초기 prop 을 버린다).
  - **pending**: pending Button 의 Text 자식은 이미 `_pendingHidden` 경로로 숨는다 (`visible: false`) — 별도 처리 없음.

## 1. 범위 · 선행 관계 (분리 4질문 lock-in)

- **범위**: 차트 6종 (bar · line · area · pie/donut · radar · radial) 전부. "몇 개를 그릴 수 있는가" 를 데이터 행 수 상수가 아니라 **차트가 차지한 픽셀 공간과 시리즈 수**에서 파생하고, 넘치는 부분을 창(window) · 축약(bucket 집계 / bucket 극값 선택) · 묶기(others) 로 처리하는 계약. 두 leg (Skia Canvas · Recharts Preview/Publish) 는 같은 계약 결과를 소비한다.
- **범위 밖**: 새 표현 옵션 (tooltip/legend 확장), 데이터 공급 (collection 식별자 — ADR-152), Properties 컨트롤 mount 비용 (ADR-210 후속 ②), 실시간 스트리밍, 시간 거리 비례 x 배치 (현행 band scale 도 index 배치 — §2.3).
- **분리 4질문** (adr-writing.md §Fork): (1) base/응용 — ADR-194 (기하 SSOT) · ADR-209 (Canvas·Recharts 분리) · ADR-210 (다중 컬럼·표시) 이 base, 본 ADR 은 그 위의 **표시 예산 계약** (응용). 역방향 의존 없음. (2) schema — 새 저장 props 는 예산 키 4개 (`budgetOverflow` · `budgetAggregate` · `budgetAxis` · `budgetOthersLabel`, 선택적 — P0 에서 `displayBudget` 객체를 평면화) 뿐이며 ADR-210 의 `valueFields/seriesConfig/valueFormat` 을 specialization 하지 않는다 (직교). (3) 선행 전제 reverse — ADR-157 의 "샘플 N행" 은 collection 목록용이고 `CHART_SAMPLE_ROWS` 는 그 동형 이식 (`computeChartScene.ts:56` 주석). 본 ADR 은 차트에 한해 그 동형을 **폐기**하되 ADR-157 은 건드리지 않는다 — 제품 코드 소비처 3곳 + 테스트 1 (§4) 이 전부 차트 전용. (4) 3차 리뷰까지 미루지 않음 — round 1 에 냈다. **사용자 confirm**: 2026-09-10 사용자가 방향 ("픽셀 공간에 몇 개가 들어가나", 스크롤·기간 축 축약, "모든 차트에 포함") 과 제목을 직접 정했다.

## 2. 계약

### 2.1 세 가지 예산을 구분한다 (round 1 h3)

| 예산                            | 뜻                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | 보장                                                                                                                                                                                                                                                                 |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **슬롯 예산 `fit`**             | 예산 축 / 최소 슬롯 간격 — 범주(슬롯) 를 몇 개까지 두는가                                                                                                                                                                                                                                                                                                                                                                                                                                | 슬롯 **간격**의 하한. 값 비례 마크 (pie 호 · radial 링 길이 · bar 높이) 의 크기는 보장하지 않는다                                                                                                                                                                    |
| **마크 예산 `M` · 점 예산 `P`** | **P0 확정 (2026-09-10, evidence `211-p0-spike.md` §2)**: 마크 비용이 종류에 따라 20배 다르다 (Recharts static: bar rect 800 → 75ms · 1,600 → 142 · 3,200 → 318 ≈ 0.085 ms/rect, line 은 시리즈당 path 1개라 점 20,000 에 123ms). 그래서 둘로 나눈다 — **`M` = 800**: 차트 하나의 **요소 마크** 총수 (bar rect · pie 조각 · radar 점 · radial 링 · dot · 값 라벨 — 축·눈금·격자·범례·창 트랙 제외). **`P` = 5,000**: line/area 의 **경로 점** 총수 (`S × 그려지는 슬롯`). 둘 다 rule 채널 | `데이터 마크 = S × 슬롯 × k ≤ M` — `k` 는 슬롯당 시리즈당 **요소** 수 (§2.2; line/area 의 path 점 자체는 0). 창·집계·others 는 `fitEff = min(fit, floor(M / (S × k)), floor(P / S))` (P 항은 line/area 만). 극값 선택은 합집합 U 를 모든 시리즈가 다시 그리므로 `S × | U   | ≤ P`와 (dot/라벨이 켜지면)`S × | U   | × k ≤ M` 을 **적응 B** 로 맞춘다 (§2.4). M 800 = ADR-210 W800 (800 rect → 75ms) 과 같은 작업량이라 G4 runtime ≤100ms 가 구성으로 성립 |
| **행 상한 `R`**                 | 모델 계산에 넣는 원본 행 상한 (rule 채널, **유한 — P0 확정 20,000**) — **두 leg 동일**. 근거: 20,000행 × S 4 모델 12–15ms p50 + 극값 8ms (≈ 25ms/렌더), 50,000 은 30 + line path 120ms 로 G4 "모델 ≤ 20ms" 밖 (`211-p0-spike.md` §2)                                                                                                                                                                                                                                                     | 모델 계산 비용 상한. 초과 시 두 leg 모두 앞 `R` 행 + 진단 `rows-truncated` (사용자-가시 안내)                                                                                                                                                                        |

- 최소 마크 크기 (예: pie 의 작은 조각 호 0.377px) 는 **보장하지 않는다** — 값 비중을 이유로 묶으면 데이터 의미가 바뀌므로 (`[1000, 1]` 은 조각 2개가 정답). 이 사실을 ADR Decision 에 명시한다.
- `fitEff = 0` (플롯이 최소 슬롯보다 좁음): 마크 0 + 진단 `plot-too-small` (warning — 데이터 보존, ADR-210 `presentation.ok=false` 경로가 아니라 scene.diagnostics 경로). `fitEff = 1`: 창은 1 슬롯, 집계는 bucket 1개 (명시한 통계 — sum 이면 전체 합, mean 이면 전체 평균), 극값 선택은 bucket 1개 (시리즈별 min/max → 합집합 ≤ 2S index, 점 ≤ 2S² — `M` 을 넘으면 §2.4 의 fallback), others 는 적용하지 않고 상위 1개만 (others 는 `fitEff ≥ 2` 부터: 실제 `fitEff − 1` + 기타 1). `fitEff = 2`: 정상 규칙.

### 2.2 종류별 예산 축과 `fit` · `k`

| 종류        | 예산 축 (픽셀)                                                | `fit`                                                                                                                                                                                                                                                                                                                                               | `k` (슬롯당 시리즈당 마크)                             | 넘칠 때 기본 (§2.4)                                                             |
| ----------- | ------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------- |
| bar         | `plot.w` (horizontal 이면 `plot.h`)                           | 묶음: `floor(plot.w / (minSlot × S))` · 누적/expand: `floor(plot.w / minSlot)`                                                                                                                                                                                                                                                                      | rect 1 + 값 라벨 (켜짐 1) → `k ∈ {1,2}`                | 범주: 창 · 순서: bucket 집계                                                    |
| line / area | `plot.w`                                                      | `floor(plot.w / minPointGap)`                                                                                                                                                                                                                                                                                                                       | 점 1 + dot (켜짐 1) + 값 라벨 (켜짐 1) → `k ∈ {1,2,3}` | 순서: 비누적 → bucket 극값 선택 (적응 B) · 누적/expand → bucket 집계 · 범주: 창 |
| pie / donut | 각도 방향: 바깥 링 둘레 × sweep 비율 `2π r_outer × sweep/360` | `floor(둘레 / minArc)` — **범주(조각) 수만**. 반지름 방향의 동심 링 수 = stack 모드의 시리즈 수 `S` (`marks/pie.ts:237-252`) 는 범주 fit 과 무관하고 `minRing` 을 보장하지 않는다 (최소 크기 미보장 원칙) — 비용은 `S × fitEff × 1 ≤ M` 으로만 제한, 초과 시 진단 `too-many-series` + 앞 `floor(M / fitEff)` 시리즈만 (링 순서 = seriesConfig 순서) | 1 조각                                                 | others                                                                          |
| radar       | 둘레 `2π r × sweep/360` (축 간 호)                            | `floor(둘레 / minAxisGap)`                                                                                                                                                                                                                                                                                                                          | 점 1 (면은 시리즈당 1, 고정)                           | others (축)                                                                     |
| radial      | 반지름 `r_outer − r_inner` (링 두께)                          | `floor((r_outer − r_inner) / minRing)`                                                                                                                                                                                                                                                                                                              | 1 링                                                   | others (링)                                                                     |

- `minSlot / minPointGap / minArc / minAxisGap / minRing` 은 `ChartMetrics` 확장 (rule chart 채널, D3 SSOT). **P0 확정값 (light/dark 실측, `211-p0-spike.md` §1): `minSlot 8` (바닥 7 — S1 막대 5.98px + 틈 1.5px 에서 개수가 정확) · `minPointGap 3` (2px 는 zigzag 진폭이 1/3 로 접힌다) · `minArc 5` (바닥 4.3) · `minAxisGap 12` (스포크는 4px 부터 갈리나 라벨 가독성 축으로 설계값 유지) · `minRing 5` (`RING_GAP 3` + 두께 2; 4 는 32/33)**. light/dark 차이 없음 — 테마 채널이 아니라 상수. 저장 props 가 아니다. `minRing` 은 **radial 전용** (radial 은 링 = 범주라 개수 예산이 맞다); pie 의 동심 링은 시리즈라 개수 예산 대상이 아니다 (round 2 m1).
- `fit` 은 `size` (두 leg 모두 픽셀 `ChartSize` 를 가진다 — Canvas layout rect, DOM `ResizeObserver`) 에서 파생하므로 같은 크기·같은 `S` 면 같은 값. 크기가 다르면 (Compare Mode 반폭) 다른 것이 계약이다 (§5 fixture).
- 창 트랙 (§2.5) 이 플롯 높이를 차지하면 **두 leg 가 같은 높이를 예약**해야 `plot` 이 같다 — 예약 여부는 `n > fitEff` 로 결정되고 두 leg 가 같은 입력에서 같은 판정을 내린다 (Canvas 는 비활성 트랙을 그린다).

### 2.3 축 종류 판정 (round 1 m1)

- 판정은 `resolveChartData` 정규화 단계에서 1회, 결과 `axisKind: "category" | "ordinal"` 을 모델·scene 에 실어 두 leg 가 같이 읽는다.
- **`ordinal` 자동 판정은 보수적이다**: dimension 의 모든 값 (결측 제외) 이 엄격 ISO-8601 (`YYYY-MM-DD` 또는 `YYYY-MM-DDTHH:mm[:ss[.sss]][Z|±hh:mm]`) 로 파싱되고 **첫 출현 순서가 단조 (오름 또는 내림)** 일 때만. 숫자형 문자열 (`"001"`, `"2024"`) 은 자동으로 `ordinal` 이 되지 않는다 (ID 를 기간처럼 묶는 사고 방지) — 사용자가 `budgetAxis: "ordinal"` 로 opt-in. 파싱 실패 하나라도 있으면 `category`.
- x 는 **범주 index** (첫 출현 순서, 현행 `series.ts:112-118`) 다. 시간 거리 비례 배치·불규칙 간격 재현은 범위 밖 — 현행 band scale 도 index 배치이므로 계약이 바뀌지 않는다. 내림차순 날짜는 그대로 내림차순 index 로 두고 bucket 은 인접 index 로 묶는다 (기간 = 인접 index 구간, 라벨은 `첫 ~ 끝`).
- 결측 dimension (`""`) 은 현행대로 빈 라벨 범주 1개 — bucket 안에서는 다른 범주와 같이 묶인다.

### 2.4 overflow — 종류 × 축 지원표

| `overflow`                   | bar               | line / area                   | pie / donut | radar  | radial |
| ---------------------------- | ----------------- | ----------------------------- | ----------- | ------ | ------ |
| `window` (창)                | ✓ 기본 (category) | ✓ 기본 (category)             | ✗           | ✗      | ✗      |
| `aggregate` (bucket 집계)    | ✓ 기본 (ordinal)  | ✓ 기본 (ordinal, 누적/expand) | ✗           | ✗      | ✗      |
| `extrema` (bucket 극값 선택) | ✗                 | ✓ 기본 (ordinal, 비누적)      | ✗           | ✗      | ✗      |
| `others` (묶기)              | ✓ (명시 시)       | ✗                             | ✓ 기본      | ✓ 기본 | ✓ 기본 |

- 저장 `budgetOverflow: "auto" | "window" | "aggregate" | "extrema" | "others"` (기본 `auto` = 표의 "기본"). **P0 계약 보정 (2026-09-10)**: `displayBudget` 객체 한 묶음 대신 **평면 키 4개** — `budgetOverflow` · `budgetAggregate` · `budgetAxis` · `budgetOthersLabel`. catalog `InspectorFieldKind` (`catalog/types.ts:137-148`) 에 객체 kind 가 없고, 객체는 `sameValue` (`chartPresentationPatch.ts:100-104`) · `Chart.tsx` 스칼라 memo · Skia allowlist 세 곳에 직렬화 키가 더 필요해 결선이 길다 (`211-p0-spike.md` §4). 뜻은 같다 (선택적, 직교, 문서 재직렬화 0). 표에 ✗ 인 조합은 validator 가 거부 → ADR-210 `presentation.ok=false` + `CHART_INVALID_SETTINGS_TEXT` 경로 재사용.
- **집계 연산은 표시 형식과 분리한다** (round 1 h1): `budgetAggregate: "sum" | "mean" | "max" | "min"` (기본 `sum` — 현행 범주 합산 `series.ts:102-107` 과 같은 의미). `valueFormat` (ADR-210) 은 문자열만 바꾸고 집계에 영향을 주지 않는다. `mean` 은 **bucket 안 범주 값의 평균** (범주 값은 이미 행 합산이므로 "행 평균" 이 아니다 — 문서에 명시). 결측은 제외 (0 아님), 음수는 그대로 합산. 극값 선택·창은 원본 점이라 집계 접미가 붙지 않는다.
- **bucket 집계** (`aggregate`): `B = fitEff` 개 bucket, bucket 크기 `ceil(n / B)` (마지막 bucket 만 작을 수 있음). 시리즈마다 같은 bucket 경계. 라벨 `첫 ~ 끝`. tooltip/축 값 문자열 = `formatValue(v)` + 접미 (`합계` / `평균` / `최대` / `최소`, 문자열 SSOT `presentation.ts`, i18n 은 §2.7).
- **bucket 극값 선택** (`extrema`, round 1 h2 — LTTB 대체 · round 2 h1/m3 로 상한·결측 계약 확정): 같은 bucket 경계에서 **시리즈마다** bucket 안 `min` 과 `max` 의 범주 index 를 고른다 (같으면 1개). 그 시리즈의 bucket 안에 **결측 run** 이 있으면 결측 index 하나 (첫 결측) 를 추가로 고른다 — gap sentinel. 선택 집합 `U` = 모든 시리즈 선택의 합집합 (`|U| ≤ 3·S·B`), 각 시리즈는 `U` 의 모든 index 에서 **원본 값** 을 그린다 (원본이 결측이면 결측 — `connectNulls:false` (`RechartsChart.tsx:555`) 가 그 자리에서 선을 끊는다). **보장**: (a) 시리즈별 전역 max/min 과 bucket 별 max/min 이 정확히 보존된다 (선택 규칙에 의해, 오차 0); (b) 원본에 결측 run 이 있는 bucket 은 visible 에서도 그 시리즈의 선이 끊긴다 (gap **존재** 보존 — 위치는 bucket 안 근사, 같은 bucket 의 결측 run 여러 개는 하나로 합쳐질 수 있다). **보장하지 않는 것**: 픽셀 단위 외관 동일성 — 선택 index 를 band 로 다시 배치하므로 M4 의 무손실 rasterization 결론은 승계하지 않는다 (M4 에서 가져온 것은 "픽셀 열 단위 min/max 선택으로 극값을 보존한다" 는 규칙뿐). **마크 상한 (round 2 h1)**: 실제 그려지는 점은 `S × |U|` 이고 최악 `|U| = 3·S·B` 라 점 수가 `3·S²·B` 까지 간다 — 그래서 B 를 고정하지 않고 **적응**한다: `B ← fitEff` 에서 시작해 실제 선택 결과 `S × |U| × k > M` 이면 `B ← ceil(B / 2)` 로 다시 고른다 (bucket 이 줄면 선택도 줄어 단조 감소; 입력이 같으면 두 leg 가 같은 B 에 이른다). `B = 1` 에서도 넘치면 (`3·S² × k > M`, 예: M 2,000 · k 1 → S ≥ 26) 진단 `too-many-series` 를 내고 **bucket 집계 (`aggregate`, 명시 통계)** 로 fallback 한다. 극값이 겹치는 보통 데이터에서는 `|U| ≪ 3·S·B` 라 B 가 fitEff 그대로다. LTTB 는 채택하지 않는다 — 대표 시리즈 하나의 모양으로 다른 시리즈 spike 를 잃는 반례가 있어서다.
- **others**: 범주 단위로 묶는다 (시리즈가 여럿이어도 범주 목록은 공유). ranking key = 범주별 `Σ_series |value|` (pie 는 현행 절댓값 면적 규약 `marks/pie.ts:201-204` 와 같은 축, radar/radial 도 같은 key). 상위 `fitEff − 1` 을 남기고 나머지를 synthetic 범주 (`key: "__others__"`, 원본 라벨과 충돌하지 않는 별도 key — 원본에 "기타" 라벨이 있어도 다른 범주로 유지) 로 **시리즈별 sum** 합산. 부호: 합산은 원본 부호로 (pie 는 그 결과의 절댓값을 면적으로 — `+10/−10` 이 0 이 되면 조각이 사라지는 것은 현행 pie 의 0 값 규약과 같다; 대신 tooltip 은 원본 합을 보인다). domain 은 others 합산 **뒤** transformed 전체에서 (§2.5) — radial 의 clamp 도 그 domain 기준.

### 2.5 창 (window)

- 모델 세 층 (round 2 m2): **input** (원본 범주·값, `series.ts` 합산 결과) → **transformed** (overflow 적용 후 전체: 창 = input 그대로 · 집계 = bucket 통계값 전체 · others = 묶은 뒤 전체 · 극값 = 선택 index 의 원본 값 전체) → **visible** (창 모드만 `[start, start + fitEff)` 로 자름, 다른 모드는 transformed = visible). **domain (축 범위) 은 항상 transformed 전체**에서 — 창은 input 과 같으니 창을 옮겨도 축이 흔들리지 않고, 집계는 통계값 범위 (`[60, 60]` 을 sum 으로 묶으면 120 이 domain 안), others 는 합산값 포함, 극값은 원본 극값이 선택되므로 input 과 같다 (`computeChartScene.ts:444-445` 의 extent 를 transformed grid 에서 계산). expand 정규화는 transformed 위에서. 범례·시리즈 목록은 input 에서.
- 창 위치 `start` 는 **저장하지 않는 뷰 상태** (Preview/Publish 컴포넌트 state, canonical write 0). Canvas 는 항상 `start = 0` 을 정적으로 그린다 (빌더는 상호작용 표면이 아니다 — 메모리 `feedback-skia-builder-not-frontend-interaction-belongs-to-preview`).
- clamp/reset (round 1 m3): `start = clamp(start, 0, max(0, n − fitEff))`. 데이터 identity (`rowsKey`) · 차트 종류 · `dataMode` · `overflow` 가 바뀌면 0 으로 reset, `size` 만 바뀌면 clamp. 마지막 창은 `n − fitEff` 에서 시작 (창 길이 불변).
- **컨트롤은 Recharts `Brush` 가 아니다** (round 1 m3: 3.10.1 `Brush` 는 손잡이 둘의 index 를 각각 움직여 창 길이가 변한다). 창 트랙 = shared 의 RAC `Slider` (`packages/shared/src/components/Slider.tsx`, D1 은 RAC 소유) 단일 thumb, `minValue 0 · maxValue n − fitEff · step 1` — 화살표 키 1 슬롯, Home/End 끝. PageUp/Down 은 RAC 기본 (범위의 1/10 을 step 에 맞춤, `useSliderState` pageSize) 을 **그대로 둔다** — 창 길이만큼 넘기는 요구는 철회 (round 2 l1: Slider 파일 변경 0 을 지키는 쪽). **P0 실측 (`211-p0-spike.md` §3)**: uncontrolled shared Slider 에서 11 키 trace 가 기대와 byte 일치 (pageSize 94 = 938/10); **canonical `Slider` 노드를 Preview 에 두면 canonical `value` 가 controlled 로 걸려 키가 움직이지 않는다** → 창 트랙은 canonical 노드가 아니라 **RechartsChart 안의 뷰 상태 Slider** (`value/onChange` 를 컴포넌트가 직접) 로 고정. 별도 ARIA 작성 없음. 트랙은 플롯 **아래** 에 `windowTrackHeight` (metrics, **P0 확정 24** — Preview 실측 `.react-aria-Slider` 상자 12 · 트랙 8 · md thumb 18 이 상자 밖으로 넘쳐 18 + 3×2) 를 예약하고 Canvas 는 같은 높이의 비활성 트랙을 그린다 (§2.2 마지막 항). fit 감소는 수평 bar 만 (높이 300 → fit 31 → 28).
- 접근성: 창 이동은 Slider 가, 마크 탐색은 기존 Recharts `accessibilityLayer` 가 (visible model 범위). tooltip 은 visible model 의 원본 값.

## 5. 검증 fixture 와 판정

- **손계산 오라클** (Q5 독립성) — 표를 먼저 적고 테스트가 표를 읽는다: 폭 500 · minSlot 8 · S 1 → bar `fit 62`; S 3 묶음 → 20; 누적 S 3 → 62 이지만 `M 2,000 / (3×1)` → 666 이라 `fitEff 62`; 폭 4 → `fit 0` (진단); 반지름 60 · minArc 5 (P0 확정) → pie `fit 75` (링 수와 무관), 값 `[1000, 1]` 은 조각 2 (작은 호 0.377px 허용 — 최소 크기 미보장 fixture); 링 (시리즈) 3 → 데이터 마크 `3 × 62 = 186 ≤ M`; radial 반지름 60 · inner 0 · minRing 5 (P0 확정) → `fit 12`; line 폭 500 · minPointGap 3 → `fit 166`; 극값 S 4 · B 250 · 겹치지 않는 극값 (bucket 당 범주 8 이상) → `|U| = 2,000`, 점 `8,000 > M` → 적응 B 125 → 62 → … 까지 `S × |U| ≤ P 5,000` (M 2,000 가정 표: 250→2,000→8,000 · 125→1,000→4,000 · 63→504→2,016 · 32→256→1,024 — P0 시험 구현 39/39 PASS, `211-p0-spike.md` §5; P1 은 P 5,000 · fallback 은 S 26 · B 1 · |U| 78 → 2,028 > 2,000 fixture 를 P 기준으로 다시 계산).
- **극값 보존** (extrema): 평탄한 시리즈 A + 서로 다른 위치에 spike 가 있는 B/C + 부호 반대 spike (상쇄) + 결측 gap `[1, null, 2]` — 각 시리즈의 전역 max/min index 가 선택 집합에 **정확히** 포함 (오차 0), 결측 run 이 있는 bucket 은 visible 에서도 그 시리즈 선이 끊김 (세그먼트 수 ≥ 1 감소 없음 판정은 bucket 단위), **실제 렌더 점 수 `S × |U| × k ≤ M`** (선택 수가 아니라 점 수), 선택 알고리즘과 무관한 원본 스캔 오라클.

## 7. 마이그레이션 · rollback (round 1 m4)

- **데이터 보존**과 **시각 동일성**을 분리한다. 데이터: `budget*` 키는 선택적, 기존 문서 재직렬화 0, 구버전은 무시 (손실 0). 시각: 영향 집합은 세 축으로 나뉜다 — raw 행 수 > 200 (A: Canvas 합계가 바뀜, Preview 는 이미 전체 행이라 동일), 집계 후 범주 수 > fitEff (B: 창/축약/others — 행 수와 무관, 폭이 좁은 50범주도 해당), 표시 마크 > M (C: `fitEff` 축소). 건수는 P0 inventory 에서 dataBinding 차트별로 (행 수 · 범주 수 · 폭) 집계한다 (로컬 프로젝트라 사전 % 없음) — **P0 결과: 로컬 Chart 2개, (A) 0 · (B) 0 · (C) 0** (`211-p0-spike.md` §4).
- 구버전 rollback: Canvas 는 200행 샘플로, Preview 는 전체 행으로 **각각** 돌아간다 (두 leg 가 다시 달라진다) — "구버전 200행 복귀" 는 Canvas 한정임을 명시.
- 행 상한 `R` 은 P0 실측으로 **20,000** 으로 도입한다 (두 leg 동일 적용 + 안내 `rows-truncated`; 근거 `211-p0-spike.md` §2).
- rollback = 커밋 revert. 토큰 `--chart-others` 는 theme 에 남아도 무해.

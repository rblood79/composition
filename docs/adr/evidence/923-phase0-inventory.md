## §A. Canvas 전용 display override 전수 (HC2 · G4 후반 입력)

### A-1. 방법

- **catalog**: `packages/shared/src/catalog/generated/componentRulesTable.ts:17` `COMPONENT_RULES_TABLE` 의 객체 키 **123** (`body` · `frame` · `Slot` · `Group` 포함). `tsx` import 로 `containerStyles.display`(top-level) · `structure.containerStyles.display` · `structure.composition.containerStyles.display` · `structure.composition.layout` 을 추출. top-level display 보유 16, top-level `containerStyles` 는 있으나 display 키가 없는 rule 9 (body · Description · GridList · Heading · Paragraph · Column · Cell · Table · Text).
- **Canvas 실효 display** (자기 style 경로): `apps/builder/src/builder/workspace/canvas/layout/engines/implicitStyles.ts:291 resolveContainerStylesFallback` — top-level `rule.containerStyles` 가 있으면 그것을 **통째로 대체** (`:341-347` 주석 "top-level 은 override 가 아니라 대체"), 없으면 `packages/shared/src/catalog/resolvers/resolveCatalogContainer.ts:77 resolveCatalogContainerBase` (layout 토큰 `LAYOUT_TOKEN_STYLES` → `structure.containerStyles` → `structure.composition.containerStyles`, last-wins). **HC2 가 말하는 "catalog `containerStyles.display`" 는 top-level 16건이지만 Canvas 가 실제 읽는 display 는 structure 층까지다** — 표의 "Canvas 실효" 열이 그 값.
- **DOM CSS**: `packages/shared/src/components/styles/**/*.css` 146 파일에서 `display:` 선언 **376** 건을 셀렉터·file:line 과 함께 파싱. 마지막 compound 가 정확히 `.react-aria-{Rule}` (속성/의사 선택자 없음, 조상 문맥 없음) 인 선언만 "base" 로 표에 싣고, 문맥(`.react-aria-Calendar .react-aria-Button`)·상태(`[data-…]`, `:hover`) 선언은 개수만 비고에 둔다. **캐스케이드 결과가 아니라 선언 기준** — 한 파일 안에서 같은 셀렉터가 두 번 display 를 내면 둘 다 인용 (generated CSS 는 "Base styles — archetype" 블록과 "Container styles" 블록이 각각 display 를 낸다 — 예 `generated/Card.css:11 inline-flex` → `:23 flex`, 같은 블록 안이라 뒤가 이긴다).
- **live / dead**: import 그래프 = `styles/index.css` `@import` + 컴포넌트 tsx 의 `import "./styles/X.css"` + css 간 `@import`. 어디서도 import 되지 않는 **27 파일**은 `[dead]` 표기 (A-4).
- 판정 열: 일치 = top display 가 live base 선언 전부와 같음 · **불일치** = (i) 다름 / (iii) catalog 만 inline-\* · DOM 선언 없음 = top 은 있는데 live base 선언 0 · (ii-a) = top 없음 + DOM inline-\* + structure 가 inline-\* 공급 · **(ii-b)** = top 없음 + DOM inline-\* + Canvas 는 `INLINE_BLOCK_TAGS`/기본값.

## §E. pencil import 경로 (breakdown §2.5 `?`)

정적 판독 (`apps/builder/src/adapters/pencil/{types,pencilSchemaMap,pencilImport,pencilExport,index}.ts` · `apps/builder/src/resolvers/canonical/importPayloadAdapter.ts` · `adapters/pencil/__tests__/*` · 변환기 본체 `packages/shared/src/types/pencil-adapter.types.ts`).

1. **display 를 쓰는가**: 안 쓴다 — 파생 규칙 0. `pencil-adapter.types.ts:258-268 collectPencilProps` 가 pen 노드의 `PENCIL_NODE_FIELDS`(`:106-121`: id/type/children/metadata/reusable/ref/descendants/slot/name/clip/placeholder/responsive) **외의 모든 키를 `props` 로 그대로 복사**한다. `.pen` 속성(`fill`, `layout` 등) → `style.display` 매핑 없음 (`display` 문자열 grep 0건 — adapters/pencil 5 파일 · importPayloadAdapter · pencil-adapter.types). 따라서 값은 "없음" 이지만, pen 노드가 `style: { display: … }` 키를 갖고 있으면 검증 없이 그대로 통과한다 (정규화 0). 타입 매핑 `pencilSchemaMap.ts:25-39` / `pencil-adapter.types.ts:240-255`: rectangle·ellipse·line·polygon·path·frame·group → `frame`, text·note·prompt·context → `Text`, icon_font → `Icon`, `metadata.compositionType` 이 있으면 원 composition 타입(예 Button) 복원 (`pencilRoundtrip.test.ts:74-99`).
2. **chain 경유?**: **✗ — hydration migration chain 도, store 직접도 아니다.** `adapters/pencil/pencilImport.ts:20 importPencilDocument` 는 production caller 0 (`index.ts` re-export + 테스트만). production 경로는 `resolvers/canonical/importPayloadAdapter.ts:32 normalizeCompositionImportPayload` ← `importRegistry.ts:144 fetchCompositionDocumentFromSource` (문서 `imports` 의 URL 을 fetch) → 레지스트리 `loaded` Map (`importRegistry.ts:99`, 비영속 캐시) → `storeBridge.ts:108 resolveCanonicalDocument(doc, cache, imports)` 의 ref 해석 입력. prefetch 호출자는 `preview/App.tsx:191-192` 와 `storeBridge.ts:113-117 prefetchResolvedTreeImports` (builder 측 호출자 grep 0 — preview 만). `usePageManager.ts:385-395` migration chain 은 지나지 않고 IndexedDB 에도 쓰이지 않는다. builder 에 `.pen` 파일 열기 UI 없음 (grep `pencil|\.pen` 비-adapter 결과는 Skia paint/시맨틱 명칭뿐).
3. **block 컨테이너 + inline-level 자식 조합 생성 가능?**: **가능.** pen `frame`/`rectangle` → canonical `frame` (catalog `frame` rule 에 display 없음 → Canvas block 기본) 아래 `icon_font` → `Icon` (`INLINE_BLOCK_TAGS "icon"` → 부모 판정 inline-block) 또는 `metadata.compositionType: "Button"` 복원 → 그대로 IFC 시뮬레이션 대상. import 는 display 를 정규화하지 않으므로 pen 에 적힌 `style.display` 도 그대로 유입. 단 2 에 따라 imported 노드는 ref 해석용 read-only 라 persisted 문서로는 들어가지 않는다 (S4 정규화 chokepoint 논의는 §8 B 갈래).

## 관찰 — ADR / breakdown 서술과 어긋난 사실 (수정 제안 없음, 기록만)

1. ADR 사실 4 "top-level rule 121" → 실제 **123** (`body`·`frame`·`Slot`·`Group` 포함) · 사실 7 "catalog inline-\* 선언 30건" → **29**.
2. HC2 의 비교 대상 "catalog `containerStyles.display`" 는 top-level 만 가리키지만, Canvas 자기 style 은 ADR-171 Phase 3 이후 structure 층까지 읽는다 (`implicitStyles.ts:291-347`) — (ii-a) 17건은 top-level 없이 이미 DOM 과 같은 outer 다. `resolveDefaultDisplay` 는 `resolveContainerStylesFallback` 과 같은 precedence 여야 한다.
3. `INLINE_BLOCK_TAGS` 6건(B) 은 display 역할이 틀렸다 — DOM·catalog 가 block-level 인데 부모가 inline-block 으로 본다. Menu 는 top-level inline-flex 가 의도된 D1 차이(B7) 라 HC2 "0" 과 충돌한다.
4. generated CSS 27 파일 미import (A-4) — DOM 실효 display 가 선언과 다른 rule 이 있다 (ProgressCircle·StatusLight·Breadcrumb·DisclosureHeader·CalendarHeader 등). 수동↔generated 충돌 4건 (Checkbox·Radio·Breadcrumbs·MenuItem) 은 live DOM 으로만 확정.
5. `pnpm test:parity -- <file>` 은 파일 필터가 안 걸린다 (`--` 통과) — G0 (a) 도 같은 형식으로 보고됐다면 전체 실행이었을 것.
6. breakdown §2.5 pencil 행의 `?` → "✗ (import 레지스트리 캐시, 비영속·ref 해석 전용; display 정규화 0)". §6 "평균 재직렬화 파일 수" → "영향 컨테이너 %·영향 문서 수" 로 대체.

### Slot 값 선택 근거 (block)

- **부모가 blockify 하지 않는다**: production 에서 Slot 은 reusable frame 편집에서만 생성되고 (`DataComponents.ts:60-80` — `layoutId` 없으면 경고) frame body 의 자식이다. body 는 `createDefaultBodyProps` (`unified.types.ts:1816`) display **block** — flex/grid 부모가 아니라 outer 가 배치를 정한다 ("영향 있음"). 실측이 그 증거: DOM `.react-aria-Slot` 이 inline-flex 일 때 placeholder 가 73.47px 로 shrink-to-fit, block 이면 400 (부모 폭).
- **block 이 맞는 이유**: Slot 은 페이지 내용이 들어가는 영역이라 page 모드 preview (`App.tsx:1044` `.preview-slot`, UA block) · Canvas (block, `resolvePageWithFrame` 가 page 내용을 Slot 에 투영) 가 이미 block 이다. 종전 inline-flex 는 archetype `default` (button 계열 base — cursor pointer · user-select none · transition) 기본값의 누출이지 Slot 의 의도가 아니다. page 모드에서 자식이 있을 때 flex 로 두면 Canvas 가 자식을 가로로 놓아 `.preview-slot` (세로 흐름) 과 갈린다 — block 만이 두 모드 모두에서 세 표면과 같다.
- **Canvas 변경 0**: `resolveDefaultDisplay("slot")` 은 종전 캔버스 기본 block → 이제 spec 파생 block. `adr923IntrinsicMeasureSplit.test.ts` 의 잔존 spec 3 단언을 Frame/Group (미등재 → block) + Slot (block 명시) 로 분리.

### StatusLight — 판정 전제와 다른 사실 (보고)

HC2 판정 (`923-phase5-cutover.md` §5) 은 "catalog inline-flex ↔ live flex" 였다. live 는 `@composition/shared/components/StatusLight` 를 직접 마운트한 값이다. 그러나 preview `App.tsx:828` 은 `rendererMap[type]` 을 먼저 찾고 `rendererMap.StatusLight` 는 `LayoutRenderers.renderStatusLight` — shared 컴포넌트가 아니라 자체 div 로 `display: "inline-flex"` 를 쓴다 (`:1459`, 주석: "catalog(D3 SSOT) generated StatusLight.css = inline-flex — 블록 stretch(flex) 였던 종전 inline 값은 Skia(fit-content 75)와 폭 발산 (CSS 388, 2026-07-13 sweep)"). publish 는 `ComponentRegistry.tsx:493` `createHtmlElement("div")`. 즉 `StatusLight.tsx` 의 flex 는 어느 production 표면에도 닿지 않는다 (같은 구조의 Avatar 는 renderer 와 shared 가 둘 다 flex 라 결론이 같다). catalog 를 flex 로 바꾸면 Canvas 가 부모 폭으로 늘어나 preview inline-flex (fit-content) 와 **새로** 갈린다 — 2026-07-13 에 닫은 발산의 재개. 따라서 값은 두고 DOM 측정 경로를 실경로로 고쳐 `일치` 로 판정했다. `StatusLight.tsx:87` flex 는 publish 가 shared 컴포넌트를 쓰게 될 때 (publish 는 현재 oracle·작업 대상 아님) 다시 볼 사항 — 참고 캡처 `sharedStatusLight = "flex"` 를 rect 게이트 artifact 에 남긴다.

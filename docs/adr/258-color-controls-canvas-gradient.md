## Context

### 도메인

- **D2 (Props/API)** — S2 1.8.0 (= RAC 1.21.0 와 같은 이름) 의 ColorArea `colorSpace` · `xChannel` · `yChannel` (+ `xName` · `yName` — 두 숨은 input 의 form 이름), ColorSlider `channel` (**필수** — `useColorSliderState.d.ts:8` `channel: ColorChannel`) · `colorSpace` · `label` (S2 string), 그리고 셋 모두의 `value` / `defaultValue` (`string | Color`) 를 binding accepts 로 들인다. 값 타입은 react-stately 정의 그대로 — `ColorSpace = 'rgb' | 'hsl' | 'hsb'`, `ColorChannel = 'hue' | 'saturation' | 'brightness' | 'lightness' | 'red' | 'green' | 'blue' | 'alpha'` (`react-stately/dist/types/src/color/types.d.ts:3,5`). S2 가 더하는 시각 prop 은 없다 — S2 ColorArea · ColorSlider 는 `size` 를 받지 않고 (`s2props.json` — 고정 192px, `ColorArea.tsx:67-68` `size: 192, minSize: 64`), ColorWheel 의 `size` 는 2026-10-10 에 들였다. ColorSlider `label` 은 RAC 의 Label 부품 글자다 (RAC 는 Label 의 기본 children 으로 채널 이름을 넣는다 — `ColorSlider.mjs:77`).
- **D3 (시각 스타일)** — 이 ADR 의 중심. 그라데이션은 rule 의 정적 값이 아니라 **문서 값 (색 공간 · 채널 · 색) 의 함수**다 — DOM 은 RAC 가 그 함수를 inline style 로 낸다. 두 consumer 가 같은 값을 읽어야 한다 (ADR-257 의 트랙 목록과 같은 종류 — resolver 파생값). thumb 의 모양 (16px · 테두리 4px `--bg-raised` · 그림자 · focus 20px) 은 지금 수동 CSS 3 파일에 중복 선언돼 있고 (`ColorArea.css:14-27` · `ColorSlider.css:36-49` · `ColorWheel.css:2-14` — ADR-106-a 가 남긴 과제 `:170` · `:202`) Canvas 는 읽지 않는다 — catalog rule 로 옮겨 두 consumer 가 같이 읽게 한다 (ssot-hierarchy §6 「수동 CSS 가 catalog 에서 파생 아님」 해소).
- **D1 (DOM/접근성)** — 변경 없음. RAC `ColorArea` · `ColorSlider` · `ColorWheel` · `ColorThumb` · `ColorWheelTrack` · `SliderTrack` 을 그대로 쓴다. 그라데이션 · thumb 위치 · thumb 바탕색을 만드는 RAC hook (`useColorAreaGradient` · `useColorSlider` `generateBackground` · `useColorWheel`) 은 D1 소유이며 다시 쓰지 않는다 — Canvas 가 **같은 함수를 자기 쪽에 둔다**. RAC 가 노출하는 CSS 변수는 없고 (`--thumb-*` 류 0건), inline style 과 data 속성 (`data-orientation` · `data-disabled` · thumb 의 `data-dragging` · `data-focus-visible`) 뿐이다.

### 현재 (실측 2026-10-11)

1. **binding accepts** — ColorArea `isDisabled` 만 (`ColorArea.binding.ts:30`), ColorSlider `isDisabled` · `orientation` (`:31-44`), ColorWheel `size` · `isDisabled` (`:37-38`). 셋 다 **`value` · `defaultValue` 가 없다.** 머리말이 색 축을 두지 않은 이유를 적어 두었다 (`ColorArea.binding.ts:31-32` 「Canvas 는 box 만 그려 두 쪽이 갈리므로 아직 두지 않는다」).
2. **Canvas 는 상자 하나** — Color 전용 Canvas 코드가 없다. `canvasBinding.ts:376-417` 의 binding 맵에 Color 항목은 `colorswatchpickeritem` 하나이고 나머지는 `ruleNodeData` → `ruleShapes.ts:196-233` 의 generic 경로 (binding 에 `skiaPrimitive` 없음) 로 rule fill `{color.base}` + border `{color.border}` 상자를 그린다 (`componentRulesTable.ts:2411-2462` · `:2710-2748` · `:2902-2945`). ColorWheel 은 지름 정사각 + `radius.full` 이라 **속이 찬 원판**이다 (`compositionRoot.ts:926-929` `catalogColorWheelDiameter` · `resolveCatalogRuleCanvasBox.ts:402-410` 기본 180 · floor 175 · 트랙 26). ColorArea · ColorSlider rule 의 S/L size 블록 (120/240 · 16/24) 은 binding 에 `size` 가 없어 닿지 않는 값이다.
3. **Preview 는 RAC 를 자식 없이 그린다** — `ruleDom` 이 `RAC[binding.source.component]` 를 직접 쓰고 (`domBinding.tsx:1574-1577`) 자식은 노드 자식인데 세 type 은 `DOM_LEAF_TYPES` (`nestingRules.ts:197-200`) 라 비어 있다. 공용 래퍼 `packages/shared/src/components/ColorArea.tsx` (thumb 포함) · `ColorSlider.tsx` (SliderTrack > ColorThumb) · `ColorWheel.tsx` 는 catalog runtime 이 import 하지 않는다 (grep 0). 그래서 코드상 — ColorArea 는 루트 inline 그라데이션은 있고 thumb 이 없다, ColorSlider 는 그라데이션을 받을 `SliderTrack` 요소가 없다, ColorWheel 은 `ColorWheelTrack` 이 없어 고리가 없다. **ColorSlider 는 그 전에 던진다** — 설치 RAC 를 `renderToString` 으로 마운트하면 value · defaultValue 없이 `useColorSliderState requires a value or defaultValue` (`useColorSliderState.mjs:22`, 2026-10-11 실측 — channel 을 줘도 같다). ColorArea 기본값은 `#ffffff` (`useColorAreaState.mjs:20`), ColorWheel 은 `hsl(0, 100%, 50%)` (`useColorWheelState.mjs:18,52`). Preview 의 실제 표시 (오류 경계 · 빈 상자) 는 Phase 0 이 live 로 확정한다.
4. **RAC 가 만드는 그라데이션** (설치 1.21.0 · `react-aria/dist/private/color/`, `renderToString` 으로 고정):
   - ColorArea (`useColorAreaGradient.mjs:44-77`): **rgb** = `linear-gradient(to right, rgb(x=0), rgb(x=255))`, `linear-gradient(to top, rgb(y=0), rgb(y=255))`, `rgb(z=값)` 세 층 + `background-blend-mode: screen` (예 `#8040c0` → `…rgba(0,0,0,1)→rgba(255,0,0,1)`, `…→rgba(0,255,0,1)`, `rgba(0,0,192,1)`). **hsl** = z 가 아닌 두 채널의 층 (hue 7 stop · saturation `[s=0], transparent` · lightness `black, transparent, white`) 을 뒤집어 겹치고 z 가 hue 면 바탕색 한 층. **hsb** = 같은 꼴 (brightness `black, transparent`). 축 기본값은 `getColorSpaceAxes` — x = 첫 채널 (≠ y), y = 다음, z = 나머지 (`Color.mjs:118-122`). thumb 는 `left/top %` + `translate(-50%, -50%)` (`:95-103`), 바탕색 `state.getDisplayColor()` (`ColorThumb.mjs:23-24`).
   - ColorSlider (`useColorSlider.mjs:42-82`): 방향 `to right` (가로 · ltr) / `to top` (세로). hue 7 stop (0 … 360), lightness 3 stop (min · 중간 · max — 중간이 없으면 흑백만 보인다), 그 외 (saturation · brightness · red · green · blue · alpha) 2 stop (min · max), 값은 현재 색에서 그 채널만 바꾼 것. **track** (`SliderTrack`) 의 `background` 로 들어간다 (`:100-108`). 예 `channel="alpha"` · `#ff0000` 세로 → `linear-gradient(to top, rgba(255, 0, 0, 0), rgba(255, 0, 0, 1))`.
   - ColorWheel (`useColorWheel.mjs:208-244`): track = `conic-gradient(from 90deg, hsl(0..360 — 13 stop))` + `clipPath: path(evenodd, 바깥 원 안 원)`, 크기 `outerRadius × 2`; thumb 는 반지름 `(inner + outer) / 2` 위의 px 좌표. 각도 ↔ 좌표 규약은 Phase 0 이 설치 소스 (`:37` · 좌표 함수) 에서 고정한다.
5. **Skia 쪽 재료는 있다** — `fills.ts` `applyFill` 이 `linear-gradient` (`MakeLinearGradient`, `:83-107`) · `radial-gradient` · `angular-gradient` (`MakeSweepGradient` + 회전 행렬, `:143-171`) 를 셰이더로 만들고, `blendModes.ts:40` 이 CSS `screen` 을 `BlendMode.Screen` 으로, `nodeRendererBorders.ts:177,576` 이 evenodd path 를 쓴다. `GradientShape` (`shape.types.ts:364-382` — linear · radial · conic 한 층 · stops) 와 `specShapeConverter.ts:1056-1131` 변환기가 있지만 **production 생산자는 0건**이다 — ADR-912 cutover (`9a0e90f4c`) 가 지운 옛 spec 이 썼다 (`ColorArea.spec.ts:190-200` linear · `ColorWheel.spec.ts:157-167` conic 고리 · `ColorSlider.spec.ts:164-206` 채널별 stop — `git show 9a0e90f4c^:packages/specs/src/components/<Name>.spec.ts`). 값 → 위치 선례는 Slider (ADR-256 Phase 7c `presence.ts:995-1027` `catalogSliderThumbLayout` — 비율 → `insetLeft %` · `marginLeft -w/2`, thumb 그림은 `skiaPrimitive: "slider_thumb"`) 와 ProgressCircle (`skiaPrimitive: "value_fill_arc"` — 고리 arc, binding 머리말이 모델로 지목한 구조).
6. **닿는 길이 없다** — 팔레트 `PALETTE_ORDER` (`paletteItems.ts:205-`) 의 Color 계열은 ColorField 하나 (`:259-260`), 세 type 은 catalog `category: "color"` 인데 팔레트 카테고리 7 에 `color` 가 없다 (메모리 `feedback-palette-order-array-is-exposure-ssot-not-catalog` — 2026-08-21 보류). Components page 원본도 없다 (`reusableOriginLibrary.ts` grep 0 — ColorField · ColorSwatch · ColorSwatchPicker 만). `componentTraits.ts` 에 항목이 없다. 지금 ColorArea 를 문서에 넣는 길은 AI · import 뿐이다. G3 하니스 (`propAxisCanvasDom.browser.test.ts`) 는 `catalogPaletteDefinitionId` → 원본 없으면 `catalogTypeDefinitionId` 로 떨어지므로 팔레트 밖 type 도 fixture 로 넣을 수 있다 (`paletteInsert.ts:39-48`).

### 제약

- **Hard**: D3 대칭 — 정지 상태 (조작 전) 의 Canvas ↔ Preview 픽셀 차이 ADR-248 G3 하니스 기준 (pixelmatch 0.1 ≤ 0.001 — raw RGB 카운트 금지, 메모리 `feedback-raw-rgb-diff-is-not-adr198-hc6-metric`) · Skia 전용 시각 효과 금지 (RAC 가 CSS 로 못 내는 것을 Canvas 에만 그리지 않는다). 그라데이션 stop 색 문자열은 설치 RAC 의 출력과 **같아야** 한다 (G1 — 같은 `Color` 구현이 만든다). pre-push perf ratchet (ADR-246). initial 번들 상한 (ADR-201 재승인 — Builder ≤ 1,421,000 / Preview ≤ 623,000 B).
- **Hard**: 기존 문서 — 세 type 의 노드가 들어 있는 저장 문서 (팔레트 밖이라 AI · import 로만 생긴다) 는 G0 이 센다. 템플릿 (원본) 이 새로 생기면 `LIBRARY_CONTRACT_VERSION` (36, `document/types.ts:90`) 을 올린다 — 기존 개발용 프로젝트 거부 · 변환 없음 (ADR-251 · 253 · 256 이 쓴 길, 사용자 수용).
- **Soft**: Color 조작기는 페이지에 많아야 몇 개다 — 셰이더는 record (값 · 축) 가 바뀔 때만 다시 만든다 (G5).

### 생성기 질문 (반복 패턴 #2)

그라데이션은 문서 값의 함수라 `generate-css.ts` 가 selector 로 낼 수 없고 DOM 은 RAC inline 이다 — 생성 CSS 의 변화는 thumb · track 의 **정적 모양** (크기 · 테두리 · 그림자 · 모서리 · disabled 회색) 을 rule 로 옮기는 것뿐이다 (`.react-aria-ColorThumb` · `.react-aria-SliderTrack` · `.react-aria-ColorWheelTrack` 선택자 — 생성기는 part selector 를 이미 낸다: Slider 의 `SliderThumb` · `SliderTrack` rule). 수동 CSS 3 파일은 그만큼 줄어든다.

## Alternatives Considered

### 그라데이션의 원천 — Canvas 가 무엇을 읽는가

#### 대안 A: prop 만 — accepts 에 색 축을 넣고 Canvas 는 지금 상자 그대로

- 설명: binding 에 4 prop 을 넣는다. Preview 의 RAC 그라데이션은 바뀌고 Canvas 는 `{color.base}` 상자.
- 위험: 기술 LOW / 성능 LOW / 유지보수 **HIGH** (D3 대칭 위반이 prop 축만큼 넓어진다 — 지금은 「상자 vs 그라데이션」 하나, 뒤에는 축마다) / 마이그레이션 LOW. **사용자 기각 (2026-10-11)**.

#### 대안 B: 공용 순수 함수 — RAC 생성기와 같은 규칙을 `packages/shared` 에 두고 Canvas 가 Skia 셰이더로 그린다

- 설명: `catalog/runtime/colorControlGradient.ts` 가 (색 공간 · 축 · 색) → 층 목록 (`{ to: 'right' | 'top', stops: css 문자열[] }[]` + 바탕색 + blend) 을 낸다 — stop 색은 설치 react-stately `parseColor(...).withChannelValue(...).toString('css')` 로 만들어 RAC 와 **같은 `Color` 구현** 이다 (RAC hook 의 분기 — rgb 3 층 screen · hsl/hsb 두 층 + 바탕 · slider 7/3/2 stop · wheel 13 stop — 를 그대로 옮긴다). resolver 가 그 결과를 record 에 싣고 (`_colorGradient` — ADR-257 `_tableTracks` 와 같은 자리), Canvas 는 `skiaPrimitive` (replace 모드 — ProgressCircle `value_fill_arc` 와 같은 길) 가 층마다 `MakeLinearGradient` / `MakeSweepGradient` 셰이더로 칠하고 (rgb 는 `BlendMode.Screen`, wheel 은 evenodd 고리 clip) thumb 원을 그린다. DOM 은 RAC inline 을 그대로 쓴다 (함수를 DOM 에 쓰지 않는다 — D1).
- 근거: 같은 입력 · 같은 `Color` 구현 → stop 문자열이 같다 (G1 이 설치 RAC 출력과 문자열로 대조 — 독립 oracle). CSS `linear-gradient` 와 Skia 선형 셰이더는 둘 다 stop 사이를 선형 보간한다 — 차이는 ① 투명 stop 의 보간 공간 (CSS 는 premultiplied — `saturation`/`brightness` 층의 `transparent`, Skia 는 기본 unpremultiplied → 검게 끼는 띠; CanvasKit `MakeLinearGradient(..., flags)` 의 premul 보간 flag 로 맞춘다) ② 7 stop hue 의 sRGB 보간 (양쪽 같음) ③ 색 공간 변환 반올림 (RAC 가 낸 css 문자열을 그대로 파싱하므로 없음).
- 위험: 기술 **MEDIUM** (투명 stop premul · wheel 각도 규약 · 다층 blend 를 Skia 상자 하나에 싣는 경로 — `GradientShape` 는 한 층이라 다층 + blend 로 확장한다) / 성능 LOW (record 당 셰이더 몇 개 · 값 변경 때만) / 유지보수 **MEDIUM** (RAC 가 생성 규칙을 바꾸면 따라가야 한다 — G1 이 설치 버전에 고정된 unit 이라 버전 올릴 때 RED 로 드러난다) / 마이그레이션 LOW.

#### 대안 C: 색 공간 정확 셰이더 — SkSL 로 픽셀마다 HSL/HSB → RGB 를 계산

- 설명: hue 고리 · 면을 stop 보간이 아니라 픽셀 단위 색 변환으로 그린다 (「진짜」 색상환).
- 위험: 기술 MEDIUM / 성능 LOW / 유지보수 LOW / **D3 대칭 위반 HIGH** — DOM 은 CSS 7 stop sRGB 보간이라 stop 사이 색이 다르다 (정확 HSL ≠ 7 점 선형 보간). Skia 에만 있는 시각 — guard 가 금지한 것. 기각.

#### 대안 D: Preview 의 DOM 에서 읽기 — Canvas 가 RAC 가 만든 inline style 문자열을 받아 그린다

- 설명: Preview iframe 이 `style.background` 를 Builder 로 보내고 Canvas 가 파싱한다.
- 위험: 기술 **HIGH** (Preview 가 열려 있어야 Canvas 가 그려진다 · Compare Mode 밖에서는 상자 · 채널은 Preview → Builder 역방향 — ADR-248 채널은 Builder → Preview 한 방향) / 성능 MEDIUM / 유지보수 HIGH / 마이그레이션 LOW. 기각.

### thumb 와 track 의 구조 — 노드인가, owner 가 그리는 부품인가

#### 대안 E1: 노드 — `ColorThumb` 새 type, ColorSlider 는 `Label + SliderOutput + SliderTrack > ColorThumb`, ColorWheel 은 `ColorWheelTrack + ColorThumb`

- 설명: 레퍼런스 (react-aria.adobe.com ColorArea · ColorSlider · ColorWheel 예제) 그대로 노드 트리. Preview 는 노드를 RAC 부품으로 그리고 (ADR-256 판정 하나 — `ColorThumb` 는 RAC `ColorThumb`, `SliderTrack` · `SliderOutput` · `Label` 은 Slider 와 같은 type), Canvas 는 thumb 노드의 상자를 값에서 놓는다 (`catalogSliderThumbLayout` 과 같은 presence 함수 — ColorArea 는 2D `%`, ColorSlider 는 축 하나, ColorWheel 은 각도 → px). thumb 모양은 `ColorThumb` rule (part rule) 하나 — 세 수동 CSS 중복이 사라진다. 원본 template 3개 + `componentTraits` 항목 + contract +1.
- 위험: 기술 MEDIUM (ColorSlider 는 Slider 의 부품 type 을 공유한다 — `SliderTrack` 의 owner 판정이 Slider 전용이면 ColorSlider 를 더한다) / 성능 LOW / 유지보수 LOW (Slider 와 같은 모양 · ADR-256 원칙 「노드 트리를 RAC 부품 그대로」) / 마이그레이션 **MEDIUM** (contract +1 · 기존 노드 — AI · import 로 생긴 것 — 에 thumb 자식이 없다: 로드 시 1회 채움 또는 「자식 없으면 Canvas 가 기본 thumb 를 그린다」 폴백 — 사용자 결정 1).

#### 대안 E2: owner 가 그린다 — thumb · track 은 노드 없이 ColorArea · ColorSlider · ColorWheel rule 의 part 값으로 Canvas 가 직접, Preview 는 `delegatedDom` 이 RAC 부품을 넣는다

- 설명: toggle indicator 의 옛 모델 (`OWNER_DRAWN_PART_OWNERS`). 노드 수 불변 · contract 불변.
- 위험: 기술 LOW / 성능 LOW / 유지보수 **HIGH** (ADR-256 이 toggle · Tree chevron · Disclosure chevron 을 전부 노드로 옮겼다 — 되돌리는 방향, 작성자가 thumb 모양을 Components page 에서 편집 못 한다 · ColorSlider 의 Label · SliderOutput 은 어차피 노드여야 ADR-254 「글자 소유 = template 바인딩」 과 맞는다) / 마이그레이션 LOW.

## Decision

**대안 B + E1 을 채택한다.** 그라데이션 · thumb 위치 · thumb 색은 **`packages/shared` 의 순수 함수 하나** (`colorControlGradient.ts` — 설치 react-stately `Color` 로 RAC 와 같은 stop 문자열) 가 문서 값에서 만들고, resolver 가 record 에 실어 Canvas 가 Skia 셰이더로 그린다. DOM 은 RAC 의 inline 을 그대로 쓴다. thumb · track 은 레퍼런스대로 노드다.

1. **D2 — accepts**: ColorArea `colorSpace` (enum rgb · hsl · hsb) · `xChannel` · `yChannel` (enum — 그 색 공간의 채널만 유효, Design 패널은 색 공간에 맞는 선택지만 보이고 검증기는 밖의 값을 거부한다 — composition 제한, binding 머리말에 적는다) · `xName` · `yName` (string) · `defaultValue` (값 타입 `racColor` — 아래, binding 기본 `#ffffff` = RAC 기본). ColorSlider `channel` (enum 8 — binding 기본 `hue`, RAC 레퍼런스 첫 예제) · `colorSpace` · `label` (Label 노드 `{label}` 바인딩 — ADR-254 Decision 5) · `defaultValue` (기본 `hsl(0, 100%, 50%)` — RAC 레퍼런스 예제, RAC 는 기본값이 없어 던진다) · `orientation` 유지. ColorWheel `defaultValue` (기본 `hsl(0, 100%, 50%)` = RAC 기본). `value` (controlled) 는 들이지 않는다 — Preview 는 uncontrolled (`defaultValue`) 이고 조작은 Preview 실행 상태 (ADR-250 · 257 과 같은 원칙 — 문서 쓰기 0, Canvas 는 `defaultValue`). `isDisabled` 유지.
   - **색 값 타입 `racColor`** (round 1 h2): 받는 구문은 설치 react-stately `parseColor` 가 받는 것뿐이다 — `#rgb` · `#rgba` · `#rrggbb` · `#rrggbbaa`, 쉼표 구문 `rgb(r, g, b)` · `rgba(r, g, b, a)` · `hsl(h, s%, l%)` · `hsla(…)` · `hsb(h, s%, b%)` · `hsba(…)` (`Color.mjs:25-29` · RGB `parse` · `HSL_REGEX` · `HSB_REGEX`). CSS 이름 색 (`red`) · 공백 구문 (`rgb(255 0 0)`) · `oklch()` 는 받지 않는다 — RAC 가 던지기 때문이며 (S2/RAC 도 같은 범위, [ColorArea Value](https://react-aria.adobe.com/ColorArea)) binding 머리말에 「RAC 색 구문」 으로 적는다. 판정 함수 하나 (`isRacColorString` — `parseColor` 가 던지지 않고 채널 값이 유한) 를 문서 값 검증기 (`document/valueType.ts` — transaction staging 의 entry 검증 → 실패면 `VALIDATION` 으로 거부, revision 불변) · library template · binding 기본값 검사 · import / AI 입력 경계가 같이 부른다. 빈 문자열 · 키 없음 = binding 기본값 (거부 아님). Design 패널의 색 입력은 입력 중 draft 를 들고 있다가 판정을 통과한 값만 commit 한다 (blur · Enter — 실패면 field 오류 표시, 명령 없음). resolver · Canvas 함수는 판정을 지난 값만 받지만, 저장 문서가 손상된 경우를 위해 parse 실패 시 binding 기본값으로 그린다 (Preview 도 같은 값을 RAC 에 넘긴다 — 두 consumer 같은 폴백, 오류 경계로 가지 않는다).
2. **D3 — 그라데이션 함수**: `colorControlGradient(kind, props)` → `{ layers: [{ to, stops }], base?, blend? }` (ColorArea), `{ to, stops }` (ColorSlider), `{ stops, from: 90 }` (ColorWheel) 와 `colorControlThumb(kind, props, box)` → `{ x %, y % | px, color }`. RAC hook 의 분기를 그대로 옮긴다 (Context 4). resolver 가 `_colorGradient` · thumb 노드의 layout 을 record 에 싣고, `_colorGradient` 는 `PAINT_ONLY_VISUAL_KEYS` 성격 (상자 불변) 이다.
3. **Canvas**: 세 binding 에 `skiaPrimitive` (replace) — 층마다 `applyFill` 의 linear/angular 셰이더 (rgb 는 `BlendMode.Screen`, 투명 stop 층은 premul 보간 flag), ColorWheel 은 바깥 원 − 안 원 evenodd clip 안에 sweep (`from 90deg` ↔ Skia 0° = 3시 — 회전 행렬 없이 같은 시작점, Phase 0 이 확정). thumb 노드는 `ColorThumb` rule 의 part 값 (크기 · 테두리 `{color.raised}` · 그림자) + record 색으로 원을 그린다. disabled 는 CSS 와 같은 회색.
4. **구조 (E1)**: 새 type `ColorThumb` (RAC `ColorThumb`, 사용자 prop 0 — toggle indicator 처럼 내부 운반 값만) · `ColorWheelTrack` (RAC `ColorWheelTrack`, prop 0). 원본 template: `ColorArea > ColorThumb`, `ColorSlider > Label {label} + SliderOutput + SliderTrack > ColorThumb`, `ColorWheel > ColorWheelTrack + ColorThumb`. `DOM_LEAF_TYPES` 에서 셋을 빼고 `componentTraits` 에 children · owners 를 적는다 (`ColorThumb.owners: ["ColorArea", "ColorSlider", "ColorWheel"]`). 필수 부품 (`requiredParts.ts`) = ColorArea `[["ColorThumb"]]` 등. Preview DOM 은 노드 순서대로 RAC 부품 (ADR-256 판정 하나). 기존 노드 (thumb 자식 없음) 의 처리는 사용자 결정 1.
5. **수동 CSS → rule**: `ColorThumb` · `ColorWheelTrack` rule 신설, ColorSlider 의 `SliderTrack` 은 Slider 와 같은 rule 에 ColorSlider 소유 값 (높이 20 · 세로 폭 20) 을 nested 로. 세 수동 CSS 파일의 thumb 중복 · track 치수 · disabled 회색을 지우고 생성 CSS 가 낸다 (ADR-106-a 잔여 종결). 값은 지금 수동 CSS 의 값을 그대로 옮긴다 (사용자 결정 2 가 레퍼런스 값으로 바꾸기를 고르면 그때).
6. **팔레트**: 사용자 결정 3 — 노출하지 않으면 이 ADR 의 결과를 사용자가 볼 길이 Components page (원본) 와 AI · import 뿐이다.
7. **문서 기본값 = Preview 초기 상태** (round 1 h1): RAC 의 세 state hook 은 `useControlledState` 로 첫 `defaultValue` 만 `useState` 에 넣는다 (`useColorAreaState.mjs:27` · `useColorSliderState.mjs:26` · `useColorWheelState.mjs:56` · `utils/useControlledState.mjs:19`). 그래서 Preview 의 Color 조작기 요소의 React `key` 에 **정규화된 문서 기본값** 을 넣는다 — `${node.id}:${canonical(defaultValue)}` (canonical = `parseColor(v).toString('hexa')` 처럼 표기 차이를 지운 값, 빈 값은 binding 기본값). Slider 의 선례와 같은 계약이다 (`delegatedDom.tsx` `slider` — `key: ${id}:${value}`, 「문서의 값 편집은 실행을 다시 시작한다」). 결과: 문서 `defaultValue` 편집 · undo · redo 는 Preview 의 끌기 상태를 버리고 새 문서 값으로 다시 시작한다. 그 밖의 prop 편집 (`colorSpace` · 채널 · `orientation` · `label` · `isDisabled` · style) 은 key 를 바꾸지 않아 끌기 상태를 유지한다 — RAC 가 `colorSpace` 를 매 렌더 `toFormat` 하므로 (`useColorAreaState.mjs:29`) 재시작이 필요 없다. Canvas 는 언제나 문서 값이다 (ADR-250).
8. **색 공간 · 채널 · 기본값은 한 명령에서 같이 정규화** (round 1 m1): 유효 색 공간 = `colorSpace` 가 있으면 그것, 없으면 `parseColor(defaultValue)` 의 공간 (RAC 와 같은 규칙). 채널은 유효 색 공간의 채널이어야 한다 (`alpha` 는 어디에나). 필드 하나씩 바꾸면 중간 조합이 무효라 (기본 hsl · hue → rgb · red 는 어느 순서로도 한 번은 무효 — 설치 RAC SSR 로 확인) 공용 함수 `normalizeColorControlPatch(type, props, patch)` 가 patch 를 **함께 바꿀 값까지 넓힌다**:
   - `colorSpace` 를 바꾸면 — ColorSlider `channel` 은 새 공간에 있으면 유지 (hue · saturation 은 hsl ↔ hsb 에서 유지 · alpha 유지), 없으면 새 공간의 첫 채널 (rgb → red · hsl / hsb → hue). ColorArea `xChannel` · `yChannel` 은 새 공간에 있고 서로 다르면 유지, 아니면 지운다 (RAC `getColorSpaceAxes` 기본 축).
   - 채널을 유효 공간 밖의 값으로 바꾸면 — 그 채널을 가진 공간으로 `colorSpace` 를 같이 바꾼다 (red · green · blue → rgb · lightness → hsl · brightness → hsb · hue · saturation 은 hsl / hsb 중 지금 공간, 아니면 hsl). ColorArea 의 다른 축은 위 규칙으로 유지 · 지움.
   - `colorSpace` 없이 `defaultValue` 만 바꿔 유효 공간이 바뀌면 (hsl 값 → `#ff0000`) — 지금 채널이 무효가 되므로 이전 유효 공간을 `colorSpace` 에 같이 적는다 (값을 바꿔도 보기는 그대로).
     넓힌 patch 는 `setFields` 한 step · 히스토리 한 항목이다 (undo 한 번에 같이 돌아간다). 이 함수는 Properties 패치 명령 (`catalogPropertiesPatchCommand` — 패널 편집) 과 AI 의 prop 쓰기 경로가 같이 부른다 (Phase 0 이 쓰기 경로 전수를 확인). 검증기는 마지막 줄로 남아 정규화를 거치지 않은 무효 조합 (import · 손상 문서 · 직접 명령) 을 거부한다. Design 패널의 채널 선택지는 필터하지 않는다 — 고르면 공간이 따라 바뀐다.
9. **ColorSlider 의 글자는 RAC 가 쓰는 글자** (round 1 m2): RAC ColorSlider 는 작성자 글자가 없으면 Label 에 채널 이름 (`ColorSlider.mjs:77` `getChannelName(channel, locale)`), SliderOutput 에 채널 값 (`useColorSliderState.mjs:76-80` `formatChannelValue(channel, locale)` — hue 120 → 「120°」) 을 쓴다. 지금의 RAC 글자 소유 경로 (`valueBindings.ts:164-184` `RAC_TEXT_OWNERS` — `SliderOutput: "Slider"` · 숫자 `Intl.NumberFormat`) 를 **소유자별 글자 함수** 로 넓힌다 — Slider 는 지금 그대로, ColorSlider 는 `SliderOutput` → `formatChannelValue`, `Label` (ColorSlider 의 직계 Label 이고 `{label}` 이 비었을 때) → `getChannelName`. 계산은 문서 `defaultValue` 를 유효 색 공간으로 바꾼 색에서 하고 (Canvas = 문서 값), locale 은 Slider 와 같은 사슬 (소유자 `locale` → 페이지 · 문서 locale → `navigator`), Preview 는 같은 locale 을 `I18nProvider` 로 준다. DOM 은 RAC 가 글자를 쓰는 부품 (`catalogRacOwnsText`) 에 `children` 을 **넘기지 않는다** — 빈 문자열을 넘기면 RAC 기본 글자를 지운다 (`domBinding.tsx:753-758`). 작성자 label 이 있으면 그 글자가 이긴다. 소유자 판정은 가장 가까운 Slider · ColorSlider 조상이고, dependent 갱신 (`valueBindings.ts:235`) 은 ColorSlider 의 `defaultValue` · `channel` · `colorSpace` 편집에 Label · SliderOutput 을 다시 해석한다. `componentTraits` 의 `SliderOutput` · `SliderTrack` owners 에 ColorSlider 를 더한다 (`componentTraits.ts:350-351`).

**위험 수용 근거**: round 1 의 네 결함 (h1 · h2 · m1 · m2) 은 Decision 7 ~ 9 와 Decision 1 의 색 값 타입이 계약으로 닫고 G1 · G3 가 조건으로 잡는다. B 의 잔존은 셋이고 전부 Phase 0 · G1 · G2 가 잰다 — ① 투명 stop 보간은 flag 하나이고 G2 의 hsl saturation fixture 가 띠를 잡는다, ② wheel 각도 규약은 설치 소스 한 곳 (`useColorWheel.mjs`) 에서 읽어 G2 thumb 위치로 확인한다, ③ 다층 blend 는 `GradientShape` 확장 또는 층마다 shape — Phase 0 이 Skia 경로의 blend 배선을 확인한다. E1 의 잔존 (기존 노드에 thumb 자식 없음) 은 G0 이 세고 사용자 결정 1 이 정한다 — 팔레트 밖이라 대상은 거의 0 이다.

**기각 사유**: A — 사용자가 기각했고 대칭 위반이 축마다 늘어난다. C — DOM 과 다른 색 (stop 보간 ≠ 정확 변환), Skia 전용 시각. D — Preview 없이는 Canvas 가 못 그리고 채널 방향이 거꾸로다. E2 — ADR-256 이 부품을 노드로 옮긴 방향을 되돌리고, Label · SliderOutput 은 어차피 노드여야 한다.

(Phase 3 착수 전)

## Consequences

### Positive

- Canvas 가 ColorArea 의 면 · ColorSlider 의 트랙 · ColorWheel 의 고리와 thumb 를 Preview 와 같은 값으로 그린다 — 2026-06-11 「의도적 손실」 종결, 머리말 3곳 · `componentCatalog.ts:1146-1152` · `colorLeafCutover.test.ts` 의 보류 서술 삭제.
- S2/RAC 색 축 prop (`colorSpace` · `xChannel` · `yChannel` · `channel` · `label` · `defaultValue`) 이 같은 이름 · 값 · 기본값으로 들어오고, S2 색 축 전환 (2026-10-09 ~ 11) 의 마지막 묶음이 닫힌다.
- thumb · track 모양이 rule 하나 — 수동 CSS 3 파일의 중복 (ADR-106-a 잔여) 이 사라지고 생성 CSS 가 낸다.
- Preview 의 ColorSlider 가 던지던 결함 (R3) 이 기본값으로 닫힌다.

### Negative

- 그라데이션 생성 규칙을 RAC 와 **두 벌** 유지한다 (D1 hook + shared 함수) — G1 이 설치 버전에 고정돼 RAC 를 올릴 때 RED 로 드러나지만, 그때 함수를 따라 고쳐야 한다.
- 새 type 2 (`ColorThumb` · `ColorWheelTrack`) · 원본 3 · contract +1 (착수 시점 최신 값 + 1 — 2026-10-11 현재 37) — 기존 개발용 프로젝트 거부.
- 색 값은 RAC 구문만 받는다 — CSS 이름 색 · 공백 구문 · `oklch()` 는 거부된다 (composition 이 받는 범위 = RAC 가 받는 범위).
- Preview 에서 끌어 둔 색은 문서 `defaultValue` 편집 · undo 때 문서 값으로 다시 시작한다.
- S2 전용 장식 (alpha 체커보드 · handle 의 loupe) 은 들이지 않는다 — S2 화면과는 다르다 (RAC 레퍼런스 기준).
- Preview 조작 (끌기) 은 Preview 에서만 보인다 (Canvas 는 `defaultValue`).

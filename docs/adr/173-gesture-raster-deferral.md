# ADR-173: 제스처 중 재래스터 이연 — 컬링 기준면 정합과 기하 무효화

## Status

Accepted — 2026-07-30 (리뷰 round 1 승인 — `reviews/173.md`, 이슈 3건 전건 fixed)

## Context

ADR-172(축 ① — 카메라 이동 중 파생 재구축 0)가 완결된 뒤 20배 규모(5,046 요소) end-to-end 재측정에서 **다음 병목이 실측으로 드러났다** (ADR-172 §"G5 종결" 갈래 B): 가시 페이지 집합이 바뀌는 팬에서 60프레임 중 Skia 재래스터 **35회 · 1회 65.1ms(21× 스케일) · 드롭 70%**. 줌은 매 프레임 가시 집합을 바꾸므로 같은 축이 더 자주 발화한다.

원인 사슬은 3개이며 전부 코드로 특정됐다:

1. **컬링 기준면 어긋남**: 캐시 surface 는 뷰포트+512px 패딩(`skia/SkiaRenderer.ts:70`)인데, 거기 그릴 내용을 정하는 가시 집합은 뷰포트+**200px**(`scene/buildVisiblePageSet.ts:7`, `skia/visiblePageRoots.ts:18-24`)로 판정된다 — 패딩 바깥 312px 는 페이지가 있어도 **빈 채로 래스터**되어 blit 으로 때울 수 없다.
2. **무효화가 기하 조건이 아니라 집합 사건**: 재래스터가 "coverage 소진(512px 이동)"이 아니라 "페이지 AABB 가 200px 경계를 넘는 사건"마다 발화한다(`SkiaCanvas.tsx:622-646` 의 `visibleContentVersion` → `invalidateContent()`). zoom 0.176 에서 페이지 간격은 화면 ~79px — 기하 조건 대비 **약 6.5배** 빈도다.
3. **발화 시점이 제스처 한복판**: 무효화가 즉시 발화해 65ms 스톨이 제스처 중에 꽂힌다. 대조군 Pen v1.2.1 은 재래스터를 **제스처 종료 후 200ms debounce** 로 민다.

**렌더러는 이미 Pen 모델이다** — `SkiaRenderer.classify()`(`SkiaRenderer.ts:216-240`)가 camera-only blit / zoom×3 재래스터 / coverage-refresh / 200ms cleanup 을 전부 갖추고 있다(주석에 "Pencil 모델" 명시, 2026-07-26 실측 정정: 파라미터까지 Pen 과 일치). 문제는 이 분류에 도달하기 **전에** 상류(React 축)의 가시 집합 사건이 `invalidateContent()` 로 강제 격상시키는 것이다. 즉 본 ADR 은 새 캐시를 만드는 것이 아니라 **이미 있는 캐시의 무효화 정책을 그 캐시의 기하와 정합**시킨다.

3-domain 판정: D1/D2/D3 어디에도 속하지 않는 렌더 파이프라인 성능 정책이다 — 시각 결과(정지 상태)는 무변경이며 D3 대칭에 영향 없다.

### Hard Constraints

1. **제스처 중 프레임 드롭 0** — 5,046 요소 실문서에서 갈래 B 벤치(±600 화면px 팬, 120Hz = 8.33ms 예산) 재실행 시 16.7ms 초과 드롭 0 (현행 42/60).
2. **편집 유발 무효화 즉시성 유지** — 이연은 카메라 유발(가시 집합 진입/이탈) 축에만 적용. 편집(콘텐츠 `contentVersion` 변경)은 현행대로 즉시 반영.
3. **정지 상태 시각 결과 무변경** — 제스처 중 일시 공백은 512px 패딩 밖(고속 이동)에 한정하고, coverage 소진 시의 기하 재래스터(안전판)는 유지한다.
4. **ADR-136 sceneVersion signature 계약 유지** — visibility version 의 축 분리가 signature 입력 목록과 정합해야 한다.

### Soft Constraints

- 검증 벤치와 대규모 문서(5,046 요소, bench-\* 4,800개 유지 — 사용자 결정 2026-07-30)가 이미 준비돼 있다 (ADR-172 §"G5 종결" §재현 절차).
- 계측 라벨 3종(`render.derived.*`)과 캐시 metrics(`__composition_CACHE_METRICS__`)가 상설화돼 있다 (ADR-172 Phase 4).
- 제스처 활성 신호(`isPanningRef`)가 이미 존재 — wheel 팬만 debounce 타이머가 필요하다.

## Alternatives Considered

### 대안 A: 무효화 정책 3종 — 기준면 정합 + 사유 분리 + 제스처 이연

- 설명: ① 컬링 반경을 캐시 패딩과 단일 소스로 정합(200→512) ② 무효화 사유를 카메라 유발/콘텐츠 유발로 분리 ③ 제스처 중 카메라 유발 무효화를 pending 으로 이연하고 종료(debounce) 시 1회 발화. 제스처 중 재래스터 사유는 렌더러의 기하 조건(zoom×3 / coverage-refresh)만 남긴다.
- 근거: Pen v1.2.1 실측 동형(제스처 중 blit 전용 + 종료 200ms 재래스터 — memory `project-pen-v121-extraction-analysis`). 렌더러 하류가 이미 같은 모델이므로 상류 정책만 맞추면 된다.
- 위험:
  - 기술: M — 제스처 종료 감지(wheel 은 이벤트 부재 → debounce)와 카메라/콘텐츠 사유 분리의 정확성
  - 성능: L — 정상 상태 가시 페이지 수 증가(반경 200→512)가 재래스터 1회 비용을 키우지만 발화가 제스처 밖으로 이동
  - 유지보수: M — 무효화 경로가 2원화(즉시/이연)되어 신규 무효화 추가 시 축 판정 의무 발생
  - 마이그레이션: L — 스키마 무변경, 정책 상수·게이트 되돌리기 용이

### 대안 B: 재래스터 비용 절감만 — content Picture 캐시 + 모션 중 snapshot 생략

- 설명: 발화 빈도·시점은 그대로 두고 1회 비용을 줄인다 (2026-07-27 프레임 분해의 레버 ①②).
- 근거: memory `project-render-frame-decomposition-flush-vs-js` — record 40% + flush CoW 가 비용의 대부분.
- 위험:
  - 기술: M — Picture 캐시 무효화 정책 신설
  - 성능: **H** — record 는 가시 요소 수 비례라 규모에서 다시 진다: 65ms 에서 40% 를 지워도 ~39ms 로 8.33ms 예산의 4.7배. 제스처 중 35회 발화가 그대로 남는다
  - 유지보수: M — 캐시 계층 1개 추가
  - 마이그레이션: L
- 비고: 본 대안은 기각이 아니라 **후속**이다 — 대안 A 반영 후 제스처 종료 재래스터 1회가 체감 hiccup 으로 남으면 별도 판정 (design §6).

### 대안 C: 컬링 반경 정합 단독

- 설명: `DEFAULT_MARGIN` 200→512 만 반영.
- 근거: 최소 변경 — 패딩 공백 문제만 해소.
- 위험:
  - 기술: L
  - 성능: **H** — 집합 사건 빈도는 반경과 무관하다(긴 팬에서 페이지가 경계를 넘는 횟수는 경계 위치와 무관하게 페이지 간격당 1회). 제스처 중 35회 × 65ms 가 그대로 남고, 반경 확대로 1회 비용은 오히려 커진다
  - 유지보수: L
  - 마이그레이션: L

### 대안 D: 현상 유지 + 규모 상한 문서화

- 설명: 현 실사용 규모(수백 요소)에서는 드롭 5% 수준이므로 상한만 기록.
- 위험:
  - 기술: L / 성능: **H** (5,046 요소 실측 드롭 70% — 사용자가 이미 체감 보고: "줌 in/out 끊김, 이동 프레임 드랍") / 유지보수: M (규모 성장마다 재론) / 마이그레이션: L

## Decision

**대안 A: 무효화 정책 3종(기준면 정합 + 사유 분리 + 제스처 이연)** 을 선택한다.

선택 근거:

1. **병목의 성격이 비용이 아니라 빈도·시점**이다 — 재래스터 총량은 Pen 도 피하지 않는다(제스처 종료 후 1회). 실측이 보여준 과잉은 "집합 사건 6.5배 빈도 × 제스처 한복판 발화"이며, 이것은 정책으로만 제거된다.
2. **하류가 이미 준비돼 있다** — `SkiaRenderer.classify` 가 Pen 모델 그대로이므로 신규 캐시·신규 계층 없이 상류 정책 정합만으로 성립한다. 잔존 위험(무효화 2원화)은 계약 테스트와 G2 로 관리 가능하다.
3. **검증이 결정적**이다 — 동일 문서·동일 벤치(갈래 A/B)가 준비돼 있어 전/후가 수치로 비교된다.

기각 사유:

- **대안 B 기각(현 시점)**: 빈도·시점을 두고 비용만 줄이면 규모에서 다시 진다(39ms > 8.33ms). 단 A 반영 후 제스처 종료 1회 재래스터의 체감이 남으면 후속으로 판정한다.
- **대안 C 기각**: 집합 사건 빈도는 반경과 무관 — 공백만 없애고 스톨은 남긴다.
- **대안 D 기각**: 사용자 체감 보고 + 실측 드롭 70% 로 성능 HIGH 확정.

## Consequences

### Positive

- 팬/줌 제스처 중 재래스터가 기하 필요분(coverage 소진)으로 줄어 5,046 요소 규모에서 드롭 70% → 0 목표 — 사용자 체감 보고("줌 끊김, 이동 프레임 드랍")의 직접 해소.
- 컬링 반경과 캐시 패딩이 단일 소스가 되어 "그릴 수 있는 영역 ≠ 그린 영역" 어긋남이 구조적으로 소멸 (`buildVisiblePageSet.ts` ↔ `SkiaRenderer.ts`).
- 512px 패딩 안 페이지가 미리 그려져 있어 소폭 팬의 공백이 사라진다.

### Negative

- 무효화 경로가 즉시/이연 2원화 — 신규 무효화 트리거 추가 시 축 판정 의무가 생긴다 (R1/R6 계약 테스트가 감시).
- 정상 상태 가시 페이지 수 증가(반경 200→512)로 layout publish·재래스터 1회 범위가 커진다 (R2 — 발화 시점이 제스처 밖이라 체감 비용은 낮음).
- 제스처 종료 시점의 1회 재래스터(65ms 급)는 남는다 — 체감 잔존 시 비용 축(대안 B)을 후속 판정한다 (design §6).
- 제스처 종료 debounce(≤200ms) 내에 새로 진입한 페이지는 커맨드 스트림 미등재라 히트 불가(`skiaFramePipeline.ts` hitBoundsMap 이 스트림 산출 — canvas-rendering.md §8.5 "미등재 = 히트 불가" 방향으로 안전). 제스처 직후 즉시 클릭에서 최대 200ms 히트 공백 — Pen 동형 트레이드오프.

## Context

### 도메인

**D3 시각 스타일** — rule (`COMPONENT_RULES_TABLE`) 의 배경 · 그림자 · 테두리 값과, 자식이 컨테이너 배경을 읽는 **파생 참조** 하나 (`{color.container}`). D1 (RAC DOM · 상태) 은 끌기 상태 (`isDragging` · `isDropTarget`) 를 읽기만 하고 바꾸지 않는다. D2 무관. 문서 스키마 · 명령 신설 **0** — 파생 참조는 테마 토큰이 아니라 rule 값 언어의 alias 이고, 조상 파생은 기존 `presence.ts` 의 파생 prop 경로 (`_inPopover` :2416) 와 같은 종류다.

### Spectrum Hub 의 층 · 컨테이너 · 그림자 규칙 (design-data 3.8.2 guideline 원문)

- **background-layers**: elevated (gray-25|75 + 그림자) · layer-2 (25|75) · layer-1 (50|50) · base (25) · pasteboard (100|25). elevated 는 「다른 내용 위에 떠 있는 것 (floating toolbar · panel · popover · menu · tooltip)」 에 드물게 쓴다. pasteboard 위에는 artboard 외 컴포넌트를 두지 않는다.
- **containers**: 컨테이너 양식 4 — 배경색 차이 · 강조 (그림자) · 테두리 (채움 없이) · 간격. 강조 컨테이너는 한 페이지에 한 묶음. 상호작용 컨테이너는 hover 에 더 큰 그림자, 끌 때 `dragged`.
- **drop-shadow**: 양식 4 (emphasized · emphasized-hover · elevated · dragged), 3층 구성, dark 불투명도 ×3. **「오버레이 (dialog 뒤) 가 있으면 추가 그림자는 필요 없다」**. **「popover 류는 dark 에서 테두리로 바탕과 분리」**. 컨테이너는 기본 그림자 없음 → 끌 때만 `dragged`.
- **grays**: 25 · 50 · 75 는 배경 층 전용 (302 G2 가 게이트).
- **states**: 끌기 상태는 고유 그림자.

### 제약

- **Hard**: 302 선행 — `pasteboard` · `layer-2` 재분류 (raised 7) · `popover-outline` alias · 층 매핑 (light base = layer-2 = elevated 25 / dark layer-2 = elevated 75) 이 있어야 G1 을 쓸 수 있다.
- **Hard**: 값 정본 = 설치 S2 1.8.2 컴포넌트 소스 (ADR-295 원칙 — 치수와 같은 정본). 배정표의 모든 행은 `Card.tsx` · `Modal.tsx` · `Popover.tsx` · `TableView.tsx` 의 `backgroundColor` · `boxShadow` · `outlineColor` 줄을 인용한다. S2 에 없는 컴포넌트 (Sheet) 는 같은 계열 (Modal) 을 따른다고 적는다.
- **Hard**: D3 대칭 — `{color.container}` 가 Canvas 와 Preview · Publish 에서 같은 hex. DOM 만 CSS 변수 상속으로 풀고 Canvas 가 `base` 로 떨어지는 것은 금지 (ssot-hierarchy §D3 「Skia 전용 · DOM 전용 표현 금지」).
- **Hard**: 번들 — Preview initial gz ≤ 325,000 (302 전 323,910 · 여유 1,090 B, 302 가 ≤ +256 B 를 쓴다) · Builder ≤ 1,414,000 (여유 2,292 B, 302 ≤ +512 B). 이 ADR 의 상한은 **302 종결 시점 재측정 여유** 이고 (G0 에서 숫자 확정), 넘으면 ADR-201 재승인이 선행 조건이 된다 (사용자 결정 6).
- **Hard**: 그림자 토큰 값 (ADR-166) 과 rule TokenRef 이름 체계는 바꾸지 않는다. 마이그레이션 코드 0 (개발 단계 원칙) — rule 값 변경은 생성 CSS 재생성으로 끝나고 문서 데이터는 손대지 않는다.
- **Soft**: 외관 변화 — Card 에 그림자가 생기고 Modal · Sheet · Tooltip 의 그림자가 없어지며 dark Popover 에 테두리가 생긴다. 사용자 프로젝트 전부에 보이므로 Phase 0 diff 표 뒤 사용자 confirm (R1).
- **Soft**: 끌기 그림자는 Preview 의 D1 상호작용 상태를 D3 가 읽는 것이라 live 검증이 끌기 동작까지 포함한다.

## Alternatives Considered

### 대안 A: 배정만 — rule 값 교체, 상속 없음

- 설명: 표의 어긋남 행을 S2 값으로 바꾼다 (Card 그림자 · Modal · Sheet · Tooltip 그림자 제거 · Dialog layer-2 · Popover dark 테두리 · Table 컨테이너 그림자 · 끌기 `dragged`). 자식의 `{color.base}` 67 은 그대로.
- 위험: 기술(L — rule 값과 생성 CSS 재생성뿐) / 성능(L — 번들 변화는 생성 CSS 몇 선언) / 유지보수(**H** — layer-1 · layer-2 · elevated 위의 자식이 계속 `base` 흰 조각을 그린다. Hub 「배경 층으로 위계」 의 절반만 되고, 새 컨테이너마다 같은 어긋남이 반복된다) / 마이그레이션(L).

### 대안 B: 배정 + 컨테이너 배경 상속 (`{color.container}`)

- 설명: A 에 더해 rule 값 언어에 alias `{color.container}` 를 두고, 컨테이너 역할 (Popover · Modal · Card · Table · Dialog · Sheet · 그리고 `base` · `layer-*` 배경을 가진 Frame) 이 자기 배경 층을 자식에게 내린다. DOM 은 컨테이너 노드의 inline style 이 `--container-bg` 를 쓰고 (값은 `COLOR_TOKEN_TO_CSS` 의 기존 변수 — `var(--bg-inset)` 등) 자식이 `var(--container-bg, var(--bg))` 를 읽는다 (S2 `--s2-container-bg` 와 같은 모양, `Provider.tsx:90 ~ :105`). Canvas 는 `presence.ts` 의 조상 파생 (`_inPopover` 와 같은 자리) 으로 `_containerLayer` 를 만들어 resolver 가 그 층의 hex 로 푼다. 자식의 `{color.base}` 67 중 「바탕을 따라야 하는 것」 을 Phase 0 표에서 가려 `{color.container}` 로 재분류한다.
- 위험: 기술(M — 두 consumer 에 각각 구현하지만 둘 다 기존 경로 (CSS 변수 · 파생 prop) 의 확장이고 새 저장 형식이 없다) / 성능(M — Preview 여유가 302 뒤 ≤ 834 B. 변수 선언 1 + 파생 1 + resolver 분기 1 이라 작지만 측정 전에는 모른다 → G3) / 유지보수(L — 「자식은 컨테이너를 따른다」 한 규칙, 컨테이너가 늘어도 자식 rule 무변경) / 마이그레이션(L — rule 값만, 문서 0).

### 대안 C: DOM 만 CSS 변수 상속, Canvas 는 base 유지

- 설명: S2 와 똑같이 CSS 변수로만 풀고 Canvas 는 기존 `base`.
- 위험: 기술(L) / 성능(L) / 유지보수(**C** — Builder 와 Preview 가 다른 색을 그린다. D3 대칭 위반이라 ssot-hierarchy §6 금지 패턴) / 마이그레이션(L).

### 대안 D: B + 페이지의 편집 · 탐색 맥락 설정

- 설명: B 에 Hub 의 맥락 (탐색 base → layer-2 → elevated / 편집 pasteboard → layer-1 · 2 → elevated) 을 Page 속성으로 두고 배정표를 맥락별 두 벌로.
- 위험: 기술(M) / 성능(L) / 유지보수(M — 배정표 두 벌) / 마이그레이션(**H** — Page 스키마 신설 · 기존 문서의 기본 맥락 결정 · 마이그레이션 코드 0 원칙과 충돌). 사용자 페이지는 탐색 맥락이 기본이고 편집 맥락은 Builder 자신 (빌더 chrome, D3 밖) 이다.

## Decision

**대안 B — 배정 + 컨테이너 배경 상속.**

1. **배정표 (코드 표 하나, `containerLayering.ts` 가 아니라 rule 값 자체)** — Phase 0 에서 S2 1.8.2 소스 줄을 인용해 freeze 한 표대로 rule 의 `backgroundColor` · `boxShadow` · `borderColor` 를 고친다. 설계 시점 값 (breakdown §2a): Popover `layer-2` + `{shadow.md}` + 테두리 1px `popover-outline` (dark gray-200 · light transparent-white-25 — 302 alias) · Modal · Sheet · Dialog 컨테이너 `layer-2`, **그림자 없음** (오버레이가 분리를 맡는다) · Tooltip 그림자 없음 · Card primary `elevated` + `{shadow.sm}` (= emphasized) → hover · focus · selected `{shadow.md}` (= elevated), secondary `layer-1`, tertiary 는 2px 테두리 (그림자 아님 — Canvas 재현을 위해 borderColor), quiet 는 루트 그림자 없음 — `CardPreview` part (Card rule `partStateStyles` `"&% .react-aria-CardPreview"` `:2608`) 에 hover · focus · selected `{shadow.md}` (리뷰 m4) · Table 컨테이너 **`base` 고정 (상태 없음) + 테두리 1px `border`, 그림자 없음** (S2 `table` 스타일 `TableView.tsx:251 ~ :280` — 배경 `gray-25` · border 1px `gray-300` · quiet 는 transparent · 테두리 0; `editPopover` `:1554 ~ :1584` 는 셀 편집 Popover 라 Table 배정 근거가 아니다 — 리뷰 h1) · header `gray-75` 는 TableHeader rule (G0 실측) · Menu · ListBox 는 자기 배경 대신 `{color.container}` (Popover 안에서는 Popover 의 layer-2, Autocomplete 등 밖에서는 그 컨테이너). 끌기: `isDragging` 가지에 `{shadow.lg}` (= dragged), 기본은 없음 (사용자 결정 3).
2. **`{color.container}` 파생 참조** — rule 값 언어의 alias. 뜻은 「가장 가까운 컨테이너 조상의 배경 층」, 컨테이너가 없으면 `base`. DOM: 컨테이너 **노드의 inline style** 에 `--container-bg` 를 쓴다 — `domBinding.runtime.ts` `authoredStyle` (`:3369`, 호출처 `:891 · :1790 · :1807 · :2486`) 가 Frame 의 사용자 배경을 DOM 에 싣는 바로 그 경로. 값은 `COLOR_TOKEN_TO_CSS[층 역할]` 조회 (`tokenResolver.ts:222 ~ :238` — base `var(--bg)` · layer-1 `var(--bg-overlay)` · layer-2 `var(--bg-inset)` · elevated `var(--bg-elevated)` · pasteboard 는 302 가 등록하는 이름) 이고 손으로 쓴 변수 이름은 없다 (리뷰 h3). `{color.container}` 는 `var(--container-bg, var(--bg))` 로 컴파일. 생성 CSS 는 선언하지 않는다 — Frame 은 `skipCSSGeneration: true` · `variants: {}` (`componentRulesTable.ts:6629 ~ :6643`) 라 정적 CSS 로는 노드별 층을 구분할 수 없다 (리뷰 h2). Canvas: `presence.ts` 조상 파생 `_containerLayer` (가장 가까운 컨테이너 조상의 resolved 배경 역할 이름) → `resolveCatalogPaint` 가 그 역할의 snapshot hex. 두 consumer 가 같은 역할 이름을 거치므로 같은 hex (G2). 자식의 `{color.base}` 67 중 재분류 대상은 Phase 0 표가 정한다 — 설계 시점 후보: Badge outline 변형 · Tag · Avatar outline · Popover 화살표 · Separator · Link 배경 · Input 배경 (S2 TextField 는 `gray-25` 고정이라 **제외**) (사용자 결정 4).
3. **바꾸지 않는 것** — 그림자 토큰 값 3 (ADR-166) · 층 토큰 값 (302) · TokenRef 이름 체계 · Frame 의 사용자 지정 배경 (Frame 이 층 토큰을 배경으로 가지면 컨테이너가 되고, 임의 hex 면 `_containerLayer` 는 그대로 상위 것 — 「층」 만 상속한다).

**위험 수용 근거**: 외관 변화 (R1) 는 overlay · 컨테이너 계열 7 컴포넌트에 한정되고 G0 diff 표가 컴포넌트별 before/after 를 보여 준 뒤 confirm 을 받는다. 두 consumer 구현 (R3) 은 둘 다 기존 경로의 확장 — DOM 은 테마 CSS 변수가 이미 `catalogThemeVarsCss` 로 나가고, Canvas 는 `_inPopover` 가 같은 파생 자리에 있다 — 이고 parity 가 같은 hex 를 잰다 (G2). 번들 (R2) 은 302 종결 시점 여유를 G0 에서 숫자로 확정하고 넘으면 ADR-201 재승인을 먼저 받는다 (G3). 끌기 그림자는 rule 조건 14 가 이미 있어 값만 붙이고 live 로 1회 확인한다 (G4).

**기각 사유**: A — 자식 `base` 고정 67 이 남아 layer-1 · elevated 위에서 흰 조각이 계속 보인다 (Hub 「배경 층으로 위계」 의 핵심이 빠짐). C — Canvas ≠ Preview, D3 대칭 위반. D — Page 스키마 신설과 기존 문서 기본값 결정이 필요하고 사용자 페이지는 탐색 맥락이 기본이라 지금 얻는 것이 없다 (편집 맥락은 Builder 자신의 chrome 이며 D3 밖).

> 구현 상세: [303-container-layer-assignment-elevation-breakdown.md](../design/303-container-layer-assignment-elevation-breakdown.md)

### 사용자 결정 6 건 (execute-adr 가 그 항목에 닿을 때 묻는다 — 4 결정 지점 밖)

1. **Card primary** — (a) S2 그대로 `elevated` 배경 + `emphasized` 그림자, hover · focus · selected 는 `elevated` 그림자 (권고 — Hub 「강조 컨테이너」) vs (b) 그림자 없이 `layer-2` 유지 (외관 변화 최소, Hub 컨테이너 양식 중 「배경색 차이」 만).
2. **Modal · Sheet · Dialog** — (a) 그림자 제거 + 컨테이너 `layer-2` (권고 — Hub 「오버레이 있으면 그림자 불필요」, S2 Modal 과 같음) vs (b) 그림자 유지 (ADR-166 의 「Tooltip < Popover < Modal 서열」 유지).
3. **끌기 그림자** — (a) `isDragging` 가지에 `{shadow.lg}` 를 GridList · Table · Tree · DropZone 에 연결 (권고 — 조건 14 가 이미 있다) vs (b) 범위 밖 (상호작용 ADR 로).
4. **`{color.container}` 재분류 범위** — (a) Phase 0 표에서 「S2 가 `--s2-container-bg` 를 읽는 자리」 + 「층 위에서 흰 조각이 보이는 자리」 만 (권고) vs (b) `{color.base}` 67 전부.
5. **Tooltip 그림자** — (a) 제거 (S2 `Tooltip.tsx` 에 boxShadow 없음, 권고) vs (b) 유지 (`neutral` 반전 배경이라 분리는 이미 충분 — 유지해도 Hub 위반은 아니다).
6. **번들** — (a) 302 종결 시점 여유 안에서 끝낸다 (권고 — 넘으면 변수 선언을 컨테이너 rule 에만 두는 식으로 줄인다) vs (b) ADR-201 상한 재승인을 선행 조건으로.

## Consequences

### Positive

- 떠 있는 요소 (Popover · Menu · Tooltip · Toast) 와 컨테이너 (Card · Table · Dialog) 가 Hub 의 층 · 그림자 · 테두리 규칙을 S2 값으로 따르고, 그 근거가 S2 소스 줄 인용 fixture 로 남는다.
- 자식이 컨테이너 배경을 따르므로 layer-1 · elevated 위의 흰 조각이 사라지고, 새 컨테이너를 추가해도 자식 rule 을 고칠 필요가 없다.
- 끌기 상태가 Hub 의 `dragged` 그림자와 연결된다 (결정 3 (a) 일 때).
- 302 와 합쳐 하나로 만들지 않아 302 는 지금 범위로 종결하고, 이 ADR 은 그 토큰 위에서 배정만 다룬다.

### Negative

- 기본 테마 외관이 바뀐다 (Card 그림자 · Modal · Sheet · Tooltip 그림자 없음 · Dialog · Table 배경 층 · dark Popover 테두리) — R1 confirm 뒤 CHANGELOG.
- rule 값 언어에 alias 하나 (`{color.container}`) 가 늘고, DOM 은 노드 inline 변수 1 (`--container-bg`) · Canvas 는 파생 prop 1 이 는다. 두 consumer 가 같은 판정 함수를 써야 한다는 제약이 추가된다.
- ADR-166 의 「elevation 서열」 주석과 Modal · Tooltip 그림자 결정은 이 ADR 이 대체한다 (166 Superseded in part — 토큰 값은 유지).
- Hub 의 편집 · 탐색 맥락, 주목 위계 (한 페이지에 강조 한 묶음), `emphasized-hover` 그림자 (S2 1.8.2 에 토큰 없음 — hover 는 `elevated`) 는 이 ADR 밖이다 (breakdown §5).

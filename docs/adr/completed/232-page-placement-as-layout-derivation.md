> **2026-09-23 후속 — 열 수 `auto` (사용자 요청)**: Settings 의 열 수에 `auto` 를 더했다. 보이는 캔버스 폭 ÷ zoom 에 들어가는 만큼을 열 수로 쓴다. 본 ADR 은 컨테이너 폭을 뷰포트에 묶는 안 (**대안 D**) 을 기각했는데 — zoom·창 크기마다 페이지가 움직여 위치가 문서 상태가 아니라 뷰 상태가 된다 (09-18 실측) — 그 판정은 **기본 모델**에 대한 것이고 여기서는 사용자가 명시적으로 고르는 모드다. **기본값도 `auto` 로 바꿨다 (사용자 판정 2026-09-23)** — 열 수를 숫자로 명시한 문서만 고정이고, 필드가 없으면 auto 다. `DEFAULT_PAGE_LAYOUT_COLUMNS` (3) 은 뷰포트를 아직 못 읽은 순간의 정수 fallback 으로만 남는다. 세는 폭은 캔버스 전폭이 아니라 **패널 토글 레일을 뺀 폭** 이다 (좌우 각 44 = 88 실측) — 전폭으로 세면 마지막 열이 레일 밑으로 들어간다. 여닫는 패널은 빼지 않는다 (열 수가 패널 상태를 따라 뛴다). 파생 입력은 zoom 연속값이 아니라 그 zoom 에서 나온 **정수 열 수** 라, 정수가 그대로면 메모 키가 같아 엔진 호출이 0 이다 (live: 정수가 같은 zoom 4회 변화 → 파생 0 · 정수가 바뀌면 1). 편집 경로 (점 → 칸 판정) 는 파생이 방금 쓴 열 수를 그대로 물려받아 화면 격자와 어긋나지 않는다. live `adr232-auto-columns-live.mjs` 10/10.

구현 기록은 [breakdown §5](../design/232-page-placement-as-layout-derivation-breakdown.md#5-게이트-실행-기록).

설계 요청: 사용자 (2026-09-22, ADR-231 Implemented 직후 페이지 정렬 결함 `f258286ef` 수리 뒤) — "page 도 canvas 내에 컴퍼넌트와 같은 element 잖아. page 들의 parents 에 이미 구현된 display 기능으로 page 정렬 자체도 같은 패턴으로 하는 게 좋지 않나." 이어진 대화에서 확정: 자유 배치 = `position:absolute` · breakpoint 별 배치 = 컨테이너의 responsive override · 칸 고정이 필요하면 `display:grid`. 컨테이너 폭을 브라우저 크기에 묶는 안은 2026-09-18 실측 (zoom 마다 칸이 바뀜) 으로 기각하고 **열 수 설정** 으로 대체.

## Context

**SSOT 3-domain 관계**: **D1/D2/D3 무변경.** 페이지 배치는 빌더 캔버스의 편집 표면이며 Preview/Publish 산출물에 나타나지 않는다 (F14 — ADR-177/181 이 이미 "문서 데이터지만 배포 무관" 으로 판정). 컨테이너 style 과 페이지 `placement` 는 canonical 문서에 실리되 export 대상이 아니다. 대칭 검증 대상은 Skia 한 leg 뿐.

**문제**: 페이지 위치가 **저장 좌표** 다 (F2). 그래서 페이지 추가 · 삭제 · breakpoint 전환 · body 크기 변화 · reload · align 여섯 사건마다 좌표를 맞춰 주는 코드가 필요하고 (F3 — 함수 14 · 파일 5 · 1,170 행), 그 정합이 깨질 때마다 사용자 가시 결함이 됐다 (F4 — 60일 8 커밋: 09-18 열 수 · reflow · ADR-231 시스템 열 · 09-22 breakpoint 유입 겹침). 한편 캔버스 요소는 같은 문제를 **부모의 display** 로 푼다 — flex/grid 자식은 위치를 저장하지 않고, 자유 배치는 `position:absolute`, breakpoint 별 차이는 responsive override (F10 · F11). 페이지만 다른 모델을 쓰고 있다.

**측정 가능한 제약**

- 프레임: 페이지 배치 파생이 편집 프레임 비용을 올리지 않는다 — 600 요소 문서 편집 p95 Δ ≤ +1 ms (ADR-231 G3 와 같은 하니스 · `layout.publish` 라벨). frame 크기 벡터가 바뀌지 않은 편집에서 root 재계산 0.
- 파생 1회 비용: 페이지 30 (leaf 30 · root 1) ≤ 1 ms.
- BC: 기존 문서의 페이지 배치는 **Home 기준 상대 world 벡터** 가 Δ0 (tier 3 모두). 화면 픽셀은 뷰포트 (pan · zoom) 가 세션 상태라 reload 를 넘어 보존되는 양이 아니며 (문서 · localStorage 어디에도 없다), 이관이 일어나는 세션 안에서만 뷰포트 보정으로 Δ0 (리뷰 round 2 h1). 재hydration Δnode 0.
- 회귀 0: `pageFrames` 소비 13 파일 (테두리 · 선택 · 미니맵 · 가시 집합) 무변경 · `pagePositions` 읽기 37 파일이 frames 로 옮겨간 뒤 히트 · 가이드 · 스크롤바 · 액션바 위치 Δ0.
- ADR-231 Phase 1 (frame 크기 = 1920 × 발행 높이) · Phase 2 live 15/15 의 시각 결과 유지 (시스템 열은 absolute 로 같은 자리).

**측정 불가능한 제약**: 캔버스가 "정렬되는 페이지" 라는 사용자 기대 (Settings 의 Page layout · gap 이 이미 있고, 09-22 보고도 "정렬이 안 된다") — Figma 식 완전 자유 캔버스가 본질이었다면 파생 모델이 맞지 않다. 그 경우도 absolute 가 자유 배치를 그대로 준다.

코드 사실 F1~F14 는 breakdown §2.

## Alternatives Considered

### 대안 A: 현행 유지 — 저장 좌표 + 정합 수리 계속

- 설명: `pagePositions` (breakpoint 별 스냅샷) 를 두고 사건마다 좌표를 맞춘다. 09-22 수리 (`placeMissingUserPages`) 로 전환·hydration 유입은 막았다.
- 위험: 기술 (M — 정합 표면 여섯 사건 × 세 breakpoint, 새 사건마다 재발) / 성능 (L) / 유지보수 (**H** — F4 60일 8 커밋, 특례 계층 3겹: 열 수 추론 · reflow 경계 · 시스템 열) / 마이그레이션 (L — 변경 0)

### 대안 B: 컨테이너 flex-wrap 파생

- 설명: 합성 root `display:flex · flexWrap:wrap · gap` 에 페이지 frame 을 자식으로 넣어 위치를 엔진에서 받는다. 저장 좌표 폐기. 자유 배치는 absolute.
- 위험: 기술 (L — 엔진 flex 는 SSOT 검증 완료) / 성능 (L) / 유지보수 (L) / 마이그레이션 (**H** — 손 배치 문서 이관 규칙 필요, 대안 C 와 같음)
- 한계: 칸 지정이 없다 — "Page 7 을 Home 옆에" 는 absolute 뿐이고, breakpoint 별 열 수는 root `width` override 로만 표현된다 (폭이 다른 페이지가 섞이면 열이 흔들린다).

### 대안 C: 컨테이너 grid 파생 + absolute 예외 + tier override (채택)

- 설명: 합성 root `display:grid · gridTemplateColumns: repeat(N, <breakpoint 페이지 폭>px) · gap · alignItems:start` (F10). direction 세 값은 `gridAutoFlow`/열 수로 매핑 (breakpoint 공통). 페이지 `placement` = 없음 (auto-placement) / `gridColumnStart/End · gridRowStart/End` (칸 고정) / `position:absolute + left/top` (격자 밖, Components 열 포함). breakpoint 별 차이는 root 와 페이지의 responsive override (F11) — 새 스냅샷 구조 0. 컨테이너 폭은 뷰포트가 아니라 **열 수 설정** (F12 의 09-18 실측 계승).
- 위험: 기술 (L — grid line 배치 · auto-flow column · absolute inset 전부 엔진 기존 경로 F10) / 성능 (L — 파생 1회 ≤ 1 ms · 메모 키로 편집당 0) / 유지보수 (L — 특례 0, 요소와 한 규칙) / 마이그레이션 (**H** — 손 배치·breakpoint 상이 문서를 absolute 로 승격하는 1회 이관 + `pagePositions` 읽기 37 파일 교체)

### 대안 D: 컨테이너 폭 = 브라우저 (뷰포트) 폭 반응

- 설명: 사용자 최초 제안의 한 조각 — root 폭을 `containerWidth / zoom` 으로 두어 창 크기에 맞춰 접는다.
- 위험: 기술 (L) / 성능 (**H** — zoom · 창 크기마다 wrap 이 바뀌어 페이지가 이동, `visiblePagePosition` 축 (F7) 이 보이는 페이지 콘텐츠 캐시를 전부 재생성) / 유지보수 (M — 위치가 문서 상태가 아니라 뷰 상태가 되어 "내 페이지가 움직였다" 문의) / 마이그레이션 (M)
- 09-18 실측: zoom 0.3 에서 열 수 2 로 바뀌어 새 페이지가 기존 열과 무관한 칸에 놓였다 → 기각 근거 그대로.

## Decision

**대안 C 채택 — 페이지 배치는 페이지 컨테이너 (합성 grid root) 의 레이아웃 파생값이다.**

1. **저장 좌표 폐기 (쓰기 0)**: `pagePositions` 쓰기 · `pagePositionsByBreakpoint` · 배치 함수 14 · reflow · 시스템 열 특례 · 09-18·09-22 수리를 삭제한다 (`pagePositions` **데이터** 는 롤백용으로 보존 — Decision 6). 페이지 frame 의 x·y 는 `readPageFrameSize` (ADR-231 유지) 로 만든 leaf 크기 벡터 + 컨테이너 style + 페이지 `placement` 를 엔진에 넣은 결과다.
2. **컨테이너 style = 문서 데이터** (`pageLayout`: direction · gap · columns · responsive override). Settings 의 Page layout · gap 은 localStorage (F9) 에서 문서로 승격되고 열 수 입력이 생긴다. 컨테이너 폭은 뷰포트가 아니라 열 수다 (대안 D 기각). 열 track 은 `max-content` 가 아니라 **고정 폭 `repeat(N, <breakpoint 페이지 폭>px)`** (desktop 1920 · tablet 768 · mobile 390 — 저장하지 않고 파생 시 계산, 현행 stride = 페이지 폭 + gap 과 같다) — 빈 열이 0 폭으로 접혀 고정 칸이 밀리는 것 (리뷰 round 2 m3 재현 B.x 220→120) 을 막는다. 저작 폭이 track 보다 넓은 페이지는 칸을 넘친다 (현행과 같음, ADR-231 후속 그대로).
3. **페이지 `placement` = 요소와 같은 세 상태**: 없음 (흐름 auto-placement) · 칸 고정 (`gridColumnStart/End` · `gridRowStart/End` longhand — responsive eligible 키만 쓴다, 리뷰 m3) · `position:absolute + left/top` (격자 밖). 드래그 · Transform X/Y · nudge 는 placement 를 쓰고, 격자 안에 놓으면 칸 스냅, 밖이면 absolute. 흐름에서 빠진 페이지의 칸은 뒤 페이지가 채운다 (요소와 같은 동작). **칸 충돌 정책 (리뷰 m5)**: 놓는 칸을 다른 고정 페이지가 차지하고 있으면 두 페이지의 칸을 **교환** (history 1 entry) · 흐름 페이지가 있던 칸이면 고정 + 뒤 페이지 재흐름 · 엔진의 명시 배치 겹침 허용은 쓰지 않는다 (고정 칸은 페이지당 유일 — 쓰기 전 검사). align 은 모든 placement 를 지워 흐름으로 되돌린다. **Home 은 이동 불가 (사용자 결정 2026-09-22)**: placement 를 갖지 않고 항상 흐름의 첫 칸 = 격자 원점 (0,0) — 드래그 · X/Y · nudge 비활성, 첫 칸은 다른 페이지가 고정할 수 없고 (교환 거부), Navigator 순서 변경도 Home 을 0번에서 빼지 못한다.
4. **breakpoint 별 배치 = override**: root 와 페이지의 `responsive.styles` (ADR-154, tier 토글 ON 이면 override 쓰기) — 키는 현행 eligibility 표 안의 longhand (`gridTemplateColumns` · `gap` · `gridColumnStart/End` · `gridRowStart/End` · `position` · `left/top`) 만 쓰고 eligibility 확장은 0 (리뷰 m3). 그래서 **direction (auto/vertical/horizontal) 은 breakpoint 공통** 이고 (`gridAutoFlow` 는 eligible 이 아님), breakpoint 별로 달라지는 것은 열 수 · gap · 페이지 칸/absolute 다. cascade 는 desktop → tablet → mobile 상속이므로 어떤 tier 를 흐름으로 되돌리려면 명시 reset (`position: "static"` · line `"auto"`) 을 쓴다 — placement 어댑터가 `"auto"` 를 엔진의 빈 문자열 (auto-placement) 로 옮긴다. 스냅샷 3벌 구조는 없어진다.
5. **시스템 페이지 (Components)** = `placement` 기본값 `absolute · left −(1920+gap) · top 0` — ADR-231 의 시스템 열을 특례 코드 0 으로 재현. ADR-231 Phase 1 (frame 크기) 은 그대로 입력이다.
6. **이관 1회 (리뷰 round 1 h1 · h2 · m4 · round 2 h1 · h2 · m3 반영)**: hydration 에서 `pageLayout.placementModel` 이 **없고** `pagePositions` 가 있으면 tier 마다 **전체 벡터** 로 이관한다 — (i) 보존 대상은 **Home 기준 상대 world 벡터** 다: 각 tier 의 Home 저장 좌표를 원점으로 모든 좌표를 평행이동하고 (leftInset 317 류 오프셋 제거), 이관이 일어난 세션에서는 뷰포트 pan 을 **`newPan = oldPan + homeStored × zoom`** (`screen = world × zoom + pan` 이므로 world 가 −H 만큼 옮겨지면 pan 은 +H×zoom, 리뷰 round 3 m1 실행 확인 — 활성 tier 의 H 로 **한 번만**) 보정해 화면이 움직이지 않게 한다 (뷰포트는 세션 상태 — reload 뒤 화면 위치는 지금도 보존되지 않는다) · (ii) **Home 을 제외한** 각 페이지의 저장 좌표가 파생 격자의 칸 좌표와 같으면 (±1px) 그 칸에 **고정** (auto 자리라도 — auto-placement 는 다른 페이지의 승격에 따라 밀린다) · 칸이 아니면 absolute · (iii) 기록 뒤 파생을 다시 돌려 저장 벡터와 Δ0 검증, Δ ≠ 0 이면 **Home 은 흐름 원점에 남기고 나머지 전부 absolute** (보수 갈래 — Home 불변식 유지, round 2 m3 재현에서 목표 벡터 일치 확인) · (iv) tier 별 값은 이전 tier cascade 결과와의 차이로 기록하고, 흐름 복귀가 필요한 tier 에는 명시 reset · (v) 전체가 기본 흐름과 일치하면 placement 쓰기 0. 완료 시 `pageLayout.placementModel = "derived"` 를 쓴다 (새 문서도 생성 시 `"derived"`). `pagePositions` 데이터는 지우지 않는다 (한 major, 휴면).
7. **읽기 모드와 복귀 경로 (round 2 h2 · round 3 m2)**: 무엇을 읽을지는 placement 의 존재가 아니라 `placementModel` 이 정한다 — `"derived"` (placement + 컨테이너 파생, placement 가 비어 있어도 합법: 기본 흐름 · align 뒤) · `"legacy"` (복귀 상태) · 없음 (미이관 → 이관 실행). **legacy 는 흐름이 없다 — 모든 페이지가 absolute** 다: 좌표는 tier 별로 `pagePositions[page][tier]` 를 먼저, 없으면 (이관 뒤 derived 에서 추가된 페이지 · lazy-write 로 비어 있던 tier) `pageLayout.legacyFallback[tier][page]` 를 읽는다. `legacyFallback` 은 **`"legacy"` 로 전환하는 순간** 그때의 파생 위치 (Home 기준 상대) 로 채워 문서에 쓰고, `"legacy"` 에서 페이지를 추가하면 그 페이지의 좌표를 현행 `calculateNextPagePosition` 과 같은 규칙 (모든 absolute 페이지를 배치된 것으로 보고 다음 칸) 으로 만들어 `legacyFallback` 에 쓴다 — 첫 칸 (Home) 과 겹치지 않는다 (round 3 m2 재현: all-absolute 부모에 flow 자식은 첫 칸으로 간다 → flow 를 쓰지 않는다). `pagePositions` 는 legacy 에서도 쓰기 0 · 배치 편집 (드래그 · X/Y · nudge · align) 은 잠긴다. 복귀 = `placementModel` 을 `"legacy"` 로 바꾸는 명시 액션 (디버그 전역 + Settings 숨김 항목) 이며 표식·placement 를 지우는 것이 아니다 → 다음 hydration 에서 재이관되지 않는다. 재이관 (`"legacy"` → `"derived"`) 은 명시 액션으로만 — placement 초기화 후 Decision 6 을 `pagePositions ⊕ legacyFallback` 을 입력으로 다시 돌린다. 이전 앱 버전으로의 복귀는 `pagePositions` 가 바이트 동일하게 남아 있어 그 안의 페이지·tier 는 좌표 Δ0 이며 (이관 뒤 추가된 페이지는 그 빌드의 보충 경로가 놓는다), 그 빌드가 알 수 없는 root 필드 (`pageLayout` · `placement`) 를 저장 시 보존하는지는 G4 (c) 에서 이전 빌드 worktree 로 검증한다.
8. **history**: `pagePositionEvent` → `pagePlacementEvent` (entries[] 유지, Cmd+Z 1회) — ADR-177 의 "위치는 문서 데이터 · undo 일원" 원칙은 유지, 좌표 저장만 대체. Implemented 시 ADR-177 을 Superseded by 232 로.

**위험 수용 근거** (마이그레이션 H): 이관은 "칸이면 고정 · 아니면 absolute · 검증 실패면 Home 제외 전부 absolute" 세 갈래로 닫혀 있어 어떤 문서도 Home 기준 상대 배치가 바뀌지 않는다 (전체 벡터 Δ0 이 G4 조건, 혼합 · 여러 행 · 불규칙 크기 · Home 오프셋 fixture 필수). 복귀는 `placementModel: "legacy"` 한 상태로 같은 앱 안에서 가능하고, 원본 `pagePositions` 가 남아 이전 빌드도 같은 좌표를 읽는다. 얻는 것은 정합 표면 자체의 소멸 — 여섯 사건이 "크기 벡터가 바뀌었다 → 재계산" 한 가지가 된다.

**기각 사유** — A: 결함의 종류가 구조에서 오므로 수리로 끝나지 않는다 (F4). B: C 의 부분집합 — 칸 고정과 열 방향 흐름이 없고 이관 비용은 같다. D: zoom · 창 크기마다 페이지가 이동해 위치가 뷰 상태가 된다 (09-18 실측).

**사용자 확인 결정 지점 3** (리뷰 전 확정 요청): (a) grid 기본 (flex 아님) · (b) 컨테이너 폭 = 열 수 설정 (track 은 breakpoint 페이지 폭 고정) · (c) 이관 = 칸이면 고정 / 아니면 absolute / 검증 실패면 Home 제외 전부 absolute, 보존 대상은 Home 기준 상대 벡터 (화면 픽셀은 세션 안 뷰포트 보정). 확정된 규칙 1: **Home 이동 불가** (사용자 2026-09-22).

## Consequences

### Positive

- 페이지 위치의 **정합 표면이 사라진다** — 추가 · 삭제 · 전환 · 크기 변화 · reload · align 이 전부 "입력이 바뀌었다 → 재계산" 한 가지. F4 류 결함의 자리가 없다.
- 요소와 페이지가 한 모델 — 드래그 · undo · Styles 패널 X/Y · tier override 가 같은 경로. 배치 코드 약 1,170 행 + 스냅샷 3벌 구조 삭제.
- 지금 없는 기능이 공짜로 생긴다: breakpoint 별 열 수 · gap, 칸 고정, 열 방향 흐름, 긴 페이지 span (`gridRow: span N`).
- 쓰기 · persist · hydration 병합이 0 — 성능은 동급 이상.

### Negative

- 흐름에서 뺀 (absolute) 페이지의 칸은 뒤 페이지가 채운다 — "하나만 옆으로 치워 두기" 는 칸 고정으로 해야 한다 (요소와 같은 규칙이지만 현행과 다르다).
- 이관 코드 1회분과 `pagePositions` 읽기 전용 잔존 (한 major).
- Settings Page layout · gap 이 localStorage 에서 문서로 옮겨가 프로젝트마다 값이 따로 간다 (지금은 브라우저 전역).
- ADR-177 Superseded · ADR-231 Phase 2 배치 절 대체 · b290d75da reflow 삭제 — 세 결정의 문서를 손본다.

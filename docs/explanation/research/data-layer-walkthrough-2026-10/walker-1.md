## 4. 조용한 실패 지점 — 오류 없이 아무 일도 안 일어나거나 틀린 결과

형식: 무엇을 하면 → 무엇이 보이나 → 알아챌 수 있나 (즉시 / 특정 입력에서만 / 어렵다).

### A (25 개 — 「어렵다」 7)

- A1. `gender === 'all'` 분기를 빼먹음 → all 을 누르면 빈 목록 → 즉시.
- A2. `u.name.includes(query)` 로 씀 → 「Ja」 와 「ja」 결과가 다름 → 대소문자 섞어 쳐야 보임 (어렵다).
- A2. `onChange` 대신 `onSubmit` 에 연결 → Enter 전까지 변화 없음 → 타이핑 중 무반응으로 보임 (특정 입력).
- A2. `contains(query, u.name)` 인자 순서 바꿈 → 거의 항상 빈 목록 → 즉시.
- A3. `selectionMode="multiple"` 누락 → tag 를 눌러도 선택 안 됨, 오류 없음 → 즉시 (누르면 무반응).
- A3. `some` 대신 `every` → 두 tag 고르면 둘 다 가진 행만 → 둘 이상 골라야 보임 (어렵다).
- A4. JS `Date` 와 `CalendarDate` 를 `>=` 로 비교 → NaN → 항상 false → 빈 목록 → 즉시.
- A4. 끝 경계를 `<` 로 → 끝날 행이 빠짐 → 어렵다.
- A4. `toISOString().slice(0,10)` 변환 → 자정 근처 행이 하루 어긋남 → 어렵다.
- A5. `exclude && u.status !== 'closed'` → 체크 해제 시 빈 목록 → 즉시.
- A6. `a && b || c` 괄호 없이 → 묶음이 OR 로 바깥에 붙어 search 무시 → 어렵다 (행 수가 더 많아짐).
- A7. `users.length` → 항상 50 → 조건을 바꿔 봐야 보임 (특정 입력).
- A8. 없는 status 키 → 「undefined」 글자 → 즉시 (글자로 보임).
- A9. mock `teamId` 가 문자열 "3" 인데 `Teams.id` 는 3 → `===` 실패 → 팀 이름 칸이 빈칸 → 즉시 (빈칸).
- A9. Select 항목 id 를 `t.name` 으로 두고 filter 는 `teamId === team` → 빈 목록 → 즉시.

## 6. 가정 (설명에 없어서 추정한 것)

1. B · C 의 Data 패널은 mock 행을 JSON 붙여넣기로 한 번에 넣을 수 있고 필드 타입을 유추한다 (테이블 1 개 = 5 동작). 행을 손으로 치면 테이블 1 개가 200 동작 이상이 되어 B 우회 수치가 10 배 커진다.

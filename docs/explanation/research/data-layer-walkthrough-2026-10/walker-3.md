# 쉬움 평가 — cognitive walkthrough (walker-3)

> 입력은 brief.md 만. 숫자는 추정이며 둥글리지 않았다. 셈 규칙: UI 클릭·선택·글자 입력 1 = 1, 코드 「의미 있는 줄」 1 = 1 (import 문 1 줄 = 1, JSX 요소 한 줄 = 1). 컨트롤을 화면에 놓는 비용은 세 방식 모두 포함 (A 는 JSX 줄, B·C 는 팔레트 추가 + 라벨·값 입력). 시작 상태: GridList 가 이미 `Users` 를 보여 준다 (A: `items={users}` 코드 존재, B·C: 바인딩 완료).
>
> 「불가」 는 brief 의 설명으로 성공 기준에 못 미치는 경우. 「시도 N」 = 신입이 가장 그럴듯하게 밟을 경로의 동작 수 (결과는 무반응). 우회는 성공 기준을 일부만 채운다 — 어디가 미달인지 적었다.

\* B 는 12 과제 중 10 이 불가다. B 의 수는 「시도·우회 경로」 의 개념이라 작게 나온다 — 과제를 끝내는 데 필요한 개념이 아니다. 비교는 가능 과제 (10 · 11) 로 한정해야 뜻이 있다: 과제 10 · 11 만의 합은 A 7 ~ 12 · B 11 ~ 14 · C 11 ~ 13.

읽을 점 (수치만):

- A 는 R 축이 7 ~ 14 개를 줄인다 (R 있음 27 ~ 39 vs 없음 47 ~ 60). C 는 R 축이 0 개를 줄인다 (RQS = QS, R = 없음) — C 의 개념은 React 어휘와 겹치지 않는다.
- C 는 Q 또는 S 축이 15 개를 줄인다 (59 → 44). A 는 Q·S 축이 12 ~ 21 개를 줄인다 (60 → 47 ~ 48 / 39 → 27).
- 「없음」 프로필에서 A 60 · C 59 — 거의 같다. RQS 에서 A 27 · C 44 — A 가 17 적다.
- C 의 전원 새 개념 (`[-]`) 고유 수 33 중 반복 등장은 「거르기 동작」(6 과제) · 「건너뛰는 값」(5) · 「값 고르기」(4) · 「이름 있는 보기」(3).

## 4. 조용한 실패 지점 (오류 없이 무반응 또는 틀린 결과)

형식: 무엇을 하면 → 무엇이 보이나 → 알아챌 수 있나. 바로 오류가 뜨는 실수 (`e.target.value` TypeError · 모르는 prop 의 타입 오류) 는 뺐다.

### A (26)

- A-1 Radio `value="Male"` 처럼 데이터와 대소문자 다름 → male 누르면 빈 목록 → 알아챔 (빈 목록), 원인은 찾아야.
- A-2 `u.name.includes(query)` → 「ja」 가 James 를 놓침 → 결과가 몇 개 빠질 뿐이라 알아채기 어려움.
- A-2 `useFilter()` 에 `sensitivity:'base'` 를 안 줌 → 기본 collator 가 대소문자 구분 → 같은 증상.
- A-3 TagGroup 에 `selectionMode="multiple"` 누락 → 클릭해도 선택 표시 없음 → 알아챔, 원인 모름.
- A-3 Tag 에 `id` 없이 글자만 → 자동 key 와 `u.tags` 불일치 → 고르면 빈 목록.
- A-4 `u.createdAt >= range.start` (Date vs CalendarDate) → `NaN` 비교 → 범위 넣으면 전부 사라짐 → 알아챔, 원인 어려움.
- A-4 `fromDate(d, 'UTC')` vs 지역 시간대 → 경계 날짜 하루 어긋남 → 알아채기 매우 어려움.
- A-5 `u.status != 'Closed'` → 체크해도 closed 안 사라짐 → 알아챔.
- A-6 `a && b || c` 우선순위 → OR 가 search 를 덮어 결과 과다 → 알아채기 어려움.
- A-6 `useMemo` 의존성에 `gender` 누락 → 라디오 바꿔도 그대로 → 알아챔 (lint 있으면 경고).
- A-7 `users.length` 를 씀 → 항상 50 → 알아챔.
- A-8 `Object.entries(groupBy(...))` 로 렌더 → 0 건 status 줄이 사라짐 → 알아채기 어려움.
- A-9 `ListBoxItem id={String(t.id)}` 또는 key 가 문자열 → `u.teamId === key` 불일치 → 고르면 빈 목록.
- A-9 데이터 `teamId` 가 문자열 → `find` 가 undefined → 팀 칸 빈 칸 → 알아챔.
- A-10 Column 에 `id` 없음 → `sortDescriptor.column` undefined → 화살표는 뜨는데 순서 그대로 → 알아챔.
- A-10 `collator.compare(a.age, b.age)` → 숫자를 글자로 → 10 이 9 앞 → 50 행에서 알아채기 어려움.
- A-10 `filtered.sort(...)` 제자리 정렬 → 상태 배열 변이 → 간헐적으로 안 바뀜 → 재현 어려움.
- A-10 `allowsSorting` 누락 → 머리 클릭 안 됨 → 알아챔.
- A-11 `fetch` 에 `signal` 안 넘김 → 빠른 입력 때 이전 응답이 늦게 도착해 덮음 → 가끔 틀림, 알아채기 어려움.
- A-11 `load` 안의 `gender` 가 stale closure → 라디오 변경이 param 에 한 단계 늦게 실림 → 알아채기 어려움.
- A-11 `encodeURIComponent` 누락 → 공백·특수문자 입력 때 빈 결과 → 가끔.
- A-12 `getItems` 가 `String(key)` 를 싣고 `list.update(textKey)` → 숫자 id 못 찾음 → 끌어 놔도 무반응.
- A-12 `acceptedDragTypes` 누락 또는 불일치 → drop 표시 안 뜨고 무반응.
- A-12 `onRootDrop` 만 배선 → 카드 사이에 놓으면 (onInsert) 무반응.
- A-12 열마다 `useListData` 따로 → 카드가 사라지거나 두 열에 → 알아챔.
- A-12 `item.getText()` 를 await 안 함 → key 가 Promise → update 무반응.

### B (18)

**과제 12 (kanban)** — 세 기준 모두 1 위. 동작 57 중 42 가 「열 3 개 × 같은 일 반복」 (조건 4 + 바인딩 3 + 머리 count 5 + 규칙 7) 이다. 보기의 「묶기」 는 집계 행을 만들 뿐 하위 목록을 만들지 않아 열을 하나씩 만든다. 규칙 쪽은 When 4 종 (onInsert · onRootDrop · onReorder · onItemDrop) 중 어디에 걸어야 「카드 사이」 와 「빈 자리」 둘 다 되는지, 그리고 인자 `keys` · `items` · `target.key` 중 어느 것이 「끌어온 카드」 인지가 조용한 실패 2 개 (C-12 첫 두 줄) 의 자리다. 볼 곳: 열 반복 비용 · dnd When 과 인자 이름.

**과제 11 (API 전환)** — 동작은 5 로 가장 적은데 새 개념 7 (전부 `[-]`) 과 조용한 실패 3. 「직렬화 형식 하나 선택」 이 비교 방식 → param 접미 (`=` · `_like` · `_gte`) 매핑을 숨기고, 형식이 못 담는 조건의 경고가 「저작 때 그 자리」 라서 이미 만든 조건 뒤에 endpoint 를 바꾸는 경로 (과제 순서가 바로 그렇다) 에서는 경고 시점이 비는지가 brief 에 없다. 응답 필드 이름이 mock 과 다를 때 Preview 가 조건을 로컬로도 적용하는지도 없다. 볼 곳: 형식 선택과 비교 방식의 대응 표시 · 경고 시점 (조건 저작 vs 원본 변경) · API 보기의 로컬 재계산 여부.

**과제 1 (첫 과제)** — 동작 13, 새 개념 7, 조용한 실패 3. 비교 방식의 기본값과 건너뛰는 값이 둘 다 「신입이 안 건드리면 틀리는」 자리다 (`male ⊂ female`, `all` 키). 과제 5 의 불가 (값 슬롯 1 개라 「변수 true 일 때만 리터럴 비교」 를 못 둠) 도 같은 조건 모형에서 나온다. 볼 곳: 조건의 비교 기본값 결정 규칙 · 건너뛰는 값의 기본 채움 · boolean 컨트롤이 조건에 들어가는 길.

## 6. 가정 (brief 에 없어 추정한 것)

1. **팔레트 기본 자식**: RadioGroup · TagGroup 은 팔레트에서 놓으면 자식 3 개가 자리표시자로 따라온다 → 라벨·값 입력만 센다 (RadioGroup 7 · TagGroup 7). Table 은 열 2 개가 따라온다 (필드 · allowsSorting 입력 2 × 2 + 컬렉션 1 + 추가 1 = 6).
2. **B·C 공통 — 같은 When 에 규칙 여러 개**: 한 규칙 = Do 하나지만, 같은 컴포넌트의 같은 When 에 규칙을 여러 개 둘 수 있고 실행 순서는 보장되지 않는다 (B 과제 11 의 Set state + reload 경로의 전제).
3. **B 변수 생성 비용**: State 절에서 추가 1 + 이름 1 + 타입 1 = 3.
4. **B 과제 10**: 대상 capability `sort` 가 GridList 에 있고 값 고르기로 This event 인자 (SortDescriptor) 를 받는다. 없으면 B 과제 10 도 불가 (B 불가 11 개).
5. **B 과제 11**: endpoint 가 `{{ gender }}` 를 읽고 `reload` 목록 명령이 현재 변수 값으로 다시 요청한다. 과제 1 · 2 에서 만들어 둔 규칙 (Set state gender · setFilterText) 을 그대로 재사용한다.
6. **C 「거르기 동작」 비용**: 컨트롤 선택 1 + 동작 선택 1 + 대상 목록 1 + 필드 1 = 4. 생성된 조건의 비교 방식 기본값은 타입에 맞는 목록의 첫 항목 (string 이면 「포함」) 이고, 건너뛰는 값 기본은 컨트롤 모양에 따른다 (SearchField 빈 글자 · 다중 선택 빈 선택 · DateRangePicker 빈 범위). 지정 키 `all` 은 손으로 넣는다 (1).
7. **C 보기 파생**: 보기의 「원본」 자리에 다른 이름 있는 보기를 둘 수 있다 (과제 7 — 거른 결과의 count). 안 되면 Text 쪽 보기에 같은 조건을 다시 만들어야 하고 (+6 × 조건 수) 조건이 둘로 갈라진다.
8. **C 집계 행**: 묶음 키는 묶기 필드 이름 (`status`) 으로, 집계 값은 `count` 로 템플릿에서 읽는다.
9. **C 「포함」 비교**: 대소문자 무시가 기본이다. 아니면 C-2 조용한 실패가 확정된다.
10. **C 과제 11 경고 범위**: brief 는 「평면 param 에 OR」 만 예로 든다. 비교 방식 불일치 (`field=` 형식에 「포함」) 도 경고하는지는 모른다 — 모른다고 두고 조용한 실패로 적었다.
11. **C dnd 배선**: `getItems` · `acceptedDragTypes` 는 자동이고 저작자는 When 과 Do 만 만든다. 성공 기준 「끌어 놓으면 옮겨짐」 은 빈 자리 drop (onRootDrop) 으로 채운 것으로 보고 onInsert 는 세지 않았다 (세면 열마다 +7).
12. **C 참조 타입 전환 비용**: 필드 열기 1 + 타입 「참조」 1 + 대상 테이블 1 = 3 (대상 필드 `id` 자동). 기존 `teamId` 값은 그대로 참조 키가 된다.
13. **A 시작 코드**: React · RAC GridList import 와 `useState(mockUsers)` 가 이미 있다. 새 컴포넌트 import 는 import 문 1 줄 = 1 로 센다. `useFilter({sensitivity:'base'}).contains('James', '')` 는 true (빈 글자 = 전부).
14. **A 과제 11**: `useAsyncList` 의 `load` 가 호출 시점의 최신 옵션을 읽는다고 보고, stale closure 는 「신입이 `useEffect` + `fetch` 로 직접 짤 때」 의 조용한 실패로 적었다.
15. **결과 왕복**: A 는 저장 1 회 (HMR 즉시), B·C 는 Preview 탭 이동 1 회. 과제 11 은 세 방식 모두 네트워크 탭 확인이 추가로 필요하지만 공통이라 세지 않았다.
16. **개념 축 대응**: 「부분 일치」 · 「범위」 · 「부정」 · 「AND/OR 묶음」 · 「묶기」 · 「COUNT/집계」 · 「JOIN/참조」 는 Q 와 S 둘 다 아는 것으로, 「IN/배열 포함」 · 「정렬」 · 「서버 필터 위임」 은 Q 만 아는 것으로 두었다 (S 표에 정렬 · IN 이 없음). 「변수」 · 「규칙 When/Do」 는 R 의 `useState` · 이벤트 핸들러와 별개 개념으로 세었다 (brief 예시가 둘을 따로 든다).
17. **B 손 분할 우회 비용**: 테이블 1 개 = 생성 1 + 필드 9 = 10, 행 50 개 복사 = 50 으로 어림했다 (복사 UI 유무 모름).

# 인터렉션 재설계 연구 — RAC · S2 근본 개념 기준 (2026-10-22)

> 목적: composition Interactions (ADR-158 「When → Do」 규칙 모델) 을 컴포넌트별 손 등재에서 **RAC · S2 의 재사용 가능한 상호작용 개념 (concept) 합성**으로 다시 세우기 위한 연구 기록. 정본 우선순위는 설치본 (`react-aria-components` 1.22.1 → `react-aria` 3.53.1 · `react-stately` 3.51.0 · `@react-types/shared` 3.37.0, `@react-spectrum/s2` 1.8.1) 의 `d.ts` · `dist/private/*.mjs` 이고, 로컬 md 스냅샷 (`.claude/skills/react-aria/references/` · `.claude/skills/react-spectrum/references/`) 은 읽기용이다 (ssot-hierarchy.md §1 D1 · D2). 이 문서는 ADR 이 아니다 — 결정 지점만 나열한다. 후속 ADR: [ADR-280](../../adr/280-interactions-rac-surface-registry-controlled-runtime.md) (base — 등록표 유도 · controlled 배관, 2026-10-22 Proposed) → ADR B (응용 — 패널 어휘 · 상속 · Form 제출 목적지, 미작성).

## 0. 요약

1. RAC · S2 의 모든 상호작용 표면은 **28 개 개념**으로 닫힌다 — press · hover · focus · keyboard (요소 층), toggle · value · valueCommit · inputValue · singleSelection · multiSelection · expansion · open · readOnlyValue · loadingState · selectionAsValue · routeSelection · focusedDate (상태 층), action · clear · remove · sort · resize · loadMore · dragDrop · form · dismiss (의미 층), navigation · other (dom 원시 핸들러) (보조 층). 각 개념은 `X / defaultX / onXChange` 삼중과 조건 (modifier) prop 몇 개로 정의되며, 컴포넌트는 그 조합일 뿐이다 (§2).
2. 설치 d.ts 로 8 가족 (검증 항목 469) 전수 대조한 결과 콜백 이름 · 시그니처 · 소유자는 md 와 일치하나, md 에서 보이지 않던 **게이트 (isReadOnly 가 hover 까지 끈다 · isPending 이 onKeyDown 도 지운다)** · **키보드 press 경로 (숨은 input 의 usePress)** · **S2 ActionButtonGroup 이 RAC Toolbar 를 렌더한다** 는 사실이 반증 · 정정으로 나왔다 (§1 · 부록 B). 뒤에 합친 overlays · sliders-color · date-time · collections 재검증에서는 **ColorSwatchPicker 에 root isDisabled 가 없다** (반증) · **S2 공개 Popover 에 focus-within 콜백 · defaultOpen 이 없다** · **S2 SideNav 의 RAC 대응은 Tree 가 아니라 NavigationTree 다** 가 더해졌다.
3. 현 `CAPABILITY_REGISTRY` 는 28 type 만 등재하고 그중 13 type 은 deferred 다 (capabilityRegistry.ts:138-450). catalog 의 상호작용 가능 type 약 40 종이 registry 에 없고, 등재된 것 중에서도 ListBox · GridList 의 `defaultSelectedKeys` capability 는 binding 이 항목 집계만 읽어 **닿지 않는다** (delegatedDom.runtime.ts:1328-1343 · 1366-1377) (§4).
4. trigger owner 가 틀린 등재가 4 건이다 — Menu.onOpenChange/open/close 는 MenuTrigger 노드, Modal.open/close 는 DialogTrigger 노드, Popover.open/close 는 가족별 trigger, Tooltip 은 TooltipTrigger (§4-d).
5. 제안: **개념 계약 (InteractionConcept) 을 한 번 선언**하고 컴포넌트는 `{concepts[], owner, s2Exceptions}` 만 선언해 registry 를 유도한다. When 은 개념의 callback (인자는 규칙 변수로 노출), Do 는 개념의 controlled prop 쓰기 (`set` · `toggle` · `clear` · `param`) 로 일반화하고 Form submit/reset · focus 만 imperative 특례로 둔다 (§5).
6. Preview/Publish 는 ADR-250 runtime prop override 를 **개념의 controlled prop** 에 꽂는 것으로 끝낸다 — remount key 와 항목 집계를 override 가 이기는 조건을 명시하면 deferred 13 종 중 8 종이 해제된다 (§5.4 · §4-b).
7. 같은 개념 표를 ADR-214 `IMPLICIT_STATE_SOURCES` 가 소비하면 관찰 (observer) 과 쓰기 (capability) 의 prop 이름 불일치가 구조적으로 사라진다.
8. 사용자 결정이 필요한 지점은 4 개 결정 지점 중 (3) SSOT 경계 (Preview 가 controlled prop 을 소유하는 것이 D1 침범인가) 와 (4) scope (ADR-158 「한 규칙 = 한 줄」 유지 vs 인자 전달 허용) 두 가지다 (§6).

## 2. 근본 개념 분류 (concept taxonomy)

개념 = 「상태 하나 + 그것을 바꾸는 이벤트 + 바꿀 수 있는지 정하는 조건」. RAC 는 모든 `X / defaultX / onXChange` 쌍을 `useControlledState` 로 구동하므로 콜백은 uncontrolled 에서도 호출된다 (press-triggers 교차 관찰 4). 표의 「삼중」 열이 비어 있으면 상태 없는 순수 이벤트 개념이다.

- **그룹이 상태를 소유한다**: ToggleButton ∈ ToggleButtonGroup · Checkbox ∈ CheckboxGroup · Radio ∈ RadioGroup · Tab ∈ Tabs · 항목 ∈ 컬렉션은 자기 isSelected/onChange 를 무시하거나 갖지 않고 그룹의 삼중을 쓴다 (useToggleButtonGroup.d.ts:12 · useCheckboxGroupItem.d.ts:4-5 · useRadio.d.ts:4-19). isDisabled 는 OR 합산, isRequired 는 항목 우선 (useCheckboxGroupItem.mjs:58).
- **두 층 게이트**: isDisabled 는 상호작용 층 (usePress/useHover 비활성 · tabIndex 제거), isReadOnly 는 상태 층 (state.setX no-op) — 단 toggle 가족과 Radio 의 hover 는 isReadOnly 도 끈다 (부록 B 정정).
- **Enter 의 네 가지 의미**: TextField = 브라우저 form submit · SearchField = onSubmit(value) 있으면 그것 · NumberField/ColorField = commit + commitValidation (shouldPreventDefault false 라 submit 공존) · TokenField = onSubmit() 또는 줄바꿈 (useSearchField.mjs:32-39 · useNumberField.mjs:167-173 · useTokenField.mjs:167-172).
- **render-prop 파생 상태** (isHovered · isPressed · isFocused · isFocusVisible · isSelected · isCurrent · isDropTarget · isPending · hasAction · allowsSelection · allowsRemoving · isExpanded) 는 콜백이 아니라 조건의 결과값이다 — 모델의 When 후보가 아니다 (D3 `data-*` 로만 소비).
- **Toast 는 trigger 도 controlled 상태도 없는 유일한 overlay** — 열림 = `ToastQueue.add` (React 밖 큐, 반환값 key 또는 S2 close 함수). 「When = RAC 콜백, Do = controlled prop」 모델에서 Toast 의 Do 는 prop patch 가 아니라 큐 호출 (현 APP_ACTIONS toast 자리) 이고, When (onClose · onAction) 은 큐 옵션으로 넣어야 한다 — 「상태 소유자 = 컴포넌트」 전제가 깨지는 지점 (overlays).
- **애니메이션 lifecycle (onEnter/onExit · isEntering/isExiting · shouldSkipAnimation)** 은 D3 transition 의 신호다 — 개념 표에 넣지 않고 render-prop 파생 상태와 같이 둔다 (S2 는 `isEntering` 만 남김) (overlays).
- **shouldCloseOnSelect (boolean 또는 () => boolean, 기본 true) 는 value → open 결합** — picker 에서 선택 하나가 onChange 와 onOpenChange(false) 를 같이 일으킨다. **값 모양 축 (scalar · range · list)** — Calendar selectionMode 'multiple' 은 DateValue[] 를 돌려주는 값 기반 다중 선택이지 Key 기반 multiSelection 이 아니고, DatePicker 는 안쪽 Calendar 에 'single' 만 넘긴다 (date-time).
- **그룹 Set + 항목 boolean 동시 호출** (DisclosureGroup/Accordion) — 두 owner 가 같은 사용자 동작에 한 번씩 fire 한다. 「그룹 안 항목 When 억제」 규칙 (§5.2) 이 expansion 에도 필요 (overlays · collections).

### 3.6 overlays

열림은 전부 `*Trigger` 래퍼 (DialogTrigger · TooltipTrigger · PreviewTrigger · S2 ContextualHelp 는 trigger 내장) 가 소유하고 삼중은 예외 없이 `isOpen / defaultOpen / onOpenChange(boolean)` (useOverlayTriggerState.d.ts:3-7) 이다. overlay 본체 (Modal · Popover · Tooltip) 는 standalone (`triggerRef` + isOpen) 일 때만 같은 삼중을 되풀이하고 별도 onClose 를 갖지 않는다. 닫힘은 독립 이벤트가 아니다 — Escape · 바깥 상호작용 · `slot="close"` · render-prop `close()` · timeout 이 전부 `onOpenChange(false)` 로 모이고, 상태 없는 Toast 는 `onClose()`, S2 DialogContainer 는 `onDismiss()` 로 모인다. 검증 결과 (부록 B) 를 반영했다 — S2 공개 Popover 에는 focus-within 콜백 · `defaultOpen` 이 없고, S2 Dialog 류는 `isEntering` · `role` 을 유지한다.

## 5. 재설계안 — 「컴포넌트별 손 등재」 를 「개념별 재사용 계약」 으로

### 5.1 개념 계약 (InteractionConcept)

개념을 한 번 선언한다 (shared 층, `packages/shared/src/interactions/concepts/`):

```ts
interface InteractionConcept {
  concept: ConceptId; // §2 의 28 개
  events: readonly { name: string; args: readonly ArgSpec[] }[]; // When 후보 — args 가 규칙 변수가 된다
  state?: {
    prop: string;
    defaultProp?: string;
    callback: string;
    valueType: ValueTypeId; // boolean · string · number · Key · Key[] · Selection · Set<Key> · Color · DateValue …
  };
  conditions: readonly string[]; // modifier prop 이름 — binding accepts 에 있어야 노출
  derivedCapabilities: readonly CapabilityTemplate[]; // set · toggle · clear · param — state 가 있을 때만
}
```

컴포넌트는 개념 목록 + owner + S2 예외만 선언한다:

```ts
interface ComponentInteractionSpec {
  type: CatalogType;
  concepts: readonly {
    concept: ConceptId;
    owner: "self" | "trigger" | "group" | "item";
    variant?: string;
  }[];
  // variant: singleSelection 의 (a)/(b)/(c) 철자, valueCommit 의 2 채널 여부, action 의 onRowAction alias
  s2Exceptions?: readonly string[]; // S2 1.8.1 이 지운 이벤트 (hover3 · onClick · kb2) — 패널 기본 숨김, D1 능력은 유지
  imperative?: readonly ImperativeCapability[]; // Form submit/reset · focus
}
```

registry 는 `deriveRegistry(concepts, specs)` 로 생성한다 — 현 `CAPABILITY_REGISTRY` 의 수기 객체 (capabilityRegistry.ts:138-450) 는 생성 결과와 같아야 하고 (Phase 1 게이트), 생성 뒤에는 삭제한다.

**derived 가능 (개념에서 기계적으로 나옴)**:

- events 이름 · 인자 타입 (press5 · hover3 · focus3 · kb2 · onChange · onSelectionChange · onExpandedChange · onOpenChange · onInputChange · onLoadMore · dnd 12).
- 상태 삼중과 그로부터의 capability: `set<prop>(param)` · `toggle` (boolean) · `clear` (null / 빈 Set / '' / NaN) · `selectItem(itemKey)` (Set 에 add 또는 replace — selectionMode 조건으로 분기) · `open/close` (= set isOpen). 지금 Tree 의 selectItem/clearSelection/expand/collapseAll (capabilityRegistry.ts:149-180) 은 전부 multiSelection + expansion 의 derived 다.
- racRef (G1 필수): 개념 선언의 d.ts 경로 + 컴포넌트의 md 파일명을 합성.
- 조건 노출: conditions ∩ binding accepts.

**컴포넌트 고유 (선언해야 함)**:

- owner (self / trigger / group / item) — RAC 가 콜백을 받는 노드. 요소 없는 trigger 는 `owner: 'trigger'` + 어느 trigger 인지 (MenuTrigger · DialogTrigger · TooltipTrigger · ContextualHelp · picker self).
- variant — singleSelection 철자 (a)(b)(c), valueCommit 의 live/end 2 채널, Table 의 onRowAction alias, ComboBox open 관찰 전용, SideNav 콜백 없음.
- Enter 의미 (submitValue · commitValue · insertNewline · native) — When 노출에는 영향 없고 설명 텍스트에만.
- 그룹-항목 관계 (CheckboxGroup ⊃ Checkbox · ToggleButtonGroup ⊃ ToggleButton · RadioGroup ⊃ Radio · Tabs ⊃ Tab · 컬렉션 ⊃ 항목) — 항목 안에 있으면 항목의 toggle 삼중을 패널에서 숨기고 그룹 삼중을 보인다.
- imperative 특례 (§5.3).
- S2 예외 목록.

### 5.2 When 축

- **owner 노드**: 규칙의 ownerId 는 RAC 가 콜백을 받는 노드다. 요소 없는 trigger (MenuTrigger · DialogTrigger · TooltipTrigger · ContextualHelp · Autocomplete · SubmenuTrigger) 도 ownerId 가 될 수 있어야 한다 — DOM 요소가 없으므로 withRuntime 의 cloneElement (domBinding.runtime.ts:2768-2786) 로는 못 붙이고 binding 이 RAC 컴포넌트 prop 으로 직접 전달해야 한다 (MenuTrigger.tsx:23-36 이 이미 그 형태). 닫힌 overlay 본체 (Popover · Modal · Tooltip · Dialog) 는 DOM 부재 (1517-1535) 라 When owner 가 될 수 없다 — open 개념의 owner 는 항상 trigger.
- **인자 → 규칙 변수**: 개념의 `events[].args` 를 규칙 실행 컨텍스트 변수로 노출한다 — onSelectionChange 의 `keys` (Selection: 'all' 또는 Set<Key>) · onChange 의 `value` · onAction 의 `key` (Menu 는 `key`, `value`) · onOpenChange 의 `isOpen` (ComboBox 는 `menuTrigger` 추가) · onRemove 의 `keys` · onSortChange 의 `column`, `direction` · onDrop 의 `items`, `dropOperation` · onSelect(FileTrigger) 의 `files` · PressEvent 의 `pointerType`, `key`, `shiftKey` 등. 지금 dispatcher 의 resolveValue 는 `!param` · `!self` · 리터럴뿐 (dispatcher.ts:85-109) 이라 `!event.<arg>` 소스 하나를 더하면 된다. 'all' 은 Set 이 아니므로 변수 타입에 `Selection` 을 둔다.
- **조건부 노출**: 이벤트는 조건 prop 값에 따라 패널에서 숨긴다 — `selectionMode === 'none'` 이면 onSelectionChange 숨김 (Menu · ListBox · TagGroup 기본 none), `onRemove` 는 항상 (유무가 affordance 를 켜므로 규칙을 달면 그 자체가 켜는 조건), `allowsSorting` 열이 없으면 onSortChange 숨김, `treeColumn` 없으면 Table onExpandedChange 숨김, getItems 없으면 dnd 숨김, isPending 중에는 press/hover/kb 가 안 온다는 설명. 조건 값은 record.props + override 에서 읽는다 (getElement 와 같은 경로, catalogPreviewInteractions.ts:225-243).
- **S2 예외**: S2 가 지운 이벤트 (hover3 · onClick · kb2 일부) 는 기본 숨김 + 「RAC 전용」 토글. onClick alias 는 모델에 넣지 않는다 (onPress 와 동일 경로, usePress.mjs:219-240).
- **중복 fire 방지**: picker 안 ListBox · 그룹 안 ToggleButton/Checkbox/Radio · Tab 은 그룹이 owner 이므로 항목 노드에는 toggle/selection 이벤트를 노출하지 않는다 (press/hover/focus 만). 근거: RAC Select context 가 ListBox 상태 소유 (delegatedDom.runtime.ts:1316-1335), useToggleButtonGroupItem 이 로컬 onChange 를 Omit (useToggleButtonGroup.d.ts:12).

### 5.3 Do 축

capability = **개념의 controlled prop 쓰기**. 네 가지 원형만 있다:

| 원형              | 적용 개념                                                                                                                     | 패치                                                                                                                                   | 지금 registry 대응                                                |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| set(param)        | toggle · value · valueCommit · inputValue · singleSelection · open · expansion(boolean) · sort · Column width                 | `{[prop]: resolved}` — valueType 으로 param 검증 (boolean · string · number · Key · Color 문자열 · DateValue ISO)                      | setValue · check/uncheck · open/close · (없던 것) sort · setInput |
| toggle            | toggle · open · expansion(boolean)                                                                                            | `{[prop]: !current}` — current 는 override ?? 문서 선언값                                                                              | toggleCheck                                                       |
| clear             | value('') · valueCommit(NaN/null) · inputValue('') · singleSelection(null) · multiSelection(new Set()) · expansion(new Set()) | 개념별 빈 값 상수                                                                                                                      | clear · clearSelection · collapseAll                              |
| param (집합 조작) | multiSelection · expansion(Set)                                                                                               | selectItem(key): selectionMode 'single' 이면 Set([key]), 'multiple' 이면 add; deselectItem(key); expand(key)/collapse(key): add/delete | selectItem · expand                                               |

- param 은 `!param` (규칙 인자) · `!self` · 리터럴 · `!event.<arg>` (§5.2) 네 소스. `selectItem(!event.key)` 로 「다른 컬렉션의 onAction 키를 이 컬렉션 선택에 넣기」 가 한 줄로 된다.
- disallowEmptySelection · isReadOnly · isDisabled 조건은 capability 실행 전 게이트 — RAC 가 막는 변경을 override 로 우회하면 RAC 상태와 어긋나므로 **거부** 한다 (readOnly 면 no-op, 로그).
- **imperative 특례** (controlled prop 이 없는 동작): Form submit · reset (`form.requestSubmit()` / `reset()` — 지금 Form 등재 :371 의 형태 유지), focus(요소) — RAC 는 FocusScope/useFocusManager 로 하고 prop 이 없어 특례 (Form 과 함께 2 개만; 도입 여부는 §6), SearchField clear 는 controlled value '' 로 가능하니 특례 아님, TagGroup remove 는 데이터 삭제가 앱 책임이라 **capability 아님** (When 만), Toast 는 APP_ACTIONS (capabilityRegistry.ts:460-472) 유지, NumberField increment/decrement 는 set(value ± step) 으로 파생 가능 (step · min/max 조건 읽어 clamp).
- ComboBox open 은 RAC 에 isOpen prop 이 없어 (useComboBoxState.d.ts:22-70) Do 대상이 아니다 — deferred 목록에 없는 것이 맞고 모델이 이를 자동으로 보장한다 (state 없는 개념엔 derivedCapabilities 가 없음).

### 5.4 Preview / Publish 실행

ADR-250 runtime prop override 가 개념의 controlled prop 에 닿는 조건:

1. **binding 이 개념 prop 을 읽는다** — withOverride 가 node.props 에 합친 키를 binding 이 RAC prop 으로 전달해야 한다 (domBinding.runtime.ts:2748-2766). 현 unwired 11 건은 전부 이 조건 위반 (Select · ComboBox · DatePicker · DateField · TimeField · Calendar · RangeCalendar · ColorSwatchPicker · Switch key 고정 · ListBox/GridList/Table/CardView/CheckboxGroup/ToggleButtonGroup 집계). 규칙: **record override 에 개념 prop 이 있으면 항목 집계보다 override 가 우선** (집계는 문서 선언 기본값으로만).
2. **controlled 전환 + remount 제거** — 지금 (b) remount 는 defaultX + key 에 값 포함이다 (nodeTreeField 1008-1012). controlled 로 바꾸면 `X = override[prop] ?? 문서값` 와 `onXChange → setRuntimeProps({[prop]: v})` 두 줄이고 key 는 node.id 고정이 된다 — Disclosure 가 이미 이 형태 (2521-2527). remount 제거 조건: (i) 그 prop 의 onXChange 가 RAC 에 있어 사용자 입력을 runtime 에 되돌릴 수 있을 것 (모든 상태 개념이 만족), (ii) 문서 선언값 변경 시 declaredAt 으로 override 를 버리는 ADR-250 R2 유지 (catalogPreviewInteractions.ts:376-393), (iii) Builder/Canvas 는 override 를 보지 않음 (Decision B).
3. **래퍼의 핸들러 전달** — withI18n(I18nProvider) · markerWrap(div) · CalendarPickerSelect 가 catalogForwardHandlers 를 쓰도록 (지금 CatalogStateFrame · RacSlotScope · SelfToggleButton · GroupToggleFrame · TagGroupRun 만 — stateFrames.components.tsx:28-33 · racSlotScope.tsx:51-53 · delegatedDom.components.tsx:82-86 · 116-117). 요소 없는 trigger 는 cloneElement 대신 binding 이 prop 으로 받는다 (§5.2).
4. **ADR-214 결합** — `IMPLICIT_STATE_SOURCES` (state/implicitState.ts:20-37) 를 개념 표에서 생성한다: 개념의 `{prop, callback}` 이 곧 observer 의 `{prop ↔ source.prop, event}` 다. 관찰 전용 (R6, 주입 0) 은 유지하되, 같은 표를 쓰므로 capability 가 쓰는 prop 과 observer 가 듣는 callback 이 어긋날 수 없다. 변수가 source 인 상태 변수는 규칙이 set 하지 못하는 현행 (interactions.ts:164-166) 도 유지 — 개념 모델에서는 「observer 가 있는 개념 prop 은 Do 에서 숨김」 으로 같은 규칙이 자동 적용된다.
5. **Publish 동일** — 개념 표 · deriveRegistry · dispatcher 확장 (`!event.*`) 은 전부 shared 층 (packages/shared/src/interactions) 에 두고 domView.runtime.ts:69-84 경로로 Publish 가 그대로 소비한다. Preview 전용 분기 금지 (ADR-158 R5).
6. **성능** — 개념 합성은 모듈 로드 시 1회 (`deriveRegistry` 결과를 상수로 동결), 핸들러 색인은 문서당 1회 유지 (bindings.ts:30-42), 조건부 노출은 패널 렌더에서만 계산하고 runtime 핫패스에서는 계산하지 않는다 (NO_HANDLERS 동결 유지, bindings.ts:77·91).

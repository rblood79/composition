# Interactions Do 전수 조사 — 컴포넌트마다 고유 기능이 나오는가 (2026-10-27)

> 사용자 보고 (2026-10-27): 「버튼 이벤트에서 meter 의 value 값을 변경할 수가 없다 … progress bar · progress circle 도 동일하다 · 다른 컴포넌트들도 대부분 show · hide · toggle visibility 밖에 안 보인다 · 전수 조사 진행하고 레퍼런스 체크 후 각 컴포넌트의 고유 기능이 나와야 한다」.
> 이 문서는 그 조사의 결과다 — 팔레트 69 type 전부를 등록부 · 패널 노출 · 설치된 RAC 1.22.1 / S2 1.8.1 타입과 대조했다. 결정은 ADR (사용자 `/create-adr`) 에서.

## 1. 결론

- **Do 의 등록부 (`CAPABILITY_REGISTRY`) 와 패널은 같다** — 패널의 Capability 목록은 `exposedCapabilities(type, 노드 prop)` 이고, 5174 live 에서 SearchField = 보이기 · 숨기기 · 토글 + Set value · Clear value, ListBox = + Select item · Deselect item · Clear selection 으로 등록부와 일치했다. 「대부분 3 개뿐」 은 패널 결함이 아니라 **등록부가 비어 있는 type 이 69 중 30** 이기 때문이다.
- 비어 있는 30 은 전부 **표시 컴포넌트** (Meter · ProgressBar · ProgressCircle · Badge · StatusLight · Text · Image · Icon · Avatar · InlineAlert · Skeleton · Card · Chart · Button · Link …) 다. RAC · S2 에는 이들의 setter 가 없다 — 레퍼런스 코드에서는 `useState` 변수를 `value={x}` 로 묶고 버튼이 `setX(…)` 를 부른다. 그 길 (「변수로 정하기」 + Set state) 이 지금 **number · enum prop 을 받지 않고** Meter 류의 원본 정의 `accepts` 에 `value` 가 없어 막혀 있다 — 이것이 사용자가 본 결함의 본체다 (§4 gap A).
- 상태 컴포넌트 39 는 RAC 상태 prop (`X` · `defaultX` · `onXChange`) 과 1:1 로 등록돼 있다. 남은 차이는 둘 — 목록 6 종의 `selectItem` 이 팔레트 기본값 `selectionMode: none` 에서 숨는데 `deselectItem` · `clearSelection` 은 보인다 (gap B) · boolean 표시 prop (`isPending` · `isLoading` · `isFilled` · `isSelected` · `isIndeterminate`) 은 Do 가 없다 (gap A 의 boolean 판).

## 6. 선택지 (ADR 에서 결정)

1. **변수 경유 (RAC 레퍼런스 그대로)** — 「변수로 정하기」 를 number · enum · variant · icon · string 전부로 넓히고 (prop 종류 = binding `accepts` 의 kind), 원본 정의 `accepts` 를 binding 표면과 같게 채운다. Do 는 지금의 Set state (set · increment · toggle · reset) 로 충분하다. 코드 보기는 `<Meter value={progress}>` + `setProgress(progress + 10)` — ADR-285 어휘 그대로 (variable · prop 바인딩 · Set state 가 이미 있음). **새 어휘 0.**
2. **Do 에 「값 정하기」 capability 등록** — 표시 컴포넌트마다 `setValue` · `setText` · `setVariant` … 를 `prop:` 쓰기 capability (공통 3 과 같은 메커니즘 — `prop: "style.display"` 처럼 `prop: "value"` + `!param`) 로 등록. 패널에서 한 번에 고를 수 있지만, 문서에는 변수가 없어 **코드 보기가 환원할 어휘가 없다** (`useState` 없이 prop 을 바꾸는 RAC 코드는 없음) — ADR-285 의 닫힌 어휘를 깨거나 생성기가 변수를 지어내야 한다.
3. **1 을 저장 형식으로, 2 를 패널 어휘로** — Do 목록에 「Meter 값 정하기」 처럼 보이되, 고르면 숫자 변수를 만들고 (이름 = `<노드 이름>Value`) 그 prop 을 변수로 정하고 Set state Do 를 저장한다. 사용자 (비개발자) 는 한 번에 고르고, 문서 · 코드 보기는 1 과 같다.

**권장: 1 을 먼저, 3 은 그 위에.** 사용자 원칙 (2026-10-22 「Interactions = RAC 표면을 UI 로, 새 어휘 금지」 · 2026-10-26 「기능 이름 하나 = 동작 하나」) 을 둘 다 만족하는 조합이 3 이고, 3 은 1 없이는 저장할 곳이 없다. gap B 는 `selectionMode: none` 에서 `deselectItem` · `clearSelection` 도 함께 거절 (op 무관) 하거나, 반대로 selectItem 을 고르면 `selectionMode` 를 `single` 로 올려 주는 안내 중 하나 — ADR 의 사용자 결정 항목.

## 6a. 사용자 결정 (2026-10-27, 같은 날)

> 「새 어휘 금지에 묶일 필요는 없다. 레퍼런스에서 제공하는 api 대로, 권장하는 패턴대로 제공하는 것이 가장 좋지 않을까? https://react-aria.adobe.com/Meter.md — 마크다운도 각각 컴포넌트마다 제공된다」

→ 선택지 2 의 방향으로, 정본은 **레퍼런스 API 표**다. Do = 컴포넌트의 API 표에서 쓸 수 있는 prop (controlled · 표시 값) 하나하나 (`value` · `minValue` · `maxValue` · `valueLabel` · `variant` · `children` · `isIndeterminate` …), When = API 표의 이벤트. 로컬 정본: `.claude/skills/react-aria/references/components/*.md` (RAC 53) · `.claude/skills/react-spectrum/references/components/*.md` (S2 71) 의 `## API` 표 — Meter 는 `| \`value\` | \`number | undefined\` | 0 | The current value (controlled). |`처럼 종류 · 기본값 · 설명이 있어 param kind 를 기계적으로 유도할 수 있다. 코드 보기는 RAC 권장 패턴대로 — 규칙이 쓰는 표시 prop 은`useState` 변수 + controlled prop 으로 환원 (`let [meterValue, setMeterValue] = useState(0)`·`<Meter value={meterValue}>`·`onPress={() => setMeterValue(…)}`). 상태 컴포넌트 39 의 기존 등록은 그대로. 결정은 ADR (사용자 `/create-adr`).

## 7. 범위 추정 (ADR breakdown 입력)

- propFollow 종류 확장 (number · enum · variant · icon) + 패널 입력 (`CatalogPropFollowSection` 의 값 칸 = kind 별 입력) + Set state 의 increment 가 number 변수에 닿는 것은 이미 있음.
- 원본 정의 `accepts` 보강 — 표 B 30 type 의 binding `accepts` 와 대조하는 정적 게이트 하나 (정의 ⊆ binding 이면 통과, 지금은 Meter 1/11).
- 코드 보기: `prop={x}` 는 어휘에 있음 — 숫자 변수 · enum 변수의 골든 1 추가.
- gap B 수리 1 줄 + 정적 테스트.
- live: Button → Set state increment → Meter · ProgressBar · ProgressCircle · Badge variant · Text 글자 — Canvas 는 기본값, Preview 에서 변화 (설계된 비대칭).

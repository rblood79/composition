# 토큰 모델 A — 노드 값의 토큰 참조 저장 · Design 패널 토큰 먼저 입력기 (2026-11-01 상세 분석)

> 읽기 전용 조사. 제품 코드 변경 0. 사용자 요청 (2026-11-01) = 「295는 착수 완료 되었으니 범위 밖 후속 작업으로 다시 상세하게 분석해」 — ADR-295 (D3 토큰 **값** 을 S2 로, Implemented 2026-10-31) 의 Decision 7 · breakdown §6.12 가 「다음 ADR」 로 남긴 **토큰 모델 A** (패널 입력기가 노드에 px · hex 리터럴 대신 토큰 참조를 저장하는 방식, 시안 `docs/design/styles-token-model/`) 를 295 이후 코드 (main `dd7a12602`) 기준으로 다시 잰다.
> 조사는 병렬 Explore 에이전트 2 (패널 위젯 · 노드 저장/렌더 경로) 가 했고, 아래 인용 라인은 메인 세션이 직접 열어 확인했다. live 로 재현하지 않은 판정은 「추정」 으로 표시했다. 후속: ADR-298 (`docs/adr/completed/298-node-token-reference-panel-token-first.md`).

## 0. 한 줄 결론

토큰 모델 A 는 **문서 스키마를 새로 만드는 일이 아니다.** 노드 `visual` 의 토큰 참조 형 `TokenUse {kind:"token", tokenId}` · resolver 의 테마 · 모드 재읽기 · 295 의 출처 기억 · 그래프 의존 색인 · 코드 보기의 `var(--catalog-token-*)` 양방향 (ADR-296 Phase 4, 11-01) 이 전부 이미 있다. 295 breakdown §1 이 예상한 「노드 typed field 에 토큰 참조 축 추가 (문서 스키마 변경)」 는 실제 코드와 다르다. 남은 일은 (1) 패널 쓰기 · 읽기 경로가 리터럴로만 오가는 것, (2) DOM 의 토큰 변수 변환이 기기 축 (글자 · 높이) 에만 있는 것, (3) 라이브러리 토큰이 rule 이 쓴 ref 만 테마 접미사 id 로 있는 것, (4) 검증 표의 키 범위, (5) fills 색 · layout inset · sizing 에 참조 형이 없는 것 (이 셋만 스키마 변경) 이다. 시안은 295 이전 값 (radius M 6 · 제목 4단 24 ~ 48 · 고정 행간) 으로 그려져 있어 2026-11-01 에 값을 고쳤다 (§3).

## 4. 토큰 모델 A 와 따로 있는 결함 · 잔여

- **DOM 그림자가 dark 에서 light 값으로 고정 (코드 근거, live 미확인)** — §2 g. 토큰 모델 A 가 `{shadow.sm}` 참조를 저장하면 역매핑 우회 자체가 사라지지만, 기존 문서의 리터럴 그림자는 그대로 남으므로 수리는 별도 `/fix` → `/cross-check` 가 맞다 (ADR-298 사용자 결정 7).
- 쓰지 않는 코드: `PAGE_GAP_PRESETS` (사용 0) · `isFontSizeFromPreset` (계산만, 사용 0) · `.property-modified` CSS (참조 0). 칸 안에서 **상속값과 작성값을 구분해 보이는 장치가 지금은 없다** — 시안의 「비움 = rule 기본값 상속」 표시는 새로 만든다.
- 감사 (DESIGN_PANEL_CONSISTENCY_AUDIT_2026-10) 와 겹치는 항목: C4 (px 길이 위젯 3종 · ScrubInput 폐기) · C5 (제거 자리) · D4 (ScrubInput 키보드 도달 불가) · E2 (Position 요약 문단) · G (번역 키). 토큰 모델 A 에 묶을지는 ADR-298 사용자 결정 6.

## 5. 정해야 할 것 (ADR-298 「사용자 결정」 으로 옮김)

1. **라이브러리 토큰 id** — 테마 접미사 없이 단계 전체를 담은 토큰 표 (rule 사용 여부와 무관) 를 둘지 (권고), 프로젝트 토큰 `TokenEntry` 에 `ref` 를 더해 그쪽을 쓸지.
2. **Fill 색 · Position inset 스키마 변경** (§2 d) 을 범위에 넣을지, Layout 의 spacing · radius · border · shadow · 글자만 먼저 할지.
3. **Border Width 슬라이더 → 토큰 칸** — 2026-09-15 「Width 는 슬라이더」 판정 변경.
4. **색 팔레트 순서** Theme 먼저 (지금 Document → Theme, `ColorPickerPalettes.components.tsx:160, 181`).
5. **Line Height 「auto」** = 저장값 없음 (글자 토큰의 행간을 따름) 의 의미 확정.
6. 감사 C4 · E2 를 이 작업에 묶을지.
7. DOM 그림자 dark 결함 — 선행 `/fix` 인지, 298 안에서 토큰 저장으로 흡수하고 기존 리터럴은 두는지.

(초판 분석에 있던 「ADR-296 Phase 4 와의 순서」 는 296 이 11-01 Implemented 되어 소멸 — 코드 보기는 이미 토큰 변수를 양방향으로 낸다.)

# catalog rule 상태 표현 · 우선순위 분기 전수 조사 (2026-11-01)

> 읽기 전용 조사. 제품 코드 변경 0. 질문 = 「React Spectrum S2 의 style 유틸 패턴 (속성마다 조건을 중첩한 트리, 우선순위 = 중첩 순서) 을 catalog rule 과 Canvas 에 적용하면 좋지 않나」 (사용자 2026-11-01). 답하기 위해 두 가지를 쟀다 — (1) rule 형식을 바꿀 때 같이 바뀌어야 하는 저장 장소 · 소비자 전수, (2) 상호작용 · 선택 상태 값을 Canvas (Skia) 와 DOM (CSS) 이 각자 어떤 우선순위로 고르는지 전수.
> 조사는 병렬 에이전트 2개 (저장 장소 · 상태 분기) 가 했고, 아래 §1 · §2 의 인용 라인과 수치 (StateName · DISPLAY_PAINT_STATE · quietStyles rootSelectors 읽기 · selectedHover 0건 · data-\* 키 56 · 생성 CSS 103 커밋 · `.button-base` hover mix · stateStyles 순서) 는 메인 세션이 직접 열어 확인했다. cascade specificity 로 계산한 판정은 「추정」 으로 표시했고 브라우저에서 확인하지 않았다. 경로는 저장소 루트 기준.

## 0. 한 줄 결론

`ComponentRule` 모양을 저장하는 곳은 `COMPONENT_RULES_TABLE` 하나뿐이라 **데이터 마이그레이션은 0** 이다. 그러나 rule 은 상태를 **5가지 방식**으로 나눠 적고, 그 값 사이의 우선순위는 데이터에 없고 Canvas (`resolveCatalogPaint.ts` 삼항 사슬) 와 DOM (`CSSGenerator.ts` 출력 순서 + specificity) 두 코드에 따로 적혀 있다. 상태 11종 중 **9종의 우선순위가 두 쪽에서 다르다** (추정 포함). S2 패턴을 가져온다면 가져올 것은 macro 자체 (빌드 때 atomic class — Skia 가 못 읽음, ADR-295 대안 E 기각 사유와 같음) 가 아니라 **조건 트리라는 데이터 형식**과, 그 트리 하나를 Canvas 는 `evaluate(tree, state)` 로, DOM 은 `compile(tree)` 로 소비하는 구조다.

### 2.2 Canvas 가 상태를 받는 곳 = 하나 · 단일 상태

- Builder 가 `CatalogCompositionRoot` 를 만들 때 `state` 인자에 `undefined` 를 넘긴다 (`apps/builder/src/builder/catalogRuntime/workspace.ts:229-233`). 그래서 `root.state` 는 늘 비어 있다.
- 실제 상태는 state-origin template 노드의 `displayState` → `catalogNodeState(node.displayState, root.state)` (`canvasBinding.ts:848, 885` · `compositionRoot.ts:2636`) → `resolver.ts:2637-2641`. 표시 상태 → paint 상태 표 `DISPLAY_PAINT_STATE` (`resolver.ts:477-485`: selected · disabled · hover · pressed · focusVisible 5종) · 표시 상태 → prop 표 `DISPLAY_STATE_PROPS` (`:467-475`). 고르는 순서 instance root layer → path patch → template (`:2065-2068`).
- 원본 라이브러리의 state-origin: hover · pressed · focusVisible · disabled 각 12 · selected 8 · unselected 9 (`reusableOriginLibrary.ts`).
- Canvas 에서 hover 를 미리 보는 기능은 없다 — `skia/hoverRenderer.ts` 는 파란 테두리 overlay 만. Design · Properties 패널에 state 선택기 없음.
- 따라서 Canvas 는 **한 번에 상태 하나**만 고른다. `isSelected ∧ isHovered` 같은 결합 상태는 Canvas 에 도달하지 못한다.

### 2.5 두 소비자 밖의 판정 자리 7곳

1. **작성 stateRules 의 DOM 런타임 시트** `packages/shared/src/catalog/runtime/stateStyles.ts:12-22, 88-104` — `[data-catalog-<state>~=prop]:where(…)` + `!important`, 값은 inline CSS 변수 (`withCatalogStateStyles` :109-161 ← `domBinding.runtime.ts:3817` ← `domBinding.components.tsx:395-405`). 모든 블록 specificity 가 같아 출력 순서 = 우선순위: disabled > selectedPressed > selectedHover > selected > pressed > focusVisible > hover. 2. **Preview inline 상태 색** `domBinding.runtime.ts:3583-3594` (ToggleButton 글자 `color: inherit`) · `:3606-3640` (Button 휴지 색은 작성됐을 때만 `--button-*` 변수 inline · disabled Button 은 휴지 칠 유지).

4. **Styles 패널 미리보기** `apps/builder/src/builder/panels/styles/utils/specPresetResolver.ts:551-575` — `interactionState: "default"` 로 rCP 직접 호출, rP 의 selected variant 교체 · owner 선택을 거치지 않음.
5. **Canvas 의 축소판 선택자 매처** qS:17-59 · `disclosureBorders.ts:41-62` (§2.4).
6. **상태 토큰 생성원** `tintToSkiaColors.ts:304-305` (`accent-hover` · `accent-pressed` = `mixWithBlackSrgb(accent, 85 | 75)`) · `neutralToSkiaColors.ts:40-63` — ~~Skia 쪽 사본~~ **정정 (ADR-297 리뷰 round 1 h2, 2026-10-31)**: `resolveThemeSnapshot.ts:263-278` 이 이 결과를 seed 위에 펼쳐 Canvas 색 맵을 만들고 `:487-495` 가 같은 맵을 DOM `--accent-hover` 로 내보낸다. 즉 **양 leg 가 읽는 토큰의 생성원** 이지 사본이 아니다 (두 항목을 빼면 기본 테마 hover 가 `#2e52cc` → `#1f54c8` 로 양쪽 다 바뀜 — 가상 삭제 진단). 판정 자리가 아니라 값 생성 자리. ## 4. ADR 에 넘기는 사실 · 결정 후보

1. **데이터 마이그레이션 0** — 범위 = 표 1 + 투영기 3 (§1.2) + 어댑터 2 + 타입 3벌 통합 (§1.5) + 잠자는 통로 1 (§1.1) + 정적 테스트 oracle (§1.4). 회귀 기준 = 생성 CSS diff 0 · Skia paint 동일.
2. **실제 결함은 형식보다 우선순위 불일치** — §2.3 「다름」 9건은 지금도 live 비대칭 후보 (추정 포함, 브라우저 미확인). 조건 트리 하나 + evaluator / compiler 가 구조적으로 닫는다. ADR Phase 0 에서 9건을 Compare Mode 로 실측해 확정 · 추정 구분.
3. **Canvas 상태 모델이 단일 상태** (§2.2) — 트리의 결합 조건 (`isSelected ∧ isHovered`) 을 Canvas 가 쓰려면 `displayState` 를 상태 집합으로 넓혀야 한다. scope 결정 사항 (CLAUDE.md §전제 4) — 결합 상태 없이 가면 `selectedHover` · `selectedPressed` 는 DOM 전용으로 남는다.
4. **생성 CSS 위에 겹친 층** — `.button-base` (`utilities.css` — 자체 color-mix, 토큰 생성원과 별개) · 수동 CSS (static 42 · selected 79 · focus 72) · Preview inline (§2.5 ②) · 작성 stateRules 시트 (§2.5 ①). **compiler 주의 (ADR-297 리뷰 round 1 h1)**: 조건 선택자를 날것으로 내면 specificity 가 source order 를 이겨 트리 순서와 갈린다 — `[data-quiet][data-hovered]` 0-3-0 > `[data-invalid]` 0-2-0 (Chromium 반례). `:where()` 정규화가 필요하다.. 조건 트리로 옮기면 적어도 `.button-base` 의 ramp 와 static 수동 CSS 는 흡수 대상이고, 안 옮기면 우선순위 불일치가 그대로 남는다.
5. **rootSelectors 56 키** 중 Canvas 가 읽는 것은 quiet · invalid · disabled 세 축뿐 (§2.4) — 조건 트리에 `isQuiet` · `isInvalid` · `isDisabled` 를 두면 축소판 매처 2개가 없어지고, 나머지 (focus · ListBox 구분선 · Toast) 는 DOM 전용으로 명시.
6. **Styles 패널 미리보기** (§2.5 ④) 가 세 번째 소비자 — evaluator 를 같이 쓰게 해야 패널 · Canvas · DOM 삼자 일치.

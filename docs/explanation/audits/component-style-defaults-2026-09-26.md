## 판정

모든 인라인을 일괄 제거하면 안 된다. 같은 값의 중복, catalog를 가리는 고정값, 생성 템플릿 설정, 소비 경로의 제약 때문에 남은 값이 함께 존재한다. 아래는 **코드 계약 조사 결과**이며 화면 회귀가 전부 재현됐다는 뜻이 아니다.

### 1. Dialog: 이전 100% 변경이 현재 HEAD에는 유지되지 않는다

- `apps/builder/src/builder/factories/definitions/OverlayComponents.ts:61`: 본문 `width:400px; maxWidth:100%`.
- `apps/builder/src/types/builder/unified.types.ts:1856`: 기본 props도 같은 값을 미러한다.
- `packages/shared/src/catalog/generated/componentRulesTable.ts:4702`: Dialog containerStyles에는 `overflow:auto`만 있고 width가 없다.
- `3f50bcf6c`에서 DialogTrigger 조합으로 바뀌면서 400px가 복구됐다. default mirror는 이후 그 값에 맞춰졌다.
- 따라서 현재 동작은 ‘부모 폭 100%’ 기본이 아니라 ‘400px, 최대 부모 폭’ 설정이다. 다만 이제 팝업 본문이므로 새 Trigger/Modal 계약까지 고려해서 결정해야 한다. factory의 ‘기본 너비 100%는 catalog’ 주석은 현재 코드와 불일치한다.

### 2. size와 theme를 가리는 고정값: 우선 검증 대상

- **ColorField**: factory/default/origin `gap:8`은 catalog의 md gap8과 같다. 하지만 sizes는 xs/sm6, lg10, xl12이므로 고정 인라인이 size별 값의 적용을 막을 수 있다. `DateColorComponents.ts`, `unified.types.ts`, generated `ColorField.css:21` 및 size 블록을 대조했다.
- **Select / ComboBox / NumberField / SearchField**: width100%와 md 기준 gap6 또는8을 생성·기본값에 저장한다. width 중복과 size별 gap 고정 문제를 별도 취급해야 한다.
- **Card**: `cardTemplateOrigins.ts:225`의 `borderWidth:1px`와 기본 props가 남아 있지만 catalog Card `sizes.*.borderWidth`는 `{border.width.thin}`이다. ‘catalog 미보유’ 주석도 현재 상태와 다르다. 테마 thin 변경 시 origin 인라인이 우선하는지 검증하고 공통 기본값으로 이관할 후보이다.
- **ColorSwatch / Modal / Popover**: 기본 props에도 `borderWidth:1px`가 있다. 기본값 선언 자체와 실제 생성 origin 주입 여부는 아래 전수 표 및 origin 목록으로 구분한다. 일괄 버그로 확정하지 않는다.

### 3. 동일 선언 중복: 이관 후보

대표적인 root `width:100%` 중복은 TextField, TextArea, NumberField, SearchField, ColorField, Select, ComboBox, DateField, TimeField, ListBox, GridList, FileUpload, IllustratedMessage, ProgressBar, Meter다. Card 전용 origin에도 동일 width가 있다.

FileUpload의 display/flexDirection/width, IllustratedMessage의 display/flexDirection/alignItems/width, Tooltip의 display도 catalog base와 생성 값이 같다. 현재 값이 같다는 사실은 확인했으나 삭제 안전성은 Canvas/Preview·패널 reset·origin 재hydration을 확인해야 한다.

### 4. 생성 의도로 남겨야 하거나 정책 결정이 필요한 항목

- **Chart**: catalog width100% 대 `packages/specs/src/chart/authoring.ts:255` 생성 width320. factory/default뿐 아니라 팔레트 creationVariants의 initialProps도 이 헬퍼를 소비한다. 세 군데 중 한 군데만 바꾸면 안 된다. 초기 배치 크기로 볼지 공통 기본 너비로 볼지 정책 결정 대상이다.
- **CardView 내부 Card 200×160**, Form 내부 FieldError display:none, 아이콘 슬롯 크기 등은 템플릿 문맥 값이다. 모든 Card·FieldError·Icon에 같은 값을 올리면 안 된다.
- **Text whiteSpace:pre-wrap**은 `creationStyleDefaults.ts`에 새 Text 편집 규약으로 명시돼 있다. 기존 문서 기본 normal과 구분하기 위한 생성 정책이다.
- **frame / Group / Slot**은 일반 catalog-only 컴포넌트와 같은 기준으로 삭제할 수 없다. 잔존 spec 및 레이아웃 계약을 함께 본다.

### 5. 기본 props에만 남은 값과 기반 시설 제약

- ProgressCircle factory는 size 기반 지름을 위해 인라인 width/height를 제거했지만 `createDefaultProgressCircleProps`에는 32×32가 남아 있다. 현재 일반 origin은 정규화 후 그 값이 없다. 기본 props fallback과 reset 경로에 영향을 주는 잔재 후보이며, 현재 원 크기가 잘못 렌더된다고 단정하지 않는다.
- CardHeader/Content/Footer/Preview 기본 props에는 catalog로 이관된 layout 미러가 여럿 남아 있다. origin에서 제거됐다고 default 함수를 무조건 비워서는 안 되며 단독 생성·reset 소비자를 확인해야 한다.
- `packages/specs/src/renderers/CSSGenerator.ts:840`의 `emitContainerStyles`는 고정 allowlist다. width/minHeight/maxHeight는 출력하지만 height/maxWidth/rowGap/columnGap 등은 이 함수에서 직접 출력하지 않는다. 다른 composition·size 출력 경로는 별개다. 이 채널 제약을 해소하지 않고 전부 containerStyles로 옮기면 DOM과 Canvas가 달라질 수 있다.
- catalog base resolver 출력에는 camelCase와 kebab-case가 혼재하고, size·variant·delegation·theme는 별도 합성된다. 표에서 catalog base가 비었다고 ‘catalog 스타일이 전혀 없다’고 해석하면 안 된다.

# RAC · S2 연동 기능 전수 목록 — 빌더 지원 현황

> 사용자 지시 (2026-10-23): 「레퍼런스의 연동 기능 모두 놓치는 것 없이 학습하고 담아 둬야 한다」. 빌더 사용자가 어떤 구성을 할지 모르므로 레퍼런스가 제공하는 연동은 전부 지원 대상이다. 새 연동을 설계하기 전에 이 표에서 레퍼런스 이름 · 모양을 먼저 찾는다 — 레퍼런스에 있는 것은 그 이름 그대로 (`useListData` · `useAsyncList` · `RouterProvider` · `loadingState` …), 없는 것만 composition 확장 (`d2Provenance.ts`).

- **출처**: 로컬 공식 스냅샷 전부 — `.claude/skills/react-aria/references/` (guides 12 · utilities 19 · interactions 18 · components 53 + hook 문서) · `.claude/skills/react-spectrum/references/` (components 71 · guides). 문서와 설치본이 다르면 **설치본이 정본** (RAC = D1, S2 = D2 — 버전은 `apps/builder/package.json` 의 `@react-spectrum/s2`).
- **연동 기능**: 컴포넌트를 데이터 · 상태 · 라우팅 · 폼/서버 · 비동기 로딩 · 다른 컴포넌트에 잇는 것. 순수 스타일 · 접근성 이름 · press/hover 같은 기본 interaction 단위는 뺐다.
- **빌더 열**: ✅ 지원 · ◐ 부분 · ✗ 없음 · ? 코드로 확인 못 함 (지원으로 간주 금지). 빌더 쪽 이름: 바인딩 = `NodeEntry.binding` (`DataBindingRef`), 규칙 = `InteractionEntry` (When · Do), 개념 = `packages/shared/src/interactions/concepts/*.ts`, 세션 = `catalogPreviewSession.ts`.
- **스냅샷 공백** (문서에 없어 설치본으로 확인할 것): `useListData` · `useAsyncList` · `useTreeData` 의 Options · Interface 표가 비어 있다 (메서드는 예제에서만). `useListData.getItem` · `filterText` · `setFilterText`, `useAsyncList` 의 `error` · `sort()` 는 문서에 없고 설치본 (react-stately) 에 있다. S2 `LoadingState` 값은 문서에 `loading` · `loadingMore` 만, 설치 타입은 `loading | sorting | loadingMore | error | idle | filtering`.

갱신: 연동을 추가 · 변경하면 해당 행의 빌더 열을 같은 커밋에서 고친다.

## 13. 구현 기록 — data-interaction.md §5 · §6 에서 옮긴 설명 · Why

규칙 파일에는 규칙 문장만 남기고 원문을 여기 둔다.

- **Preview/Publish 의 상태는 첫 render 부터 controlled**: running Preview (`setRuntimeProps` 가 있는 렌더) 의 binding 은 상태 prop 을 `catalogControlledProps` (`catalog/runtime/runtimeStateProps.ts`) 로 넘긴다 — 값은 항상 정의 (`undefined` 로 uncontrolled 에 떨어지는 render 금지 — react-stately 는 `value !== undefined` 로 판정), RAC 의 변경은 record 의 runtime 값으로, `default*` 와 controlled prop 을 같이 넘기지 않는다, key 에 상태값을 넣지 않는다 (remount 금지). 현재 값은 `catalogRuntimeStateOf` 하나 (runtime override ?? 시작 상태 — 그룹이 저장한 선택 · 펼침, ADR-308) 를 렌더와 dispatcher 가 같이 읽는다. **Why**: 항목 집계를 `defaultSelectedKeys` 로 넘기던 ListBox · GridList 는 규칙이 쓴 선택이 RAC 에 닿지 않았고, dispatcher 는 집계를 몰라 다중 선택의 `selectItem` 이 기존 선택을 지웠다 (ADR-280 Phase 0 RED).
- **ComboBox 는 선택과 입력 글자를 둘 다 controlled 로 받는다 — 글자는 `CatalogComboBox` 가 쓴다**: RAC 는 `selectedKey` · `inputValue` 가 둘 다 controlled 면 글자 동기화를 쓰는 쪽에 맡긴다 (`useComboBoxState` — 레퍼런스 「Fully controlled」). `onSelectionChange` 가 key 와 그 항목 글자를 한 번에 쓰고 (blur 의 같은 key 호출 = 글자 되돌림, `null` = `allowsCustomValue` 의 custom 값이라 글자를 둔다), 다른 곳의 선택 (규칙 · load) 과 늦게 온 항목 글자는 `ComboBoxStateContext` 를 읽는 자식 effect 가 쓴다. 항목 글자는 `selectionManager.collection` (전체) 에서 — `state.collection` 은 닫혀 있을 때 마지막으로 보인 목록이다. 글자를 쓰는 render 는 `menuTrigger: "manual"` 이다. **Why (2026-10-23)**: 항목 action (virtual 클릭) 은 목록을 먼저 닫고 선택을 알린다 — 닫힌 · focus 된 칸에 글자가 오면 RAC 가 타이핑으로 보고 다시 열었다 (live 재현).
- **Tree 선택 스타일**: TreeItem origin 의 `TreeItemContent` 첫 자식은 `Checkbox[slot=selection]` 이고, `selectionStyle=checkbox` 와 선택 가능한 `selectionMode` 에서만 Canvas presence · DOM 에 나타난다. Tree의 스타일 변경은 하위 selection Checkbox 의 presence 를 갱신한다. **Why (2026-10-23)**: `checkbox → RAC selectionBehavior=toggle` 변환만으로는 행에 Checkbox DOM·Canvas 노드가 생성되지 않아 Property 값이 시각적으로 무효였다. 노드가 없는 행에 붙는 자동 체크박스는 공용 `Tree` 의 데이터 행 경로에만 둔다 (`autoSelectionCheckbox`). **Why (2026-10-24)**: 공용 `TreeItemContent` 가 늘 자동 체크박스를 그려, 내용 노드 없는 TreeItem 은 DOM 에만 체크박스가 생기고 Canvas 에는 없었다 (ADR-256 후속 16 비대칭의 재발).
- **load 반환 선택 (`useAsyncList` load `selectedKeys`)**: `loadCollectionEndpoint` 가 `responseMapping.selectedKeysPath` (key 배열 · `"all"`) 를 읽고, 세션 `onLoadedSelection` → `CatalogPreviewInteractions.selectLoaded` 가 그 collection 에 묶인 record 의 runtime 선택에 쓴다 — `reload` 는 교체, `loadMore` 는 합침 (레퍼런스 reducer), Select · ComboBox 는 첫 key 의 `selectedKey`, `selectionMode: single` 목록은 하나만. 반환이 없으면 선택은 그대로. endpoint 편집기는 `cursorPath` · `selectedKeysPath` 를 draft 로 보낸다 (`toEndpointDraft` — `""` = 지움). **Why (2026-10-23)**: draft 에 `dataPath` 만 있어 편집기의 두 칸이 store 에 닿지 않았다 (입력칸의 지역 값만 보였다).
- **목록 끝 · 입력 검색 (S2 자동 연결)**: 연결된 ListBox · GridList · Table · Tree · Menu 는 「더 보기」 조건 (창 밖 행 또는 `session.pages`) 이면 DOM 이 끝에 RAC `*LoadMoreItem` (`catalogLoadMoreItem`) 을 두고 세션 `showMore` 를 부른다. 바운드 ComboBox · Autocomplete 의 목록이 `{{ filterText }}` endpoint 면 (`session.serverFilterOf`) 입력이 `setFilterText` 로 가고 클라이언트 필터를 끈다. 같은 collection 의 늦은 응답은 `loadSequence` 로 버린다. ComboBox 의 클라이언트 필터 방식은 문서 `defaultFilter` (`contains` · `startsWith` — RAC 함수 prop 의 데이터, S2 는 뺀 prop · `rac` 출처) 를 `CatalogComboBox` 가 `useFilter({sensitivity: "base"})` 로 함수로 만든다 — 서버 필터 (`defaultFilter: () => true`) 가 이긴다. 바운드 Select · ComboBox 도 `loadingState` 를 받아 DOM 이 S2 자리에 스피너를 둔다 — Select trigger 의 chevron 앞 (`loading`, 닫혀 있을 때) · ComboBox Group 의 버튼 앞 (`loading` · `filtering` 500ms 뒤) — `catalogPickerSpinner`. picker 안 ListBox 의 끝은 Popover 너머 picker 의 바인딩으로 더 불러온다 (`boundOwnerOf`).
- **날짜 · 시각 값은 문서가 저장하고 읽는 함수는 하나다 (ADR-309, 2026-11-12)**: 날짜 계열 6종 (DateField · TimeField · DatePicker · DateRangePicker · Calendar · RangeCalendar) 의 `value` 는 ISO 글자 (범위 `{start, end}` · Calendar 다중 선택은 날짜 목록) 이고, DOM · Canvas (입력 글자 · 달력 모델) · dispatcher 시작 상태가 `catalog/runtime/dateValueRead.ts` 하나를 읽는다 — 시작 값 = `value`, 없으면 `defaultValue` (실행 중 값은 키 유무 — 지운 `null` 은 시작 값으로 돌아가지 않는다), 날짜만 있는 값 + 시각 단위 = 자정, Calendar 는 선택 모드에 맞춰 읽고 RAC 의 변경을 ISO 목록으로 쓴다 (빈 목록은 RAC 에 `null`). Canvas DateInput 은 owner 의 값을 파생 값 `_dateValue` 로 받아 owner 편집 때 다시 그려진다. **Why**: 날짜만 있는 값을 시각 단위 DateField 에 주면 RAC 가 렌더 중 예외를 던져 Preview 가 비었고, Calendar 다중 선택의 목록은 RAC 예외 · 쉼표로 이은 글자 저장이 됐다 (리뷰 round 1 반례, 원복 RED).
- **날짜 runtime 파서도 값 모양을 따른다 (2026-11-02)**: RAC DateValue prop은 `parseDateValue`의 date/dateTime/zoned 분기를 쓰고, time-only는 날짜 컴포넌트에 넘기지 않는다. **Why**: 날짜 전용 `parseDate`로 `2026-11-06T00:00:00`을 읽으면 정상적인 달력 선택이 파싱 오류와 빈 입력으로 돌아왔다 (원복 RED, DateField·DatePicker·DateRangePicker DOM 회귀, 한국어·Second Preview 실측).

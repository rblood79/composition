# 반복 표시 · 반복 구간 · Code 보기 (ADR-310)

> 2026-11-21 (ADR-315 Phase 7) 규칙 문서 크기 상한 (`pnpm docs:rule-size`) 때문에 원문 그대로 옮겼다. 규칙 파일에는 요약과 이 파일 링크가 남는다. 이 기능을 고치기 전에 읽는다.

원래 자리: [data-interaction.md](../../../rules/data-interaction.md) §6.

- **반복 표시 `repeat` (ADR-310 Phase 3, 2026-11-15 · contract 67)**: 연결된 목록 (`binding` 을 가진 owner) 은 `NodeEntry.repeat: true` 가 붙은 항목 하나를 데이터 행마다 반복하고, 표시 없는 항목은 고정 항목으로 제자리 (앞 · 뒤) 에 그린다 — RAC 「Combining collections」. resolver 의 세 경로 (소유 노드 · slot 채움 · 프로젝트 template 자리) 가 `repeats(id)` 하나로 판정하고, 원본 (library) template 자리는 반복하지 않는다. 행이 닿는 항목 단계는 shared `catalogRowItemGroups` (resolver 와 같은 길 — 항목 없는 부품을 지나 내려가고 Tabs 는 TabList 로도 넘긴다). 표시는 명령이 붙인다: 연결 (`catalogBindingCommand` → `markRowTemplates` — 사용자 결정 2: 「첫 항목만 템플릿으로 — 나머지 지움」 (기본) · 「모두 고정 항목으로 두고 데이터는 뒤에」 = 마지막 항목 복제본, Design 패널 Collection 칸에 고정 항목 2 개 이상일 때 선택지) · binding 이 든 노드의 `insertNodes` (기본) · 항목 없는 목록은 원본 항목을 소유 노드로 넣으며 (`rowTemplateInsert`) · 「템플릿 바꾸기」 (`setRowTemplate` — Canvas · Layers 우클릭 「Use as row template」) · 해제는 표시만 지워 템플릿이 고정 항목 하나로 남는다 (`clearRowTemplates`). 검증 `REPEAT_NOT_ITEM` (항목 type 만) · `REPEAT_WITH_KEY` (같은 노드의 `binding.key` 와 함께 불가). Layers 는 템플릿 행 하나에 반복 아이콘 · 「× 행 수」 (결정 3 — 데이터 행마다 행을 두지 않는다, 데이터 0 행이면 × 0), Canvas 는 템플릿을 고르면 그 행들에 점선 외곽 (`catalogOverlay.ts` `repeatRows`). 연결한 Table 도 같다 (Phase 4): TableBody 의 Row 하나가 템플릿이고 열마다 Cell 이 `{열 key}` 를 읽는다 (표시를 붙일 때 내용 없는 Cell 에 넣고 key 없는 Column 에 그 key 를 적는다 — 라벨 편집이 Cell 의 필드와 열 정렬 key 를 갈라놓지 않게, `fillTableTemplateCells` · 열 추가는 템플릿 Cell 에 그 열 key, 행 없는 Table 은 연결이 Row 를 넣는다), 다른 Row 는 고정 행 (합계 행) — 옛 합성 행 (`projectTableRows`) 은 삭제. 정렬 · 고정 높이 자르기는 반복 앞에서 (`boundTableRows`), 반복된 행 안의 record 는 저작 HTML id 를 받지 않는다 (RAC 가 Cell id 를 key 로 쓴다 — 첫 행만), 반복 행 안 노드 추가는 증분 영역을 그 행 밖 owner 로 올려 잡는다. 섞인 목록의 데이터 행 key 가 고정 항목 key 와 겹치면 행을 버리거나 key 를 바꾸지 않고 Layers 템플릿 행에 경고 (`boundRowsOf` 의 `keyConflicts` — 그려진 record 의 `props.id` 로 읽어 고정 항목 key 편집이 바로 보인다). **Why**: 「첫 항목 = 템플릿」 이 암묵 규칙이라 연결하면 나머지 항목이 숨은 표본이 됐고 (resolver 다섯 곳 · Layers · 연결 명령), 고정 항목과 데이터 행을 한 목록에 섞을 수 없었다.
- **반복 행 안 편집**: 증분 해석이 경로 · 키를 적을 때는 행 record id (`…#row:<key>`) 가 아니라 resolver 가 묻는 템플릿 자리 (접미사 뗀 id — `resolvePruned` 의 `position`) 로 적는다. 행 템플릿의 빈 글자 `""` 는 표본 글자가 아니다 (`withoutSampleContent` 가 남긴다). 비우지 않은 일반 글자 (「Select row」) 는 표본으로 빼고 행은 원본 기본값을 보인다 — 행이 읽는 글자는 `{field}` 뿐이다 (사용자 결정 2026-11-15: 연결 뒤 쓴 일반 글자를 행마다 보이는 안은 택하지 않음). **Why (2026-11-15)**: 연결한 Table 의 Row 템플릿 Cell · Checkbox 편집이 `RESOLVED_INSTANCE_MISSING` 으로 거부됐고, 비운 Checkbox 라벨은 행마다 원본 기본값 「Checkbox」 로 돌아왔다 (`adr310TableTemplate.test.tsx`).
- **반복 구간의 데이터 위치 (ADR-310 Phase 5, 2026-11-15)**: 반복 항목 · section 의 행은 resolver `repeatRows` 한 함수가 처음 맞는 곳에서 읽는다 — 1번 그 노드 자신의 `binding` (항목 · section 을 직접 연결 — `catalogBindingCommand` 가 항목 type 대상이면 `setOwnRows` 로 그 노드에 `repeat`, 목록 owner 는 연결이 없어도 된다) → 2번 반복 중인 바깥 행의 하위 행 (`fieldMap.children` — 묶음 section 안 항목) → 3번 owner 의 행 (그 뒤 Select 값 모양 · Pagination 쪽 번호 · Table 열 선택 메뉴가 더해졌다 — 지금 순서는 data-interaction.md §6 「반복 표시」). 자기 데이터 구간 (1번) 은 owner 의 템플릿 판정 · 「첫 항목만」 지우기 · 해제 · 「템플릿 바꾸기」 에서 빠진다 (`ownerItemGroups`). 구간마다 자기 `LoadMoreItem` (`catalogRenderRuns` — 구간 바로 뒤, section 안 구간은 목록 끝) 이 자기 collection 을 부르고 표시 창 key 는 그 항목 id 다. 연결 없는 목록의 `loadingState` 는 구간들의 것 (모두 idle → idle, 아니면 처음 도는 구간), 불러온 선택은 가장 가까운 목록 owner 에. 행 갱신은 구간 항목이 아니라 그 목록을 영역으로 잡는다 (`planBindingOwners` — 행 0 개 구간은 record 가 없다). 중첩 반복의 record 행 key 는 바깥 key 와 합친다 (`withRowKey` — `g2/g2b`). RadioGroup · CheckboxGroup · ToggleButtonGroup · SegmentedControl 도 연결하면 항목 하나를 반복한다 (`GROUP_REPEAT_ITEMS` — 그 그룹 owner 아래에서만 항목, Card · Table 머리글의 Checkbox 는 아님), 행 key 는 Radio · Checkbox 의 `value` · ToggleButton · SegmentedControlItem 의 `id` (`keyRowItem`). Layers 「× N」 은 구간마다, 구간 사이 key 중복도 경고한다. **Why**: 한 목록에 데이터 둘 (RAC `<Collection items>` 둘) 을 두면 owner 하나를 읽던 runtime 소비자 (sentinel · 로딩 · 선택) 가 둘째 source 를 불러오지 않았다 (F15).
- **Code 보기의 반복 항목 · 끌기 경계 (ADR-310 Phase 6, 2026-11-15)**: Code 보기는 반복 항목을 렌더 함수로 쓰고 (`generate.ts` `writeChild` · `writeRender` — 본문 = 템플릿 트리, 표본 글자는 resolver 처럼 뺀다), 본문은 하나의 `rows` span 이라 읽기 전용이다 (고치면 `notInCode`). `<Collection>` · `map` 원소의 anchor 는 반복 항목 노드이고 `items` 의 binding 주인은 가장 가까운 연결 owner (`codeViewViews.ts` `bindingHolder` — 1번은 자기). 코드가 새로 쓴 `<Collection>` 은 노드가 아니라 목록의 행 (`rowTemplateInsert`). Preview 끌기는 목록 항목을 순서대로 받아 (`CatalogDragItems` — 반복 노드의 record = 데이터 행, 첫 행은 템플릿 자신의 record 라 `#row:` 로 가르지 않는다) 고정 항목 key 를 빼고 고정 항목 옆 drop 을 구간 처음 · 끝으로 바꾼다 (사용자 결정 4). **Why**: 템플릿이 Phase 3 에서 노드가 됐는데 Code 보기는 합성 한 줄을 내 템플릿 편집이 코드에 보이지 않았고, 고정 항목은 데이터에 없어 그 옆 drop 이 「항목 없음」 으로 실패했다.

## 표시 창 · 쪽 · Tabs 항목 노드 (ADR-310 Phase 1 · 2 · 7)

규칙 파일에는 불변식만 남기고 설명 · Why 를 여기 둔다.

- **「더 보기」 표시 창 (ADR-310 Phase 1, 2026-11-15)**: 세션이 연결된 목록마다 (collection + 연결 노드 id — rows 감싸개의 `ownerId`) 표시 창을 갖고 100 에서 시작한다 (`displayWindows` → `catalogBoundRows` 의 `limit`). 끝 sentinel 은 불러온 행이 창 밖에 남았거나 (`session.moreLoaded` — 마지막 투영이 창에서 잘렸는가) 다음 페이지가 있을 때 나오고, `showMore` 가 창을 늘리거나 다음 cursor 로 받은 뒤 늘린다 — cursor 가 없으면 아무것도 하지 않는다. `reload` (검색 · 정렬 포함) 는 창을 처음으로. **Why**: 투영이 늘 `[0, 100)` 이라 mock 250 행은 끝이 없고 `loadMore` 가 받은 101 번째 행은 세션에만 있었다 (리뷰 round 1 반례). 표본 대상 (ADR-157) 의 `rowCount` · `rowsShown` 으로 판정하면 높이를 정한 목록 · 표본 밖 family 가 빠진다. cursor 없이 창만 늘리면 같은 sentinel 이 다시 보여 끝없이 돈다 (구현 중 실측). 다음 페이지가 불러오는 중이거나 새 행 없이 끝났을 때도 창을 늘리지 않는다 — `loadMore` 는 불러오는 중이면 바로 돌아오므로 새 행이 들어왔는지로 판정한다 (Phase 2 에서 찾은 회귀: picker 목록 끝의 응답이 늦으면 다시 그리기와 sentinel 호출이 끝없이 이어져 `pickerLoading.test.tsx` 가 멈췄다).
- **표시 방식 「페이지」 · 조회 단위 (ADR-310 Phase 7, 2026-11-15)**: 목록 노드의 `rowDisplay` (`pages` · `size`) 를 세션이 읽어 쪽 목록마다 조회 단위 (`pageUnits` — collection + 목록 노드) 를 둔다. 로컬은 `catalogBoundRows` 의 `start` 로 자르고, 원격은 단위의 요청 (`loadPageUnit` — `page` · `pageSize`) 항목을 그 목록에만 — collection 의 불러온 항목 · 편집 기록은 건드리지 않는다 (편집은 단위 항목 위에 다시 적용). Pagination 은 `pagesOf` 로 목록을 가리키고 번호는 resolver `repeatRows` 의 행 출처 (`paginationRows` — row source 의 `pages` 속성, Builder 에는 없음) 다. 쪽 바꾸기는 목록과 그 Pagination 을 다시 해석한다 (`refreshNodes`). **Why**: 세션의 원격 조회 상태가 collection 하나에 묶여 있어 쪽 번호만 목록별로 두면 B 의 3 쪽 응답이 A 의 행을 바꿨다 (본문 F18 · 리뷰 round 2 H1).
- **Tabs 항목 = 노드 (ADR-310 Phase 2, 2026-11-15 · contract 67)**: Tab 과 TabPanel 은 key (Tab `id` ↔ TabPanel `itemId`) 로 짝인 노드다 — Tabs 의 `items` 배열은 없다. 놓은 Tabs 는 원본의 루트 slot 으로 TabList · Tab · TabPanel 을 모두 자기 노드로 갖는다. Tab 의 삭제 · 복제는 같은 명령에서 짝 TabPanel 을 지우거나 새 key 로 복제한다 (`catalogPairedTabPanels` → `removeTargets` · `duplicateNodes`), 「+」 는 Tab + TabPanel 을 한 명령으로 넣는다. **Why**: contract 65 의 배열은 항목 안에 자유 내용 · 노드 편집 · slot 을 둘 수 없었고 (사용자 결정 A2), TabPanels 래퍼를 없앤 뒤 TabPanel 만 template 자리로 남아 짝 명령이 노드 삭제와 template 숨김을 함께 해야 했다.

## 트리 행 (`useTreeData`)

- **트리 데이터 (`useTreeData`)**: 바인딩 `fieldMap.children` (중첩 배열) 또는 `fieldMap.parentId` (평면 행의 부모 key) 를 Tree에서 고른다. `catalogBoundRows` 는 평면 행일 때 전체 목록을 부모 key로 색인한 다음 루트 행에 `children` 을 싣고, resolver 가 바운드 Tree 의 행 TreeItem 안에 같은 행 template 을 하위 행마다 다시 놓는다 (`nestTreeRows` — template 의 표본 하위 TreeItem 은 빠진다, instance 「TreeItem/Default」 는 template 루트로 내려가서). **Why (2026-10-23)**: `children` 배열만 읽으면 일반적인 `id`·`parentId` 테이블의 관계가 모두 한 단계로 표시된다. TreeItem 은 `CATALOG_ROW_ITEM_TYPES` 다 (2026-10-23 전에는 빠져 바운드 Tree 가 행을 반복하지 않았다). Preview 세션은 중첩 배열에는 `replayItemEdits`, 평면 행에는 `replayFlatTreeEdits` 를 사용한다 — `append` · `insert` · `prepend` 의 `parent`, `move` 의 `toParent` (`null` = 맨 위), key 를 받는 편집은 트리 어느 단계든 찾는다.

# catalog 부품 — picker 의 선택 목록 · 달력 · Menu (ADR-253 · 256)

> 2026-11-21 (ADR-315 Phase 7) 규칙 문서 크기 상한 (`pnpm docs:rule-size`) 때문에 원문 그대로 옮겼다. 규칙 파일에는 요약과 이 파일 링크가 남는다. 이 기능을 고치기 전에 읽는다.

원래 자리: [catalog-subparts.md](../../../rules/catalog-subparts.md).

- **picker 의 선택 목록 (ADR-253 Phase 4, 2026-10-07)**: Select · ComboBox 의 항목은 그 안의 ListBox — ListBox 원본의 instance — 의 slot 채움이다 (library `slotFills`). Select · ComboBox 의 ListBox 는 Popover 노드 안에 있다 (ADR-256 Phase 6c · 6d — `Select > … + Popover > ListBox` · `ComboBox > Label + Group(Input + Button) + … + Popover > ListBox`, Preview 는 RAC Select · ComboBox 안에서 자식을 순서대로 그린다). DatePicker · DateRangePicker 의 달력 (Calendar · RangeCalendar 원본의 instance) 은 S2 `CalendarPopover` 처럼 `Popover (여백 0) > Dialog (여백 24 · 16) > 달력` 이고 Popover 는 도움말 앞이다 (2026-11-18 — 그전 6e 는 Dialog 없이; S2 의 여백 `div` 는 Dialog 의 여백, 이름은 picker 의 `DialogContext` — 대체 이름 없음) — 달력 binding 은 picker 안에서 자기 값 · 상태를 넘기지 않아 RAC 의 달력 context 가 이기고, 크기 · `firstDayOfWeek` · `pageBehavior` · min/max 는 picker 의 것, `visibleDuration` · `weeksInMonth` 는 안 Calendar 노드의 것 (picker ↔ 달력 조회는 Dialog 를 건넌다 — Canvas `calendarPicker` · DOM `catalogCalendarPicker`). 시각 단위 picker 의 Dialog 는 달력 뒤에 `frame > TimeField` (range: 시작 · 끝) 를 갖고, day 단위면 둘 다 없다 (`catalogPickerTimeAbsent`); TimeField 의 값 · 단위 · 시간제 · 경계는 picker 의 것 (DOM RAC `TimeFieldContext` ← picker 상태, Canvas `catalogPickerTimeFieldOf`). 달력 노드 트리는 S2 `Calendar.tsx` 의 것 — `CalendarHeader (머리 줄) > CalendarMonth (달별 제목 묶음, 반복)` + `frame > CalendarGrid (반복 — CalendarMonth 밖 grid 는 resolver 가 달마다 복사, 2026-11-18)`. DOM 은 ListBox 노드의 요소를 RAC Popover 안에 그리고 (RAC `ListBox` 그대로 — 이름 · 선택 · focus 는 RAC 의 Select · ComboBox context 소유, D1), Canvas 는 닫힌 목록을 그리지 않는다 (`presence.ts` `catalogHiddenAtRest` 의 `OVERLAY_BODY_TYPES` 분기). 항목을 picker 루트의 직계 자식으로 두지 않는다 — 항목의 소유자 계약 (`componentTraits.ts` `ListBoxItem.owners: ["ListBox"]` → `nestingRules.ts` `RAC_SUBPART_OWNER_TYPES`) 이 막는다 (옛 renderer 한계 표는 ADR-256 Phase 11 에서 삭제했다 — 모든 family 가 노드 트리로 그린다). 항목의 선택 표시는 picker Popover 안 sheet 글리프 (RAC 레퍼런스 `.dropdown-item` 의 lucide check — ListBox rule `rootSelectors["&:is(.react-aria-Popover *)"]` 의 `[data-selected]::before`, 생성 `ListBox.css`. 수동 `ListBox.css` 팝오버 규칙은 Builder 자체 picker 전용 `:not([data-catalog-id])` — 2026-10-13) 가 기본이고, 작성자가 항목에 `showWhen: isSelected` 노드를 넣으면 그 노드가 RAC 의 선택을 따르고 글리프가 비킨다 (`data-selection-mark` — MenuItem 과 같은 길, 6f). **Autocomplete** (ADR-256 Phase 6g) 는 RAC `Autocomplete` 그대로 요소가 없다 — 원본 `Autocomplete > SearchField + ListBox`, Canvas 는 rule 의 `display: contents` (엔진 구현) 로 자식을 부모 흐름에 세운다. **Menu** (ADR-256 후속 4, 2026-10-09) 도 레퍼런스대로 `MenuTrigger > ActionButton + Popover > Menu` 다 — Menu 노드는 어디에 있든 RAC `Menu` (목록 — Canvas 도 목록으로 그린다), trigger 는 ActionButton 노드 (S2 `MenuTrigger` 대로, 2026-11-05 `71922bd0f` — 그전에는 Button), 닫힌 목록은 MenuTrigger 의 Popover (`catalogHiddenAtRest`). MenuTrigger · DialogTrigger · TooltipTrigger 노드는 RAC 처럼 요소가 없다 — DOM 은 자식만, Canvas 는 rule 의 `display: contents` (ADR-256 G5 예제 2 · 9, 2026-10-12 — 전에는 ADR-255 의 배치 `div`). 요소가 없는 노드 (rule 루트 `display: contents`, 그리고 DOM binding 이 요소를 만들지 않는 RAC 부품 — TreeItemContent · SideNavItemContent · SubmenuTrigger · CalendarMonth/YearPicker, 그리고 자식이 있는 FileTrigger — Canvas 도 `display: contents` · 칠 없음 (2026-11-14), S2 Skeleton (ADR-314 — 내용을 감싸는 로딩 context, 원본 루트 = slot `Content`, 빈 Skeleton 은 Canvas 만 점선 자리 `catalogEmptyDropSpot`), `catalogElementlessType`) 의 Design 패널 Layout · Style · Text 탭은 안내만 내고 Canvas 간격 손잡이도 뜨지 않는다 (Screen 은 남김, 2026-11-13 전수 감사 — 전에는 패널이 편집을 받고 Canvas 에만 그렸다). **Why (2026-10-15)**: Canvas 한 번 클릭은 instance 인 MenuTrigger 를 고르고, 그 Radius · Border 편집은 MenuTrigger record 에만 쓰여 어디에도 그려지지 않았다 (사용자 보고 「button radius 적용 안 됨」). Autocomplete 안 Menu 는 열린 목록이고 입력값이 거른다 (G0 예제 4). 하위 메뉴는 `SubmenuTrigger > MenuItem + Popover > Menu` (Design "+" 가 한 번에 넣는다) — MenuItem 안 MenuItem 은 하위 메뉴가 아니다. 사용할 수 없는 항목은 S2 이름 그대로 `UnavailableMenuItemTrigger > MenuItem + Popover > frame > Heading[slot=title] + Content` (S2 체크리스트 §9.3, 2026-11-23 — 같은 "+" 가 넣는다): `isUnavailable` 이면 DOM 은 RAC `SubmenuTrigger` (누르면 도움말, Popover 이름 = 제목 Heading 의 HTML id), 아니면 항목만. 정보 아이콘은 MenuItem 원본의 `slot=descriptor` 노드 (`showWhen: isUnavailable` — composition 상태 키, `unavailableMenuItem.ts`), DOM 은 항목의 상태 frame 에 `isUnavailable` · `hasSubmenu: false` 를 얹어 꺾쇠 대신 그것을 그리고, trigger 의 prop 편집은 `catalogStateDependents` 가 안 조건부 노드를 다시 판정한다. MenuItem 은 S2 `menuitem` grid (2026-11-18): 열 = 선택 표시 · 아이콘 · 라벨 (설명은 그 아래 줄) · 단축키 · chevron (`slot=descriptor`), column gap 0 · 간격은 부품 margin — MenuItem rule 의 `staticSelectors` · `sizeSelectors` 가 정본 (선택 부품은 library 조립 때 ListBox 항목에서 복사 — `selectionItemTemplates.ts`, 배치는 rule). Section 머리 = `Header > Heading + Text[slot=description]`, 「+ Section」 은 Section 뒤 Separator 를 같이 넣고 Menu 안 Separator 는 첫 자리 · 끝 자리 · 다음이 Separator 이면 숨는다 (`catalogMenuSeparatorHidden` — S2 `isSeparatorHidden`).

## field 상자의 크기별 값

원래 자리: catalog-subparts.md 「라벨 행 · 앞 글자 · 도움말」 — field 의 control Group 이 상자일 때 (`CATALOG_BOXED_FIELDS`) 의 값. 규칙 파일에는 구조와 Why 가 남는다.

- **상자가 된 순서**: 2026-11-13 NumberField · ComboBox · DatePicker · SearchField · 11-14 DateRangePicker · TextField · TextArea · ColorField · DateField · TimeField · 11-23 TokenField (`62de3c626` — S2 TextArea 의 `FieldGroup`) — S2 는 버튼을 `FieldGroup` 안에 둔다.
- **버튼 · 글리프**: 버튼은 상자 안 S2 `inputButton` 정사각 (`{size.field-button.<S>}` — field rule delegation, NumberField 증감 글리프 (Button 정의의 증감 slot part rule `STEPPER_GLYPH_PX`) · ComboBox · Select chevron · DatePicker · DateRangePicker 달력 = XS 12 · S 14 · M 16 · L 18 · XL 20 (사용자 2026-11-13 — Button 의 `1lh` 단이 아님, field rule 의 `.react-aria-Button .react-aria-Icon svg` delegation, control Group 을 건너 `CATALOG_PART_RULE_PASS_HOSTS.Group` · `WRAPPED_PART_TOKENS`). SearchField 는 브라우저 기본 지우기 버튼 `::-webkit-search-cancel-button` 을 숨긴다).
- **끝 padding · gap**: S2 간격은 자식 margin 이 아니라 객체의 layout 기본값이다 (`fieldPrefix.ts` `boxEnd`) — NumberField: Group gap = stepper gap · 끝 padding = stepper 끝 여백, ComboBox: 끝 padding = 높이 × 3/16 − 테두리 · gap 4 (사용자), DatePicker: 끝 padding S 2 · M 4 · L/XL 6 · gap = 날짜 gap (`DATE_BOX_GAP` XS 2xs · S ~ L xs · XL sm), DateRangePicker: 끝 padding 4 (S2) · 같은 gap · 시작 DateInput 은 내용 폭 · 끝 DateInput 이 남는 폭 (`catalogFieldBoxInputStyle`), SearchField: 시작 padding = 다른 field 의 `edge-to-text` (사용자 — S2 `pill` 아님) · 끝 padding 0 (S2 `paddingEnd: 0` — 지우기 버튼이 상자 끝, 사용자 2026-11-14) · gap 8 (사용자) · 지우기 버튼 = 높이 폭, 모서리 = template 의 pill (quiet 이면 inline 에서 빠진다) (DatePicker 는 DateRangePicker 상자에서 구분 글자 · 둘째 DateInput 을 뺀 모양 — 사용자 2026-11-13).
- **Input padding**: 앞 글자 뒤 간격 = Input 시작 padding (XS 4 · S 5 · M 6 · L 7 · XL 8 − 상자 gap, `catalogFieldBoxInputStart` — prefix margin 아님, 2026-11-13). NumberField · ComboBox · SearchField 의 Input 은 시작 · 끝 padding 0 — 버튼 · 아이콘과의 간격은 상자 gap 하나다 (사용자 2026-11-13, `catalogFieldBoxInputEnd`), DatePicker · DateRangePicker 의 DateInput 도 끝 padding 0 (상자 내려놓기는 `CATALOG_FIELD_BOX_INPUT_STYLE` — template 값 없음).

## TreeItem · Disclosure 의 chevron

원래 자리: catalog-subparts.md 「toggle indicator 노드」 — 두 chevron 은 owner-drawn part (`OWNER_DRAWN_PART_OWNERS`) 가 아니다.

- **TreeItem 의 chevron** 은 ADR-256 Phase 5h (2026-10-09) 부터 owner-drawn part 가 아니다 — 레퍼런스대로 `TreeItem > TreeItemContent > Button[slot=chevron] > Icon + 글자` 의 작성자 Button 노드 (DOM = RAC 가 펼치기 속성을 주는 RAC Button, 모양은 `Tree.css` · Canvas 상자는 `catalogTreeChevronLayout`, glyph = Icon 노드 — 잎 항목에선 숨김 · 펼치면 `chevron-down` · 색은 항목 글자색). TreeItemContent 의 첫 자식은 선택 `Checkbox[slot=selection]` 이다 (2026-10-24 `ce44113f2`). 옛 `TreeItemChevron` 노드 (2026-10-04 「1안」) 는 쓰이지 않는다.
- **Disclosure 의 chevron** 도 ADR-256 Phase 8c (2026-10-08) 부터 owner-drawn part 가 아니다 — 레퍼런스대로 `Disclosure > DisclosureHeader > Heading > Button[slot=trigger] > Icon + 제목 Text {title}` + `DisclosurePanel` 의 작성자 노드 (DisclosureHeader = S2 제목 줄 `div`, 2026-11-18 — 부품 조회 · part rule · 증분 의존이 frame 처럼 건넌다: `PART_FRAME_TYPES` · `PART_RULE_LAYOUT_FRAMES`) (DOM = RAC Disclosure 가 trigger 에 펼침 속성을 주는 RAC Button, 모양은 Disclosure sheet 의 하위 선택자 · Canvas 는 같은 값을 Disclosure part rule 로 — Heading 과 frame 을 건넌다, glyph = Icon 노드 — 펼치면 `chevron-right` 만 돈다: DOM `[aria-expanded='true'] .react-aria-Icon[data-icon='chevron-right'] svg` 90° · Canvas `chevron-down`). 펼침 판정은 DisclosureGroup 안이면 가장 가까운 조상 그룹의 키 (`catalogDisclosureGroupOf` — RAC 그룹 context 처럼 깊이 무관). 옛 `DisclosureChevron` · `DisclosureContent` type 은 8e (2026-10-08 `30ed56745`) 에서 삭제했다 — 옛 `DisclosureHeader` type 도 그때 삭제했고, 지금의 DisclosureHeader 는 2026-11-18 (`74d31b094`) 에 S2 제목 줄로 새로 둔 것이다.

## 컬렉션 빈 상태의 Layers 표시

원래 자리: catalog-subparts.md 「컬렉션 빈 상태 = 직계 자식 IllustratedMessage」.

Layers 이름은 「EmptyState」 (`layerTree.ts` `nameOf` — 노드 이름이 없을 때, type 은 IllustratedMessage 그대로: RAC · S2 에 EmptyState 컴포넌트는 없고 `renderEmptyState` prop 자리만 있다), 기본 그림은 S2 예제의 `folder-open` (template `descendantPatches`). Layers 는 Canvas 가 그리는 것만 행으로 낸다 — 항목이 있으면 EmptyState 행 없음, 바운드 데이터가 0행이면 항목 틀 행 없이 EmptyState 만 (`workspace.collectionRowHidden` → `layerTree` host `collectionRowHidden`). EmptyState 는 컬렉션과 함께만 지워진다 — `removeTargets` · `moveNodes` 가 `REQUIRED_PART_NOT_REMOVABLE` 로 거절 (`emptyStateCollectionOf`, 직계 자식만 — 항목 안에 직접 넣은 IllustratedMessage 는 자유) · Layers 삭제 버튼 없음 (`CatalogLayerNode.emptyState`). RAC 가 요구하는 부품이 아니라 `RAC_REQUIRED_PARTS` 에는 넣지 않았다 (그 표는 조상 어디서나 찾는다).

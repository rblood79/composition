# Table — 열 트랙 · 칸 · 가상 스크롤 · 표 상태 (ADR-257 · 277 · 310 · 315)

> 2026-11-21 (ADR-315 Phase 7) 규칙 문서 크기 상한 (`pnpm docs:rule-size`) 때문에 원문 그대로 옮겼다. 규칙 파일에는 요약과 이 파일 링크가 남는다. 이 기능을 고치기 전에 읽는다.

## catalog 부품 — 열 트랙 · 칸 (원래 자리: [catalog-subparts.md](../../../rules/catalog-subparts.md))

**Table 열 트랙 (ADR-257 Phase 1, 2026-10-10)**: 열 폭은 Column 의 S2 `width` · `minWidth` · `maxWidth` 가 정본이다. Table 의 머리글 행과 모든 Row 는 각자 grid 이고 트랙 목록은 Table 마다 하나 (`runtime/tableTracks.ts` → 파생 `_tableTracks`) — Canvas `styleOf` 와 DOM (Row inline · 머리글 `tr` 은 `--table-column-tracks`) 이 같은 값을 읽는다. Column · Cell 에 flex 몫을 주지 않고, Cell 자신의 폭은 쓰지 않는다 (Column 의 Styles 폭은 그 prop 으로 간다). 칸 값 (ADR-257 Phase 3) — Cell · Column `align` · Cell `showDivider` · Table 의 `overflowMode` (Column · Cell 로 전파) 은 Column · Cell rule 의 `containerVariants` 가 정본이고 resolver 가 record `visual` 에 실어 두 consumer 가 같이 읽는다. Column `align` 은 같은 열 Cell 에 물려주지 않는다 (S2). Column · Cell 원본의 글자 Text 는 S2 의 plain `span` 이라 Skeleton 참여자가 아니다 (`skeletonContext.ts` `tablePartWords`). 선택 checkbox 열은 Table 원본이 늘 갖고 (Column · Cell 의 `Checkbox[slot=selection]`, 2026-11-18), `selectionMode` none · `selectionStyle` highlight 이면 없다 — `catalogTableSelectionPartHidden` 하나를 Canvas · DOM · 트랙이 읽는다. 머리 줄 전체 선택 Checkbox 는 multiple 만 (S2 `TableHeader`). 행 추가 · Quick Connect 교체 · 정렬 연결 · Column 「+」 는 선택 열을 데이터 열로 세지 않는다 (`collections.ts` `tableSelectionPart`). **GridList 항목 · CardView 의 Card 도 같다 (2026-11-18 사용자 「노드로 늘 둠」)**: 원본이 선택 Checkbox 노드를 갖고 (Card 는 받침 `frame > Checkbox` + SelectionIndicator 덮개 — S2 `CardCheckbox` · `SelectionIndicator`), checkbox 선택일 때만 보인다 (`catalogSelectionCheckboxHidden` — Tree 와 같은 판정, Canvas · DOM). Preview 조작 (ADR-257 Phase 4) — Column `allowsSorting` 의 정렬 · `allowsResizing` 의 폭은 Preview 실행 상태 (문서 · Canvas 무변경, `tableSort.ts`) — 정렬 화살표는 S2 `ColumnContents` 처럼 정렬됐을 때만 이름 앞에 그린다 (DOM `CatalogSortIndicator` — `catalogColumnSortContent` 가 Column 내용 감싸개 맨 앞에 넣는다, Canvas 는 작성된 정렬의 파생 `_sortMark` part. 2026-11-19 `2e449e6a7` 전에는 이름 뒤에 늘 자리를 두고 Canvas 가 그 20px 을 비웠다): 바운드 행은 resolver 가 세션 `tableSort` 로 정렬, 크기 조절 Table 은 RAC `ResizableTableContainer` 안에서 RAC 열 폭 px 가 트랙 (`--table-resized-tracks`). **drag 열 (ADR-295 후속, 2026-10-31)**: drag 규칙 (`onReorder` · `onDragEnd` … — `collectionDragState.ts` `catalogCollectionDragState`, Preview 의 `dragAndDropHooks` 와 같은 판정) 이 있는 Table 은 S2 · RAC 레퍼런스처럼 맨 앞에 drag 열 (16 · 터치 20) 을 둔다 — 문서 노드가 아니다: 트랙 앞에 `16px` (`compositionRoot.withTableDrag` → `_tableTracks` · `_allowsDragging`), Canvas 는 빈 composed part, DOM 은 RAC Column + Row 마다 Cell > RAC `Button[slot=drag]` (`catalogTableDragPart` — 손잡이는 행에 키보드 focus 가 있을 때만, `Table.css`). RAC Column `width` 는 px 숫자라 CSS 기기 식을 못 받아 JS 기기 배율 (`useCatalogDeviceUnit` — 문서 root 의 `--catalog-token-size-unit`, S2 `useScale()` 대응) × 16 — 크기 조절 Table 의 RAC 열 폭 계산이 터치에서도 S2 값 (20) 을 쓴다. **선택 checkbox 열 (2026-10-31)**: 폭을 작성하지 않은 선택 열은 S2 `width={scale === 'medium' ? 40 : 52}` — 터치 값이 × 1.25 가 아니라 기기 두 벌 토큰 `{size.table.selection-column}` (`device.ts`) 이다. Canvas 트랙은 토큰 px, DOM 트랙은 `--catalog-token-size-table-selection-column` (파생 `_tableDeviceTracks` — `tableTracks.ts` `deviceTrack`), 크기 조절 Table 의 RAC 선택 Column 은 `useCatalogDeviceTokenPx` 로 같은 값을 `width` · `minWidth` 에 받는다 (`CatalogTableSelectionColumn` — 없으면 RAC 기본 1fr · 75). 칸 여백은 S2 `paddingX: 16` (Cell · Column rule), 선택 checkbox 열의 Column · Cell 은 끝 8 — 파생 `_tableSelectionPart` (`presence.ts`) 를 Canvas `catalogBoxModel` · DOM 이 읽는다 (작성한 오른쪽 여백이 이김). 칸 안 선택 Checkbox 는 줄 위쪽 (`vertical-align: top`) — Column · Cell 의 part rule (`tableCellCheckboxPartRules`) 을 엔진 · DOM inline 이 같이 읽는다. **Why (2026-11-15)**: 그 값이 수동 `Table.css` 에만 있어 엔진은 inline-flex Checkbox 를 baseline 에 놓았고 머리글이 Canvas 35 · DOM 32 였다. Table 에는 크기 축이 없다 (S2 TableView — 칸 글자 `controlFont` · 행 높이 `density`, 2026-10-31 삭제). **표는 Table 하나다 (ADR-277, 2026-10-21)**: S2 이름의 둘째 표 type 은 type · origin · rule · 생성 CSS · DOM 렌더러 · 팔레트 항목을 전부 지웠고 (`"Table" || "TableView"` 쌍 14 자리도 Table 하나), 팔레트 「table」 의 origin template 이 그 starter (Column ×3 Name · Type · Status + Row ×1 Cell ×3 — `component-table__1_1..3` · `__2_1`) 를 받는다. binding 이 없던 Table 의 첫 Quick Connect 는 열을 schema 로 교체하고 (`resolveColumnMode(plan, replaceColumns, hasBinding)` — 판정은 `target.binding.props`, snapshot 객체가 아니다), 재연결은 보존 기본 + 교체 스위치. `insertTableColumns({ replace: true })` 는 정적 Row 마다 Cell 을 새 열 수만큼 다시 만든다 (해제 뒤 `tableAlignedIn` 참). contract 44 (ADR-278 로 45). GridList (S2 ListView) · Badge 의 `overflowMode` 도 rule 의 `overflow-mode` 블록이 정본이다 (ADR-257 후속) — GridList 값은 항목에 전파되고 (`CATALOG_OVERFLOW_MODE_OWNERS`) 항목 rule 의 nested 블록이 label · description Text record 에, Badge 는 자기 record visual 에 (DOM 은 inline + `Badge.css` `[data-overflow-mode]`).

## 실행 — 가상 스크롤 · 행 창 · 표 상태 (원래 자리: [data-interaction.md](../../../rules/data-interaction.md) §6)

- **표시 방식 「가상 스크롤」 (ADR-310 Phase 8, 2026-11-15)**: `rowDisplay.mode: "virtual"` 목록은 DOM 이 RAC `Virtualizer` 로 감싼다 (lazy `catalogVirtualizer.components.tsx`, 세션은 불러온 행 전부 — Table 은 행 창). `Layout` 옵션은 Canvas 가 읽는 값에서 낸다 — 목록 `catalogVirtualLayout` · grid `catalogGridLayoutCells` · Table 열 폭 `catalogTableTrackWidths` · 방향 `catalogVirtualFlow` (그려진 흐름 — 줄바꿈 · 역순 · 여러 열 grid 는 막고 패널이 이유). Preview · Publish 에는 배치 geometry 가 없어 행 크기를 추정하고 RAC 가 잰다 — 잰 크기가 다음 추정이다 (`CatalogListLayout`). 데이터 행 record (`…#row:<key>`) 아래 자식 · 그린 요소의 React key 는 템플릿 자리다 (`catalogChildKey` · `catalogRowStableElement` — 행 view 를 다른 행에 재사용해도 하위 트리를 다시 마운트하지 않는다). 높이를 정한 Table 도 가상이면 Preview 에서 모든 행 (`boundTableRows`). **Why**: 추정 40 · 실제 32 로 새 행마다 다시 배치하고, 행 id 로 key 를 잡아 재사용 행의 자식이 다시 마운트돼 4x 스크롤 p95 25 ms (같은 조건 순수 RAC 17.5) 였다 — G8 하니스 `adr310-g8-virtual-live.mjs`, frame 기준 = 같은 문서의 순수 RAC 가상 목록 (사용자 결정 8).
- **표 상태 (ADR-315 Phase 1 ~ 3, 2026-11-20)**: Preview · Publish 의 Table 실행 상태는 세션의 표 상태 하나 (`runtime/tableState.ts`), 쓰기는 `session.setTableState` 하나 — 조각 사이 규칙 (`catalogTableStateWith`) 을 지나고 데이터 조각 (정렬 · 검색 · 열 필터) 이 바뀔 때만 행을 다시 읽는다 (열 조각은 행 source 를 부르지 않는다). 열은 Column key. 「Remember state」 표는 Publish 에서만 브라우저에 남는다. **정렬 · 거르기는 보기의 구현 하나**: 정렬 `collections/view/sortOrder.ts` `viewSortOrder`, 검색 · 열 필터 `rowFilter.ts` `viewRowsPassing` (비교는 `viewCompare` — 정렬된 행 번호를 거른다, 유사 검색 등급 `fuzzy.ts`) — 새 비교를 따로 만들지 않는다. 표 상태 → 요청은 번역 하나 (`runtime/tableStateQuery.ts`) 이고 서버가 쪽을 나누는 표는 요청이 조각 전체를 담을 때만 받는다 (`catalogTableSliceServable` — 여러 정렬 `multiSort` · 검색 `searchParam` · 필터 연산자 접미사; 줄여 보내지 않는다, 세션 · 패널이 같은 판정). 이 모듈은 `view/serialize` 를 값으로 import 하지 않는다 (Builder 첫 화면에 행 변환기가 실린다 — `tableStateQueryImports.static.test.ts`). 데이터 조각 변경의 재해석은 `root.reorderRows` — 행 내용은 그대로라 자리 · key 가 같은 행의 record 를 유지하고, 가상 표는 보이는 행을 먼저 · 나머지 창은 paint 뒤 (`session.stageRowWindows`); 행 내용이 바뀌는 변경은 `refreshRows` · `refreshNodes`. 머리글 누름은 `session.pressTableSort` (RAC 에는 첫 정렬만, `_sortEntries` 는 순번 표시용), 후보 값은 보기의 `facet` (자기 조건 제외 · 비교가 같다고 보는 값은 한 후보). Why · 실측: ADR-315 breakdown §9.
- **가상 스크롤 Table 의 행 창 (2026-11-19)**: Preview · Publish 의 가상 스크롤 Table 은 정렬 뒤 행 중 창만 record 로 만든다 (resolver `windowedRows` · TableBody `rowWindow.keys` = 모든 행의 key). DOM 은 모든 행을 같은 자리 · 같은 element key 로 그려 (`CatalogWindowRows` — record 없으면 빈 RAC Row) 창이 지나가도 RAC Row 가 남고, 보이는 행이 16 행 벗어나면 세션 `showRows` → `root.moveRowWindow` 가 남는 행을 그대로 두고 옮긴다. 창 이동의 전제는 「다른 것은 바뀌지 않았다」 — 데이터 · 정렬 · 문서 변경은 `refreshRows` · `refreshNodes`. record 를 읽는 새 소비처는 가상 Table 의 모든 행에 record 가 있다고 가정하지 않는다. 헤더 정렬은 행 source 가 창 · 쪽을 자르기 전에 한다 (`CatalogRowSort` → `catalogBoundRows`). Why · 실측 · 남은 한계: ADR-310 breakdown 「후속 — 행 창」 · 「후속 — 정렬 순서 · 정렬 클릭 · 「포함」 필터」.
- **Table 실행 — 가상 스크롤 · 행 창 · 표 상태 (ADR-310 Phase 8 · ADR-315)**: 가상 목록은 RAC `Virtualizer` (lazy) 이고 `Layout` 옵션은 Canvas 가 읽는 값에서 낸다 — 행 record 아래 React key 는 템플릿 자리다. 가상 Table 은 정렬 뒤 행 중 창만 record 를 만든다 — record 를 읽는 새 소비처는 모든 행에 record 가 있다고 가정하지 않고, 창 이동은 「다른 것은 바뀌지 않았다」 가 전제다 (데이터 · 정렬 · 문서 변경은 `refreshRows` · `refreshNodes`). 실행 상태는 세션의 표 상태 하나 (`runtime/tableState.ts`), 쓰기는 `session.setTableState` 하나 — 데이터 조각 (정렬 · 검색 · 열 필터 · 묶기) 만 행을 다시 읽고 열 조각 (숨김 · 순서 · 고정 · 폭) 은 행 source 를 부르지 않는다 (카운트 게이트). 열은 Column key. 정렬 · 거르기 · 집계는 보기의 구현 하나 (`viewSortOrder` · `viewRowsPassing` · `viewAggregateOf`) — 새 비교 · 집계를 따로 만들지 않는다. 표 상태 → 요청은 번역 하나 (`runtime/tableStateQuery.ts` — `view/serialize` 를 값으로 import 하지 않는다), 서버가 쪽을 나누는 표는 요청이 조각 전체를 담을 때만 맡긴다 (`catalogTableSliceServable` — 줄여 보내지 않는다, 묶음 조회 `groupOf` · 고정 조회 `keys` 는 endpoint 가 선언할 때만; 아니면 전량 로드 상한 10,000 뒤 로컬). 열 투영은 resolver 한 곳 (`resolution/tableColumns.ts`), 묶음 · 계층 · 상세 행은 RAC 펼침 행, 행 고정은 데이터 층에서 가른 뒤 sticky, 칸 병합 판정은 `runtime/tableCellMerge.ts` (창 · 높이 자르기 전), 칸 범위 선택은 `runtime/tableCellSelection.ts` (D1 예외 — [ssot-hierarchy.md](../../../rules/ssot-hierarchy.md) §1). Worker 는 두지 않는다 (ADR-315 Phase 7 판정 — 10 만 행의 계산이 HC4 상한 아래) · 로컬 조회 상한은 10,000 그대로 (`VIEW_LOCAL_LOAD_CAP`, 사용자 결정 7). Why · 실측: ADR-315 breakdown §9.

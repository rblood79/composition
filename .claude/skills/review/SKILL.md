# 코드 리뷰

요청 범위의 diff와 실제 소비 경로를 검토합니다. 범위가 없으면 dirty diff,
clean이면 HEAD 변경을 사용하되 동시 작업의 무관한 변경은 구분합니다.

프로젝트 고유 위험은 [계약 체크리스트](references/contracts.md)에서 변경에 해당하는
부분만 대조합니다. 일반적인 취향·가상 위험을 결함으로 만들지 않습니다.
재현 조건, 영향, 파일·라인을 근거로 보고하고 미확인 가설은 별도로 표시합니다.
심각도와 확신을 구분하며 확신을 임의의 수치 점수로 표현하지 않습니다.

기존 검증 근거가 현재 변경을 포함하는지 확인하고, 확인이 필요한 동작만 실행합니다.
리뷰만 요청되면 판정까지, 수정도 요청되면 해당 범위의 수리와 검증까지 완료합니다.
위임은 사용자 요청이 있을 때만 합니다. 임의 도구 호출 횟수로 조사를 중단하지 않습니다.

결과에는 주요 이슈와 검증 범위·한계를 적습니다. 이슈가 없으면 그대로 보고합니다.

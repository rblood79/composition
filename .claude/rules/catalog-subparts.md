# catalog 부품 노드 · 소유 축 참조표

> D1/D2/D3 경계와 대칭 원칙은 [ssot-hierarchy.md](ssot-hierarchy.md) §1 D3 가 정본이다. 아래는 그 원칙이 컴포넌트 가족별로 어떤 노드 트리 · 소유 축 · 심볼로 구현돼 있는지의 사실 — 바뀌면 여기만 고친다 (2026-10-15 ssot-hierarchy.md 에서 분리).

**D3 sub-part — field 가족의 부품 노드 (ADR-253 Phase 3, 2026-10-07 — ADR-923 Phase 5 후속의 2026-09-03 · 09-04 판정을 대체)**:

- field · 그룹의 Label · Description · FieldError · Input · DateInput · Button (NumberField 증감 · FieldButton · Select 의 trigger) 은 **부품 원본의 instance** 다. Preview/publish DOM 은 그 노드를 RAC 컴포넌트로 부모의 RAC context 안에서 직접 그리고 (`catalog/runtime/domBinding.runtime.ts` · `delegatedDom.runtime.ts`), 모양은 **부품 자신의 rule** 이 정본이다. 부모 rule 의 delegation 은 배치 (폭 · flex · margin · 버튼 자리) 만 선언한다 — 정적 게이트 `adr253PartShapeOwner.static.test.ts`.
- **편집 축**: style 은 부품 노드 자신이 정본이다 (Styles 패널이 그대로 편집, Canvas 와 DOM 이 같은 record). **글자 축만** 부모 소유인 부품은 `TEXT_ONLY_SUBPART_PARENTS` (Label · Description · FieldError · Input · Select 의 SelectValue — 글자는 부모의 `label` · `description` · `errorMessage` · `placeholder` prop 이 정본). 술어는 `resolveDelegatedSubpartOwnerType` (글자 축 · 전체 — Properties 패널) 와 `resolveSubpartStyleOwnerType` (style 축 — Styles 패널 · AI style 편집) 이고, catalog record 로는 `catalogSubpartOwnerType` (`catalogRuntime/subpart.ts`) 이 읽는다.
- **두 축 모두 부모 소유로 남은 것**: field 의 control `Group` (NumberField · ComboBox · DatePicker · DateRangePicker 바로 아래의 RAC `Group` 노드 — ADR-256 Phase 6b, `FIELD_CONTROL_GROUP_HOSTS`. 모양 · 배치는 field rule 의 delegation 이 주고 DOM 은 Group 노드의 style 을 읽지 않는다 — NumberField · ComboBox · DatePicker · DateRangePicker 는 노드를 RAC `Group` 으로 그린다 — SearchField 는 레퍼런스대로 Group 이 없다: `SearchField > Label + Icon + Input + Button + Description + FieldError`, 배치는 SearchField rule 의 grid (`0px 1fr auto` — 글리프가 빈 열에서 Input 앞쪽 위로, 지우기 버튼이 Input 끝 위로) (ADR-256 G5 예제 5, 2026-10-12) (ComboBox 는 `.combobox-container` — RAC picker 가 그 Group 을 Popover 기준으로 삼는다, 6d · 6e). field 의 size 는 Group 을 건너 부품에 닿는다. 판정 `ownsSubpartDirect`) 와 owner 가 그리는 part (`OWNER_DRAWN_PART_OWNERS` — 아래 toggle indicator). style 축만 부모 소유인 부품은 없다 (`STYLE_ONLY_SUBPART_PARENTS` 비어 있음).
- **picker 의 선택 목록 (ADR-253 Phase 4, 2026-10-07)**: Select · ComboBox 의 항목은 그 안의 ListBox — ListBox 원본의 instance — 의 slot 채움이다 (library `slotFills`). Select · ComboBox 의 ListBox 는 Popover 노드 안에 있다 (ADR-256 Phase 6c · 6d — `Select > … + Popover > ListBox` · `ComboBox > Label + Group(Input + Button) + … + Popover > ListBox`, Preview 는 RAC Select · ComboBox 안에서 자식을 순서대로 그린다). DatePicker · DateRangePicker 의 달력 (Calendar · RangeCalendar 원본의 instance) 도 Popover 노드 안에 있다 (6e — Dialog 없이, 레퍼런스대로) — 달력 binding 은 picker 안에서 자기 값 · 상태를 넘기지 않아 RAC 의 달력 context 가 이기고, 크기 · `firstDayOfWeek` · `pageBehavior` · min/max 는 picker 의 것, `visibleDuration` · `weeksInMonth` 는 안 Calendar 노드의 것 (ADR-256 Phase 9 — 달력 노드 트리는 `CalendarMonth` 반복 묶음 > header + CalendarGrid). DOM 은 ListBox 노드의 요소를 RAC Popover 안에 그리고 (RAC `ListBox` 그대로 — 이름 · 선택 · focus 는 RAC 의 Select · ComboBox context 소유, D1), Canvas 는 닫힌 목록을 그리지 않는다 (`presence.ts` `TRIGGER_OVERLAY_CHILDREN`). 항목을 picker 루트의 직계 자식으로 두지 않는다 — 항목의 소유자 계약 (`componentTraits.ts` `ListBoxItem.owners: ["ListBox"]` → `nestingRules.ts` `RAC_SUBPART_OWNER_TYPES`) 이 막는다 (옛 renderer 한계 표는 ADR-256 Phase 11 에서 삭제했다 — 모든 family 가 노드 트리로 그린다). 항목의 선택 표시는 picker Popover 안 sheet 글리프 (RAC 레퍼런스 `.dropdown-item` 의 lucide check — ListBox rule `rootSelectors["&:is(.react-aria-Popover *)"]` 의 `[data-selected]::before`, 생성 `ListBox.css`. 수동 `ListBox.css` 팝오버 규칙은 Builder 자체 picker 전용 `:not([data-catalog-id])` — 2026-10-13) 가 기본이고, 작성자가 항목에 `showWhen: isSelected` 노드를 넣으면 그 노드가 RAC 의 선택을 따르고 글리프가 비킨다 (`data-selection-mark` — MenuItem 과 같은 길, 6f). **Autocomplete** (ADR-256 Phase 6g) 는 RAC `Autocomplete` 그대로 요소가 없다 — 원본 `Autocomplete > SearchField + ListBox`, Canvas 는 rule 의 `display: contents` (엔진 구현) 로 자식을 부모 흐름에 세운다. **Menu** (ADR-256 후속 4, 2026-10-09) 도 레퍼런스대로 `MenuTrigger > Button + Popover > Menu` 다 — Menu 노드는 어디에 있든 RAC `Menu` (목록 — Canvas 도 목록으로 그린다), trigger 는 Button 노드 (모양은 Button rule), 닫힌 목록은 MenuTrigger 의 Popover (`TRIGGER_OVERLAY_CHILDREN.MenuTrigger`). MenuTrigger · DialogTrigger · TooltipTrigger 노드는 RAC 처럼 요소가 없다 — DOM 은 자식만, Canvas 는 rule 의 `display: contents` (ADR-256 G5 예제 2 · 9, 2026-10-12 — 전에는 ADR-255 의 배치 `div`). 요소가 없는 노드 (rule 루트 `display: contents` — `catalogElementlessType`) 의 Design 패널 Layout · Style · Text 탭은 안내만 낸다 (Screen 은 남김). **Why (2026-10-15)**: Canvas 한 번 클릭은 instance 인 MenuTrigger 를 고르고, 그 Radius · Border 편집은 MenuTrigger record 에만 쓰여 어디에도 그려지지 않았다 (사용자 보고 「button radius 적용 안 됨」). Autocomplete 안 Menu 는 열린 목록이고 입력값이 거른다 (G0 예제 4). 하위 메뉴는 `SubmenuTrigger > MenuItem + Popover > Menu` (Design "+" 가 한 번에 넣는다) — MenuItem 안 MenuItem 은 하위 메뉴가 아니다.
- **quiet (`isQuiet`)**: field 의 상자 부품 (Input · DateInput) 이 자기 상태로 그린다 — 부품 rule 의 `&[data-quiet]` 한 정의, 요소의 `data-quiet` 는 quiet field 의 부품에 파생 값 (`presence.ts` `derivedProps.isQuiet`) 으로 실린다. Canvas도 같은 rootSelectors를 `quietStyles.ts`에서 읽어 배경·모서리·밑줄을 그린다 (ADR-253 Round 3 수리). 부모의 invalid/disabled는 부품 파생 값으로 전달한다. 상자가 Input · DateInput 이 아닌 Select (trigger Button) 는 Select rule 의 `quiet.true.nested` 가 정본이다 — trigger 에 `_quietOwner` 파생 값, Canvas 는 `catalogQuietStyles` (`catalog/runtime/quietStyles.ts` — `canvasBinding.ts` · `ruleShapes.ts` 가 읽는다) 로 같은 선언을 읽고, quiet trigger 는 `.button-base` 칠을 끈다. DateRangePicker 는 `isQuiet` 를 받지 않는다 (S2 에 없음) (2026-10-07 ADR-253 후속).
- **라벨 행 · 앞 글자 · 도움말 (ADR-259, 2026-10-13)**: field 도움말은 `FieldLabel` (라벨 행 — S2 `FieldLabel` 의 `div`, 사용자 prop 0) 안 Label 뒤의 `ContextualHelp` 원본 instance 다 (`ContextualHelp > Button > Icon + Popover > Heading[slot=title] + Content + Footer`). 행은 도움말을 넣을 때만 생기고, field 레이아웃에서 Label 의 자리를 이어받는다 — 별칭 하나 (`CATALOG_FIELD_LABEL_PART_ALIASES`) 를 생성 CSS (`partAliases` → `:is(.react-aria-Label, .react-aria-FieldLabel)`) 와 Canvas part rule (글자 값 제외) 이 같이 읽는다. 부품 조회는 행을 건너서 (`PART_FRAME_TYPES`) 행 안 Label 이 field 의 라벨로 남는다. 버튼은 RAC Button `slot={null}` (field ButtonContext 차단), 이름 · Popover 이름 · 글리프는 ContextualHelp 의 `variant` 와 제목에서 파생된다 (D1 = S2 oracle). 앞 글자는 control Group 맨 앞의 Text · Icon (`slot=prefix`) 이고, 앞 글자가 든 Group 이 Input rule 상자를 그린다 (S2 `FieldGroup` — DOM `FieldBox` 별칭 · Canvas 같은 rule, 안 Input 은 상자를 내려놓는다). Group 이 없는 TextField · TextArea · ColorField 는 넣을 때 감싼다.
- **오버레이 본체 = slot (ADR-278, 2026-10-21)**: Dialog `content` (`__content-region`) · `actions` (`__actions-region`), Popover · Tooltip 은 OverlayArrow 뒤 region frame (`__content-region`) 에 `content`, ContextualHelp `content` · `footer`, Menu `Items` — library contract 45. 놓은 instance 는 본체 기본 내용 (제목 · 설명 · 항목) 을 소유 노드로 갖고 (`ownSlotContents`), 커스터마이징은 Local 컴포넌트 instance 를 slot 에 (Design 패널 slot 절 · Layers drop) — Preview 의 RAC Modal · Popover · Tooltip · Menu 가 그 내용을 띄운다. 컬렉션 slot 의 채움 목록 (`catalogSlotInsertOptions` `items` 분기) 도 project 정의를 후보에 넣고 `assertNestable` 이 루트 type 으로 거른다 (MenuItem 루트만 Menu `Items` 에). Canvas 는 오버레이를 열지 않는다 — Components page 샘플만 patch `displayState: "open"` (`DescendantPatchFields.displayState`, resolver 가 instance root 층 → patch → template 순으로 읽음) 으로 본체를 ◆ trigger 오른쪽에 그린다 (`presence.ts` 닫힌 오버레이 분기가 `open` record 는 숨기지 않음). **Local page 카드의 ◆ 도 같다 (2026-10-22, 사용자 보고)**: record 의 source 가 project 컴포넌트의 template root 인 trigger (`compositionRoot.ts` `originBodyOpen` → `componentOriginOf`) 의 본체 (`presence.ts` `OPEN_BODY_TRIGGERS` = DialogTrigger · TooltipTrigger · ContextualHelp · MenuTrigger) 는 patch 없이 열린다 — page 의 instance 는 source 가 instance 노드라 닫힌 채. **Why**: ADR-279 로 원본이 Local page 에 서자 Dialog · Popover 컴포넌트의 본체가 Canvas 에서 0×0 (`display: none`) 이라 Design 패널은 240 을 보여도 편집할 상자가 없었다. picker 의 Popover 는 본체가 부품이라 slot 이 아니다 (Local 카드에서도 닫힌 채).
- **컬렉션 빈 상태 = 직계 자식 IllustratedMessage (사용자 결정 2026-10-23)**: ListBox · GridList · Tree · TagList · Menu (`componentTraits` `emptyStateCollection`) 는 항목 밖에 IllustratedMessage 하나를 직계 자식으로 받고, **원본 template 이 기본으로 하나 갖는다** (`reusableOriginLibrary.ts` 의 `component-*__empty-state` — 놓고 데이터 연결하면 끝, 사용자 지적 2026-10-23 「사용자가 EmptyState 까지 또 해야 하는 것은 잘못」. 허용은 `nestingRules.ts` `CATALOG_EMPTY_STATE_COLLECTIONS`, 지운 뒤 다시 넣기는 `catalogSlotInsertOptions`). 끝에 붙이는 넣기 (항목 「+」 · slot fill · 팔레트) 는 빈 상태 앞에 둔다 (`structure.ts` `catalogAppendIndex`). Layers 이름은 「EmptyState」 (`layerTree.ts` `nameOf` — 노드 이름이 없을 때, type 은 IllustratedMessage 그대로: RAC · S2 에 EmptyState 컴포넌트는 없고 `renderEmptyState` prop 자리만 있다), 기본 그림은 S2 예제의 `folder-open` (template `descendantPatches`). Layers 는 Canvas 가 그리는 것만 행으로 낸다 — 항목이 있으면 EmptyState 행 없음, 바운드 데이터가 0행이면 항목 틀 행 없이 EmptyState 만 (`workspace.collectionRowHidden` → `layerTree` host `collectionRowHidden`). EmptyState 는 컬렉션과 함께만 지워진다 — `removeTargets` · `moveNodes` 가 `REQUIRED_PART_NOT_REMOVABLE` 로 거절 (`emptyStateCollectionOf`, 직계 자식만 — 항목 안에 직접 넣은 IllustratedMessage 는 자유) · Layers 삭제 버튼 없음 (`CatalogLayerNode.emptyState`). RAC 가 요구하는 부품이 아니라 `RAC_REQUIRED_PARTS` 에는 넣지 않았다 (그 표는 조상 어디서나 찾는다). DOM 은 RAC `renderEmptyState` 로 그리고 (`catalogEmptyState` — 바운드 목록 첫 로드 중엔 S2 진행 원), Canvas 는 같은 조건을 `catalogHiddenAtRest` 의 `catalogCollectionHasItems` (RAC `collection.size` 처럼 `item` 만 — section 안 항목 포함, loader · Header · Separator 제외) 로 읽는다. 수동 `[data-empty]` 규칙은 Builder 자체 목록 전용 (`:not([data-catalog-id])`). TableBody · CardView 는 아직.

**바탕의 제목 · 설명 (ADR-254, 2026-10-07)**: Dialog · Popover · InlineAlert · Tooltip 의 제목 · 설명은 Heading · Description 원본의 instance 다 (AI 가 넣는 Heading 도). 컨테이너 rule 은 그 모양을 선언하지 않는다 (InlineAlert 는 size 를 전달 — 설명은 한 단계 위, `CATALOG_SIZE_STEP`. 설명은 S2 `Content` 안 — ADR-256 Phase 10). **Card 는 예외 (ADR-256 Phase 10, 사용자 결정 2026-10-11 「S2 그대로」)**: S2 처럼 `Card > CardPreview + Content (Text[slot=title] + Text[slot=description] + 자유 내용) + Footer` 이고 title · description prop 이 없다 — 글자는 Text 노드의 것, 모양은 Card 가 주는 S2 `TextContext` slot 이라 Card rule 의 `[slot]` 선택자 (`staticSelectors` · `sizeSelectors`) 가 정본. Content · Footer 는 S2 범용 type (Card · InlineAlert 공용) 이고 배치는 부모 rule 이 준다. 바탕 원본 (공용 컨테이너) 은 두지 않는다. Dialog 제목은 RAC `Heading slot="title"` 로 Dialog 의 이름이다 — `aria-label` 폴백은 제목이 없을 때만 binding 이 넘긴다.

- **Button · ToggleButton 의 글자 · 글리프 (ADR-276, 2026-10-20)**: 팔레트 Button · ToggleButton origin 은 `Button > Icon{icon} + Text{label}` (옛 IconButton template) 이다 — 글자는 instance 의 `label` prop 이 Text 자식에 묶이고 (`presentWhen: "nonEmptyText"` — `label: ""` 이면 노드 없음 = icon-only + `aria-label`), 글리프는 `icon` prop (기본값 없음 — 비우면 채워지지 않은 `{icon}` 이 숨는다). Button 자체 `children` 문자열 · 자식 노드 명령 (`setIcon` · `clearIcon`) 은 없다. 중첩 Button 자리 (NumberField 증감 · Select trigger · ButtonGroup · Pagination · trigger …) 도 같은 template 을 받아 자기 글자를 `label` 로 적는다 (글자 없는 자리는 `label: ""`). FieldButton 은 `icon` 을 Button 의 Icon 자리에 묶는다. Text 자식의 크기 · 색은 Button rule 의 child part rule (`buttonChildScaleRules` · 색 상속) — ToggleButton 도 같다 (`catalogToggleButtonGlyphOwner` 가 Text 도 소유). Button · ToggleButton 은 `CATALOG_TEXT_STYLE_CONTAINERS` — typography (letterSpacing · textAlign · textDecoration …) 가 Text 자식에 닿는다. 더블클릭은 Text 자식을 편집한다 (`resolveCatalogTextEditRecord`). IconButton origin · 팔레트 항목은 삭제 (S2 에 없음). contract 43.
- **글자 소유 = template 바인딩 (ADR-254 Decision 5)**: template 이 부모 prop 에 묶은 글자 (`{label}` · `{title}` · `{description}`) 는 그 prop 이 정본이다 — Canvas 인라인 편집은 그 prop 에 쓰고 Properties 는 부모 소유로 안내한다 (`catalogRuntime/textBinding.ts`). 판정은 type 표가 아니라 바인딩이다 (InlineAlert 의 설명은 Content 너머). 자유 slot 에 넣은 글자 · 묶이지 않은 글자는 노드 자신의 것.
- 금지: 자식 style 을 RAC 내부 sub-part 로 운반하는 custom prop 신설 (RSP 미규정 — D2 위반).

**그룹 항목 묶음 노드 — RadioItems · CheckboxItems (ADR-251, 2026-10-03)**: RAC `RadioGroup` · `CheckboxGroup` 의 children 안에 composition 이 두는 항목 상자 (`div.radio-items`, RAC 구조 밖 · role 없음 — D1 무변경) 를 문서 노드로 둔다. 값 (방향 · gap) 은 그룹 rule `orientation` 블록이 정본 (D3), 묶음 노드는 사용자 prop 이 없고 `size` 만 내부 운반 값 (D2 신규 prop 0). DOM 은 그룹이 묶음을 흡수하고 shared 컴포넌트의 상자 하나가 그린다 — 묶음에 작성한 style 은 DOM 에 닿지 않는다 (TagList 와 같은 편집 범위).

**toggle indicator 노드 — CheckboxIndicator · RadioIndicator · SwitchIndicator (2026-10-04 사용자 지시 「1안」)**: Checkbox · Radio · Switch 의 indicator 상자 (RAC toggle 이 직접 그리는 `div.checkbox` · `.react-aria-Radio::before` · `div.indicator`) 를 template 첫 자식 노드로 둔다. 크기는 toggle rule `size.indicator` 가 partRule 로, 칠은 toggle rule primitive 를 노드 상자에서 실행한다 (D3 정본 = toggle rule). 노드는 사용자 prop 0 (D2 신규 prop 0) · DOM 출력 0 (D1 무변경 — 부모가 흡수) · 편집 surface 는 toggle 로 귀속 (`OWNER_DRAWN_PART_OWNERS` — sub-part owner 판정). **ADR-256 Phase 3 (2026-10-08)**: Checkbox · Switch · Radio 는 레퍼런스대로 RAC `*Field` (`div` — 세로 묶음) > `*Button` (`label` — indicator + 글자 행) + Description (+ FieldError — Radio 는 없음) 다. Radio 고리는 `::before` 가 아니라 indicator 노드 자리의 `div.indicator` 요소다. indicator 는 그 버튼 안에 있고 owner 는 버튼을 건너 찾는다 (`OWNER_DRAWN_PART_HOSTS`). 버튼의 행 배치 · gap 은 Checkbox rule 의 `.react-aria-CheckboxButton` 블록이 정본이며 버튼 자체 rule 은 없다. 버튼 안 글자 (Label type) 는 RAC `Label` 이 아니라 `span` (그룹의 label context 를 받지 않는다). **TreeItem 의 chevron** 은 ADR-256 Phase 5h (2026-10-09) 부터 owner-drawn part 가 아니다 — 레퍼런스대로 `TreeItem > TreeItemContent > Button[slot=chevron] > Icon + 글자` 의 작성자 Button 노드 (DOM = RAC 가 펼치기 속성을 주는 RAC Button, 모양은 `Tree.css` · Canvas 상자는 `catalogTreeChevronLayout`, glyph = Icon 노드 — 잎 항목에선 숨김 · 펼치면 `chevron-down` · 색은 항목 글자색). 옛 `TreeItemChevron` 노드 (2026-10-04 「1안」) 는 쓰이지 않는다. **Disclosure 의 chevron** 도 ADR-256 Phase 8c (2026-10-08) 부터 owner-drawn part 가 아니다 — 레퍼런스대로 `Disclosure > Heading > Button[slot=trigger] > Icon + 제목 Text {title}` + `DisclosurePanel` 의 작성자 노드 (DOM = RAC Disclosure 가 trigger 에 펼침 속성을 주는 RAC Button, 모양은 Disclosure sheet 의 하위 선택자 · Canvas 는 같은 값을 Disclosure part rule 로 — Heading 과 frame 을 건넌다, glyph = Icon 노드 — 펼치면 `chevron-right` 만 돈다: DOM `[aria-expanded='true'] .react-aria-Icon[data-icon='chevron-right'] svg` 90° · Canvas `chevron-down`). 펼침 판정은 DisclosureGroup 안이면 가장 가까운 조상 그룹의 키 (`catalogDisclosureGroupOf` — RAC 그룹 context 처럼 깊이 무관). 옛 `DisclosureHeader` · `DisclosureChevron` · `DisclosureContent` type 은 8e 에서 삭제했다.

**Color 조작기 (ADR-258 Phase 2, 2026-10-12)**: ColorArea · ColorSlider · ColorWheel 은 레퍼런스 노드 트리다 — `ColorArea > ColorThumb` · `ColorSlider > Label + SliderOutput + SliderTrack > ColorThumb` · `ColorWheel > ColorWheelTrack + ColorThumb`. 그라데이션 · thumb 자리 · 표시색은 문서 값의 함수 (`runtime/colorControlGradient.ts` — 설치 react-stately `Color`, oracle = 설치 RAC 출력) 하나를 RAC (Preview inline) 와 Canvas (파생 `_colorGradient` · `_colorThumb` → `skiaPrimitive` 4, `runtime/colorControlParts.ts`) 가 같이 따른다. thumb · track 의 모양 · disabled 회색은 rule (ColorThumb · ColorArea · ColorSlider · ColorWheel — `rootSelectors` 가 RAC 상태 표시의 정본, `skipStateStyles`).

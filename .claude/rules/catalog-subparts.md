# catalog 부품 노드 · 소유 축 참조표

> D1/D2/D3 경계와 대칭 원칙은 [ssot-hierarchy.md](ssot-hierarchy.md) §1 D3 가 정본이다. 아래는 그 원칙이 컴포넌트 가족별로 어떤 노드 트리 · 소유 축 · 심볼로 구현돼 있는지의 사실 — 바뀌면 여기만 고친다 (2026-10-15 ssot-hierarchy.md 에서 분리).

**D3 sub-part — field 가족의 부품 노드 (ADR-253 Phase 3, 2026-10-07 — ADR-923 Phase 5 후속의 2026-09-03 · 09-04 판정을 대체)**:

- field · 그룹의 Label · Description · FieldError · Input · DateInput · Button (NumberField 증감 · FieldButton · Select 의 trigger) 은 **부품 원본의 instance** 다. Preview/publish DOM 은 그 노드를 RAC 컴포넌트로 부모의 RAC context 안에서 직접 그리고 (`catalog/runtime/domBinding.runtime.ts` · `delegatedDom.runtime.ts`), 모양은 **부품 자신의 rule** 이 정본이다. 부모 rule 의 delegation 은 배치 (폭 · flex · margin · 버튼 자리) 만 선언한다 — 정적 게이트 `adr253PartShapeOwner.static.test.ts`.
- **편집 축**: style 은 부품 노드 자신이 정본이다 (Styles 패널이 그대로 편집, Canvas 와 DOM 이 같은 record). **글자 축만** 부모 소유인 부품은 `TEXT_ONLY_SUBPART_PARENTS` (Label · Description · FieldError · Input · Select 의 SelectValue — 글자는 부모의 `label` · `description` · `errorMessage` · `placeholder` prop 이 정본). 술어는 `resolveDelegatedSubpartOwnerType` (글자 축 · 전체 — Properties 패널) 와 `resolveSubpartStyleOwnerType` (style 축 — Styles 패널 · AI style 편집) 이고, catalog record 로는 `catalogSubpartOwnerType` (`catalogRuntime/subpart.ts`) 이 읽는다.
- **field 의 control `Group` 은 자기 style 의 주인이다 (2026-11-13, 사용자 보고 「ComboBox · DatePicker 의 Group Layout 탭 사용 안 됨」 — 그전에는 두 축 모두 부모 소유)**: NumberField · ComboBox · DatePicker · DateRangePicker · SearchField · TextField · TextArea · ColorField · DateField · TimeField 바로 아래의 RAC `Group` 노드 (ADR-256 Phase 6b, `FIELD_CONTROL_GROUP_HOSTS`). 기본 모양 · 배치는 field rule 의 delegation 이 주고, Group 에 작성한 값이 두 consumer 에서 이긴다 — DOM `nodeTreeControlGroup` 이 작성 style 을 inline 으로, Canvas 는 record 의 작성값 (상자 Group 은 `fieldBoxLayout` 이 작성한 키를 비운다). `ownsSubpartDirect` 는 control Group 을 부모 소유로 세지 않는다 (게이트 `drawnBoxModel.test.ts` 「a field's control Group is edited directly」). 구조 — NumberField · ComboBox · DatePicker · DateRangePicker · SearchField 는 노드를 RAC `Group` 으로 그린다 — SearchField 는 S2 대로 `SearchField > Label + Group(Icon + Input + Button) + Description + FieldError` 다 (2026-11-13 사용자 「NumberField 처럼 S2 구조로」 — 전에는 ADR-256 G5 예제 5 의 레퍼런스 grid: 글리프 · 지우기 버튼을 margin 으로 Input 위에 겹쳤다. RAC SearchField 는 `GroupContext` 를 주지 않아 Group 이 field 의 disabled · invalid · read-only 를 직접 받는다, 지우기 버튼의 글리프 크기는 Group 을 건너 field rule 에서 — `CATALOG_PART_RULE_PASS_HOSTS.Group`) (ComboBox 는 `.combobox-container` — RAC picker 가 그 Group 을 Popover 기준으로 삼는다, 6d · 6e). field 의 size 는 Group 을 건너 부품에 닿는다. 판정 `ownsSubpartDirect`. NumberField 의 Group 은 S2 `FieldGroup` 상자 자체다 (`CATALOG_BOXED_FIELDS` — 패널 실효값은 상자 레이아웃 입력을 읽고, radius · 칠 · Min H 는 그리는 값 — `catalogDrawnFieldBoxVisual` · `catalogFieldBoxRole` → Styles context `drawnPaint`: Group = Input rule 의 크기별 radius · 테두리 · 바탕, 안의 Input · DateInput = radius 0 · 투명 · min-height 0 (`CATALOG_FIELD_BOX_INPUT_STYLE`), 작성값이 이김 — 2026-11-13). 두 축 모두 부모 소유로 남은 것은 owner 가 그리는 part (`OWNER_DRAWN_PART_OWNERS` — 아래 toggle indicator) 뿐이다. style 축만 부모 소유인 부품은 없다 (`STYLE_ONLY_SUBPART_PARENTS` 비어 있음).
- **picker 의 선택 목록 · 달력 · Menu (ADR-253 Phase 4 · ADR-256)**: Select · ComboBox 의 항목은 Popover 안 ListBox (ListBox 원본의 instance) 의 slot 채움이고, DatePicker · DateRangePicker 의 달력은 `Popover > Dialog > 달력` (S2 `CalendarPopover`), Menu 는 `MenuTrigger > Button + Popover > Menu` 다. 항목을 picker 루트의 직계 자식으로 두지 않는다 (소유자 계약 `RAC_SUBPART_OWNER_TYPES`). Canvas 는 닫힌 목록을 그리지 않는다 (`TRIGGER_OVERLAY_CHILDREN`). 요소가 없는 노드 (`catalogElementlessType` — trigger · `display: contents` · RAC 부품) 의 Design Layout · Style · Text 탭은 안내만 낸다. 상세 (트리 · 값 소유 · 선택 표시 글리프 · Autocomplete · 하위 메뉴 · MenuItem grid · Why): [reference/catalog-subparts-details.md](../skills/composition-patterns/reference/catalog-subparts-details.md) — picker · 달력 · Menu 를 고치기 전에 읽는다.
- **quiet (`isQuiet`)**: field 의 상자 부품 (Input · DateInput) 이 자기 상태로 그린다 — 부품 rule 의 `&[data-quiet]` 한 정의, 요소의 `data-quiet` 는 quiet field 의 부품에 파생 값 (`presence.ts` `derivedProps.isQuiet`) 으로 실린다. Canvas도 같은 rootSelectors를 `quietStyles.ts`에서 읽어 배경·모서리·밑줄을 그린다 (ADR-253 Round 3 수리). 부모의 invalid/disabled는 부품 파생 값으로 전달한다. 상자가 Input · DateInput 이 아닌 Select (trigger Button) 는 Button rule 의 `isPicker` · `isQuiet` 조건 가지가 정본이다 (71922bd0f — S2 Picker quiet: 테두리 · 여백 0, focus 는 밑줄 inset shadow) — trigger 에 `_quietOwner` 파생 값, quiet trigger 는 `.button-base` 칠을 끈다. DateRangePicker 는 `isQuiet` 를 받지 않는다 (S2 에 없음) (2026-10-07 ADR-253 후속).
- **라벨 행 · 앞 글자 · 도움말 (ADR-259, 2026-10-13)**: field 도움말은 `FieldLabel` (라벨 행 — S2 `FieldLabel` 의 `div`, 사용자 prop 0) 안 Label 뒤의 `ContextualHelp` 원본 instance 다 (`ContextualHelp > ActionButton (quiet · icon-only) > Icon + Popover (여백 0) > frame (268 · 24) > Heading[slot=title] + Content + Footer` — S2 `ContextualHelpPopover`, 2026-11-18). 행은 라벨을 가진 모든 원본이 늘 갖고 (2026-11-18 사용자 결정 「노드로 늘 둠」 — 라벨 글자가 비면 행도 없다, `catalogFieldLabelRowAbsent`), 안 Label 의 색은 S2 `fieldLabel()` `neutral-subdued` (FieldLabel rule 의 `.react-aria-Label` — 글자가 자기 것인 Meter · ProgressBar · LabeledValue 라벨은 파생 `catalogFieldLabelRowColor`), field 레이아웃에서 Label 의 자리를 이어받는다 — 별칭 하나 (`CATALOG_FIELD_LABEL_PART_ALIASES`) 를 생성 CSS (`partAliases` → `:is(.react-aria-Label, .react-aria-FieldLabel)`) 와 Canvas part rule (글자 값 제외) 이 같이 읽는다. 부품 조회는 행을 건너서 (`PART_FRAME_TYPES`) 행 안 Label 이 field 의 라벨로 남는다. 버튼은 S2 처럼 quiet ActionButton `slot={null}` (field ButtonContext 차단 — 크기 · 칠은 ActionButton rule 의 icon-only 정사각), 이름 · Popover 이름 · 글리프는 ContextualHelp 의 `variant` 와 제목에서 파생된다 (D1 = S2 oracle). 앞 글자는 control Group 맨 앞의 Text · Icon (`slot=prefix`) 이고, 앞 글자가 든 Group 이 Input rule 상자를 그린다 (S2 `FieldGroup` — DOM `FieldBox` 별칭 · Canvas 같은 rule, 안 Input 은 상자를 내려놓는다). 앞 글자 없이도 모든 field 의 Group 이 늘 상자다 (`CATALOG_BOXED_FIELDS`, 2026-11-13 NumberField · ComboBox · DatePicker · SearchField · 11-14 DateRangePicker · TextField · TextArea · ColorField · DateField · TimeField — S2 는 버튼을 `FieldGroup` 안에 둔다): 버튼은 상자 안 S2 `inputButton` 정사각 (`{size.field-button.<S>}` — field rule delegation, NumberField 증감 글리프 (Button 정의의 증감 slot part rule `STEPPER_GLYPH_PX`) · ComboBox · Select chevron · DatePicker · DateRangePicker 달력 = XS 12 · S 14 · M 16 · L 18 · XL 20 (사용자 2026-11-13 — Button 의 `1lh` 단이 아님, field rule 의 `.react-aria-Button .react-aria-Icon svg` delegation, control Group 을 건너 `CATALOG_PART_RULE_PASS_HOSTS.Group` · `WRAPPED_PART_TOKENS`). SearchField 는 브라우저 기본 지우기 버튼 `::-webkit-search-cancel-button` 을 숨긴다). S2 간격은 자식 margin 이 아니라 객체의 layout 기본값이다 (`fieldPrefix.ts` `boxEnd`) — NumberField: Group gap = stepper gap · 끝 padding = stepper 끝 여백, ComboBox: 끝 padding = 높이 × 3/16 − 테두리 · gap 4 (사용자), DatePicker: 끝 padding S 2 · M 4 · L/XL 6 · gap = 날짜 gap (`DATE_BOX_GAP` XS 2xs · S ~ L xs · XL sm), DateRangePicker: 끝 padding 4 (S2) · 같은 gap · 시작 DateInput 은 내용 폭 · 끝 DateInput 이 남는 폭 (`catalogFieldBoxInputStyle`), SearchField: 시작 padding = 다른 field 의 `edge-to-text` (사용자 — S2 `pill` 아님) · 끝 padding 0 (S2 `paddingEnd: 0` — 지우기 버튼이 상자 끝, 사용자 2026-11-14) · gap 8 (사용자) · 지우기 버튼 = 높이 폭, 모서리 = template 의 pill (quiet 이면 inline 에서 빠진다) (DatePicker 는 DateRangePicker 상자에서 구분 글자 · 둘째 DateInput 을 뺀 모양 — 사용자 2026-11-13). 앞 글자 뒤 간격 = Input 시작 padding (XS 4 · S 5 · M 6 · L 7 · XL 8 − 상자 gap, `catalogFieldBoxInputStart` — prefix margin 아님, 2026-11-13). NumberField · ComboBox · SearchField 의 Input 은 시작 · 끝 padding 0 — 버튼 · 아이콘과의 간격은 상자 gap 하나다 (사용자 2026-11-13, `catalogFieldBoxInputEnd`), DatePicker · DateRangePicker 의 DateInput 도 끝 padding 0 (상자 내려놓기는 `CATALOG_FIELD_BOX_INPUT_STYLE` — template 값 없음). 작성 값이 이긴다 (Canvas `fieldBoxLayout` · DOM 둘 다). **Why (2026-11-13)**: 버튼 margin 으로 주자 Group 의 right padding · gap 이 0 으로 보이고 고쳐도 margin 이 남아 화면과 맞지 않았다 (사용자 보고). TextField · TextArea · ColorField · DateField · TimeField 의 Group 도 늘 상자다 (2026-11-14 사용자 「S2 구조 패턴으로」 — S2 `FieldGroup` `control()`: 시작 · 끝 padding `edge-to-text`, 안 Input · DateInput 은 padding 0, DateField · TimeField 의 크기별 최소 폭은 Group 에). prefix 를 지워도 Group 은 남는다 (그전에 저장된 문서는 마이그레이션하지 않는다 — 사용자 2026-11-14, prefix 를 넣을 때 감싸던 분기도 삭제). DOM: DateField · TimeField 의 RAC `GroupContext` (field props · ref) 는 안 DateInput 의 것이라 상자 Group 은 받지 않는다 (`DATE_BOX_GROUP_BINDINGS` — id · role · 키 처리가 한 요소에).
- **invalid 아이콘 = S2 `FieldErrorIcon` (2026-11-18)**: invalid · enabled 인 TextField · TextArea · NumberField · ComboBox · ColorField · DateField · TimeField · DatePicker · DateRangePicker 는 상자 안 마지막 입력 뒤에 `triangle-alert` 를 그린다 — 노드가 아니다 (Select 의 `pickerTrigger.ts` 글리프와 같은 방식). 입력이 끝 padding 으로 자리 (`1lh` + `fontRelative(6)` + `fontRelative(-2)`) 를 비우고 (`fieldPrefix.ts` `catalogFieldErrorIcon` → `catalogFieldBoxInputEnd`), Canvas 는 입력 record 의 파생 `_fieldErrorIcon` 으로 그 자리에 그리고, DOM 은 입력 뒤 글리프 요소를 그물 폭 0 margin 으로 겹친다 (`withFieldErrorIcon`). 필수 표시는 DOM 이 NBSP + 표시를 `nowrap` `span` 으로 묶는다 (`necessityGrouped` — 노드 · 배치 무변경).
- **오버레이 본체 = slot (ADR-278, 2026-10-21)**: Dialog `content` (`__content-region`) · `actions` (`__actions-region`), Popover · Tooltip 은 OverlayArrow 뒤 region frame (`__content-region`) 에 `content`, ContextualHelp `content` · `footer`, Menu `Items` — library contract 45. 놓은 instance 는 본체 기본 내용 (제목 · 설명 · 항목) 을 소유 노드로 갖고 (`ownSlotContents`), 커스터마이징은 Local 컴포넌트 instance 를 slot 에 (Design 패널 slot 절 · Layers drop) — Preview 의 RAC Modal · Popover · Tooltip · Menu 가 그 내용을 띄운다. 컬렉션 slot 의 채움 목록 (`catalogSlotInsertOptions` `items` 분기) 도 project 정의를 후보에 넣고 `assertNestable` 이 루트 type 으로 거른다 (MenuItem 루트만 Menu `Items` 에). Canvas 는 오버레이를 열지 않는다 — Components page 샘플만 patch `displayState: "open"` (`DescendantPatchFields.displayState`, resolver 가 instance root 층 → patch → template 순으로 읽음) 으로 본체를 ◆ trigger 오른쪽에 그린다 (`presence.ts` 닫힌 오버레이 분기가 `open` record 는 숨기지 않음). **Local page 카드의 ◆ 도 같다 (2026-10-22, 사용자 보고)**: record 의 source 가 project 컴포넌트의 template root 인 trigger (`compositionRoot.ts` `originBodyOpen` → `componentOriginOf`) 의 본체 (`presence.ts` `OPEN_BODY_TRIGGERS` = DialogTrigger · TooltipTrigger · ContextualHelp · MenuTrigger) 는 patch 없이 열린다 — page 의 instance 는 source 가 instance 노드라 닫힌 채. **Why**: ADR-279 로 원본이 Local page 에 서자 Dialog · Popover 컴포넌트의 본체가 Canvas 에서 0×0 (`display: none`) 이라 Design 패널은 240 을 보여도 편집할 상자가 없었다. picker 의 Popover 는 본체가 부품이라 slot 이 아니다 (Local 카드에서도 닫힌 채).
- **컬렉션 빈 상태 = 직계 자식 IllustratedMessage (사용자 결정 2026-10-23)** — Menu 만 S2 대로 「No results」 Text 한 줄 (사용자 결정 2026-11-18, `catalogEmptyStateType` · 모양은 Menu → Text part rule `menuEmptyStatePartRules`): ListBox · GridList · Tree · TagList · Menu · CardView · Table (`componentTraits` `emptyStateCollection`) 는 항목 밖에 IllustratedMessage 하나를 직계 자식으로 받고, **원본 template 이 기본으로 하나 갖는다** (`reusableOriginLibrary.ts` 의 `component-*__empty-state` — 놓고 데이터 연결하면 끝, 사용자 지적 2026-10-23 「사용자가 EmptyState 까지 또 해야 하는 것은 잘못」. 허용은 `nestingRules.ts` `CATALOG_EMPTY_STATE_COLLECTIONS`, 지운 뒤 다시 넣기는 `catalogSlotInsertOptions`). 끝에 붙이는 넣기 (항목 「+」 · slot fill · 팔레트) 는 빈 상태 앞에 둔다 (`structure.ts` `catalogAppendIndex`). Layers 이름은 「EmptyState」 (`layerTree.ts` `nameOf` — 노드 이름이 없을 때, type 은 IllustratedMessage 그대로: RAC · S2 에 EmptyState 컴포넌트는 없고 `renderEmptyState` prop 자리만 있다), 기본 그림은 S2 예제의 `folder-open` (template `descendantPatches`). Layers 는 Canvas 가 그리는 것만 행으로 낸다 — 항목이 있으면 EmptyState 행 없음, 바운드 데이터가 0행이면 항목 틀 행 없이 EmptyState 만 (`workspace.collectionRowHidden` → `layerTree` host `collectionRowHidden`). EmptyState 는 컬렉션과 함께만 지워진다 — `removeTargets` · `moveNodes` 가 `REQUIRED_PART_NOT_REMOVABLE` 로 거절 (`emptyStateCollectionOf`, 직계 자식만 — 항목 안에 직접 넣은 IllustratedMessage 는 자유) · Layers 삭제 버튼 없음 (`CatalogLayerNode.emptyState`). RAC 가 요구하는 부품이 아니라 `RAC_REQUIRED_PARTS` 에는 넣지 않았다 (그 표는 조상 어디서나 찾는다). DOM 은 RAC `renderEmptyState` 로 그리고 (`catalogEmptyState` — 바운드 목록 첫 로드 중엔 S2 진행 원), Canvas 는 같은 조건을 `catalogHiddenAtRest` 의 `catalogCollectionHasItems` (RAC `collection.size` 처럼 `item` 만 — section 안 항목 포함, loader · Header · Separator 제외) 로 읽는다. 수동 `[data-empty]` 규칙은 Builder 자체 목록 전용 (`:not([data-catalog-id])`). **CardView · Table (S2 체크리스트 부록 D.3 2단계, 2026-11-23)**: CardView 는 위와 같다 (빈 상태 노드 = 두 열을 걸치는 grid item `gridColumnStart 1 / End -1` · 가운데). Table 의 빈 상태는 TableBody 가 아니라 **Table 의 직계 자식** (TableBody 뒤, slot 없는 원본 자리) 이다 — TableBody 의 자식은 늘 Row 라는 전제를 열 · 행 명령 · 행 표본 · 칸 정렬 검사가 읽는다. DOM 은 그것을 RAC TableBody 의 `renderEmptyState` 로 넘기고 빈 본문의 RAC `tr` · `td` 는 `display: contents` (`Table.css` — 가상 RAC 표와 같다), Canvas 의 항목 판정은 TableBody 의 Row (`catalogCollectionHasItems`). 좌우 margin auto · 위아래 40 (S2 빈 본문 40 inset) 이라 Table (block) 과 TableBody (flex) 두 문맥에서 같은 자리다. Code 보기는 그 자리를 구조 위치로 세지 않는다 (`codeViewEmptyStatePosition` — S2 는 `renderEmptyState` prop).

- **S2 감싸개 frame — SideNavPanel · Tag (2026-11-18)**: SideNavPanel = `frame (내용, 세로 · grow) > SideNav` + `frame (바닥, margin 4) > ActionButton[slot=collapse, quiet]`, SideNav 항목의 Icon 은 SideNavItemLink 안 (S2 `treeRowLink`). **Table 열 트랙 · 칸 (ADR-257 · 277 · 315)**: 열 폭은 Column 의 S2 `width` · `minWidth` · `maxWidth` 가 정본이고, 트랙 목록은 Table 마다 하나 (`runtime/tableTracks.ts` → 파생 `_tableTracks`) 를 Canvas `styleOf` 와 DOM 이 같이 읽는다 — Column · Cell 에 flex 몫이나 자기 폭을 주지 않는다. 칸 값 (`align` · `showDivider` · `overflowMode`) 은 Column · Cell rule 의 `containerVariants` 가 정본이다. 선택 checkbox 열 · drag 열 · 터치 폭 (기기 두 벌 토큰) · 칸 여백은 파생 값 하나 (`catalogTableSelectionPartHidden` · `_tableSelectionPart` · `_tableDeviceTracks`) 를 두 consumer 가 읽는다. 표는 Table 하나다 (ADR-277). ADR-315: 숨김 · 순서 · 고정은 resolver 의 열 투영 한 곳 (`resolution/tableColumns.ts`) 이 트랙 · 머리글 · 모든 행의 칸에 같이 적용한다 (Builder 는 「Hidden by default」 Column 을 record 로 남겨 Layers 에서 흐리게 보인다). 고정 경계선은 rule (`pinned-edge`), 작성 정렬의 표시는 감싸개 record 의 `_sortMark` 와 그 앞 part. 병합 열이 있는 표는 행 선을 칸이 그린다 (Row `cell-lines` · Cell `merge-line` 파생 변형 — Canvas 칠 · DOM inline · 엔진 입력이 같이 읽는다). 상세 (정렬 표시 · 크기 조절 · drag 열 · 선택 열 · 터치 값 · Why): [reference/table-data-grid.md](../skills/composition-patterns/reference/table-data-grid.md).

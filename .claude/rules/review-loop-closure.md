# 판독 루프 종결 규칙 — 커버리지 지적은 끝이 없다 (CRITICAL)

> 정본. 2026-09-03 사용자 지적으로 확정 — ADR-923 본체 (34 라운드, 13~28 이 HIGH 0) 와 FieldError 후속 (5 라운드, 4·5 가 동작 변경 0). frontmatter `paths` 없음 = 상시 로드. 실행자 (Claude) ≠ 판독자 (Codex) 루프와 `/review` · `/review-adr` 결과 처리에 같이 적용한다.

## 1. 라운드 상한 — 종결은 실행자가 선언한다

- **phase 당 판독 1회 + 수리 검증 1회.** 수리 검증에서 HIGH 0 이면 phase 닫힘. 실행자가 선언하고 ledger 에 기록한다.
- "종결 round" 가 한 번 열리지 않으면 재시도하지 않는다. 종결 기준이 판독자에게 있어 도달 불가한 상태이므로 사용자에게 보고한다.
- 후속 목록 항목의 닫힘도 실행자 선언이다. 근거는 동작 확정 (원복 RED + live 1회). 판독자의 "닫힘" 판정을 종결 조건으로 두지 않는다.

## 2. 이슈 판정 — severity 보다 재현 여부

- 판독 이슈를 받으면 먼저 묻는다: **production 에서 실제로 깨지는 시나리오가 있는가.** 있으면 severity 그대로 수리한다.
- 없는 커버리지 지적 (`evidence-missing` · 게이트 미비 · "테스트가 이 층을 안 돈다") 은 **LOW deferred**. 라운드 재개 사유가 아니다.
- 커버리지 지적에 "채우기" 로 답하지 않는다. **가설 1개 + 반증 케이스 1개**로 답한다. 반증이 RED 면 결함으로 승격해 수리, GREEN 이면 LOW deferred 로 기록하고 끝낸다.
- 스킵 금지는 CRITICAL/HIGH 뿐이다 (CLAUDE.md §작업 워크플로). MEDIUM 은 위 판정을 거친다.

## 3. 절차는 변경 종류에 맞춘다

| 커밋 종류                        | 원복 RED                  | 회귀               | live    | 문서                          |
| -------------------------------- | ------------------------- | ------------------ | ------- | ----------------------------- |
| 동작 변경                        | 전량                      | 관련 스위트 전량   | 필수    | evidence · README · CHANGELOG |
| 동작 변경 0 (테스트·리팩터·문서) | 새 게이트가 반응하는 행만 | 해당 패키지 스위트 | 생략 가 | evidence 한 절                |

동작 변경 0 인 커밋에 원복 매트릭스 전량 재측정을 돌리지 않는다.

## 4. 판독 프롬프트 필수 문구

> production 재현 시나리오가 없는 커버리지 지적은 LOW deferred 로 분류하고 라운드 재개 사유로 삼지 않는다. phase · 후속 항목의 닫힘 판정은 실행자가 한다.

## 5. Red flags

- "종결 round 재시도" 가 2회째다 → 즉시 사용자 보고.
- 커밋 diff 에 `src` 동작 변경이 0 인데 원복 매트릭스를 전량 다시 잰다.
- 한 라운드의 이슈가 전부 `evidence-missing` / `doc-drift` 다 → 종결 선언 시점.
- 다음 라운드 프롬프트를 쓰며 "이번엔 닫히겠지" 라고 생각한다 → 종결 기준이 판독자에게 있다는 신호.
